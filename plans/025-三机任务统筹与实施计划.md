## 一、家机 win-x64 节（本机维护）

### 1.1 本轮（**229-a**，基线 d423a07）：**F1-30-ASan 三项之①——AddressSanitizer 可选构建接入 + 内存错误检出（单测面）**

**1. 目标与验收判据**

- 目标：① 宿主接入 **ASan 可选构建**（`-DCN_ENABLE_ASAN=ON`）；② 用 ASan 构建**跑单测检出内存错误**（泄漏/越界/UAF）；
  ③ 缺陷零容忍（有则根治）；④ **默认构建产物零变化**。
- 验收判据：ASan 构建**零警告**；ASan 下**单测全过**且**无内存错误报告**；默认构建锚定链**逐字节不变**。

**2. 写集（最终）**

- `CMakeLists.txt`（`CN_ENABLE_ASAN` 选项块·**位置=所有 target 定义之前**）
- 文档：`plans/021`（§3-F F1-30 行 + 戳）、本节、`更新日志.md`、`HANDOFF.md`、`lessons.md`、`三机任务看板.md`

**3. 实施步骤与实测结果**

1. **CMake 接入 ✅**：`option(CN_ENABLE_ASAN ...OFF)` + 平台分支——MSVC `/fsanitize=address`（**显式移除 `/RTC1`**
   Debug 运行时检查冲突 + `/INCREMENTAL:NO`）/ GCC `-fsanitize=address -fno-omit-frame-pointer`；
   **★位置纪律：必须置于所有 target 定义之前**（`add_compile_options` 只影响其后的 target——
   否则 gtest 无 ASan 注解而主目标有 → **LNK2038 STL 注解不匹配**；且删除块时须核对 `endif` 配对）。
2. **ASan 构建零警告 ✅**（`cmake -S . -B target/build-asan -DCN_ENABLE_ASAN=ON` → `--build ... --config Debug`）。
3. **ASan 版单测 ✅**：**1327/1327 全过**；ASan 报告**无越界/无 UAF**；唯一输出=`AllocFailureReturnsNull`
   测试**故意超大分配**触发的 `allocation-size-too-big` → 按标准实践以 **`ASAN_OPTIONS=allocator_may_return_null=1`**
   运行（该测试语义=验证分配失败返回 null，ASan 默认 abort 与之冲突——**非缺陷**）。
4. **默认构建零变化 ✅**：主构建重建（零警告 + 单测 1327/1327）→ **锚定链逐字节不变**
   （426813 行·`f67e8f4f48f5a3914769`）——**CMake 改动仅在 ASan 开启时生效**。

**4. 验证链（实测）**

ASan 构建（零警告）→ ASan 单测（1327/1327·无内存错误报告）→ 主构建重建（零警告 + 1327/1327）→
锚定链逐字节不变 ✓。

**5. 边缘情况与诚实边界（收工回填）**

- **ASan 版 E2E 未跑**（会话收尾·时间边界）——**检出面=单测 1327 用例**；E2E 面可后续轮补（命令已文档化）。
- **MSVC 的 ASan 不含 LeakSanitizer**（Windows 平台限制）→ **泄漏检出面为零**（越界/UAF 检出面正常）；
  **泄漏检测**请用 Linux 侧（`ASAN_OPTIONS=detect_leaks=1`）或 valgrind（深度机 225-a 已用）——**诚实边界**。
- **两构建共用输出目录**（`target/Debug`）→ **ASan 构建会覆盖普通产物**：**ASan 验证后必须重建主构建**
  （本轮实测：混用产物导致 `LNK1319 237 项不匹配` → 清理 `target/Debug/*.{exe,lib,exp}` 后重建恢复）；
  使用纪律入 lessons。

**6. 与他机交叠分析**

- 深度机 227-a（A7 本体·v2 树）/ 单位机（mem2reg/D8/F2-33）：**零交叠** ✓（本轮只改根 `CMakeLists.txt`）
- 契约面：**默认构建产物零变化**（锚定链逐字节不变）→ **他机无需复跑**；ASan 为**开发期可选**构建 ✓
