## 三、与 C++ 对比：需强化完善的方面

1. **引用/移动语义缺失（本次实测确认缺陷）**：规格书 5.6 友元示例（账户&）、泛型示例（T& 交换）都声明了引用参数，实测 整32& **语义检查放行、x64 代码生成汇编失败**（ml64 A2022 操作数尺寸不一致）——半实现状态。C++ 的 T&、右值引用、移动语义是容器性能与接口设计的基础（如 向量<T> 追加大对象、字符串返回）。
2. **标准库覆盖度**：项目自评 P0 完成约覆盖 C++ 常用核心域 ~80%，但**实际交付与设计方案的差距**：数学库缺随机数/对数/复数；映射/集合为 O(n) 线性查找；无迭代器/range-for（遍历容器只能手写索引循环）；向量<T> 有 8 字节槽缺陷。
3. **智能指针/RAII 规范**：全部靠手写析构 + 手动释放，无 unique_ptr/shared_ptr 等价物（P1 待定）。字符串裸指针 + 调用方负责释放的约定，是 C++ 的原始版（无 std::string 的自动管理）。
4. **工具链成熟度**：无 CI、无增量编译、无 Sanitizer/泄漏检测集成、DWARF 调试信息仅预留、无性能基准数据。MSVC 上构建依赖 VS 开发者环境（本次实测 PATH 中无 cmake）。
5. **预处理器能力弱于 C++**：只有条件编译，无宏展开（#定义 仅定义开关），无 #include（模块制已替代，合理）。

## 四、与 Rust 对比：需强化完善的方面

1. **错误传播运算符缺失**：结果/可选 强制检查很好，但嵌套调用（如 文件→读取→解析 三层）每个 结果 都要手写 if 分支。Rust 的 ? 运算符可一键传播。建议加 传播 关键字或 ?（可选链语法已有 ? 预留 token）。**这是自举前最值得补的语言糖之一**。
2. **迭代器与链式组合缺失**：Rust 的 map/filter/fold 链式处理是生产力核心；CN 有 lambda 但无迭代器抽象。建议 P1：遍历(回调) 简化版 + range-for（对 元素 属于 容器）。
3. **模式匹配缺失**：枚举带值但没有 match/解构，错误处理只能 .正常/.值 判断。若引入 选择 增强（值匹配 + 解构）可显著提升表达力。
4. **类型跨模块隔离未完成**：v2.0 核心承诺「跨包同名符号不冲突」在函数维度已达成，**类型/常量维度仍是全局去重**（缺陷 A-2）——这正是 Rust crate 的立身之本。
5. **包生态缺失**：货舱.toml 无注册中心/版本解析；无 build script、无 features 开关。FFI 缺失意味着无法借用 C 生态（正则/数据库/图形库），这是与 Rust 生态差距的根。
6. **无测试/文档/格式一体化**：cargo test/doc/clippy/fmt 是 Rust 生产力闭环，CN 只有 gtest + E2E 脚本。

## 六、亮点确认（保持，不必动）

3. 模块系统 v2.0 完成度高（10 层、54 E2E 全绿）。

5. 测试纪律好：1110 单测 + 54 E2E + lessons.md 25 条经验沉淀，这是项目最珍贵的资产。

## 七、后续路线建议（等您批复）

### 核心判断
阶段 7 自举 = 用 CN 重写 6 万行编译器。**自举的成功率取决于 CN 表达力与标准库成熟度**——用现在缺引用、缺错误传播、缺迭代器的语言写编译器（语法分析器、符号表、IR 都是重样板代码场景），会非常痛苦。因此建议顺序：

**第一批（正确性收尾，A-1~A-5）→ 第二批（工程化，B-1~B-3 + README）→ 第三批（语言补强，C-1~C-3 择需）→ 第四批（阶段 7 自举）→ 长期（生态）**

### 第一批：正确性缺陷修复（A-1~A-5，约 5~8 项任务）
1. A-1 引用类型：修实现或降规格（建议修实现：T& 参数/返回，容器 读取 可返回引用）
2. A-2 类型级 crate 分桶（最高优先级后续项，HANDOFF 已论证）
3. A-3 向量 8 字节槽修复（容器.cn 按 sizeof 分配）
4. A-4 跨模块泛型类字段类型键统一
5. A-5 模块边界 5 项（moduleFilter 传播等）

### 第二批：工程化（1~2 天级任务）
6. CI 接入（gitcode CI 或 GitHub Actions：构建 + 1110 单测 + 54 E2E 门禁）
