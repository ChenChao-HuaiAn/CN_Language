## 一、问题诊断（用户痛点与旧模式失败根因）

**用户痛点（2026-09-18）**：
1. 开发锁唯一 ⇒ 每刻只有 1 机产出代码变更，另 2 机最多测试——**浪费 2 台机器**；
2. 测试机发现漏洞只能登记排班、不能当场修——**不够灵活**；
3. 09-15 曾放开三机并行，但公共文件写入总出错，且他机看到错误不主动维护（不在职权范围）。

**09-15 多锁直推失败的三大根因**（lessons 4410·231-a 裁决实录）＋衍生事故：
1. **语义耦合**：写集不相交只防 git 文本冲突，防不住「A 改的接口/语义正是 B 任务的依赖面」；
2. **验证基线漂移**：A 的验证结论锚定的基线被 B 的提交推进后失准（「结果打架」）；
3. **一致性真空**：多锁下没有任何一台机器对全局状态负责，合并口径靠各机自行裁决；
4. 衍生事故：轮次撞号双占（185-a）、rebase 冲突标记入库多日（229-a/233-a）、HANDOFF 指数膨胀
   （lessons 206）、验证轮同信息 30+ 连推（281-a）、plans/021 裁决留档三犯（B5/C21）。

**关键认知**：旧模式的错误不在「并行」，而在「N 机直推同一条共享分支（develop）」——
共享可变状态无隔离。业界几百人并行开发同一仓库（rustc/Chromium/Google）从不靠单锁，
靠三件套：**分支隔离 + 串行受控集成 + 门禁跑在合并结果上**。三大根因各有对应解，
不需要退回单锁：
- 语义耦合 → 门禁在「develop+分支」的**合并结果**上跑（不是分支孤证）；
- 基线漂移 → 集成时强制 rebase 到最新 develop 再验证，结论永远标注 commit；
- 一致性真空 → develop 恒绿恒唯一事实源，分支=隔离实验区，集成=唯一入关口（串行）。

## 三、用户裁决记录（2026-09-18）

1. **缺陷处置权=分级处置**：机制级缺陷（实现 bug·根因唯一·不新增语言语义）当场开分支修、
   修完随证据备案；语义/规范级（语言语义/新关键字/规范缺口/架构决策）先呈报三方案经裁决再修。
2. **跨平台门禁=按风险分层 try-build**：三平台产物相关写集（src/tests/CMake/build/ci.ps1）
   → 三平台 try-build 全绿才集成；纯文档/平台无关脚本 → 本机门禁；另两平台始终集成后验证兜底。
3. **共享文档=随分支走+集成时合并**：开发期文档改动全进分支，集成时随代码串行合并；
   看板保留直推作轻量实时状态。

## 四、机制细则（与 AGENTS.md §8 同步的摘要）

1. **分支即开发（§8.1）**：分支名 `任务/<机>-<轮次>-<标识>`；推分支=认领（分支名远端唯一=
   天然防撞号——185-a 教训机制化根治）；分支 ≤1 工作日、每日 rebase；看板降为纯信息板。
2. **队列即集成（§8.2）**：`scripts/integrate.py`=develop 唯一入关口——fetch→rebase（冲突自己解·
   禁止 develop 手解）→写集分类→门禁（跑在合并结果上）→push ff-only（CAS 竞争输家自动重试 ≤3）→
   github 镜像补推→通告段广播影响面。
3. **分层验证（§8.3）**：try-build 触发面=src/**、tests/**、CMakeLists.txt、build.ps1、
   scripts/ci.ps1；流程=推分支→通告段点名→另两机在分支上验各自平台→回签→全绿才
   `--try-build-done` 集成；超时 2 小时挂起不降级；集成后验证常设（B8 采样/回归轨/全量门禁）。
4. **缺陷分级（§8.4）**：判定=修复会改变 plans/001 规范条文/新增语法→语义级；其余→机制级；
   模糊按语义级。机制级修复须含 famscan 复跑归零+负测/E2E 转正。
5. **文档随分支（§8.5）**：开发期 plans/025/HANDOFF/更新日志/plans/021/lessons 改动全进分支；
   分区规则保留=合并友好结构保证；直推窄通道=看板+服务轮写面；服务轮同轮单提交。
6. **职权 fix-forward（§8.6）**：「不在职权范围」废除→「一切行为面改动走自己的分支」；
   他机分支问题=通告+可基于其分支开修复分支；develop 红=全员停+破坏者优先修+任何人可 revert。

### 6.8 任务队列纪律（2026-09-21 用户批「方案甲」·机械防线挂 check_handoff/check_progress_sync）

1. **优先级区约束**：认领非高优区任务前，核对高优区（P0/A 区）无「本机平台可做且无阻塞」项；
   跳过须在 025「交叠分析」写明理由留痕。
2. **状态行必带「下一棒」**：021 §三凡 🔄/⬜/⏸ 的表格行必须写明「下一棒=」（动作与归属）；
   🏃 豁免；check_handoff 拦截。
3. **观察期/挂起带截止条件**：观察期行写收口判据（如「连续 3 轮零复发→转硬错误」）；⏸ 行写重启
   触发——禁止无期限观察/挂起。
4. **挂账老化审计**：check_progress_sync 对 🔄/⏸ 行做老化 WARN（引用轮次落后 git 最新非窄通道轮次
   >40 轮即报警）；报警行当轮必须处置。
5. **侦查→修复接力登记**：侦查/评估轮收工必须在 021 立后续行（修复轮/架构轮候选），不允许侦查完无下文。
6. **依赖即父子号（2026-09-22 用户令）**：任务依赖其他任务先完成的，必须以父子任务号（`父号-三位子序`）
   或行内显式引用「`任务 NNN`」立账——**禁止只写轮次号**（轮次=执行批次非任务实体·销账后依赖链断裂）；
   check_handoff 拦截无任务号引用的依赖语义「下一棒」。**父子销账方向（2026-09-27 用户令）：父任务
   销账前置=全部子任务销账**——子可先销（父行显示子完成度）；全部子销后父方可销（父销项行必须列
   子任务清单）；禁止父先销带走未完成子。

**七条总纲**：
1. **分支即开发**：废除开发锁；每机每轮一条任务分支，推分支到 gitcode=认领生效（§8.1）。
2. **队列即集成**：develop 是唯一事实源，入 develop 必经 `scripts/integrate.py`（全表至多一个集成
   在飞·push 原子 CAS·输家自动重试，§8.2）。
3. **门禁即审查**：门禁跑在**合并结果**（rebase 最新 develop 后）上，不在分支孤证上（§8.2）。
4. **异步验收·零等待**：集成不需要任何他机回签/批准；跨平台正确性由集成后异步验收+修复义务保障（§8.3）。
5. **修复权分级放开**：机制级任何机当场开修复分支修完备案；语义/规范级先呈报三方案经用户裁决（§8.4）。
6. **文档随分支走**：共享文档开发期改动全进分支，集成时串行合并（§8.5）。
7. **develop 尽绿+fix-forward**：平台红灯按义务链修复（引入者优先→任何机可修→超 48h 任何人可
   revert）；**红灯期间不冻结集成**（§8.3/§8.6）。

**两态角色**：**开发轮**（任务分支·可多机并行）｜**服务轮**（补验收/探针/E2E——免分支免轮次号·
仅写 §8.5 窄通道；B8 面台账巡视=默认动作·B9 famscan 维持）。

### 8.1 分支即开发（认领=推分支）

- **分支命名**：`任务/<机>-<轮次>-<标识>`。轮次号纪律（先到先得）：`git fetch` 后以**远端 develop
  看板在飞行轮次号**为占用权威（不看 git 历史），取未占用号（可跳号）；分支名远端唯一防同机撞号
  （被拒即换号重推）；跨机同号由看板先行拦截+check_handoff 唯一性检查兜底。
- **看板先行（强制第一动作）**：开工第一动作=`git fetch`→定分支名→**直推看板本机行**（🏃+分支名+
  一句话）到 develop（§8.5 窄通道①）→**然后**才开分支动手（看板=在飞唯一实时广播·写进任务分支=
  他机不可见）。**收工销账**：集成成功后立即清空本机行（⬜+各列「-」）并直推。
- **认领=推分支**：fetch→看板行已直推→开分支→六要素落盘 025 本机节（§8.7）→首次提交并 push 分支
  ——push 成功=认领生效。github 镜像只推 develop，任务分支不推。
- **看板行格式**：🏃+分支名+一句话（纯信息板无锁语义；check_handoff 校验含 `任务/` 分支名+「开工
  自检」：当前分支为 `任务/*` 时看板必含该分支名）。
- **分支生命周期**：单分支 ≤1 工作日，长任务拆多分支接力；每日至少 rebase 一次 develop。
- **集成即删分支（710 用户裁决）**：integrate.py 集成成功后自动删远程任务分支（不删即积压）；
  放弃/中止分支当轮收工手动删或定期 `python scripts/branch_cleanup.py` 兜底（默认 dry-run）；
  挂等保全分支（看板 ⏸ 引用）不受影响。
- **停机移交（2026-09-27 用户令）**：某机停机/开发机唯一化时，其全部在飞/挂等任务由在飞开发机
  **移交接手**（不允许无限期挂等）——①逐行甄别回写 021「下一棒」（分支资产三态=重推保全/摘取
  rebase 集成/判废删）；②看板停机机行清空+接手机通告段移交广播；③摘取他机分支禁 force push。
  移交≠销账·任务面不降级。
- **修复分支**：任何机可从最新 develop 开修复分支；紧急可基于他人在飞分支开自己的修复分支——
  **禁止直接改他人分支、禁止 force push 他人分支**。

### 8.2 队列即集成（develop 唯一入关口=scripts/integrate.py）

**一切入 develop 的行为面改动必须经 `python3 scripts/integrate.py`**（在任务分支上运行）：
①前置自检（分支名合法/树干净/已推远端）→②fetch→③rebase 最新 develop（冲突在**自己分支**解·
脚本自动 abort；**禁止在 develop 上手解冲突**——233-a 铁律）→④写集分类（自动判定门禁深度·见 §8.3）
→⑤门禁（冲突标记 grep+三门禁+写集核对〔`git status` 出现非本轮写集文件=事故信号〕；写集触
src/tests/v2/stdlib/构建编排=零警告构建+单测+E2E 全量；纯文档/平台无关脚本=快速门禁）→⑥
`git push gitcode develop`（**ff-only**·被拒回②重试 ≤3 次）→⑦补推 github 镜像+看板通告段发
**验收请求**（基线 commit+要点+影响面）即收工。

**6.5 已验复用直推（2026-09-29 用户令）**：同一写集已在本机对「与最新 develop 差异仅文档/新基线」
的内容跑过一次全量门禁且全绿时，允许免重跑直推集成。口径（缺一不可）：①**内容等价**：当前树相对
develop 的写集与已验轮次逐字节一致（`git diff <已验树> <当前树> -- <写集>` 为空·或差异仅文档面）；
②**证据留痕**：提交信息写明「全量门禁已对同内容验 N 次全绿＋直推」+看板披露；③**路径**：fetch→
merge develop（限文档冲突）→快速门禁→`git push gitcode HEAD:develop`（ff-only·禁 force）；④**红线**：
写集/内容任何实质变化（源码 1 字节/新测试/构建编排）→必须重跑全量；新引入红灯点名放行=违规。

**全表至多一个集成在飞**（push 原子 CAS·输家自动重试）；**禁止 force push 共享分支 develop**；
OOM 等平台固有败面不算打架。

**integrate.py CLI（866 登记·911 扩批量化面）**：`--dry-run`（只检查不推送）；`--allow-known-red <名>`（点名披露
既有红放行·禁用于本轮新红）；批量化面（911·8.2-B）=`--join/--status/--solo/--wait/--seal-now/--takeover/--drop <分支>/--selftest/--verified-same-content`；`--try-build-done`/`--win-verified` 已废（传入仅提示）。写集触发面
**运行时权威=`scripts/integrate.py` 内 `全量门禁触发模式` 常量**。

### 8.3 异步验收制（v3·跨平台正确性保障）

**8.2-B 批量集成（bors 式·911 立·用户批准方案甲·治 6.5 所述竞争循环的根治机制）**：
6.5 是「同一份内容免重付体检费」的事后补救；本条是「**一次全量验整批**」的结构性根治——
批=原子集成单位（对批链顶跑一次门禁=跑在整批合并结果上·语义耦合覆盖不降级·竞争作废归零，
业界对照=rustc/bors batching/GitHub merge queue）。**收工标准动作改为**：任务分支上
`python3 scripts/integrate.py`（自动报名入看板「集成队列」段→等待成为批主→组批→整批集成；
`--join` 仅报名、`--wait` 挂轮询等待）。机械规则（全部内置于脚本·参数为脚本顶部可调常量）：
①**先到先得当批主**：报名时刻最早者=批主（341-a 同哲学）；**收拢期 10 分钟**（批主报名后
窗口内报名者入批·攒满 5 个提前封批·**队列仅自己时立即单飞不等待**）；
②**组链**：按报名序 cherry-pick 叠链（develop→成员1→成员2→…）——冲突=**踢出后到者**
（批不因成员卡死·被踢者本机解完冲突重新 `--join`·原批主本机分支冲突亦可自行解后重报）；
③**门禁红**：脚本打印「成员×写集」归因辅助，批主归因后 `--drop 任务/<分支>` 踢出重组链重验；
④**批主失联 ≥30 分钟**：成员可 `--takeover` 接管组批（防会话死亡卡队）；
⑤**销账**：push 成功即删全部成员远端分支（710 集成即删）+清队列行+镜像补推；批主发验收请求
（基线+成员清单+影响面）；**cherry-pick 复制提交 SHA≠原分支头**——成员分支「已并入」判定
以脚本删除为准，勿以 `--merged` 为据；
⑥**分片（可选加速）**：`run_e2e.py --shard i/n`（用例名排序取模·并集守恒）——在线机可在
看板认领分片并行跑、批主汇总各片退出码判绿；他机不在线=批主本机全跑（弹性降级·不降正确性）；
⑦**逃生门**：`--solo`=原单分支路径（队列机制异常时用·行为=911 前）；`--dry-run` 演练不推远端。
看板写入全部走 plumbing 直推（临时 index+commit-tree·零 checkout 不扰动工作树）。
911 轮实测量纲：单飞批=旧路径等价+零竞争作废；批内每多一个成员=少一次全量门禁（约省
15~45 分钟/成员·取决于平台）。

**全表至多一个集成在飞**：push 本身即原子 CAS（v1 看板锁洞察的延续），竞争输家自动重试；
批量集成下「集成在飞」的粒度=批（批间竞争频率远低于分支间·输家整批重组链重试）。
**禁止 force push 共享分支 `develop`**（铁律保留）。
78/79 OOM 等平台固有败面与并行无关，按已知败面口径处理，不算打架。

**integrate.py CLI 参数（866 轮登记·911 扩）**：`--dry-run`（只走检查与门禁、不推送）；
`--allow-known-red <名>`（点名披露既有已知红后放行集成——必须行内写明点名依据，禁止用于
本轮新引入红）；`--join`/`--status`/`--solo`/`--wait`/`--seal-now`/`--takeover`/`--drop <分支>`/
`--selftest`（正反例自测）=8.2-B 批量集成面；`--try-build-done` / `--win-verified` 已随协议 v3
废除（传入仅打印提示、接受即忽略）。写集分类的触发面清单以
`scripts/integrate.py` 内 `全量门禁触发模式` 常量为运行时权威（§8.3 列表与代码的任何出入以呈报裁决为准）。

**共享文档编辑六纪律**（2026-09-16 用户令·交接.md 指数膨胀事故后立）：
1. **锚点=节标题，整节替换**：old/new 都从「`## 本机节` 标题行」到「下一 `## ` 标题前」整段替换；
   禁以节内行为锚局部插入（会把替换退化成追加）。
2. **一分区一记录**：任何时刻只保留最新一轮完整记录（历史由 git+019/021 承载）。
3. **标题行首独立成行**：「正文。### 标题」粘连=事故签名，回滚重做不得提交。
4. **写后即检**：编辑共享文档后必跑 `python3 scripts/check_handoff.py`（校验面=五文件：交接/更新
   日志/021/025/看板——冲突标记/重复节标题/≥30 字重复行等）；不过禁止提交。**新文件出现同类事故
   必须同轮扩门禁**。
5. **diff 规模警戒线**：单次编辑「只增不删」（新增>100 行而删<50 行）或净增>+80 行=事故签名，
   停下核对（健康整节替换净变化 ±60 行内）。

### 8.6 职权与 fix-forward

- **契约变更广播**：改 `.expected`/E2E runner/`plans/001`/cn-language-spec 等**三机共享契约**：
  必须在开发分支进行（禁服务轮顺手改），集成后看板「契约变更通告」区本机段标注变更+影响面
  （哪些用例/平台需复跑）；影响面执行完毕后（或最迟下次本机 push）删除通告段。看板表内不承载通告。

### 8.8 本机多开规约（worktree 任务池·2026-09-20 用户三裁决批准·449-a）

> 每并行任务=1 个 git worktree+1 条任务分支+1 个会话（根治多会话共享工作树互踩）。

- **worktree 任务池**：树=主仓库同级 `wt<轮次>`（**必须距 Documents 两级**·gtest 相对路径依赖此
  深度）；生命周期对齐分支 ≤1 工作日；管理=`python scripts/wt.py create <轮次> <标识>`/`list`/
  `remove <轮次> [--delete-branch]`。
- **主工作树职责收窄**：主树=develop 基准+集成+看板窄通道直推；**禁止在主树开任务分支或写任务代码**。
- **会话两形态**：重开发轮=多会话各绑一 worktree；批量轻任务=单会话后台代理各在指定 worktree 路径
  工作。开工前必 `wt.py list`+看板他机行。
- **全量门禁串行锁**：`scripts/gate_lock.py`（目录锁=主树 `target/gate.lock`·跨树共享·陈锁 4h 心跳
  接管）——同机至多一个全量门禁在飞（防 OOM 互抢）。ci.ps1/integrate.py 已内置锁；手动长验证用
  `gate_lock run -- <命令>`（run 等待默认无限）；**禁止 run 包裹 ci.ps1/integrate.py**（双层=自死锁）。
- **构建提速**：`build.ps1 --parallel`；sccache=Ninja 开发树专用（`target/build-ninja`·`cmd /c
  target\ninja_build.cmd`）；VS 生成器不支持 CMAKE_CXX_COMPILER_LAUNCHER；Ninja+MSVC 必须 `/Z7`
  替代 `/Zi`（并发写 PDB=C1041）；勿用 `-DCMAKE_CXX_FLAGS` 覆盖（顶掉 /EHsc→C4530 被 /WX 拦）。
- **并行度**（28 核/128GB 口径）：活跃开发任务 ≤3+全量门禁 ≤1（锁保证）；每树磁盘 ~1.7GB+
  缓存 5GB 封顶；`.git` 对象库全树共享。
