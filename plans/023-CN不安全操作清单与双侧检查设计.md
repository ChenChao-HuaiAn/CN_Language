## 二、设计原则（Rust 对照）

1. **对标 Rust unsafe 面，逐条注明**：凡 Rust 要求 `unsafe` 的操作 → CN 要求 `不安全 函数`；Rust 中**安全**
   的操作 → CN 默认安全（例外须有 CN 特定理由；本清单零例外收紧——见 §五）。
   *Rust 经验*：unsafe 面越大，审计负担越重；「宁少勿滥」是 Rust 社区共识（RFC 2585 同向）。
2. **最小不安全面**：每类操作都问「它是否真的能产生越界/悬垂/UB」——能，则纳入；不能（纯地址比较、纯转换），
   则不纳入（避免把安全惯用法逼进 unsafe）。
3. **双层同构**：宿主（`src/cn_compiler/semantic`）与 v2（`CN语言编译器v2/语义`）检查判定同构——
   同一条规则、同一种诊断、同一套边界案例（plans/020 移植纪律）。
4. **检查零运行时开销**：全部检查位于语义层（编译期诊断），不生成任何运行时代码（观察期=纯诊断；
   收口后=编译期拒绝）——Rust 同（unsafe 检查不产生运行时检查）。
5. **观察期迁移机制延续**（plans/019 阶段4 模式）：新类先以观察期**警告**出现（不阻断存量），
   迁移面清零后随波 6 切**硬错误**。
6. **字符串语义排除**（波 1 教训固化）：`字符串` / `字符*` 是字符串视图（非裸指针）——
   所有指针类检查一律排除（134-a 已立 `isStringSemanticType` 单一事实源，本清单全部检查共用）。

## 三、Rust unsafe 面 → CN 对照表

| # | Rust 中需 `unsafe` 的操作 | CN 对应物 | 现状态（宿主） | 处置 |
|---|---|---|---|---|
| 1 | 解引用裸指针（读）：`*p` | `*p`（一元 `*` 读） | **无检查**（仅查类型合法性） | **纳入**（B6） |
| 2 | 解引用裸指针（写）：`*p = x` | `*p = x` | **无检查** | **纳入**（B7） |
| 3 | 指针偏移/算术：`p.add(n)`/`p.offset(n)` | `p ± n` | ✓ 已实现（观察期） | 保持（A1） |
| 4 | 指针下标（解引用糖）：`*p.add(i)` | `p[i]` 读 | **无检查** | **纳入**（B8） |
| 5 | 指针下标写 | `p[i] = x` | ✓ 已实现（观察期） | 保持（A2） |
| 6 | 指针成员访问（解引用糖）：`(*p).f` | `p.字段`（CN 的 `.` 自动解引用一级） | **无检查** | **纳入**（B9） |
| 7 | 访问 union 字段 | `u.字段`（含结构体内联合体嵌套） | ✓ 已实现（观察期；嵌套已覆盖） | 保持（A3） |
| 8 | 访问/修改 `static mut` | `静态` 变量写 | **无检查** | **纳入**（B10，仅写） |
| 9 | 调用 unsafe fn | 调用 `不安全 函数` | 允许（责任上移） | 保持——Rust 同（调用点须在 unsafe 内，CN 采取**更宽**口径：调用点允许，审计面=被调方签名；理由：CN 无 `unsafe {}` 块语法，以函数粒度为不安全单元，Rust `unsafe fn` 的调用约束在 CN 由「不安全函数清单审计」承接） |
| 10 | FFI：`extern` 调用 | `外部 函数` 调用 | ✓ 已实现（观察期） | 保持（A4） |
| 11 | 访问 `extern` 静态变量 | CN 无外部静态变量语法 | — | 不适用 |
| 12 | 实现 `unsafe trait` | CN 无 trait | — | 不适用 |
| 13 | 裸释放（Rust 无直接对应；CN 特有） | `释放(p)` | ✓ 已实现（观察期） | 保持（A5） |
| 14 | 指针比较：`p1 == p2` / 序比较 | `p1 == p2` 等 | 放行（按地址；判空保留） | **不纳入**（Rust 安全；理由见 §五.1） |
| 15 | 整数→指针转换：`addr as *const T` | `指针(地址)` 构造/类型转换 | 放行 | **不纳入**（Rust `as` 安全；理由见 §五.2） |
| 16 | 取地址：`&x` | `&x` | 放行 | **不纳入**（Rust 安全） |
| 17 | 常量空指针解引用（Rust 运行时 UB） | `无` 字面量解引用/成员访问 | **无检查** | **纳入**（B11；CN 从严=编译期硬错误，见 §六.3） |
| 18 | 数组常量越界（Rust 编译期拒绝） | `数组[常量]` 越界 | 待查（宿主应有常量折叠面） | 本清单外（既有边界检查面，后续专项评估） |

> 结论：CN 需要 `不安全 函数` 的操作 = **A 组 5 类（现行）+ B 组 6 类（本轮新编）**，共 **11 类**。

### B 组：新编六类（本轮编制；**已批准并实施**——150-a 实装宿主 B6~B11 / 153~157-a v2 挂点与硬错误收口）

#### B6 裸指针解引用读（`*p`）

- **定义**：一元 `*` 作用于**裸指针**（`整N*`/`浮N*`/`类*`/`结构体*`/`空类型*` 等，**不含字符串语义类型**），
  结果为所指对象的读访问——可产生悬垂读/越界读/未对齐读。
- **正例**（不安全函数内合法；安全函数内=违规）：
  ```cn
  不安全 函数 取值(整64* p) -> 整64 {
      返回 *p;              // 裸指针解引用读：不安全函数内合法
  }
  ```
- **负例**（安全函数内）：
  ```cn
  函数 读(整64* p) -> 整64 {
      返回 *p;              // 违规：裸指针解引用读应在 不安全 函数 内
  }
  ```
- **边界案例**：
  - `字符*` / `字符串` 的解引用**安全**（字符串视图；见 §六.1）——`*s`（s 是 字符*）= 首字节读 ✓ 安全；
  - 引用类型（`整64&`）解引用=安全（引用非裸指针）；
  - 常量空指针 `*无` → **B11 硬错误**（优先于本类判定）。
- **现状**：无检查（135-a 探针：`*p` 读编译通过零警告）。

#### B7 裸指针解引用写（`*p = x`）

- **定义**：一元 `*` 作为赋值目标（可写左值）的裸指针写访问。
- **正例**：
  ```cn
  不安全 函数 置值(整64* p, 整64 v) {
      *p = v;               // 合法
  }
  ```
- **负例**（安全函数内）：
  ```cn
  函数 置值(整64* p, 整64 v) {
      *p = v;               // 违规：裸指针解引用写应在 不安全 函数 内
  }
  ```
- **边界案例**：`p[i] = x` 已被 A2 覆盖（不重复报告——判定优先级 A2 先于 B7）；
  复合赋值（`*p += 1`）同族覆盖；`字符*` 写 `*s = '字'`？——`字符*` 是字符串视图但**写字符串视图**
  值得单独裁决（字符串字面量区通常只读）——**本轮建议**：`字符*` 解引用**写**纳入本类（保持安全函数外违规），
  理由：字符串视图写=修改底层缓冲区（含只读字面量区的固有风险）；读（B6）才豁免。
  **★ 此项列为待用户裁决子项（B7-a）→ 已裁决＝豁免**（150-a 实装：`isStringSemanticType`
  六类统一豁免，探针「`字符*` 场景零警告」——与上文「建议不豁免」不同，以获批实装为准）。
- **现状**：无检查（135-a 探针确认）。

#### B8 指针下标读（`p[i]`）

- **定义**：下标运算对象为**裸指针**的读访问（等价 `*(p + i)`）。
- **正例**：
  ```cn
  不安全 函数 第二项(整64* p) -> 整64 {
      返回 p[1];            // 合法
  }
  ```
- **负例**（安全函数内）：`返回 p[1];` → 违规。
- **边界案例**：`p[i] = x`（写）走 A2；`字符串[i]` 安全（专有 O(1) 字节访问设计，A-1）；
  `字符*[i]` **安全**（字符串视图，与 `字符串[i]` 同族）；数组下标（`数组[i]`）安全（栈数组，编译器已知边界）。
- **现状**：无检查（135-a 探针确认）。

#### B9 指针成员访问（`p.字段`）

- **定义**：成员访问的接收者是**裸指针**——CN 的 `.` 对指针自动解引用一级（v2.1 统一），
  `p.字段` 等价 `(*p).字段`，隐含解引用读（随后若赋值则隐含写，与 A2/B7 的写面按同一优先级处理）。
- **正例**：
  ```cn
  不安全 函数 取X(点* p) -> 整64 {
      返回 p.x;             // 合法（隐含解引用）
  }
  ```
- **负例**（安全函数内）：`返回 p.x;` → 违规。
- **边界案例**：
  - 非指针接收者（值/引用）**安全**；
  - `字符*` / `字符串` 的成员访问（如 `字符串长度` 为函数、`字符串.字段` 若存在）→ 字符串语义安全（§六.1）；
  - 链式 `a.b.c`：逐段判定——仅当某段接收者为裸指针时该段违规（诊断定位到该段）；
  - 联合体成员访问（A3）与本类可同时命中（`u.甲` 且 u 是联合体指针 `联合体*`）——**A3 优先**（报告一次，
    detail 标注「联合体字段访问（经指针解引用）」）。
- **现状**：无检查（135-a 探针：`p.x` 编译通过零警告）。

#### B10 可变静态变量写（`静态` 变量写）

- **定义**：对 `静态` 声明变量的赋值（含复合赋值/自增自减/经引用传参的可变借用？——见边界）——
  可变全局状态（Rust：`static mut` 访问需 unsafe）。
- **正例**：
  ```cn
  静态 整64 计数 = 0;
  不安全 函数 新增() {
      计数 = 计数 + 1;      // 合法（不安全函数内）
  }
  ```
- **负例**（安全函数内）：`计数 = 计数 + 1;` → 违规。
- **边界案例**：
  - **读**（`返回 计数;`）**安全**（Rust 对照的 CN 裁剪：CN 静态变量为进程级单线程语义，并发安全随阶段 5
    立项后重评——plans/022 波 8+）；
  - 静态变量的**初始化**（声明处 `= 0`）安全（编译期/启动期一次性）；
  - **经指针/引用写**（`整64* p = &计数; *p = 1;`）——B7 已覆盖（`&静态变量` 后写=指针写面）；
    精确归因（「写的是静态」）需别名分析——**不做**（说明：B7 已拦，静态专项归因留后续）；
  - 静态容器的元素写（`静态 向量<...> v; v.追加(...)`）——**纳入**？（方法调用内的可变借用）——
    **本轮建议：暂不纳入**（方法内部语义不可静态见；NLL/借用面专项），列入「后续评估」（§十.4）。
- **现状**：无检查（135-a 探针确认）。

#### B11 常量空指针使用（`无` 字面量的解引用/成员访问）

- **定义**：**编译期可判定**的空指针使用——空指针字面量（`无`）或编译期常量 `空类型*` 值直接进行
  解引用读/写/成员访问/下标——确定性 UB（Rust 中为运行时 UB；CN 从严=**编译期硬错误**，非观察期）。
- **正例**（合法）：
  ```cn
  整64* p = 无;             // 声明/判空比较：合法（Task 6.2 判空惯用法）
  如果 (p == 无) { 返回 1; } // 判空：合法
  ```
- **负例**（编译错误）：
  ```cn
  整64* p = 无;
  整64 v = *p;              // 错误：编译期常量空指针解引用
  点* q = 无;
  返回 q.x;                 // 错误：编译期常量空指针成员访问
  ```
- **边界案例**：
  - 常量传播范围：字面量 `无` / 常量初始化 `常量 整64* 空 = 无;`（一层常量引用传播；深度常量折叠
    按既有常量系统能力——与宿主 `常量传播` 同面）；
  - 函数返回空指针（`返回 无;`）→ 调用点**不**判定（跨函数，非编译期常量）——留给运行时；
  - 观察期豁免：**无**——确定性错误，零误报面（存量粗扫未见此形态）。
- **现状**：无检查（135-a 探针：`*p`（p=无）编译通过）。

## 五、不纳入清单的候选（含理由）

1. **指针比较（`p1 == p2` / `<` / `>` 等）**——不纳入（保持安全）。
   *Rust 对照*：raw pointer 的 `==`/`<` 等比较在 Rust 中**是 safe**（比较地址值，不解引用；`core::ptr::eq`
   亦 safe）。CN 现状已放行（按地址比较；判空 `p == 无` 为核心惯用法，Task 6.2）。
   收紧会把 235 处存量（粗扫）安全惯用法逼进 unsafe 且**零安全收益**（比较本身不产生 UB）。
   **保留**既有约束：指针与整数比较已拒绝（`semantic_expr_op.cpp` 比较分支）。
2. **指针类型转换（整数→指针 / 指针互转）**——不纳入。*Rust 对照*：`addr as *const T` 是 safe（解引用才 unsafe）。
   CN 的 `指针(地址)` 构造与显式类型转换同理（产生指针值不产生 UB）。
3. **取地址（`&x`）**——不纳入（Rust 安全）。CN 已有「返回局部变量地址」的悬垂专项检查（另一条防线，§十.3）。
4. **不安全函数调用**——不纳入（责任上移；Rust 同模型）。
5. ~~**联合体成员为复合类型（结构体/数组）**——不纳入（语法层已拒绝：135-a 探针 `联合体 形状 { 点 p; ... }` 报「结构体字段预期名称」）~~

## 六、边界判定细则

### 6.1 字符串语义排除（全清单统一）

`字符串` / `字符*` 是**字符串视图**（IR 层同为 ptr；波 1 = 134-a 已立 `isStringSemanticType` 单一事实源）：
- A1（指针算术）：`+` 涉及字符串语义 = 拼接（波 1 已修）；`-` 涉及 `字符*` = 指针步进（保留警告）；
- B6/B8（解引用读/下标读）：`字符*` 的 `*s` / `s[i]` **安全**（字符串视图访问，与 `字符串[i]` 同族）；
- B9（成员访问）：`字符*`/`字符串` 接收者**安全**；
- **B7-a 已裁决＝豁免**：`字符*` 的解引用**写**（`*s = c`）**豁免**（150-a `isStringSemanticType`
  统一豁免；上文「本轮建议不豁免」系编制时建议存档，以获批实装为准）。

### 6.2 解引用糖的判定

`p.字段` / `p[i]` / `*p` 三者对裸指针是同一件事（隐含解引用）；判定按**优先级**避免重复报告：
1. B11（常量空指针）最高；
2. A2（指针下标写）先于 B7（解引用写）；
3. A3（联合体字段访问）先于 B9（指针成员访问）；
4. 其余按形态唯一归类（`*p` 读=B6、`*p = x` 写=B7、`p[i]` 读=B8、`p.x`=B9）。

### 6.3 常量空指针的判定范围

- 命中：`无` 字面量、`常量` 声明的 `空类型*`（一层引用）；
- 不命中：函数调用结果（跨函数）、条件分支产生的空值（流分析超范围）；
- 语义：**硬错误**（`DiagnosticLevel::Error`）——与观察期警告分开（确定性错误不需要迁移期）。

### 6.4 静态变量写

- 命中：`静态` 变量的直接赋值/复合赋值/自增自减；
- 不命中（留后续）：经引用/方法调用的可变借用写（§十.4 后续评估）。

### 6.5 诊断格式与观察期字样

- 观察期类（A1~A5 + B6~B10）：`[安全区边界·观察期] <kind>应在 不安全 函数 内（<detail>；plans/019 阶段4 分批收口后变错误）`
  ——沿用现行格式（kind 文本=清单类别名：`指针算术`/`裸指针解引用读`/`裸指针解引用写`/`指针下标读`/
  `指针成员访问`/`静态变量写`……）；
- 硬错误类（B11）：`编译期常量空指针<解引用|成员访问>（确定性错误；plans/023 B11）`；
- 收口后（波 6）：观察期类全部改 `DiagnosticLevel::Error`，去掉「观察期／分批收口」字样。

## 十二、联合体拥有型成员处置（2026-09-14 用户裁决：方案 A + D）

> **来源**：135-a §五.5 误判（见 §五.5 更正）经本轮复核翻转后暴露的**真实缺口**——联合体成员可为
> 拥有型类型（字符串等），而联合体**无 tag**（不判定活跃成员），编译器对其实施了一套「按偏移 0
> 无条件释放」的**半截机制**。用户 2026-09-14 裁决：**方案 A（成员类型限定·默认拒绝）+ D（手动释放
> 标注·逃生舱）**（对标 Rust `union` 成员必须 `Copy`/`ManuallyDrop<T>` 的完整模型）。
> **状态**：**已批准，待实施**（实施轮见 `plans/021` §3 排班队列）；语言级语义变化（放行→拒绝）已经批准。

### 12.1 实测证据（2026-09-14，家机 win-x64；探针 `target/p23probe/`）

| 编号 | 形态 | 实测结果 |
|---|---|---|
| p11 / p15 | 联合体含字符串成员：单写 / 覆写 / 消亡（**只操作字符串成员**） | 残留 **0** ✓——写入位归一化（preFree+接管）正确 |
| p12 | 联合体整体拷贝（`联 b = a;`，含串成员） | asm 深拷（`__cn_str_copy`）+ 残留 **0** ✓ |
| p16 | 字符串变量 → 联合体字符串成员 | 深拷（残留 0）✓ |
| p13 | `u.名字 = 串; u.数值 = 777;`（**非字符串成员覆写**） | **残留 1（句柄泄漏）**——覆写路径不释放旧句柄 |
| p13 | 只写整数成员后消亡 | asm:627 函数尾 **`call __cn_str_free`（无条件按偏移 0 释放）**——把 12345 当句柄 free（被 `cn_free_tracked` 追踪表守卫兜住不崩 = **类型混淆·巧合正确**） |
| p14 | **指针成员持有「活」字符串句柄** → 联合体消亡 | asm 铁证链：573-577 存入活句柄 → 654-677 写入联合体偏移 0 → **704 `call __cn_str_free` 误释放活对象** → 之后「活」变量读取=**静默 UAF**（净计数不变：误释放 −1 与覆写泄漏 +1 相抵，仅 asm 可定案） |

**根因**：IR 层拥有型字段释放设施（79-a `collectOwnedStrFields`）按「结构体字段布局」假设收集与发射
（`ir_fields.cpp` 无 `isUnion` 判定）——联合体「共享偏移 + 无 tag」语义下退化为「按偏移 0 无条件释放」：
只覆盖「偏移 0 的值恰为可释放句柄」的单一情形，对非活跃成员（泄漏）与指针活跃成员（误释放=UAF）均不正确。
**Rust 对照**：`union` 成员必须 `Copy` 或 `ManuallyDrop<T>`——Rust 从根上禁止拥有型（有 Drop）成员，
CN 现放行了该形态。

**影响面（硬数据）**：全仓库扫描（stdlib + v2 树 + tests）共 **5 处**联合体声明，**全部纯标量成员，
零处含拥有型成员** → 本方案**零迁移成本**；`A3` 字段访问检查不受影响。

### 12.2 方案 A（主体·默认拒绝）

1. **成员类型限定**（语义层硬错误）：源码级用户自定义联合体的成员类型限定为**可平凡复制类型**——
   标量 / 指针 / **递归判定的纯标量聚合**（结构体、数组，其成员全为可平凡复制）；
   **拥有型类型**（`字符串`、容器、类对象、含拥有型的聚合）→ **编译期硬错误**（诊断注明 Rust 对照）。
2. **删除 IR 半截机制**：联合体不再收集拥有型字段的释放与写入归一化（`collectOwnedStrFields`
   的 `isUnion` 早退）——类型上不再可能命中；**生成代码净减少 = 性能正向**（零运行时开销）。
3. **结果/可选 合成联合体不受影响**：其降级结构体有 `是否正常`/`是否某些` tag，条件释放已实现
   （79-a）；本规则**只作用于源码级用户自定义联合体**。

### 12.3 方案 D（逃生舱·显式手动释放，对标 `ManuallyDrop`）

- 联合体成员可显式标注**「手动释放」**：语义层放行该（拥有型）成员；编译器**不生成**其自动释放；
  用户须在 `不安全 函数` 内以显式原语自行释放（`字符串释放` 内置已存在，`semantic_builtins.cpp:111`）。
- 标注成员的一切字段访问仍受 **A3**（联合体字段访问 = 不安全区）约束——责任显式化，无隐藏行为。
- 与 A 的关系：**默认安全（A）+ 显式逃生（D）** = Rust `union`（成员须 Copy/ManuallyDrop +
  字段访问 unsafe）的完整对应物。
