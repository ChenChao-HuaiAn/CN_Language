### 2.2 语言能力（实测确认，非纸面）
- 类型：整8~整128/正8~正128/浮32/浮64/布尔/字符/字符串/空类型/结构体/枚举/联合体/指针/数组/函数指针/结果<T,E>/可选<T>；i128 内建（C++ 无标准内建，Rust 有）
- 函数：重载/默认参数/lambda（捕获）/引用参数（T&）/引用返回（e2e 102/103）/变参打印/命令式 选择 匹配（e2e 63）
- OOP：类/单继承/虚函数+vtbl/接口（变量/参数/返回多态，e2e 100/105 同一地址语义）/抽象/友元/静态/常量成员/运算符重载（含单目，e2e 92）/构造析构重载/父类构造初始化列表（e2e 95）
- 泛型：类/函数单态化、接口约束（对标 trait bound）、泛型与函数指针（e2e 99）
- 错误处理：结果/可选 + 强制检查 3 规则 + 错误传播运算符 ?（e2e 60，对标 Rust ? / C++23 std::expected）
- 模块 v2.0：文件即模块/包=crate/:: 路径/导入全形式/默认私有/可见性交集矩阵/货舱.toml 本地依赖/跨包 $ 前缀符号隔离（e2e 87）/跨模块同名类隔离（e2e 93）
- 安全：数组越界（错误码2）/空指针（错误码3）运行时检查默认开启（-O2 生效）——超过 C++ 默认、贴近 Rust panic
- 优化器：SSA（Phi 未接汇编）/常量折叠/代数简化/DCE/CSE/复写传播/全局值传播/LICM/强度削减/内联/尾调用/线性扫描寄存器分配（-O0~-O3，x64 启用）
- 后端：Win x64（MASM + ml64/link）+ Linux ARM64（GAS）双后端；-O2 起 x64 寄存器分配
- 自举：5 大组件 CN 版 4,760 行 + 79 真实闭环设计（ml64 汇编 → link → CN 版再编译 → 产物逐字节比对 + map 符号自检防虚假验收）

## 六、结论与建议

**一句话定位**：CN 是「带运行时安全检查的现代 C++（语法中文化 + Rust 风格模块/错误处理）」，在安全默认、错误处理、模块系统三点上已超过 C++、贴近 Rust；当前最紧迫的不是加语言特性，而是修复 tracked 内存注册表缺陷（A-1/A-2/A-3）——它同时卡住 78 链式构建 与 79 自举闭环 两条阶段 7 验收路径。

**建议顺序**：
1. P0 内存收尾：重审 tracked 链表（HANDOFF 已指出 cn_realloc_tracked 的 realloc 换址注册/去注册竞态）；或简化策略——79 主.cn 补齐 内存::释放全部()（与 78 对齐），并让字符串释放 在 tracked 下成为显式强制；对 79 的 读全部 增加逐行释放（78 已示范）
2. P0 回归护栏：本报告已实现 run_e2e.py 内存防护（--max-mem-mb 默认 4096MB，78/79 超限自动终止判失败）——提交保留，防止内存失控再拖垮开发机；另建议把 79 内存峰值加入 bench 脚本
3. P1 工程：提交本次 3 处单测可移植性修复（B-1），CI 即恢复绿
4. P1 语言：补 字符串释放 语义文档 + 智能指针 MVP（唯一/共享），从根上减少手动释放失误
5. P2 能力：按 005 路线 P4/P6 推进（SSA Phi 接线 → 线程 → 迭代器）——当前 107/109 的功能面已足够支撑自举，优先级让位于内存正确性

**本次会话新增/修改文件**：
- tests/e2e/run_e2e.py —— 内存防护（78/79 超限自动终止 + --max-mem-mb）
- tests/unit/runtime/test_input_api.cpp —— MSVC 可移植性修复（_dup/_dup2/_close/_fileno）
- tests/unit/semantic/test_bootstrap_lexer.cpp —— MSVC 可移植性修复（_fullpath + UTF-8 路径读取）

## 七、修复执行结果（2026-08-25 追加）
