## 〇、设计目标补充：面向操作系统/内核级性能

> 用户目标：开发完成后能用于编写类 Linux 的操作系统，性能必须强。据此为 P3-19（接口多态）确立
> **性能优先的设计原则**（与 Rust「优先泛型单态化、trait对象(dyn)仅用于边界」哲学一致；CN 泛型已编译期单态化）：

1. **接口分派定位为“边界多态”，不是“热循环内多态”**：内核热路径（调度/中断/内存分配内层）应直接使用
   具体类型或泛型（可内联、零间接）；接口变量用于边界/插件化点（对标 Linux 的 ops 结构体）。
2. **每次接口调用代价目标 = 1 次间接跳转**（固定全局槽偏移加载 + call *目标），不附加额外多层间接。
3. **零成本转换**：类↔接口同一地址（A1），转换无算术、无开销（热路径安全）。
4. **稳定 ABI + CFI 友好**：全局接口槽位固定偏移 → 内核/驱动模块跨编译单元可见的稳定接口；
   分派目标均为已知符号表，利于控制流完整性（CFI）检查。
5. **布局缓存友好**：接口分派区置于对象首（类虚表指针之后、字段之前），一次访存、良好局部性。
6. **未来性能路线（列入后续批次）**：接口调用去虚拟化（devirtualize）——单一实现接口 / 最终类(sealed)
   的接口调用可在编译期内联；接口调用点可提供 CFI 校验。
7. **验收含性能口径**：接口调用仅比直接调用多 1 次间接；接口区新增内存 = O(接口方法数×8)/对象。


## 一、目标语义（验收目标）

```
接口 形状   { 虚拟 函数 面积() -> 整32 }
接口 可缩放 { 虚拟 函数 缩放(浮64 比例) -> 浮64 }

类 圆 : 形状, 可缩放 {
公开: 整32 半径;  函数 圆(整32 r) { 半径 = r }
    重写 函数 面积() -> 整32 { 返回 半径 * 半径 * 3 }
    重写 函数 缩放(浮64 比例) -> 浮64 { 半径 = 半径 * 比例; 返回 半径 }
}
类 矩形 : 形状 { 公开: 重写 函数 面积() -> 整32 { 返回 100 } }

函数 用形状(形状* 图形) -> 整32 { 返回 图形.面积() }   // （范围决策 C，见下）

函数 主() -> 整32 {
    形状* 图形 = &圆(5)        // 类→接口 指针转换（隐式）
    整32 a = 图形.面积()        // 运行时多态分派 -> 圆.面积 = 75
    形状 图2 = 矩形()          // 值形式（对象指针 + 附加虚表）
    整32 b = 图2.面积()        // -> 矩形.面积 = 100
    返回 0
}
```

实现后要求：同一 `形状*` 可指向 圆/矩形，`图形.面积()` 经接口分派命中各自实现（运行时多态）。

## 二、方案对比与推荐

| 方案 | 思路 | 优点 | 缺点 |
|------|------|------|------|
| A 附加虚表指针（C++ 风格） | 每个实现类对象额外存「接口子虚表指针」，接口名定位于虚表之一 | 贴近 C++、省内存 | 需指针调整/多重寻址，布局复杂 |
| B RTTI 分支分派 | 调用点对已知实现类做运行时类型分支 | 无布局变化 | 脆弱、每加实现类要改派发点、不支持库外扩展 |
| **C 全局接口槽位 + 对象附加虚表区（推荐）** | 编译期给每个 (接口,方法) 分配全局唯一槽位；实现类对象在类虚表指针后追加一个「接口分派区」按全局槽位放置实现符号地址；`图形.面积()` 经 `对象.接口区[全局槽]` 间接调用 | 一次寻址、多接口天然支持、与现有单虚表不冲突；符合规范 06-六「附加 vtable」字面 | 对象布局增大（每个实现类多一个接口区）；槽位是全局注册（实现类多时槽位稀疏） |

**推荐 C**：CN 单继承 + 接口模型，规模小；C 方案的附加虚表区符合规范预留表述，且无需指针调整（接口变量=同一对象地址）。

## 三、设计要点（推荐 C）

### 1) 全局接口槽位注册（编译期）
- 收集所有 接口 声明（Program.interfaces），对每个 (接口名, 方法名) 分配全局递增槽位 `IF0/IF1/...`（顺序=声明顺序，稳定）。
- 语义层登记 `接口方法槽位[(接口,方法)] = 全局槽`。

### 2) 对象布局（附加虚表区）
- 现有：实例 = [类虚表指针?] + [字段区]（hasVtable 时首 8 字节为 vtable 指针）。
- 新增：实现接口的类的实例 = [类虚表指针?] + **[接口分派区]** + [字段区]；接口分派区大小 = max(实现的全局槽) + 1（8 字节/槽）。
NaN
- `computeClassLayout` 相应增大 totalSize/偏移（接口区置于字段区之前、虚表指针之后）。

### 3) 类→接口 转换（值/指针）
- 隐式转换：类可实现其接口之一，值/指针均可转成接口类型（同一对象地址，无指针调整）。
- 语义：`canConvert(T类 -> 接口)` 通过 iff 类实现该接口；赋值/实参/返回 类型检查复用该规则。

### 4) 接口调用 `图形.面积()`
- 语义：静态类型为接口 形状 → 该成员必须是 形状 的接口方法；解析出 (接口=形状, 方法=面积, 全局槽=IFx)；返回类型=接口签名返回类型。
- IR：`加载 对象指针` -> `LoadPtr(对象.接口区 + IFx*8)` 取方法地址 -> 经地址间接 `Call`（实参=对象 addr + 方法实参）。
- codegen：接口无 this 转换（复用对象指针作 this），方法符号=该类实现（接口区已填）。

### 5) 与现有 OOP 机制交互
- 类虚表（assignVtable）：原语义不变（父类槽位+重写+新虚拟）；接口方法的重写仍同时进入类虚表（现有行为保持）。
- `verifyInterfaceImpl`（接口方法齐全性校验）：现用；保持。
- 接口方法重载：暂不支持（每接口方法唯一名，签名唯一）。
- 泛型/继承：接口实现类可继承（父类实现的接口方法子类沿用/重写）——接口区按继承链并入。

### 6) 范围边界
- ~~接口类型作为函数参数/返回 不做~~ → **已完成（007-P3 C2，e2e 105）**：指针/值参数、值返回、链式、成员方法形参、继承实现类全可用；参数泛型化仍延后。
- 接口类型**数组/嵌套泛型接口**——延后。
- 接口方法的**运算符/静态成员**——不支持。
