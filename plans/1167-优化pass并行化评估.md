## 3. 可行性矩阵

判定标准：pass 是否只读写「单个 IRFunction 及其块/指令」，是否触碰模块级容器
（stringConstants/stringIndex/globalStatics/globalStaticInits）、诊断、跨函数数据。

| pass | 级别 | 输入/输出依赖 | 跨函数共享状态 | 结论 | 理由 |
|---|---|---|---|---|---|
| ConstFold | -O1 | 函数内块级常量表 | 无 | **可函数级并行** | 逐函数逐块本地表；出口归一化也只逐函数扫描 |
| AlgebraicSimplify | -O1 | 函数内寄存器/常量映射 | 无 | **可函数级并行** | 映射按函数局部构造，跨块替换仅在本函数内 |
| CopyPropagation | -O1 | 函数内块级槽值表 | 无 | **可函数级并行** | 仅 `fn.varSlots` 只读 |
| DCE | -O1 | 函数内引用位图 + 级联 16 轮 | 无 | **可函数级并行** | 全部状态是循环内局部变量 |
| CSE | -O2 | 函数内模式表/Load 表 | `reportedDuplicates_`、`lastModule_` | **可（需分片）** | 唯一真实共享可变状态；按函数下标分片后语义不变 |
| CrossBlockDCE | -O2 | 函数 CFG 可达性 | 无 | **可函数级并行** | label 索引/可达性均为函数局部 |
| LICM | -O2 | 函数 DomTree/自然循环 | 无 | **可函数级并行** | `DomTree`、循环集合均函数局部 |
| StrengthReduce | -O2 | 函数内逐指令 | 无 | **可函数级并行** | `nextReg` 为函数局部变量 |
| TailCall | -O2 | 函数内尾递归重写 | 无 | **可函数级并行** | `runFunction(fn)` 纯函数内 |
| GlobalValue | -O3 | 函数内汇合块感知常量表 | 无 | **可函数级并行** | 只读 `fn`，不读写模块全局表 |
| SSA | -O3 | 函数 CFG/Phi | 无 | **可函数级并行** | `buildFunction(fn)`、`lowerPhis(fn)` 均函数局部 |
| Mem2Reg | -O3 | 函数内槽分类/支配树 | 无 | **可函数级并行**（先修 #1255） | 全部状态函数局部；当前 36.5s 来自非收敛而非结构限制 |
| Inline | -O3 | **跨函数**：caller 写、callee 读，且按函数序 mutate | `module.functions` | **不可并行 / 需重构** | 串行语义依赖「先内联的函数体可被后序 caller 读取」；并行会改变内联结果。实测 5ms，不值得 |
| `normalizeModuleConstWidths` | 出口 | 逐函数逐指令 | 无 | **可函数级并行** | 40ms，可一并纳入 |
| PassManager fixpoint | — | pass 间顺序依赖 | — | **不可并行** | 每轮 pass 是 barrier；只能在 pass 内部按函数并行 |

代码位置：`src/cn_compiler/opt/pass_manager.cpp:35-46`（fixpoint）、
`src/cn_compiler/opt/cse.hpp:51-55`（唯一共享可变状态）、
`src/cn_compiler/opt/inline.cpp:155-189`（跨函数顺序依赖）、
`src/cn_compiler/opt/licm.cpp:80`（DomTree 重建）、
`src/cn_compiler/opt/mem2reg.cpp:266`（逐函数槽提升）。

## 4. 方案设计（若实施）

### 4.1 粒度与调度

- **函数级 fork-join**：每个 pass 把 `module.functions` 的下标区间作为任务，
  原子计数器取号（与 1145 的 `runTasksParallel` 同构），结果直接写回各自 `IRFunction`。
- **线程池持久化**：一个编译进程一份池（`runOptLevel` 生命周期），跨 27 次 pass 调用复用；
  避免每次 pass 创建/销毁 N-1 个线程（1145 当前是每阶段建线程，opt 场景调用次数多，
  应改为复用）。
- **判定阈值**：函数数 < 64 或总指令数 < 20000 时走串行（E2E 小用例零回归）；
  环境变量 `CN_OPT_THREADS`（1=串行逃生门/对拍；未设=硬件并发上限 8/16）。
- **改造范围**：第一阶段 9 个 -O2 pass（覆盖 98.5% opt 时间）；第二阶段 -O3 的
  GlobalValue/SSA/Mem2Reg（须先修 #1255）；Inline 保持串行。
- CSE 去重状态改为 `vector<unordered_map<const IRBlock*, unordered_set<int>>>`，
  按函数下标分片；`lastModule_` 在 fan-out 前由主线程判定/清空。分片后
  「每块首次报告」语义与串行完全一致（块指针按函数天然分区）。

### 4.2 确定性保障

- 每个函数只被一个 worker 写；pass 的输出与该函数的指令顺序一一对应，与调度顺序无关。
- `changed` 用 `std::atomic<bool>` 归并（OR 可交换），fixpoint 轮数不变。
- 不触碰 `module.stringConstants` / `stringIndex` / `globalStatics` / `globalStaticInits`
  （已 grep 确认现有 pass 只读写 `module.functions`）。
- Inline 串行；产物文本顺序不变。
- 验证口径：同一输入 `CN_OPT_THREADS=1` 与 `=8` 生成汇编**逐字节一致**，且与改前一致。

### 4.3 预期收益（Amdahl，Debug -O2）

| 线程数 | 单 pass 效率（按 top1 估计） | opt 时间 | 总墙钟 | 总加速 |
|---:|---|---:|---:|---:|
| 1（现状） | 1.0× | 2.73s | 16.7s | 1.00× |
| 4 | 3.2~3.8× | ~0.74s | ~14.7s | 1.13×（-12%） |
| 8 | 6.4~7.5× | ~0.38s | ~14.4s | 1.16×（-14%） |
| ∞（理论上界） | — | 0 | ~14.0s | 1.19×（-16.3%） |

8 线程逐 pass 预测：LICM 689→92ms、DCE 474→74ms、CSE 473→63ms、ConstFold 288→41ms、
CopyProp 277→39ms、CrossBlock 216→30ms、Algebraic 179→25ms、TailCall 48→7ms、
Strength 44→6ms、归一化 40→6ms；合计约 0.38s。

Release 口径：opt 0.72s→约 0.10s，总 9.0s→8.4s（**-6.9%**）。

若 1145 并行 codegen 合入：代码生成 16.6% 也会被压缩，opt 在剩余墙钟中的占比升到约 20%，
两项收益近似相加（预计总墙钟可到 7s 量级）。

## 5. 风险与建议

### 5.1 数据竞争点清单

1. **`CSEPass::reportedDuplicates_`（`cse.hpp:51`）**：跨函数、跨轮持久；必须按函数分片，
   否则并发 `unordered_map` 写入即 UB。`lastModule_` 同理只在主线程访问。
2. **模块级容器**：`IRModule::stringConstants/stringIndex/globalStatics/globalStaticInits`
   当前无 pass 写；需在实现时加断言/注释冻结（未来 pass 若写，必须加锁或回主线程）。
3. **`module.functions` 不得在 pass 内增删**：现有 pass（含 Inline）都不改变函数数量；
   并行前需 `assert`/静态检查，防止未来回归。
4. **Inline 的跨函数顺序依赖**：不能并行（本报告结论：保持串行）。
5. **诊断**：opt 各 pass 当前不产生 `Diagnostic`；若未来引入内部错误诊断，需要
   每 worker 本地缓冲、主线程按函数序合并（与 1145 的 `FunctionOutput.diagnostics` 同构）。
6. **异常安全**：worker 内若抛异常会 `std::terminate`；统一 try/catch 收集后主线程重抛。
7. **内存**：峰值 RSS 392MB；并行后 glibc per-thread arena 可能再增 10%~20%，
   在 CI 容器需观察 OOM 余量。
8. **线程数过订阅**：与 1145 codegen 池、多会话并行、gate 锁叠加时可能 CPU 饱和
   （参见 566 裁决）；`CN_OPT_THREADS=1` 必须是可靠逃生门。
9. **MSVC 兼容**：1145 已踩过 `std::function` move-only 的坑，线程池接口应沿用其
   `shared_ptr<void>` 生命周期锚模式。
10. **静态状态**：`const_fold.cpp` 的 `static const std::string kEmptyType` 为只读，
    C++11 起线程安全；其余 opt 文件无 `static` 可变状态（已 grep 确认）。

### 5.2 验证要求

- 单测：每个 pass 在 1/8 线程下 IR 文本 dump 逐字节一致，`changed` 返回值一致，
  fixpoint 轮数一致；CSE 专门覆盖跨轮去重。
- 全量双测：宿主 + v2，全 E2E；`CN_OPT_THREADS=1/8` 各跑一遍对比产物。
- 自举对拍：`cn build CN语言编译器v2/主.cn` 在 1/8 线程下 `.s` 逐字节一致，
  -O1/-O2/-O3 全档。
- TSan：至少 opt 单测 + 一个 v2 子集（`-fsanitize=thread` 构建）。
- 性能：`bench_self_host.py` M1 在 1/2/4/8 线程各 3 次取中位，确认 ≥1.12× 才合入。

### 5.4 建议（按优先级）

1. **先修 #1255**（-O3 fixpoint 非收敛）：16 轮→预计 3~4 轮，-O3 总时间 75.5s→20s 量级，
   收益是并行化的数倍；且不修的话，并行化只是在放大错误轮次。
2. **合入 1145**（并行 codegen）并将其线程池/线程数约定下沉公共层；opt 并行直接复用，
   避免两套线程池和两次线程创建。
3. **评估 1207**（LICM 无循环函数快筛 + 跨轮 CFG 快照；当前只在 `任务/1206` 分支，
