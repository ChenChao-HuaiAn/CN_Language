## 七、云端预验门禁（1008·方案甲 test-then-commit）

> **立法**：用户裁决 2026-10-03（云端连续红的架构诊断——107 轮数据：58% 归 171 非确定性缺陷
> 连坐、24% 归修复中间态直推 develop、17% 归 L1 漏检真回归）。旧模式（941 fast-lane）=
> commit-then-test（先进 develop 云端再验，红灯窗口期结构性存在）；预验=test-then-commit
> （绿才进 develop，Chromium CQ/rustc bors/GitHub merge queue 同构）。

- **链路**：integrate.py（触及全量面的集成）→ 链顶推 `gitcode ci/预验-<sha10>` →
  `ssh TX_02` nohup 触发 `CN_CI_BRANCH=ci/预验-<sha10> ci_daemon.py --once --force --wait-lock`
  （锁排队=与 develop 常驻轮串行，3.6G 内存禁止双全量并发〔923 OOM 铁律〕）→
  轮询 `ci-logs/预验_<sha10>.json`（60s 间隔·总超时 75min）→ 绿放行 push develop／红拦截。
- **零重复算力联动**：预验**绿**时 daemon 写 latest.json+上报（链顶即将成为 develop 头），
  push 后 develop 常驻轮按「已跑过」（绿的 result_*.json 判定·1008 修正）跳过；
  预验**红**只写 预验_/result_ 文件（latest 保持 develop 语义不被污染）。
- **开关**：`--cloud-gate` 显式确认／`--no-cloud-gate` 逃生门（TX_02 异常时回退 941 事后兜底）／
  **默认开（1015 翻开·2026-10-04：常量 `云端预验默认开=True`——develop 回绿达成〔1013
  终验 c4c28311 轮绿〕·翻默认轮已同步 AGENTS §8.2-P/027 §8.2-P5 与本节）**。
  纯文档/脚本写集轮不预验（快速门禁+事后兜底仍覆盖）。
- **各机依赖**：ssh config 配 `TX_02` 别名（三机 ~/.ssh/TX_0x.pem 已在）；可选
  `scripts/ci_client.json`（gitignore·`{"ssh":"TX_02","目录":"/home/ubuntu/cn-ci"}`）覆盖默认。
- **执行位置（1021 池化后）**：默认走 TX_01 任务池（§八·多 runner 认领）；池不可达自动降级
  本节 ssh 直发 TX_02 原路径；再失败 `--no-cloud-gate` 逃生门。
- **升级部署**：daemon/integrate 改动进 develop 后——`ssh TX_02 'cd ~/cn-ci && git fetch origin develop && git reset --hard origin/develop && sudo systemctl restart cn-ci'`
  （跑轮会自 reset；restart=加载新 daemon 代码·选空档避免杀在跑轮）；家机实例=各克隆
  `git pull` 后 `sudo systemctl restart cn-runner@1 …cn-runner@7`（§八）。
- **红灯两纪律（同裁决·立即生效）**：①修复中间态禁推 develop（半成品只留任务分支+本节 §三
  分支预验）；②临时用例（*tmp*）禁入 develop（integrate.py 写集机械拦截）。

## 八、预验执行器池（1021·用户裁决=任务认领池+家机多实例）

> **立法**：用户 2026-10-05——「云端只有一台机器做预检测排队太久·家里 28 核 128G 闲着·
> 家机多虚拟机（4核8G/个）与云机谁空闲用谁」。慢大头=78/79 自举固定点（编译 CN 全部源码
> 两遍·串行链不可拆机），池化收益=**任务间并行**（多集成互不排队）而非单任务加速。

- **链路**：integrate（触及全量面）→ push `ci/预验-<sha10>` → TX_01 `task_enqueue`（幂等；
  已完成绿直接复用·红重置重跑）→ 各 runner 常驻循环 `task_claim`（TX_01 写锁内原子+回收
  心跳断 `CN_TASK_STALE_SEC`=300s 的执行中任务）→ 认领者 fetch 预验分支→`跑一轮`→
  `task_complete`（校验认领者·防回收后旧 runner 复活覆盖）；跑期间 runner 每 60s 心跳续约。
- **三层降级（行为超集）**：①池（多 runner·不排队）→ ②池不可达/超时=integrate ssh 直发
  TX_02（1008 原路径·`--wait-lock` 串行）→ ③`--no-cloud-gate` 逃生门（941 事后兜底）。
- **零重复算力联动（1008 池化续接）**：池绿结果存 TX_01 详情字段；TX_02 develop 轮
  「已跑过」=本地 result 绿 **或** `池已绿()` 查询——预验家机跑绿后 push develop，
  TX_02 轮询轮跳过；家机实例同时仍写本地 result/预验_ 文件+上报（成绩牌双保险）。
- **角色**：TX_02=池认领+develop 轮询双职（无 env·现状兼容）；家机实例=`CN_CI_ROLE=pool`
  纯池角色（develop 兜底归 TX_02）；`CN_CI_BRANCH` 点名模式跳过池（ssh 降级路径纯净）。
- **资源口径（399 终态·2026-10-10 用户令；823 补深度机）**：家机 28核128G → WSL2 VM 全局限
  `processors=24 memory=100GB`（留余量给日常）；WSL 原生 ×2（`CN_BUILD_JOBS=4`+
  `CN_E2E_JOBS=4`）+ 交叉模拟 ×3（`CN_BUILD_JOBS=2`+`CN_E2E_JOBS=2`·模拟轮本身慢
  降并行换内存安全）+ win ×3（`CN_E2E_JOBS=6`+gate_lock 全机互斥）≈ 池内 5 任务
  并行不排队；深度机 ×2（823·2核2G cgroup 硬限+Nice=10·`CN_BUILD_JOBS=2`+
  `CN_E2E_JOBS=2`）再 +2 并行。单任务到达时 1 实例独跑（约 8~12min·TX_02 13~16min
  同量级）；实例数=预期并发集成数，可随 `cn-runner@N`/`cn-arm64@N` 增减。

### 预验分片与退化策略（1297/1369·2026-10-21）

- **分片模型**：`ci/预验-*` 轮由主实例构建前 `task_shard_enqueue` 登记片 1..n-1 缺口
  （`CN_SHARD_N` 默认 3·片 0=主实例重型独立面 78/79），空闲池实例自主认领
  （`task_shard_claim`）；主实例按片收（CAS 抢补/从片红即停 902）。片状态/明细查询

## 十二、树锁——单树并发互斥（555·2026-10-13）

> **背景**：多机多会话并行开发中「同一棵树内并发跑 E2E/构建」无任何锁——target/audit2
> 缓存互踩、v2p 双建交错写、后起者清场杀先起者（rc=143 有实录）、LNK1168 编译器占用。
> 既有 gate_lock（§七 machine 域）只管全机全量门禁串行；本节补每树一把的**树锁**，
> 把「一树一会话」纪律变机械（AGENTS §7 末节同源立法）。

- **语义**：每棵 worktree 一把 `本树根/target/tree.lock`（脚本所在仓库根·不经
  git-common-dir 反推主树·`CN_TREE_LOCK_DIR` 可覆盖）；`tests/e2e/run_e2e.py` 与
  `scripts/gate_quick.py` 入口自动取锁（等待无限·排队进度 30s 一打印·整运行期持锁·
  异常/Ctrl+C 均释放），同树后来者串行排队，**跨树天然并行**（锁文件在各自 target/ 下）。
- **实现**：全复用 `scripts/gate_lock.py` 锁原语（os.mkdir 原子目录锁+info.json+
  陈锁接管 917 双判据〔持锁存活锚死秒级/心跳停 4h 兜底〕+心跳 60s）；
  `--scope machine|tree` 双域（默认 machine 向后兼容），`status|release --scope tree`
  查询/清锁；自测 `python scripts/test_tree_lock.py`（四场景 18 断言）。
- **嵌套规则（最高风险点）**：`gate_quick.py --l2` 调 run_e2e 子进程时注入
  `CN_TREE_LOCK_HELD=1`；gate_lock/run_e2e 见之即跳过取锁——防「外层持锁、内层再等」
  自死锁（495-a/595-a 两次双层锁教训的树域防线）；`gate_lock run --scope tree` 形态
  同样向子进程注入该变量，machine 域不注入（既有行为不变）。
- **逃生门**：`CN_NO_TREE_LOCK=1` 环境变量或 run_e2e `--no-tree-lock` 参数（完全跳过·
  仅确知本树无并发会话时用）；`wt.py remove` 遇活跃树锁拒绝删树（rc=1 打印持有者·
  `--force` 显式跳过）——防删树杀掉在飞 E2E/构建。
- **与 CI 池的关系**：预验池各实例独立克隆/worktree、单实例内 daemon 串行跑轮（§八/§九/§十），
  天然不触发树锁等待；池实例每轮 reset+clean 会连同 `target/tree.lock` 一起清掉
  （锁目录在 target/ 下·无残留陈锁面）；machine 域 gate.lock 语义与 595-a 拒绝名单一律不变。

## 十四、接棒判死探询协议（728l·2026-10-14·教训 #150）

> **背景**：看板巡检自动接棒的判死标准=「静默 27min + 无进程 + 改动冻结」三信号，
> 但教训 #150 实录证明 Agent 长推理/大段写码可静默超 27 分钟（期间无任何工具调用，
> 三信号全静默）——535 因此被误判死亡、二次派工撞车（二次接棒凭「发现同树活跃会话
> 立即停手升级请示」条款零损失救场）。本协议把「判死与接管之间」的缓冲确认机械化：
> **三信号命中后不得直接接管**，先探询→等待窗口→复查第四信号→才可接管。

**工具** = `scripts/patrol_probe.py`（子命令 探询/复查/selftest）。

**四步流程**：

1. **探询**（判死三信号命中后的第一动作）：
   `python scripts/patrol_probe.py 探询 <号> [--窗口 30] [--理由 "…"] [--交接]`
   - 任务备注追加带时间戳探询行（服务端备注=整字段替换语义·脚本先读旧再追加，不覆盖
     历史）；`--交接` 可选在看板交接区另落一条（全局注目通道）；同任务重复探询=续窗。
   - 探询行格式（方括号头=机器可解析·后面=人类说明）：
     `[探询 10-14 07:30 窗口30 基线a1b2c3d4 来源<机器>] 巡检判死三信号静默…请所有者
     回话（更新备注/推分支/续意图心跳任一即自动放行）…逾期按接管流程接棒`
   - 备注达 2000 上限时自动降紧凑形态；仍写不进=**显式拒绝**（禁静默截断丢留痕依据）。

2. **等待**：窗口期内不做任何接管动作。窗口默认 **30 分钟**（任务建议 15~30；长推理
   高风险任务/大重构用 `--窗口 45` 对齐教训 #150「等 ≥45 分钟」建议）。窗口内怕误判可
   再次探询续窗（复查按最后一条探询行的时刻/窗口计算）。

3. **复查**（窗口满后）：`python scripts/patrol_probe.py 复查 <号>` → 采集「第四信号」：

| 信号 | 来源 | 判活条件 |
|---|---|---|
| S1 任务更新时戳 | 看板服务 | 探询写入后任务另有更新（有人回话/动账） |
| S2 意图心跳 | 看板服务 | 在做=号的意图行心跳时戳 > 探询时戳 |
| S3 远端分支新提交 | gitcode 直连 | 分支 sha ≠ 探询基线（服务挂时仍可得） |
| S4 本机树活动 | 本机 | 树内源文件 mtime 新鲜（在写码）或树锁心跳新鲜（构建/E2E 在跑） |
| S5 本机进程引用 | 本机 | ps 命令行引用树路径/任务分支（排除巡检自身进程链） |

   - 任一出现活动=**活跃放行**（不接管）；全部可得信号静默且窗口满=**静默确认**（可
     接管）；窗口未满=**观察中**；看板服务不可达=**未知不接管**（fail-safe）。

4. **接管**：仅 `复查` exit 0（静默确认）才执行原接管流程（`wt.py create <号>
   --takeover`）；二次派工任务书必须含「发现同树活跃会话立即停手升级请示」条款
   （教训 #150③）。

**exit code 契约**（巡检自动化机械闸门）：探询 0=探询行已写入（可进入等待）/1=未写入
（不得接管）；复查 0=静默确认可接管 /1=不接管（活跃放行/观察中/未知/非在飞）。

**fail-safe 铁律（宁慢勿误）**：看板服务不可达=探询写不进、任务/意图信号读不到——
一律不接管，恢复后重试。漏报仅延迟接管；误接管撞车=双倍损失（535 实录）。

**巡检 automation prompt 增补段**（主会话 CronUpdate 应用：判死→探询→等待→复查→接管）：

    【接棒判死·先探询后接管（728l 机制·教训 #150）】判死三信号（心跳静默/无进程/
    改动冻结）命中后禁止直接接管，必须走四步：①探询=运行 python scripts/patrol_probe.py
    探询 <号>（默认窗口 30 分钟；大重构/长推理高风险任务加 --窗口 45）；探询写失败
    （看板服务不可达）=不接管。②等待=窗口期内不做任何接管动作。③复查=运行
    python scripts/patrol_probe.py 复查 <号>——exit 0=静默确认可接管；exit 1=不接管
    （活跃放行/观察中/未知）。④接管=仅复查 exit 0 才执行原接管流程（wt.py create <号>
    --takeover）；二次派工任务书必须含「发现同树活跃会话立即停手升级请示」条款
    （教训 #150③）。

**自测**：`python scripts/patrol_probe.py selftest`（离线 21 断言：构造/解析往返·追加
不覆盖·长度保护显式拒绝·判决五态）；`--在线` 加做真实往返（探询写入→读回断言→恢复
原备注·默认号 728l）。

### 16.1 b 面：验证器自检套件（已实施·L1 挂载）

**命令**：`python3 scripts/check_verifier_selfcheck.py`（纯本机·零池依赖·秒级；
临时 DB/目录 + 上报桩隔离，零 HTTP/零外发）。**挂载=L1 gate_quick 静态段**
（每次提交自动跑）；退出码 0=全绿（判定面可信）/1=有红（判定面失效或自检面失判别力）。

**原理**：坏结果注入四态单测——把**已知该被拦的结果**（红/超时/空结果）注入验证
机器各判定面，断言机器**必须判红**（若判绿=验证机器失效）；绿态为对照（防「恒红」
反方向失灵）。注入面六处：

| 面 | 被测 | 断言要点 |
|---|---|---|
| 聚合面 | `ci_daemon.聚合绿` | 红/超时（rc=-99）聚合为红；白名单七键逐个注入红；非白名单键（对账周检）rc=1 不拖轮绿（973 登记语义） |
| 落盘/上报面 | `ci_daemon.落盘`（临时目录+上报桩） | **ci/预验- 红/超时不得写 latest.json 不得上报**（1008 放红漏洞防线）；预验绿写 latest+上报（联动对照）；空结果 fail-fast（不静默产绿） |
| 解析放行面 | `integrate.解析预验结果` | 红/超时 JSON 判红；空文本/空对象/绿字段坏形态判红（868 收严）；服务端回读 0/1 形态契约 |
| 服务端存储面 | `queue_service.处理写`（临时 DB 直调） | 红/超时/空结果注入的绿列=0、详情留档、空详情不崩；认领失败分类（975）对同步超时算设施失败、对真实红/空结果不误报 |
| 跨端管线面 | 纯函数管线 | runner 聚合 → 服务端详情 JSON 往返 → 集成解析：四态端到端判定与注入态一致 |
| 元断言+结构锁 | 自检面自身 | **坏验证器（恒绿聚合/恒放行解析/坏落盘）注入必须被自检面抓住**（判别力自证·防自检空转——比验证机器坏更隐蔽的失效）；跑一轮同步键首写/绿存储形态结构锁 |

**边界（诚实）**：证明的是**判定链语义**（红不会被翻绿），不替代 a 面「真跑一轮
全量后仍必红」的端到端考核；HTTP/鉴权/并发认领面由 `test_pool_selftest.py` 承担
（分工：彼=服务活着且协议对，此=判定语义不撒谎）。与 728m（§十五·基础设施「活着吗」）
互补三层：728m=活着吗 / b 面=判定语义可信吗 / a 面=端到端必红能力。

### 16.2 a 面：阴性对照轮（设计·可选实施·本期未实施）

**概念**：医学化验的阴性对照（negative control）——已知**应为阳性/必红**的标本走
**真实生产链路**（真池 runner 认领、真跑全量），断言产出**必须红**；**报绿=验证机器
故障**（比红更严重的告警——机器本身失灵，所有绿记录不可信）。

**标本构造（与代码演进正交·关键设计）**：
- 分支名 `ci/阴性对照-标本`（`ci/` 前缀=非 `任务/` 分支——integrate/台账/销账链
  天然不碰；**永禁并入 develop**）。
- 内容=某 develop 头 + 对**稳定 E2E 用例**（如 `tests/e2e/01_hello/主.expected`）
  追加一行哨兵注释/文本——**任何编译器输出不可能与该期望相等**→ 该用例必红；
  哨兵与编译器语义演进完全正交（不像「重放历史红提交」会因修复而误变绿）。
- 标本用例被改名/删除的失效态→该用例若不存在，轮结果不再含对应红（记 INCONCLUSIVE
  待人工更新标本，不误判 PASS——见断言面）。

**槽位与节拍（复用 ci_reconcile 模式·不自创机制）**：ci_daemon 兜底/develop 面轮
静态段后挂「阴性对照段」（复刻 `scripts/ci_reconcile.py` 的周期段形态：
`ci-logs/阴性对照.json` 检查点 + `CN_NEGCTRL_PERIOD_DAYS` 默认 30 天）。到期动作=
把标本分支 tip 以 `ci/对照-<标本sha10>` 之名 `task_enqueue` 入池（复用现有池通道，
零新协议）；**平台由 770 轮转天然逐期轮换**（win→linux→arm64——逐平台考核）。

**断言与告警（巡检面）**：查 `/api/task_result?sha=<标本sha10>`——
- 状态=完成 ∧ 绿=0（且步骤红含 e2e）→ PASS（考官诚实）；
- 绿=1 → **FAIL「验证机器假绿」**（机器故障·最高告警级）；
- 无行/排队/执行中/超时 → WARN（无结论非通过）。
落地点二选一（实施时定）：infra_healthcheck §十五 B 段扩展（B4 阳性对照行）或
独立巡检命令；标本行被任务历史裁剪（保留 200 行）时由巡检触发防御性重入队
（同 §八 池行 miss 防御模式）。

**成本与实施清单（估 ~40 行）**：① 标本分支创建+维护命令（一次性+用例改名时）；
② ci_daemon 阴性对照段（周期判定+入池·复刻 ci_reconcile 骨架）；③ 巡检断言
（上述 4 态）；④ 告警面接入（journal/看板徽标）。每期成本=一轮全量池算力
（8~16 分钟）——月度节拍可忽略。

**边界（诚实）**：考核面=「池 runner 在 e2e 面必红必报」的端到端能力（覆盖 E2E
红上报链）；不覆盖「部分步骤被跳过/静态段假绿」等更细形态（那些由 b 面四态单测
逐面承担）。阴性对照轮本身故障（无人认领/池离线）≠ 考核失败=INCONCLUSIVE（WARN），
需与 FAIL 区分。
