> **定位**：腾讯云双机（TX_01 队列服务+预验任务池/TX_02 CI 农场）+家机 WSL2 runner 池的
> 部署、日常运维、故障处置与回退路径。

## 一、架构（五节点+家机 runner 池·1021）

```
三机（家机 win / 深度机 linux-x64 / 单位机 arm64）
   │ develop push（gitcode）                    │ 队列操作（integrate.py 服务端优先）
   ▼                                            ▼
预验任务池（1021）：integrate 触及全量面 → push ci/预验-<sha10> → TX_01 task_enqueue
   │
   ├─▶ TX_02 CI 农场（4C·systemd cn-ci）—┐   TX_01 队列服务（2C·systemd cn-queue）
   │    池认领 + develop 轮询双职         │    SQLite 队列/门禁/预验任务·HTTP:8300
   │                                     ├──▶ 结果页 http://<TX_01公网>:8300/
   └─▶ 家机 WSL2 runner ×7（4核8G/实例）─┘    （task_claim 原子认领·心跳断 300s 回收重派）
        CN_CI_ROLE=pool·谁空闲谁认领·多任务免串行排队
```

- **L3 全量门禁**（云端每推送+每日 04:30 cron 兜底）替代开发轮本机全量税（15~45min→0）。
- **本地裸全量护栏**（021 任务 354·2026-10-05 用户令）：`run_e2e.py` 无 `--filter/--shard`
  的裸全量无 `--full-reason "<任务号+理由>"` 直接拒（exit 2）——任务中途验证走三档阶梯
  （--filter 定向 / gate_quick --l2 / 云端 integrate）；CI 脚本（ci.ps1/ci_daemon/
  check_source_coverage/integrate 分步与复验）内置 reason 畅通。
- **队列状态零 git 提交**：中间态（集成中/失败恢复）只进服务端；边界（报名/销账）双写兼容旧机。
- 双测铁律不降：E2E 全量仍每推送必跑（linux 面=池（TX_02+家机）；win 面=家机异步验收；arm64 面=单位机）。

## 四、故障处置

| 症状 | 处置 |
|---|---|
| TX_01 服务挂/不可达 | 集成失败退出并提示稍后重试或 `--solo`（**v5（1016）看板直推通道已退役**——原「自动回退看板路径」不复存在·v4 看板已归档）；恢复：`ssh TX_01 'sudo systemctl restart cn-queue'`（Restart=always 通常自愈），恢复后重跑 integrate 即可 |
| TX_02 CI 挂 | develop 无云端全量记录——恢复：`sudo systemctl restart cn-ci`；期间每日 04:30 cron 也会自行补跑 |
| CI 高负载 SSH 进不去 | 全量门禁 4 核打满属正常（E2E 30~90min）——等跑完或从控制台 VNC；E2E 已 nice -n 10 降优先级（924） |
| 磁盘增长 | `ci-logs/run_*.log` 会累积——`ssh TX_02 'find ~/cn-ci/ci-logs -name "*.log" -mtime +14 -delete'`；旧 `result_*.json`/`预验_*.json` 同理（latest.json 保留） |
| 锁残留（daemon.lock） | flock 随进程结束自动释放；若 ps 无 ci_daemon 仍疑锁→直接删文件 |
| 队列行残留（服务端） | `curl -X POST .../api/clear -H "Authorization: Bearer <令牌>" -d '{"分支们":["…"]}'` |
| 令牌泄漏/轮换 | TX_01 改 `cn-queue.service` Environment 后 `systemctl daemon-reload && restart`；同步改 TX_02 `ci_config.json` 与各机 `queue_client.json` |
| 预验超时/触发失败（1008） | integrate.py 报「云端预验超时/触发失败」——①`ssh TX_02 'systemctl status cn-ci'` 看是否挂死；②常驻轮正在跑 develop 长轮属正常（预验 `--wait-lock` 排队·总超时 75min）；③确需先集成：`--no-cloud-gate` 逃生门（回退 941 事后兜底·事后恢复）；④`ci/预验-*` 远程分支残留→`git push gitcode --delete ci/预验-<sha10>` 或 branch_cleanup.py 兜底 |

## 七、云端预验门禁（1008·方案甲 test-then-commit）

> **立法**：用户裁决 2026-10-03（云端连续红的架构诊断——107 轮数据：58% 归 171 非确定性缺陷
> 连坐、24% 归修复中间态直推 develop、17% 归 L1 漏检真回归）。旧模式（941 fast-lane）=
> commit-then-test（先进 develop 云端再验，红灯窗口期结构性存在）；预验=test-then-commit
> （绿才进 develop，Chromium CQ/rustc bors/GitHub merge queue 同构）。

- **链路**：integrate.py（触及全量面的集成）→ 链顶推 `gitcode ci/预验-<sha10>` →
  `ssh TX_02` nohup 触发 `CN_CI_BRANCH=ci/预验-<sha10> ci_daemon.py --once --force --wait-lock`
  （锁排队=与 develop 常驻轮串行，3.6G 内存禁止双全量并发〔923 OOM 铁律〕）→
  轮询 `ci-logs/预验_<sha10>.json`（60s 间隔·总超时 75min）→ 绿放行 push develop／红拦截。
- **零重复算力联动**：预验**绿**时 daemon 写 latest.json+上报（链顶即将成为 develop 头），
  push 后 develop 常驻轮按「已跑过」（绿的 result_*.json 判定·1008 修正）跳过；
  预验**红**只写 预验_/result_ 文件（latest 保持 develop 语义不被污染）。
- **开关**：`--cloud-gate` 显式确认／`--no-cloud-gate` 逃生门（TX_02 异常时回退 941 事后兜底）／
  **默认开（1015 翻开·2026-10-04：常量 `云端预验默认开=True`——develop 回绿达成〔1013
  终验 c4c28311 轮绿〕·翻默认轮已同步 AGENTS §8.2-P/027 §8.2-P5 与本节）**。
  纯文档/脚本写集轮不预验（快速门禁+事后兜底仍覆盖）。
- **各机依赖**：ssh config 配 `TX_02` 别名（三机 ~/.ssh/TX_0x.pem 已在）；可选
  `scripts/ci_client.json`（gitignore·`{"ssh":"TX_02","目录":"/home/ubuntu/cn-ci"}`）覆盖默认。
- **执行位置（1021 池化后）**：默认走 TX_01 任务池（§八·多 runner 认领）；池不可达自动降级
  本节 ssh 直发 TX_02 原路径；再失败 `--no-cloud-gate` 逃生门。
- **升级部署**：daemon/integrate 改动进 develop 后——`ssh TX_02 'cd ~/cn-ci && git fetch origin develop && git reset --hard origin/develop && sudo systemctl restart cn-ci'`
  （跑轮会自 reset；restart=加载新 daemon 代码·选空档避免杀在跑轮）；家机实例=各克隆
  `git pull` 后 `sudo systemctl restart cn-runner@1 …cn-runner@7`（§八）。
- **红灯两纪律（同裁决·立即生效）**：①修复中间态禁推 develop（半成品只留任务分支+本节 §三
  分支预验）；②临时用例（*tmp*）禁入 develop（integrate.py 写集机械拦截）。

## 八、预验执行器池（1021·用户裁决=任务认领池+家机多实例）

> **立法**：用户 2026-10-05——「云端只有一台机器做预检测排队太久·家里 28 核 128G 闲着·
> 家机多虚拟机（4核8G/个）与云机谁空闲用谁」。慢大头=78/79 自举固定点（编译 CN 全部源码
> 两遍·串行链不可拆机），池化收益=**任务间并行**（多集成互不排队）而非单任务加速。

- **链路**：integrate（触及全量面）→ push `ci/预验-<sha10>` → TX_01 `task_enqueue`（幂等；
  已完成绿直接复用·红重置重跑）→ 各 runner 常驻循环 `task_claim`（TX_01 写锁内原子+回收
  心跳断 `CN_TASK_STALE_SEC`=300s 的执行中任务）→ 认领者 fetch 预验分支→`跑一轮`→
  `task_complete`（校验认领者·防回收后旧 runner 复活覆盖）；跑期间 runner 每 60s 心跳续约。
- **三层降级（行为超集）**：①池（多 runner·不排队）→ ②池不可达/超时=integrate ssh 直发
  TX_02（1008 原路径·`--wait-lock` 串行）→ ③`--no-cloud-gate` 逃生门（941 事后兜底）。
- **零重复算力联动（1008 池化续接）**：池绿结果存 TX_01 详情字段；TX_02 develop 轮
  「已跑过」=本地 result 绿 **或** `池已绿()` 查询——预验家机跑绿后 push develop，
  TX_02 轮询轮跳过；家机实例同时仍写本地 result/预验_ 文件+上报（成绩牌双保险）。
- **角色**：TX_02=池认领+develop 轮询双职（无 env·现状兼容）；家机实例=`CN_CI_ROLE=pool`
  纯池角色（develop 兜底归 TX_02）；`CN_CI_BRANCH` 点名模式跳过池（ssh 降级路径纯净）。
- **资源口径**：家机 28核128G → WSL2 VM 全局限 `processors=24 memory=100GB`（留余量给日常）；
  7 实例×（`CN_BUILD_JOBS=4`+`CN_E2E_JOBS=4`+`--max-mem-mb` 6G）≈24 核满载·7 任务不排队；
  单任务到达时 1 实例独跑（约 8~12min·TX_02 13~16min 同量级）。实例数=预期并发集成数，
  可随 `cn-runner@N` 增减。

## 九、win 池实例（291·2026-10-08 用户裁决·混合随机平台池）

**理念（用户裁决）**：win 实例与 linux 实例**同池认领同一任务集**——任务不带平台标签、
谁空闲谁认领（池协议零改动·任务表/门禁表/面板全不动）；win 实例领到任务跑 win 面
全量、linux 实例跑 linux 面；**任一平台红灯=平台差异缺陷暴露**（预验位红=develop 进
不去·拦截前移）。目的=杜绝平台差异（#269 虚表 NX/#176 CRLF 翻转这类 linux 云端全绿
放行后 win 才炸的缺口），非保证每轮两平台都绿。门禁表 PK=(sha,平台) 天然分平台显示
（win-x64 行与 linux-x86_64 行并排）。

**配比（用户指定）**：win 4 + WSL 3（+TX_02）≈ 池内两平台各半=任务被 win/linux 领到
概率≈各半（win 面高频随机验证）。WSL 由 7 收至 3（runner@4~7 stop+disable·2026-10-08）。

**部署（win 本体·一次性）**：
```

mkdir C:\CN_CI\win-pool && cd C:\CN_CI\win-pool

cd repo && for i in 1 2 3 4; do git worktree add --detach ../wt$i origin/develop; done
# ② third-party junction（gtest 两级深度=CMakeLists 固定 ../../third-party）：
python -c "import _winapi; _winapi.CreateJunction(r'C:\Users\ChenChao\Documents\third-party', r'C:\CN_CI\third-party')"
# ③ 每实例 ci_config.json（gitignore·含上报地址=win 轮进门禁表平台列）：
#   {"上报地址":"http://<TX_01>:8300/api/report","令牌":"<令牌>","池地址":"http://<TX_01>:8300","池令牌":"<令牌>"}
# ④ 计划任务（登录触发·错峰延迟 3/5/7/9 分钟·开机即上线·关机即离线=心跳 300s 回收）：
schtasks /Create /TN CN-CI-win1 /TR "cmd /c set CN_CI_ROLE=pool&& set CN_RUNNER_ID=%COMPUTERNAME%-win1&& set CN_GATE_LOCK_DIR=C:\Users\ChenChao\Documents\CN\CN_Language_C\target\gate.lock&& python C:\CN_CI\win-pool\wt1\scripts\ci_daemon.py --loop" /SC ONLOGON /DELAY 0003:00
```

**win 侧机制（ci_daemon 平台分支·linux 行为零变化）**：
- 平台运行时探测（sys.platform→win-x64/linux-x86_64·替换 5 处硬编码）——共享文档不指定本机类型。
- 锁=msvcrt.locking（统一 seek(0)）；物理内存=GlobalMemoryStatusEx；构建=vcvars64+Ninja+sccache
  （**首配必带 /Z7**——默认 /ZI 集中 PDB 并行必撞 C1041；参数拼接勿粘连）；cmd /c 复合串内嵌
  引号经 subprocess 转义必坏——生成 ASCII 临时脚本跑（win_configure/win_build.cmd·固定名覆盖写）。
- 三段外套 gate_lock（CN_GATE_LOCK_DIR 指向主开发树锁目录=与人工门禁全机互斥）；30 分钟未获得
  =让出（不落盘不 complete·服务端回收重派=本机忙让给别人）。
- E2E --target win-x64·CN_E2E_JOBS 默认 6（4 实例峰值 4×6+构建<28 线程）。
