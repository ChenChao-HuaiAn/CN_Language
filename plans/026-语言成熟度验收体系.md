## 二、五大测试支柱实施细则

### 2.1 支柱一：规范覆盖率矩阵（根治「想到才测」·优先级第 1）

- **做什么**：脚本解析 plans/001 全部 EBNF 产生式与语义条文（46 保留字、各语句/表达式/类型/模块规则），
  生成「条文编号 × {正例， 边界例， 负例}」矩阵；每格必须有 `tests/e2e/`（或 unit）用例指针，**空格即
  缺口清单=自动生成的排班队列**（进 plans/021 §3，不再靠灵感发现「规范有实装缺」类缺口）。
- **量级**：预计 **1000~1500 用例**（存量 313 为基底，缺口约千级但结构化——每条直接对应一条规范）。
- **验收**：`scripts/check_spec_coverage.py` 报告 100% 且接入 `ci.ps1` 门禁；plans/001 每次契约变更联动重跑。
- **归属**：开发轮（写脚本+补用例）；矩阵缺口清单的批量补用例可拆多轮。
- **前置**：无（纯增量、零语言变更——立即开工项）。

### 2.2 支柱二：CN-Smith 生成式差分测试（收敛主力·优先级第 2）

CSmith 方法论（2008 年起在 GCC/Clang 上发现数百 bug 的手段）——唯一能让测试量超越人力的途径。

- **做什么**：①**随机程序生成器**：按规范文法生成随机合法 CN 程序（控制内存/运行时间上限，避开
  非确定性面）；②**差分矩阵**：每程序在 宿主/v2 双实现 × 三后端（win/x64l/arm64）编译，产物全部
  运行、输出必须一致（分歧=立即定位出错侧）；③**负向注入**：随机注入语法/语义错误，验证编译器
  **永不崩溃、必有诊断**（T6 类问题机械化歼灭）；④**语料池**：v2 全树（8.25MB asm 语料）、stdlib、
  全部历史用例加入轮换。
- **量级**：持续运行，目标每日万级程序；不设「多少算够」——以 §三收敛信号判定。
- **验收**：生成器+差分 runner 固化为 `scripts/`（或 tools/）工具，三机验证轮（角色③/🧪 档期）持续跑；
  逃逸缺陷按反证三件套流程根治并自动留负测。
- **前置**：无硬前置（生成器可增量：先正向后负向、先单后端后全矩阵）。

### 2.3 支柱三：性能基准门禁（优先级第 4·前置 F1-26 Phi 落地）

- **生成代码性能**：固定基准套件 **20~50 任务**（排序/图/字符串/数值计算/IO 密集/分配密集，
  Benchmark Game 风格），CN 与 C++ 同算法实现对照、三平台跑；判据=**几何平均 ≥1.0×C++ 且最差单项
  ≥0.9×**（禁止平均好看单项崩盘），附方差与统计显著性报告。
- **编译器自身性能**：v2 全树自编译语料跑 `bench_self_host`：自举 CN 编译器 vs C++ 宿主编译器的
  时间/内存曲线；判据=**逐文件编译时间与峰值内存全面占优**（双目标①的直接口径）。
- **验收**：`scripts/bench_*` 进每轮门禁；任何改动使基准劣化 >2% 即红灯（rustc-perf 同款机制）；
  每轮性能趋势入 plans 留档。
- **前置**：F1-26（Phi 落地）+D8（冗余 mov）——否则基准失真；基准套件本身可先建（先行跑基线）。

### 2.4 支柱四：安全属性矩阵（比肩 Rust 的具体含义·ASan 扩面第 3 优先、矩阵第 5）

- **属性清单反向穷举**：从 Rust 保证清单+CWE Top 25 编制 **~50 条安全属性**（UAF/双重释放/泄漏/
  越界读写/悬垂指针/别名可变性/迭代器失效/数据竞争/整型溢出语义〔T9 方案 D〕/未初始化读……），
  每条**四件套**：CN 机制说明（编译期拦截/运行时兜底/明确不保证）+正例+负例+检测器证据。
- **Rust 负测移植**：borrowck compile-fail 集语义等价移植（**500~1000 条**精选）——每条=Rust 拒绝的
  错误写法 CN 也必须拒绝（含诊断质量锚定）。
- **运行时检测全量常开**：**全部** E2E+单测在 ASan+valgrind 双检下运行零报告（F1-30 已接入构建，
  从单测面扩到 E2E 全量；valgrind 为 linux 侧口径）。
- **形式化（远期·诚实边界）**：Rust 有 RustBelt/Stacked Borrows 背书；CN 长期项=借用检查器核心
  soundness 形式化论证（CompCert 路线子集化务实版）。不阻塞 M5 判定，但保留在路线图——否则
  「比肩 Rust」在学术口径站不住。
- **前置**：ASan 扩面无前置（立即）；矩阵与负测移植随 C3 波 4/7/8 铺开（E1 并发=数据竞争条目前置）。

### 2.7 第 2 层细则：工具链 CLI 契约（249-a 建成·B4 转入）

- **对象**：cn 驱动**自身**行为——子命令 × 形态 → 退出码 + 诊断（不涉语言语义；语言面=支柱一）。
- **设施**：`scripts/check_cli_contract.py`——**五维面 49 格**（非点检查）：
  ①子命令面：build/compile/run/check/ir/ast/token 全 7 命令 × 成功/失败；
  ②退出码语义面：rc 0/1/3/5/255 透传（B4 锚定）+运行期错误码→rc+编译失败码；
  ③选项面：四优化级 -O0~3/--opt/--no-regalloc/--debug/--验证-ir/--cfi/--发布/--release/--verbose/
  --output（含深层目录自动创建）/交叉 --target 产物形态/--version/--help/未知选项；
  ④命令行形态面：无参数/未知子命令/缺文件/不存在/目录输入/空文件（库组件口径）；
  ⑤通道与诊断面：stdout-stderr 分流+诊断格式 `文件:行:列: 错误:` 正则锚定+分层口径锚定
  （token=词法层/ast=语法层/ir=全流水线——各拒本层错误、放行下游层）。ci.ps1「1.5/4」接入。
- **矩阵首批发现（建成即产出·面检查价值实证）**：①**目录作为输入被静默"检查通过"**（Linux
  `ifstream` 打开目录"成功"读出空内容）→ 已同轮根治（readSourceFile 前置目录拒绝·跨平台）+格锚定；
  ②ast/token 对下游层错误放行经实测=分层设计口径（首版格期望按单层假设写错·已修正为分层锚定）；
  ③`--version` 文案过期（linux-x86_64 标"初期/plans/016"）=轻面登记。
- **来源事件 B4**（2026-09-17 单位机探针）：`std::system` POSIX 返回值=waitstatus（退出码 N→N<<8）被
  直接透传 → linux 双后端 `cn run` 退出码恒 0（假绿）；win 侧 MSVC CRT 恰=退出码故不显形（平台掩盖缺陷）。
- **规则**：`cn_main.cpp` 全文件 `std::system` 消费点必须经 `systemExitCode` 归一（同族穷尽 5 消费点：
  846 主缺陷/508·512 诊断失真/280 布尔化恰好正确/253 无害——前两者 249-a 已归一，后两者亦归一防未来误用）。
- **反证留档**：还原 846 行为裸 `return std::system(...)` → 格 2/3 FAIL（8/10）→ 复原 → 10/10——门禁
  对 B4 类缺陷的机械捕获能力已实证。
- **跨机欠账**：win 侧形态（MSVC CRT 语义）单位机不可实测——家机 CI 跑同脚本即覆盖（自动探测平台）。

### 2.8 第 3 层细则：编译器源码覆盖率（第二波·✅ 250-a 建成）

- **与支柱一的区别**：支柱一矩阵=「规范条文 → 用例」覆盖（语言行为面）；本层=「编译器自身源码行/
  分支」覆盖（实现面）——暴露「测了规范但没测到的代码路径」（死分支/隐性路径/未触发的防护），二者互补。
- **设施（250-a 落地·linux gcov 口径）**：①`CMakeLists.txt` `CN_ENABLE_COVERAGE` 选项（GCC/Clang
  `--coverage`；MSVC=FATAL_ERROR 明确不支持；产物隔离输出 `target/cov/` 不污染常规构建）；
  ②`scripts/check_source_coverage.py` 一键全链：coverage 构建零警告→清旧 gcda→单测→全量 E2E
  （先清 v2p 指纹缓存=强制「cn 编译 v2 全树」刺激入 gcda）→CLI 契约矩阵→`gcov -b -i` JSON 聚合
  （行/分支·132 编译单元源文件）→报告入档 `target/coverage/`→**阈值门禁**（行/分支覆盖率
  ≥基线−0.5pp，基线按平台键控入库 `scripts/coverage_baseline.json`）→**新代码红线**
  （`--diff-base REV`：其后新增/修改的源码可行行必须被门禁语料触达；含双重防假绿守卫=
  gcov 告警拒判+gcda 早于 gcno 失配拒判）；③`ci.ps1 -Coverage` 参数化步（常规链默认不跑——
  插桩全链约 1 小时，专项/定期轮启用；产物缺失（win/MSVC）=提示跳过）。
- **首跑基线（250-a·linux-arm64/gcc-9.3.0·全语料口径）**：行覆盖 **79.5%**/分支覆盖 **48.26%**；
  首跑即暴露覆盖结构=ir_verify.cpp 0%（--验证-ir 校验器语料未触达）、linux_x64 后端 5~12%
  （arm64 机器 E2E 语料不运行 x64l 目标产物=跨机覆盖定量证据）、ast_printer 14.6%——低覆盖清单
  =后续语料补强/死代码清理的输入（面检查价值实证）。
- **反证两件（250-a 实测）**：①阈值——基线人为抬至 90%→门禁 FAIL（精确指认差值）→复原 PASS；
  ②红线——`--diff-base HEAD` 绿；注入「从不被调用的探针函数」→红线 FAIL 指认未触达行→复原绿；
  实验中连带实证 gcda/gcno 失配通道（gcno 重生成后旧 gcda 被静默弃用=覆盖假归零）→ 同轮落入
  脚本双重守卫。
- **口径**：源码口径=编译器本体 `src/cn_compiler/**`+`src/cn_main.cpp`（`src/runtime/**` 由产物
  程序执行，不入编译器覆盖口径）；行覆盖=任一插桩对象（cn/cn_unit_tests）该行 count>0；分支覆盖=
  branches count>0 占比。
- **诚实边界**：win/MSVC 无 gcov=仅 linux 口径（026 既批）；覆盖率数字平台相关——他机首跑各自
  `--update-baseline`；「每轮入档」的执行节奏=涉 src 改动轮在收工验证链附注覆盖率数字
  （全链专项跑），常规轻轮不强制 1 小时全链——由 `-Coverage` 开关与排班承载。

### 2.9 第 4 层细则：采样轮协议（256-b 落盘·**用户已批复「按这个办」**·待实施认领）

> 回答「点状缺陷靠运气发现」的机制正解：**「发现新类别」= 采样（概率但高频·命中率实测 0.2%/样本→日万级采样≈日百级命中）；
> 「该类永不静默」= 机械不变量检查（确定性·见 §2.9 尾注）——两网分工，缺一不可。**

**采样轮协议（自治循环·五步）**：

```
每轮循环（建议间隔 10 分钟或跑完即起·给机器留余量）：
  ① git fetch → 有新提交则拉取 + 重建（用新编译器）
  ② 生成 N 个新样本（轮换种子）+ 历史命中样本回归轨（新编译上重跑·防回归）
  ③ 差分（-O0 vs -O3）→ 自动分级：编译失败 / 运行失败 / 输出分歧
  ④ 命中样本存档（「命中样本库」·防 target/ 清场丢失）+ 排班追加一行
     （最小复现路径 + 基线 commit + 类别判定）
  ⑤ 本轮三件套记入采样日志 → 下一轮
```

**设计要点（256-b 落盘）**：
- **双轨语料**：新采样轨（换种子·负责撞新问题）+ 回归轨（历史命中样本·负责证「修好的没复发」=每轮修复的独立复验）；
- **命中样本库**：命中即存档（当前 D31 的 s269.cn 尚在 target/ 险境——实施时一并抢救入库存档）；
- **三件套日志**：①基线 commit ②采样量/命中数 ③命中归类（新类别/旧类反复）——**即 M3 计时的秒表**（「连续 4 周零新缺陷类别」以日志起算）；
- **三机通用·不绑机器**：脚本按架构自动探测目标（cnsmith_diff 已跨平台化·256-a），三机任一空闲机可跑=**验证轮**（角色③·免开发锁·写面 target/+/tmp/共享文档本机分区）；
- **节流**：轮间睡 10 分钟或跑完即起（CPU 密集型·给开发轮让路）；
- **交付物**：`scripts/cnsmith_daemon`（一键自治循环·三机通用）+ 命中样本库目录 + 采样日志文件；
- **扩展路线（后续子项·不在首期）**：四优化级两两一致（-O0/1/2/3 矩阵）；**差分「v2 维」**（宿主 vs 自举 v2 批量对比·D28/D29 族会被批量抓出）；自动最小化（命中样本 delta-debugging 缩小·对标 creduce）。

**诚实边界**：采样空间无限，「发现」永远是概率性——协议的价值是把概率冲到「潮水级」+让人类角色降为「看日志+审排班」；「杜绝本类」的确定性由机械不变量承担（**每次发现都强制升级一条铁律**·§三-5「冒一个→校准一层」）。
