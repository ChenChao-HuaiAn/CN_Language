## 〇、大白话摘要（给用户的一分钟版）

**要做什么**：给 CN 语言补上「多线程」能力——让程序能同时干几件事（这是写操作系统 M8、跟 Rust 比安全的必经之路），同时配一套「编译期安全带」（对标 Rust 的 Send/Sync）：哪类数据能 safely 递给别的线程，编译器说了算，递错了直接编译报错，而不是运行到一半数据被踩坏。

**CN 的独特优势**（为什么我们比 Rust 做这件事更简单）：Rust 里两个线程共用一份数据是常态，所以它需要一大套复杂的检查。CN 的默认规则是「传出去就是拷贝一份」（值语义深拷贝），两个线程天然各拿各的、互不干扰——**竞争的土壤在默认路径上已经不存在**。所以我们只需要在少数几扇「显式共享的门」上装安检（引用/锁/裸指针），不用全语言戒严。这正是 019 哲学四句话的延伸。

**不用新增任何关键字**：线程、锁、原子全部做成标准库类型（`stdlib/线程.cn`），「可跨线程」标记做成两个空接口，借用语言里现成的泛型约束语法 `泛型 <类型 T : 接口>`——46 个保留字终态不动。

**怎么裁决**：直接翻到 §六 对比表和 §十 裁决语。

## 二、核心设计洞察：CN 值语义让 Send/Sync 缩小一个数量级〔基准=019〕

Rust 需要 Send/Sync 是因为它的默认是「共享可变」风险面大（多处别名同一份数据）。CN 四句话哲学逐条对照：

| 哲学（AGENTS §3.1） | 在并发安全上的落点 |
|---|---|
| ① 默认路径零规则 | 线程实参**按值拷贝**进新线程（容器/字符串深拷贝）——两线程天然无别名、无竞争，**不学任何规则即可安全开线程**（代价=拷贝，由 ④ 承接） |
| ② 显式放弃安全=显式获得性能 | 跨线程零拷贝走 `转移()`（旧名禁用——复用阶段 1 仿射检查，**不新造机制**）；原子弱内存序为性能逃生门 |
| ③ 危险面收口而非全语言戒严 | 竞争只可能来自三扇门：**借出视图/引用**、**共享可变（互斥锁所护之物）**、**不安全指针**——安检只装这三处 |
| ④ 拷贝消除是编译器义务 | 线程实参拷贝的代价由 054 最后使用自动转移等拷贝消除设施逐步吸收，不在本立项新增义务 |

**结论**：CN 的 Send/Sync 只需要「类型级标记＋三个检查点」，推导规则表一张纸装得下（§四）；Rust 的生命周期参数化线程（scoped thread）、'static 约束等大半设施在 CN 无别名默认下**没有对应问题域**，不需要对标。

## 三、并发标准库 API 面（方案甲·提案）

新增 `stdlib/线程.cn` 模块（对齐 stdlib 现行 12 模块的「类＋公开: 标签」组织与 `导入 模块::名称` 用法）。

### 3.1 线程与并入

```cn
导入 线程::线程

// 线程入口=普通函数（示例自定义普通函数，非语言构造语法）
函数 求和任务(整64 次数) -> 整64 {
    整64 总计 = 0;
    循环(整64 i = 0; i < 次数; i++) {
        总计 = 总计 + i;
    }
    返回 总计;
}

函数 主() -> 整32 {
    // 启动：入口函数＋实参。实参按值【拷贝】进新线程（安全默认·无别名）
    线程<整64> 工人 = 线程::新(求和任务, 1000000);
    // 并入(join)：等待结束、取回返回值。未并入的线程在 主 返回时=运行时错误（宁严勿松）
    整64 结果值 = 工人.并入();
    返回 0;
}
```

- `线程<T>`：泛型类，`T`=入口函数返回类型。
- `线程::新(入口, 实参)`：**检查点①**（§四）施加处——实参类型必须 `可跨线程转移`。
- `.并入() -> T`：同步点（内存屏障语义=顺序一致）；线程内运行时错误与单线程同语义（进程退出＋诊断）。

### 3.2 互斥锁与锁守卫（共享可变的唯一合法通道）

```cn
导入 线程::互斥锁

函数 主() -> 整32 {
    互斥锁<整64> 计数器 = 互斥锁<整64>::新(0);
    // 线程体经 lambda/函数指针操作 计数器（须以引用形态共享——检查点②）
    // .上锁() 返回 锁守卫<T>：RAII 对象，析构自动解锁（异常/提前返回不漏解锁）
    锁守卫<整64> 守卫 = 计数器.上锁();
    守卫.值() = 守卫.值() + 1;
    返回 0;
}   // 守卫析构=自动解锁
```

- `互斥锁<T>`：`T 可跨线程转移` ⇒ `互斥锁<T> 可跨线程共享`（锁使共享安全，Rust `Mutex<T>` 同构）。
- `锁守卫<T>`：**不可跨线程转移、不可共享**（守卫只在加锁线程的栈上存活——Rust `!Send` 同款，宁严勿松）。

### 3.3 原子类型族与内存序（plans/026 L4 承载）

- 具名族：`原子整32 / 原子整64 / 原子正64 / 原子布尔 / 原子指针`（对齐 026「原子类型族」表述；具名族比泛型 `原子<T>` 少一层约束判定，第一版从简）。
- 方法：`.装载()` / `.存储(新值)` / `.加一()` / `.交换(新值)` / `.比较交换(期望, 新值) -> 布尔`。
- 内存序：`内存序` 枚举=`松弛 / 获取 / 释放 / 顺序一致`；**全部方法默认 顺序一致**（安全默认），显式传内存序=性能逃生门（哲学②）。三后端映射：win=Interlocked 系 / POSIX=`__atomic` 内建 / ARM64=ldar/stlr 族。

### 3.4 通道（波 3）

`通道<T>`＋`发送端<T>`/`接收端<T>`（多生产者单消费者，Rust mpsc 同构）：`.发送(值) -> 结果<空类型, 字符串>`（接收端已关闭=错误）、`.接收() -> 结果<T, 字符串>`（通道关闭且空=错误）。条件变量（Condvar）波 3 一并评估——互斥锁＋通道已覆盖多数场景，若引入则同样 RAII 化。

## 四、Send/Sync 语义：两个标记接口＋推导规则＋三个检查点〔基准=019〕

### 4.1 标记接口（零新增关键字）

```cn
// 编译器内建标记接口（提案条文·plans/001 新章）：空接口体，禁止用户手工实现（第一版）
接口 可跨线程转移 { }   // 对标 Rust Send：该类型的值可以【转移】到另一线程
接口 可跨线程共享 { }   // 对标 Rust Sync：该类型的引用可以【共享】给另一线程
```

- 自动实现由编译器按 §4.2 组合规则推导；用户显式逃生门 `不安全 实现 可跨线程转移` 挂波 2（收口在 不安全区，哲学③）。
- 供用户声明约束时直接复用现行泛型约束语法：`泛型 <类型 T : 可跨线程转移>`——**零新语法机制**。

### 4.2 推导规则表（组合式自动衍生，对标 Rust auto trait）

| 类型 | 可跨线程转移 | 可跨线程共享 | 依据 |
|---|---|---|---|
| 数值/布尔/字符/枚举 | ✅ | ✅ | 位面拷贝无别名 |
| 字符串（拥有型）/拥有型容器 | ✅ | ✅ | 深拷贝值语义（基准①） |
| 结构体/类 | 全字段 ✅ 则 ✅ | 全字段 ✅ 则 ✅ | 组合传递 |
| `容器<T>`/`可选<T>`/`结果<T,E>` | T ✅ 则 ✅ | T ✅ 则 ✅ | 元素语义随元素 |
| 引用/借出视图（`T&`、`容器.元素()` 类返回） | 所指 T **共享** ✅ 则 ✅ | 同左（&T 转移 ⟺ T 共享，Rust 同构） | 别名面安检 |
| **借出视图**（元素/读取/获取 等返回的引用视图） | ❌ 第一版一律 ❌ | ❌ | 容器可被他线程改写→悬垂，宁严勿松（A21 借出检查同族） |
| 裸指针 `T*` | ❌ | ❌ | 不安全面收口（哲学③），走 `不安全 函数` 审计 |
| `互斥锁<T>` | T ✅ 则 ✅ | T ✅ 则 ✅ | 锁使共享安全 |
| `锁守卫<T>` | ❌ | ❌ | 守卫只在加锁线程栈上 |
| `原子X` 族 | ✅ | ✅ | 内部同步 |
| `发送端/接收端<T>` | ✅（T ✅） | ❌（第一版） | 对标 Rust mpsc |

### 4.3 三个检查点（违例=编译期错误，对标 Rust E0277 诊断形态）

1. **线程入口实参**：`线程::新` 实参（含 lambda 捕获展开后的全部捕获）必须 `可跨线程转移`。诊断示例：
   `错误: 类型 '互斥锁<整64>*' 不可跨线程转移（裸指针不转移）——请转移拥有型数据，或改以 互斥锁 保护后共享引用`
2. **跨线程共享位**：被两线程同时可达的可变访问位（互斥锁所护之 T 经 `.值()` 出借、静态可变量跨线程引用）必须 `可跨线程共享`。
3. **显式约束**：`泛型 <类型 T : 可跨线程转移>` 等约束由现行泛型约束检查机制承载（任务 D46 重放检查同链）。

**与既有防线的复用关系**：跨线程转移的「原线程旧名禁用」直接复用阶段 1 转移仿射检查（不新造）；借出视图跨线程拒绝与 A21 借出生命周期检查同族（同一别名面）；不安全指针路径已由阶段 4 `不安全 函数` 收口——并发安检是**受检区新增一条防线**（019 分层模型），不是平行新体系。

## 五、示例：三方案下的同一段代码（观感对比）

```cn
// 目标：两个线程各统计一半，主线程汇合（安全区写法——三种方案下写法相同）
导入 线程::线程

函数 数数(整64 到) -> 整64 {
    整64 和 = 0;
    循环(整64 i = 1; i <= 到; i++) { 和 = 和 + i; }
    返回 和;
}

函数 主() -> 整32 {
    线程<整64> 甲 = 线程::新(数数, 500000);   // 实参拷贝进线程——无别名
    线程<整64> 乙 = 线程::新(数数, 500000);
    整64 总 = 甲.并入() + 乙.并入();           // 并入=同步点，其后断言确定性
    返回 0;
}
```

差别在「编译器拒绝什么」：方案甲/乙在此**编译期**拒绝把裸指针/借出视图递给线程；方案丙放行、运行时才报（§六）。

## 九、诚实边界（开工前预判）

1. 本呈报全部 API/语义为**提案未实装**——示例不可编译，非实测示例（文档头已声明）。
2. 第一版无 `不安全 实现` 手工标记逃生门（波 2 提供，收口在不安全区）；期间遇推导规则覆盖不了的类型（如 FFI 句柄包裹类）只能等待或暂不跨线程——宁严勿松。
3. 无 `.分离()`（detach）：线程必须并入；`主` 返回时存在未并入线程=运行时错误（进程退出语义静默杀线程是竞态温床）。
4. 借出视图第一版一律禁跨线程（§4.2）——「受锁保护的借出」等精细化挂波 3 后评估，先拒绝再放开。
5. **E2E 确定性口径**：线程调度时序不可复现——断言只允许出现在 `.并入()`/锁/原子同步点**之后**（先于同步点断言=用例设计缺陷）；fuzz/压测型并发用例不入 E2E 门禁（时长不稳），另立采样轨。
6. 网络模块（033 余项）不在本呈报：网络库依赖本并发库落地，随 033 本体另行立项呈报。
7. v2 侧全链对齐在波 3（宿主先行）；期间 v2 编译并发程序=特性缺口拒绝（对齐「v2 未实现的内容就去实现 v2」推进，不降级双测）。
8. 内存序第一版默认顺序一致，弱序（获取/释放/松弛）为显式性能逃生门；弱序正确性归用户责任（诊断文档明示），编译器不做弱序验证（业界同口径——正式模型化验证属长期研究面）。
