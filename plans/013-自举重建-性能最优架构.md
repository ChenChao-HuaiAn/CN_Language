## 〇、为何必须重建（现状病根）

当前 CN 自举组件（CN语言编译器/）用【字符串行】作为所有层间中间表示：

```
词法   : 向量<字符串> "类型|文本|行"
解析   : 向量<字符串> "缩进+节点"
IR生成 : 向量<字符串> "调用|符号|参数数|标志|参数码"
代码生成: 向量<字符串> asm 行
```

**病根**：每层都把结构化数据序列化成字符串，下一层再解析字符串。导致：
1. 每层 O(文本量) 的序列化+解析，重复劳动
2. 百万级字符串分配（实测代码生成模块峰值数 GB）
3. 无驻留：相同符号名/类型名在每个 token/AST/IR 行重复分配
4. 层间无结构化对象，无法直接引用/复用
5. 字符串比较/查找大量 O(n)

性能实测（**v1 字符串行口径·历史数据**）：CN/C++ ≈1.04x（字符串行依然不慢，但内存失控 + 无法超越 C++）；v2 重建后的性能对标见 [`plans/021`](021-任务进度观察表.md) 与 `plans/026`。

## 一、性能最优架构总览（对标 rustc/LLVM）

**核心原则**：
- 中间表示用【结构化数据】（结构体数组/AoS），不用字符串行
- Arena 一次性分配：整个编译单元一个 arena，结束一次释放
- 字符串驻留：符号名/类型名 -> Symbol(u32 ID)，字符串只存一份
- 哈希符号表/作用域：O(1) 查找
- 只最后一层输出文本（汇编），其余全是结构化对象

```
源文件 -> 词法器 -> Token[]（结构化） -> 语法分析 -> AST（arena节点）
  -> 语义/类型 -> 标注AST+符号表（哈希） -> IR生成 -> IR[](结构化指令)
  -> 代码生成 -> asm文本（最后一次文本化） -> 汇编/链接
```

## 二、分层设计（每层性能最优）

### 1. 运行时基础设施（src/runtime 新增）

**A1. Arena 分配器（已有 内存::竞技场分配，启用/强化）**
- bump 分配，8 字节对齐；编译单元共享一个 arena
- 整个编译结束一次性 __cn_arena_reset，无逐对象 free
- 消除：百万级小 malloc、堆碎片、reset-UAF

**A2. 字符串驻留表（新增，对标 rustc Symbol / LLVM StringPool）**
```
内置：驻留(字符串) -> 整32 ID   // 相同内容返回同一 ID，只存一份
内置：字符串(整32 ID) -> 字符串 // ID 反向查文本（调试/错误消息）
内置：字符串长度(整32 ID) -> 整64
```
- 内部：哈希表 内容->ID + 字节池（每字符串一份）
- Token/AST/IR 里所有文本/符号字段都是 ID(u32)，O(1) 比较
- 消除百万级重复字符串分配

**A3. 高效 growable 数组（对标 std::vector）**
- 已用 向量<T>；确保 追加 amortized O(1)（已是）
- 大量用 向量<整32>/向量<整64> 存 ID，避免字符串

### 2. 词法器（词法分析.cn 重建）

**Token（结构化 AoS）**：
```
结构体 Token {
    整32 类型    // 关键字/标识符/字面量（枚举码）
    整32 文本     // Symbol ID
    整64 行       // 源行号
}
```
- 输出 向量<Token>（不是 向量<字符串>）
- 一次性扫描源码字节；标识符/数字直接算 ID

### 3. 语法分析器（语法分析.cn 重建）

**AST（arena 节点，索引引用）**：
```
struct ASTNode {
    int32 kind;      // 节点类型码
    int32 start, end; // 子节点在节点池 [start,end) 或 child 索引
    int32 text;      // 关联 Symbol ID
    int64 extra;     // 数值/行号等
}
向量<ASTNode> 节点池   // arena：一次性分配，索引引用
```
- 递归下降产出自顶向下节点到节点池
- 子节点用索引(int32)引用：cache 友好、无指针管理

### 4. 语义/类型分析（语义分析.cn 重建）

- 符号表/作用域：映射<整32, 符号信息>（Symbol ID -> 声明），O(1)
- 类型检查标注到 AST 节点（extra 存类型 ID）
- 函数签名表：映射<整32, 签名>
- 不产生新字符串（只用 ID）

### 5. IR 生成（IR生成.cn 重建）

**结构化 IR 指令**：
```
struct IRInsn {
    int32 opcode;   // Add/Sub/Load/Store/Call/Branch...
    int32 result;   // 虚拟寄存器号(-1 无)
    int32 a, b;     // 操作数寄存器/常量
    int32 type;     // 类型码
    int32 extra;    // 附加（符号 ID/块标签/变量名）
}
```
- 指令在 arena 数组；函数=基本块列表；寄存器=整数
- 常量池：字符串常量驻留到字符串表(ID)

### 6. 优化器（可选增强）
- 常量折叠/DCE/CSE 直接在 IR 指令数组做（整数/寄存器比较 O(1)）
- 位置即向量索引，删除用 swap-pop

### 7. 代码生成（代码生成.cn 重建）

- 只有这一步生成字符串（asm 行）
- IR 指令数组线性遍历 -> 汇编文本

## 三、性能关键点（为什么不妥协）

1. 零字符串中间表示：token/AST/IR 全用结构化 + ID，杜绝文本化
2. Arena 分配：编译单元整体管理，无逐对象 free 记账，无碎片
3. 字符串驻留：相同内容只存一份，比较用 ID O(1)
4. 哈希查找：变量/函数/类型解析 O(1)，无线性扫描
5. 数组 cache 局部性：AoS 紧凑结构体，顺序遍历友好
6. 无拷贝：层间传 向量/索引（借用），不复制节点

## 五、自举验收

自举 = CN 版编译器能编译自身源码（产出可运行的 CN 版编译器）。逐层：
1. 词法器编译自身 -> 结构化 Token
2. 语法分析器编译自身 -> AST
3. 语义/IR/代码生成 编译自身 -> 汇编 -> 链接 -> CN 版编译器
4. 用 CN 版编译器再编译自身（二阶自举固定点）
5. 性能 bench：CN/C++ 组件链耗时比 < 1.0

## 七、v2 整程序级预编译缓存（任务 1272·宿主 #1156 对偶）

**目标**：重复编译同一输入闭包时直接复用汇编产物，跳过语义/IR/优化/代码生成，
压缩自举闭环双跳（M2 v2p 自编译 / M5 cn_self 再编译）时间。

**实现**（CN语言编译器v2/驱动/程序缓存.cn + 主.cn 两遍加载；1272 返工后形态）：
1. **闭包扫描**（只扫描=1）：读取/预处理/分词/导入与挂载递归解析，按拓扑序记录
   每模块（路径/模块路径/moduleDir/源内容 128 位摘要/包根/入口标记）；不解析。
2. **键计算**：键格式版本 + v2 自身可执行文件内容 128 位摘要与路径 + 目标平台 +
   优化级别 + 排序宏集合（-D + 货舱 [特性]）+ 货舱依赖名/版本 + 拓扑序全闭包。
   命中前必须读取全部源文件——键覆盖真实输入，非 mtime 猜测。
3. **命中**：直接落盘缓存汇编文本，并原样重放该次编译 stderr（运行时
   `__cn_diag_capture_*` tee 捕获，含 `[p6h]` 进度行与警告）→ 三态 stderr 逐字节一致。
4. **未命中**：正常完整编译；成功后 `读整文件文本` 读回 asm（与落盘逐字节同源），
   tmp+rename 原子写入条目（头部+asm+警告+校验和；tmp 名含 PID+序号，失败清理）。
   写前 TOCTOU 复核：逐单元重读源 + 货舱.toml 重算摘要，不一致=不写。
   货舱复核与扫描同源（均用 读源文件 的末行换行归一化）——无末尾换行货舱.toml
   不误判；测试夹具覆盖无末尾换行/无货舱。键格式版本 KEY-2（含货舱四字段）。
   条目文件名=入口/选项签名 + **编译器内容摘要 16 hex**（不含路径）——v2p/cn_self
   交替编译互不覆盖（磁盘约 2 份/身份）。
5. **三态一致关键**：闭包扫描会提前驻留全部源码字符串，改变字符串池编号 →
   asm 字节漂移（实测 strData_614 vs 657）。扫描后 `__cn_intern_truncate` 回退到
   -D 扫描后的基线，并以字符串快照重建注入宏（重置注入宏们→设注入宏），
   使完整编译的 Symbol 分配序列与无缓存单遍编译**逐位一致**。
6. **旁路/通道**：`CN_NO_V2_PROGRAM_CACHE=1`、`--verbose`、check/ir/验证类命令显式
   不动缓存；78/79 自举链（run_e2e 锚定链）**强制 NO_CACHE**——fix_s 不得命中上一轮
   cn_self 条目，固定点测试保留真实重编译证据；`CN_V2_PROGRAM_CACHE_DIR` 覆盖目录（默认 cwd 下 target/cache/v2program）；
   `CN_V2_PROGRAM_CACHE_STATS=1` 统计；`CN_V2_PROGRAM_CACHE_VERIFY=1` 命中仍完整
   重编译并逐字节比对（不符=显形+以重编译产物覆盖）。损坏/版本不符显形回退重建。

**实测量级**（本机 win-x64·v2 全树 137 文件·asm ~32.9MB / 172.9 万行·返工后 HEAD）：
| 状态 | 耗时 | 说明 |
|------|------|------|
| 冷（首建缓存） | 875s | 扫描 + 完整编译 + TOCTOU 复核 + 写 34.1MB 条目 |
| 热（命中） | 22s | 扫描 + 读条目 + 落盘 asm + 重放 stderr |
| 无缓存 | 942s | 单遍完整编译 |
- M2 热/无缓存 = 42.8x；热/冷 = 39.8x（最终分支 4a6307cef 实测；1,794,847 行 asm / 34.1MB）。冷路径较无缓存多约 2%~20%（TOCTOU 重读闭包）。
- M5 cn_self：冷 978s、无缓存 989s；**rebase 后 fix_p 与 fix_s 出现单处分支块序
  差异（bb411_25/26 标签互换，stderr 一致）**——cn_self 自身缓存/无缓存产物一致、
  纯链接（无 v2p.obj）一致、宿主 -O0/-O2 构建的 v2p 产物一致，属自举产物与宿主
  产物行为差异；待独立缺陷任务定位（本任务不以缓存掩盖固定点红）。
  （78/79 门禁链强制 NO_CACHE，上述 M5 热收益为同编译器连续调用的手工口径，
  非门禁固定点收益。）
- 冷 vs 无缓存 asm/stderr 逐字节一致（三态 cmp 通过）。

**安全边界**：自身身份=可执行文件内容哈希（非加密，指纹用途；GetModuleFileNameW /
/proc/self/exe 直接定位，不经 argv[0]）；探针失败=显式告警禁用缓存；条目名含身份
摘要，v2p/cn_self 交替编译互不覆盖；缓存目录默认相对 cwd，跨 cwd 不复用（重定向
显式共享时键仍含路径/内容摘要）；cargo [货舱] 名称/版本 + 原文摘要 + 路径入键；
TOCTOU 复核不过=不写。运行时失败信号（utf8ToWide/ftell/环境转换）登记 9 条
`存量过渡`（AI 无自行发许可通道 #1238·已呈报待批）；其余旧哨兵已改状态/出参 API。
