## 一、语言设计概述

### 1.1 语言定位
CN语言是一门全中文语法的系统级编程语言，参考C++的编程范式，面向需要底层控制力的应用场景。语言设计遵循"中文优先、手动控制、零成本抽象"的原则。

### 1.1a 分层安全总则（2026-09-30 用户裁决「方案一」立法·910 轮落盘）

> **分层安全**是 CN 内存安全的最高准绳之一，与「设计哲学四句话」（plans/019/AGENTS §3.1）并列：
> ① **编译期能证明的，必须在编译期拦**——常量下标越界、常量除零、常量空指针解引用（B11）等编译期可判定形态一律硬错误，不得静默放行到运行期；
> ② **编译期证不了的，安全区以确定性失败兜底**——运行期检查（错误码+立即终止，非未定义行为）是安全区的**合法防线**（Rust panic 同款语义：可控行为，不是脏崩溃）；
> ③ **完备访问通道并行提供**——追求编译期完备的场景使用结果化 API（返回 结果/可选 + 强制检查三分支，§07），用户自选；
> ④ **不安全 函数=真零运行期检查**——手动管理区编译器不插检查；既有检查面降级为纵深防御（不作为安全依据）。
> 对照：Rust 安全区依赖运行期 panic（下标/除零）——CN 在①上更严（编译期优先成文），在②上同型（确定性失败），在④上对齐 Zig 的发布零开销模型。

> **①具体化——常量下标越界/常量除零编译期硬错误（912 轮实施·任务 114）**：字面量下标 ×
> 静态数组长度（`整32[3] 表; 表[5]`）=编译期硬错误——读/写共用路径、含一元负号（`表[-1]`）
> 与 `0x` 十六进制字面量、**不安全 函数内同拦**（编译期确定性错误无条件·rustc 常量下标 deny
> 同款）、宿主+v2 双侧同拒；常量除零/取余零（字面量对 `10/0`、`10%0`）同为编译期硬错误
> （319-a/T8+575-a/T100 既有检查锚定）。运行期错误码 2 越界检查保留=②兜底；常量传播面
> （变量持有常量初值作下标/除数）随常量折叠后续波。

### 2.1a 上下文关键字（非保留字，不占用命名空间）

> 原则（§2.2）：凡只在固定语法位置出现的词，一律上下文识别、不入保留字表（`plans/024` §十）。
> 识别判据（parser 文本判定，162-a 落地）：

| 词 | 语法位置（唯一） |
|---|---|
| 原始、多行 | 字符串字面量前缀位（后紧跟引号才是前缀，否则=标识符） |
| 公开、私有、保护 | 可见性标签位（`公开:`/`私有:`/`保护:`——顶层与类体内） |
| 静态、常量 | 声明前缀位（顶层＋局部语句＋for-init＋类成员修饰） |
| 虚拟、重写、抽象 | 类/接口成员修饰位（后随 函数） |
| 作为 | 重命名导入位（`导入 路径 作为 别名`） |
| 模块 | 顶层声明位（`模块 名`——后随标识符即声明，分号可选） |
| 运算符、遍历、每个、属于、对 | 既有上下文词（§2.2 先例） |

> **保留字不可作标识符（任务 271 甲案·2026-10-07 用户裁决落文）**：§2.1 关键字分类表
> 所列保留字（含 **自身**=OOP this）在**任何标识符位**（字段名/变量名/函数名/参数名）
> 均为编译错误——Rust `self` 同款。双侧实现：宿主词法层 Kw_Self（天然全位拒绝）；
> v2 词法关键字表（271 起·字段/变量名位判 令牌_标识符 天然拒绝+表达式位建标识符
> 节点保 this 语义）。验收=E2E 638（字段名位+变量名位 dual 同拒）。背景：270 轮实证
> 此前 v2 未关键化「自身」致字段名位一拒一放（209 翻案根源）。

> { { 1, 2 }, { 3, 4 } }`；元素类型按剥维递归（`结果<整32,整32>[2][2] 网 =
> { { 正常(1), 正常(2) }, { 正常(3), 正常(4) } }` 合法·容器/类/结构体元素同规则）。
> ①**缺格补「类型默认态」**（#1473 已批甲案·同构推广到每层内层）：写了列表但
> 未写满→缺格补该类型默认态——数值族=0/浮 0.0/布尔假/字符 0；字符串=空串态

> `枚举名.成员`（点号·与字段访问统一）或**裸成员名**（选择 条件为枚举类型时按类型定向
> 解析·C-4 既有）——`枚举名::成员` **非法**（`::` 保留给模块/包路径限定·08 章路径语义），
> 编译期拒绝（宿主原放行系越立法实现，随本条收口负向诊断）。

> **数组值语义（#252 立法·2026-10-07·087/087b 同口径）**：数组=值聚合（trivially
> copyable·与上方 3.5a 清单一致）。**整体赋值**（`乙 = 甲;`·两态同型 `T[N]`）=

### 3.5a 联合体成员类型（164-a·plans/023 §十二 方案 A+D，2026-09-14 用户批准）

联合体（`联合体 名 { ... }`）成员类型限定为**可平凡复制类型**——标量（数值/布尔/字符/空类型）、
指针（含 `字符*` 借用视图）、数组（元素可平凡复制）、枚举、**递归判定的纯标量聚合**（结构体/
嵌套联合体其成员全可平凡复制）。

**拥有型类型**（`字符串`、容器、类对象、含拥有型的聚合）作成员 → **编译期硬错误**：
联合体「共享偏移 + 无 tag」语义下无法判定活跃成员，自动释放/写入归一化不可实现
（原实现「按偏移 0 无条件释放」= 泄漏/误释放 UAF 的根因，p13/p14 探针实证）。
**对标**：Rust `union` 成员必须 `Copy`。

**逃生舱「手动释放」**（对标 Rust `ManuallyDrop<T>`）：成员可显式标注——

```

    手动释放 字符串 名;    // 编译器不生成自动释放；责任移交用户
    整64 数;
}
```

标注成员：语义层放行拥有型；**编译器不生成自动释放与写入归一化（清旧）**——用户在
`不安全 函数` 内以显式原语（`字符串释放` 等）自行释放；成员的新值写入/深拷仍正常。
字段访问仍受 `不安全` 区边界约束（联合体字段访问=不安全操作，§5.2 三语法点）。

### 3.7 隐式类型转换

- 字符 ↔ 整数
- 字符* ↔ 字符串
- 字符串 ↔ 字符*
- 空类型* ↔ 任意指针
- 整数 -> 整64（宽化）
- 浮32 -> 浮64（宽化）
- **数值 -> 字符串（仅 `+` 拼接上下文）**：当 `+` 左操作数为 `字符串`/`字符*` 时，右操作数为整数/浮点/布尔/字符/枚举，自动隐式转换为字符串后再拼接（等价于 `整数转字符串/浮点转字符串/字符转字符串` 运行时转换）。布尔转换结果为 `"真"`/`"假"`。此转换**仅**在字符串拼接语境触发，不参与其他算术/比较上下文。
- **混合符号隐式转换禁止（2026-09-10 方案A，Rust 对齐；第五十一轮二元面+第五十六轮赋值/传参/返回面+第四族复合赋值 #488）**：有符号（整N）与无符号（正M）的**变量间**混合符号交互编译期拒绝，须显式 `类型名(表达式)` 构造转换。覆盖四族：①**二元运算**（比较 `== != < > <= >=`、算术 `+ - * / %`、位运算 `& | ^ << >>`）；②**赋值初始化/赋值**（`正64 b = 整32变量` / `整64 x = 正32变量` 拒绝）；③**函数传参/返回**（整N 实参传 正M 形参、正M 变量自 整N 函数返回拒绝）；④**复合赋值**（#488·2026-10-12 用户裁决 A 案）：复合赋值 `甲 += 乙` 等价于展开 `甲 = 甲 + 乙`，与对应二元运算**同规则**——目标类型与右值类型同属整数族且符号相异、右值非整数字面量形态（含 `-1`）时编译期拒绝（`正32 甲; 整64 乙; 甲 += 乙` 拒，诊断与二元面一致；指路显式转换如 `甲 += 正32(乙)`）；右值为整数字面量时豁免（`甲 += 1` 字面量按目标类型参与·放行），十种复合赋值运算符 `+= -= *= /= %= &= |= ^= <<= >>=` 全部同此规则。w19 旧裁「复合赋值面不拦混合符号」随本条废止（双侧实现分叉治理——v2 权威面执法=复合赋值脱糖合成二元进二元检查为正确行为，宿主补拦截对齐）。依据：隐式宽化在混合符号下静默改变值语义（实证 `正64(2^63)` 与 `整64(-1)` 比较值域反转；`正32` 与 `整64` 两侧编译器行为分叉——探针 target/p50x64l/mixed_cmp 宿主 rc=9 / v2 rc=11 / 数学真值 13；`整32(-1)` 赋 `正64` 出 `2^64-1`）。**字面量豁免**：一侧为整数字面量（含一元负号字面量 `-1`）时豁免，字面量按另一侧类型参与运算/赋值/传参（同 Rust 字面量推断惯例，`大 > 100`、`正64 b = 5`、`读值(100)` 等惯用形态不受影响）。同符号混合宽度（正32 与 正64、整32 与 整64）维持既有宽化放行；字符 ↔ 整数互通不受本条影响。
- **显式类型转换的位模式语义（2026-09-10 第五十五轮 ④文档化，Rust `as` 对齐）**：`类型名(表达式)` 构造转换在整数族间的行为定义为位模式变换（零运行时开销，与 Rust `as` 逐条同款）：**升宽**——有符号源符号扩展（`整64(-1)` 即位模式全 1；`正64(整32(-1))` = `2^64-1`，Rust `i32 as u64` 同款）；无符号源零扩展（`整64(正32(4000000000))` = `4000000000`）。**同宽跨符号**=位模式重解释（`整64(正64(2^63))` = `-2^63`，Rust `u64 as i64` 同款）。**降宽**=低位截断（`整32(正64大值)` 取低 32 位）。窄宽（整8/整16/正8/正16）参与转换先按其位宽扩展到目标宽度再按上述规则。双侧实现锚定：宿主 emitCast（`movsx`/`movzx` 按源分派）与 v2 类型转换发射族（方案甲源类型分派）第五十一轮探针逐字节一致（4000000000 / -9223372036854775808）。

### 3.7a 整数运算语义统一（C18/B12/T27/T36/T8·2026-09-17 用户批量裁决方案甲·319-a 落盘）

- **编译期常量硬错误（Rust debug 溢出检查对齐）**：两侧均为整数字面量（含一元负号字面量）的常量表达式，按结果类型（`commonNumericType` 域）编译期预演：①**常量除零**（`10/0`、`10%0`）编译期硬错误（运行期除零已有错误码防护，常量折叠面同样拒绝）；②**常量溢出**（`2147483647+1`、`整32` 域乘溢）编译期硬错误。无符号与整128 结果域宽于 int64 预演承载的面不检查（不误报）。
- **变量面运行期溢出=错误码 8 确定性失败（#474·2026-10-11 用户裁决乙案·取代原「变量面两补码统一回绕」条文）**：安全区（§1.1a②）的二元 `+ - *`、自增自减 `++ --`、复合赋值 `+= -= *=` 在运行期结果超出操作数类型值域时——立即报「运行时错误(错误码8): 溢出错误」终止（确定性失败·非未定义行为；Rust debug 溢出 panic 对齐、Swift 永远检查对齐；O0=O3 一致·三后端一致；检查落分支预测友好的冷段）。**`整MIN / -1` 与 `整MIN` 一元取负同族纳入错误码 8**（Rust debug 同款；本句推翻原条文的 `INT_MIN/-1 ≡ INT_MIN` 特判定义化——2026-10-11 用户裁决乙案扩展·呈报复核）；`x % -1` 数学值非溢出维持定义 `≡ 0` 不变。确需回绕语义者用显式内置函数 `回绕加/回绕减/回绕乘`（见下条）——回绕语义自变量面收缩为显式知情通道。**`不安全` 函数内不插溢出检查**（§1.1a④ 真零运行期检查·纵深防御），回绕函数照常可用。原回绕锁用例族期望值随本立法翻转（682 自增族）或移交回绕函数用例（502/658/681/697——回绕语义验证职责由回绕函数用例继承）。
- **显式回绕内置函数（#474·2026-10-11 用户裁决乙案）**：`回绕加(a, b)` / `回绕减(a, b)` / `回绕乘(a, b)` 三编译器内建函数承载两补码回绕语义——适用**全整型族**（整8/整16/整32/整64/整128、正8/正16/正32/正64/正128，按实参类型分派·同型收同型）；语义=现行两补码回绕（`整16`: `回绕加(32767, 1) ≡ -32768`、`整8`: `回绕减(-128, 1) ≡ 127`、`正8`: `回绕加(255, 1) ≡ 0`），与算术运算符**同类型规则**（窄域保持窄域〔#285〕·混合宽度按既有宽化提升·混合符号禁止与字面量豁免同 §3.7）；编译期常量实参按回绕语义折叠**不报错**（`回绕加(2147483647, 1)` 折叠 ≡ `-2147483648`，与常量溢出硬错误条文不冲突——显式回绕即知情）；错误码 8 溢出检查对回绕函数不生效（其语义本就是回绕）。
- **窄类型算术保持窄域（#285 甲案·2026-10-08 用户批·v14 采样轮 p1007_05 立法升级；溢出处置句 #474 2026-10-11 修订）**：同宽窄整数（整8/整16/正8/正16）的二元算术（`+ - * / %`）**结果保持操作数宽度**——`整8 b = 整8a + 1` 全程整8 域，运行期溢出=错误码 8 确定性失败（#474·取代原「溢出按 T9 回绕（`127+1≡-128`、`-128-1≡127`；`整16` 同理）」措辞——回绕语义收敛到 `回绕加/回绕减/回绕乘`）；与更宽操作数混算时按既有宽化规则提升至较宽侧。Rust `i8 + i8 = i8` 同款；与 §3.7「字面量按另一侧类型参与」豁免连贯（操作数/结果/赋值全窄域一体）。宿主原「窄算术提升整32+赋回拒绝」实现随之修正（算术结果窄域+存回截断），v2 既有窄域回绕为零改动锚（p1007_05 五值：-128/127/-32768/100/-56——其回绕值随 #474 转为错误码 8 触发面或回绕函数锚）。容器元素窄域（如 `向量<整8>` 追加 200 读回 -56）同此口径。窄伴侣+字面量的拉窄放行（含带后缀字面量）见下文『整数字面量转换定级』③。

- **同型字面量亦查域·负号形态按负值判域（T36 扩面·#506甲·2026-10-13 用户裁决）**：T36 值域检查扩展至**同型直赋面**——无后缀字面量恒定级为 `整32`（与值大小无关）而值可超域，目标类型与字面量恒定级相同时原同型短路零检查放行=编译期静默回绕（`整32 甲 = 2147483648` 实锤），现**声明初始化/赋值/返回/推断**四通道一律编译期拒绝（`整32 甲 = 3000000000` 拒、`变量 甲 = 2147483649` 拒、Rust E0308「literal out of range」同款）；**负号形态按数学负值判域、不按位宽回绕判**——`整32 甲 = -2147483648`（恰为 `整32::MIN`）域内合法，`2147483648`（纯正字面量超上界）拒。确需超域值位模式者走显式类型转换通道（§3.7 降宽=低位截断）。**宽化目标亦查目标域（#506甲 口径精确化·558 轮澄清）**：「目标类型与字面量恒定级相同」句指同型直赋面的最小受检保证，实现实际覆盖同型与一切可隐式转换面——目标宽于字面量恒定级时亦按**目标类型值域**判（`整64 x = 99999999999999999999` 拒），非仅同型受检。字面量定级参与面（带后缀严格/无后缀随侧/128→64 特例）见下文『整数字面量转换定级』条。
- **无后缀大字面量提升链（m27_02/03 定性更正·适用面 638 收窄·2026-10-14 用户裁决甲案）**：超出 `整64` 域的无后缀字面量按提升链归 `整128`（既有行为）——**适用面=表达式求值与显式目标类型场景**（表达式面如打印/传参/二元运算操作数，显式声明如 `整128 x = 巨字面量`），此类表达式在整128 域内求值（`(-2^63)/(-1) = +2^63` 为域内正确值，非错值）；期望整64 回绕语义的场景须显式 `整64` 类型上下文或后缀。**推断声明通道不适用本链**（#638 甲案「一种语言不该有歧义」：推断通道无后缀字面量恒定级=整32，值装不下〔含超 int64 巨字面量〕一律编译期拒绝并报错引导显式写类型，如 `变量 甲 = 2147483649` 拒→`整64 甲 = 2147483649;`——Rust `let x = 2147483649;` E0308 同款；原 497 推断真值域提升放行〔`变量 丙 = 99999999999999999999` 归 整128〕与本条适用面歧义随本裁决废止，813 用例翻转）。域内无后缀字面量的随侧定级见下文『整数字面量转换定级』①。
- **整数字面量转换定级（788 锁用例·2026-10-15 立法·执法锚=E2E 1004 拒绝族/1005 放行族 dual）**：整数字面量在二元运算/赋值初始化/实参/返回/移位/位运算等转换推导面的参与类型，按**三分法**定级（宿主 `literalTypeOf` 与 v2 推导族同构·745 轮 q1~q16 探针矩阵实证）：①**无后缀非负字面量=随侧豁免标记**——其参与类型随另一侧整数族操作数定级（`1 + 2U` 与 `2U + 1` 对称放行），为**对新手友好的设计选择**（§3.7 字面量豁免：`大 > 100`、`正64 b = 5`、`读值(100)` 惯用形态不受打扰）；负号字面量**不随侧**（无符号域不承载负值：`-1 + 2U` 维持混合符号拒绝）；两侧均无后缀=无随侧对象（各自恒定级整32·杜绝互随顺序敏感）。②**带后缀字面量按后缀定级（严格）**——参与类型=后缀指定类型（§4.3 映射表：L→整64/LL→整128/U→正32/UL→正64/ULL→正128），不随另一侧；结果宽于目标即四通道（赋值/声明初始化/返回/守卫）编译期拒绝（`整32 甲; 甲 = 3000000000L + 0;` 拒「无法将 '整64' 隐式转换为 '整32'」·1004 十三形态）；混合符号字面量豁免与复合赋值字面量豁免仍按 §3.7 适用（`癸 + 1U`、`丁 += 1L` 放行·1005）。③**285 窄域适配拉窄放行**：一侧为窄整数（整8/整16/正8/正16）、另一侧为字面量形态（含带后缀）时，字面量按窄侧参与——仅算术面 `+ - * / %`（`整8 甲; 甲 = 甲 + 1L;` 放行·1005），与「窄类型算术保持窄域」（本条 #285 条）衔接；位面/移位面无此适配、按严格面判定（1004 `甲 = 1L & 2;`、`甲 = 1L << 2;` 拒）。④**128→64 同符号窄化特例**：整128→整64、正128→正64 **表达式源**隐式放行（方案C 2026-08-14 立法·宿主 canConvert 3c 条同构·410 `大 = 0 - 9223372036854775807LL;` 放行）；跨符号组合（整128→正64 等）不在特例内、随混合符号面拒。⑤**值域门槛先行**：字面量直赋通道（声明初始化/赋值/返回/推断）先查**目标类型值域**再论其他——超域字面量一律编译期拒绝（`整32 丁 = 3000000000;`·1004），④特例不放行字面量直赋超域形态（`整64 大 = 9223372036854775808LL;` 拒；与 T36、#506甲、558 同源）。衔接：①②⑤与「字面量窄化值域检查」（T36 条）、「同型字面量亦查域」（#506甲 条）、「无后缀大字面量提升链」（#638甲 条）互为边界（域内随侧·超域走提升链/拒绝面），③与「窄类型算术保持窄域」（#285 条）同域。**豁免面（①无后缀非负随侧、③窄伴侣拉窄）为语言设计选择、非查表 miss**——实现侧推导族旧「带后缀字面量恒 0 豁免标记」是缺陷（788 已清除），不得与本条设计豁免混淆。

### 3.7b 浮点→整数显式转换：饱和截断（#475 甲案·2026-10-13 用户裁决「Rust as 全对齐」·528 全宽收族落地）

- **饱和截断+NaN→0（Rust `as` 逐条对齐）**：显式 `整N(浮表达式)` / `正N(浮表达式)`（N=8/16/32/64/128·浮32/浮64 源）语义定为**饱和截断**：①**NaN → 0**；②正超域（含 +inf）→ 目标类型 MAX；③负超域（含 -inf）→ 有符号 MIN / 无符号 0；④域内向零截断（`整32(3.99) = 3`）。锚例（#475 立案现象翻转）：`整32(1.0e18) = 2147483647`（原 C 系 UB 形态输出 -1486618624）、`整64(1.0e19) = 9223372036854775807`、`正64(1.0e19) = 10000000000000000000`、`整128(0.0/0.0) = 0`。族内一致性：整128/正128 与 ≤64 全宽同语义（464 浮→整128 专用 ABI 通道同构收族）；**三后端运行期发射与编译期常量折叠同语义**（`整32 甲 = 整32(1.0e18)` 常量形态与变量形态同为 2147483647）。**与 §3.7「显式类型转换的位模式语义」衔接**：整数族间转换维持位模式变换不变，浮源转换只走本条饱和语义（浮点→整数不在位模式变换域内）。原 C 系形态自本条废止（x86 `cvttsd2si` 超域/NaN 落「整数不定值」+窄目标模回绕；arm64 `fcvtzs` 有符号直转无符号目标出负值）。

### 3.7c 浮点→字符显式转换：标量域饱和（#475 批甲·2026-10-14 用户裁决「饱和化纳入字符语义」·533 落地）

- **字符标量域饱和+NaN→0（528 浮→整族同构落点）**：显式 `字符(浮表达式)`（浮32/浮64 源）语义定为**按 Unicode 标量有效域 [0, 0x10FFFF] 饱和**：①**NaN → 0**（U+0000）；②非正值（含 -inf）→ 0（域下界）；③上超域（含 +inf）→ `0x10FFFF`（U+10FFFF 域上界）；④域内向零截断（`字符(65.9) = 'A'`）。锚例：`字符(1.0e18) = 0x10FFFF`（原 i32 域饱和形态 2147483647 随本条废止）、`字符(-5.0) = 0`、`字符(0.0/0.0) = 0`。**代理区 [0xD800, 0xDFFF] 处置=透传**（钳制域为连续区间 [0, 0x10FFFF]，域内代理区值原样保留——替换字符映射或无效化属新增语义未获授权，实施轮细化决策留痕）。**与 §3.7b 的分域关系**：浮源饱和按目标域分域——整族目标按目标类型值域（§3.7b），字符目标按本条字符标量域；整源→字符维持 §3.7「字符↔整数」位模式互通不变（本轮不扩面）。**三后端运行期发射与常量形态同语义**（runtime `__cn_fXX_to_char` 单点：宿主 IR 层直发调用通道 + v2 字符目标码发射特判，宿主+v2 双侧同构）。

### 3.9 局部变量确定初始化检查（def-init·2026-09-23 落盘·010/482-a 用户裁决甲）

**未初始化的局部值类型变量不得读取**——编译期数据流拒绝（Rust E0381「use of
possibly-uninitialized variable」对照），零运行时成本（不生成任何检查指令）：

- **登记面**：函数内无初始化器的「纯值类型」声明——标量（整8~整128/正8~正128/
  浮32/浮64/布尔/字符/枚举）、数组（元素级跟踪，长度编译期已知）、结构体（叶子字段级）。
  赋值（含下标/字段左值）、复合赋值与自增自减（先读后写·读面拒绝）置为已初始化。
  **枚举纳入（2026-10-28 用户裁决乙案·#1735/#1760）**：枚举局部变量声明后未赋值
  就读取=编译期拒绝，与布尔/浮64/整型完全同构（此前枚举不在清单，宿主放行且
  默认首成员 0）；「先赋值后读」与「声明后未读直接覆盖赋值」保持合法（声明点
  无初值标量补零对其他类型仍是正确防御·#1735 v2 修复保留）。
- **豁免面**：拥有型（类/容器/字符串/结果/可选——既有入口零初始化或默认构造防御
  兜底）、指针/引用、函数参数（调用方实参初始化）。
  **指针/引用豁免的前提=换防非免检（426 甲案·2026-10-11 用户批）**：豁免 def-init
  登记的前提是**声明点零初始化**（槽补零·BSS 同语义·双侧发射层既成事实，汇编实证
  `mov $0`→槽）+**解引用/间接调用点判空判零防线**（093/§5.8 子案 A 家族·零值→
  错误码3 确定性失败）——指针族从「编译期禁读」换防为「运行期确定性失败」，与值类型
  编译期铁面各管一段、互为纵深；实现者不得将豁免理解为免检（426 实录：v2 豁免判定
  尾字符照抄宿主形态撞「类型文本=剥星基名」表示差，恒失灵致 `整32* p;` 裸读误拒=
  一侧拒绝一侧放行零分叉违例·修复=判定改核类型节点附加位）。
  **函数内静态不豁免（#324 甲案·2026-10-09 用户批·v16 e2b 分叉根治）**：`静态 类型 名;`
  （函数内·无初值）落入登记面拒绝（Rust `static` 须显式初值同款）——显式初值消除
  「零初始化时机」歧义（静态初始化一次性语义见 §5.2b）；**顶层静态（模块级）不在
  函数内登记面**，无初值放行（入口构造/指针槽既有通道不变）。
- **类类型字段级联默认构造（#283 甲案·2026-10-08 用户批·v14 采样轮 p1007_02 立法升级）**：
  类实例构造时（`类名()` 合成默认构造或用户构造函数），其**类类型字段**（类/容器/字符串/
  结果/可选）由编译器**自动级联调用其默认构造**——C++ 成员自动默认构造同款（用户构造函数
  未显式构造的字段同此）。「无构造类允许默认构造**仅分配**」（§H7）中的「仅分配」指
  **类实例本身的存储分配**，不豁免字段的级联构造；析构级联（~T 级联释放字段）既有，
  构造/析构自此对称。本条是拥有型豁免面「默认构造防御兜底」前提的字段位补全——豁免的
  前提是字段确实被构造。标量字段不额外清零（既有零初始化语义不变）。
  门禁=容器字段免手工构造即安全可用（tests/cnsmith_hits/run_err/p1007_02 转绿·dual）。
- **控制流敏感**：如果=两支汇合取并集（未初始化须「所有路径都未初始化」才保持）；
  以 `返回` 终止的分支不参与汇合；当/循环体内赋值不外溢（可能 0 次执行）——
  **唯一例外=循环填充惯用法（1771·2026-10-28 用户裁决·双侧同口径）**：循环体内
  **非常量下标写**（`槽[i] = …`·含经取地址通道的基数置位）的整体置位在循环体外
  溢生效（循环执行即填充的惯用语义；循环 0 次执行时体内写未发生的漏报=设计接受
  的漏报方向诚实边界，运行期越界/判零防线兜底）；循环体内常量下标写（`槽[0] = …`）、
  标量写与结构体字段写仍不外溢（保守口径不变·未写键保持拒绝）；
  无否则分支的真支赋值不改变汇合状态。
- **取地址=初始化通道**：`&x` 视为「可能被写」（出参惯用法；Rust `&mut` maybe-init
  同款）——取地址后读取放行。数组名作调用实参（指针退化）同此口径；**数组元素取
  地址（`&槽[0]`）同此口径（1771 落文）**：元素取地址=place 引用非值读（不触发
  元素读判定），且按基数整体置位（别名逃逸=被调方可经指针写任意元素——e2 填
  (&槽[0],…) 填充后读放行惯用法）。
- **诚实边界**：非常量下标写=整体置位、读=保守拒绝；数组/结构体经地址逃逸后
  的字段级精度由被调行为决定（无过程间分析，与 C++ -Wmaybe-uninitialized 同界）。
- 实测锚定：E2E 533（放行矩阵·双编译对照）/534（拒绝矩阵·双侧同拒）；
  1610（数组循环填充读取放行·一维+二维·双编译对照）/1611（数组元素取地址出参）；
  宿主单测 DefInitCheckTest 14 例。

> `字符串[i]` **读**按 **UTF-8 字节**索引（与`字符串长度`/`字符串子串`/`字符串查找` 字节口径
> 一致），结果类型 **整8**（带符号字节值——`"内"`（E5 86 85）首字节即 -27，非码点 20869）；
> 下标须为整型；越界=运行期错误（错误码 2，与数组下标同通道·306-a T4 防线=分层安全②）。
> `字符串[i]` **写=编译期拒绝**（2026-09-30 用户裁决 112 甲：字符串为**不可变拥有型**——
> 修改走拼接/`字符串子串` 重建，原地字节操作用 `字符` 数组或不安全区指针；与 069「字符*
> 视图下标拒绝」同一语义家族；宿主+v2 双侧同拒）。`字符` 类型保持「Unicode 标量值」定义不变（4 字节）——
> 完整字符按需构造：`字符转字符串`（码点路径：值 <0 或 ≤0xFF 单字节直放、>0xFF 按 UTF-8 编码；
> U+0080~00FF 边界按单字节直放=**T40 双来源口径 2026-09-20 闭合**）或 `字符串子串`（字节路径）。
> 逐字节重建例：`字符转字符串(s[0]) + 字符转字符串(s[1]) + 字符转字符串(s[2])`。
**条件运算符（三元）：** `条件 ? 真值 : 假值`（右结合，惰性求值，仅对选中分支求值）

> **成员访问统一为 `.`（v2.1，2026-09-03 用户裁决，对齐 Rust/Go 与旧版 Rust 风格 CN）**：
> 废除 `->` 成员访问形式（编译硬错误并附迁移提示「请改用 .」）；`.` 左侧为指针时

> 迁移前写法 `指针->字段` 已于 2026-09-03 全量下线（含 v2 自举源码与全部测试）。

> **位运算语义（2026-09-09 用户裁决，对齐 Rust 定义化纪律；移位量面 #474 2026-10-11 用户裁决乙案修订）**：位运算符仅适用**整型**（浮点不允许位运算）。右移 `>>`：有符号=算术右移（符号扩展）、无符号=逻辑右移（补零）。**移位量超宽=确定性失败（#474 修订·原「移位量先按位宽取模再移位」定义化条文废除）**：移位量 `k ≥ 操作数类型位宽` 时——**编译期常量移位量**（`5 << 40`，整32 操作数）编译期硬错误（§1.1a①·诊断含「移位量超宽」·宿主+v2 双侧同拒）。**巨字面量移位量**（有效数字 >18 位·超出 int64 预演承载）=同面编译期硬错误——诊断「超任一整型域宽」（字面量文本位必超任一整型域·#547 预检·E2E 849 锁面）；**运行期变量移位量**（`a << k`，k 为变量）立即报「运行时错误(错误码8): 溢出错误」终止（§1.1a②·O0=O3 一致·三后端一致）。确需取模移位者手写显式闭环 `a << (k % 位宽)`（`%` 运算即显式知情·合法放行，无需回绕移位函数）。**移位丢高位不属溢出检查对象**（`1 << 31` 结果 `整32` 域内合法——仅移位量本身超宽才失败，Rust `<<` 溢出检查同口径只查移位量）。`~x` = 按位非（位模式 ≡ `x ^ -1`）。复合赋值 `&= |= ^= <<= >>=` 逐条同上（`<<=`/`>>=` 的移位量超宽检查同本条）。

> **运算符重载**：类/结构体可定义成员 `函数 运算符X(参数) -> 返回类型` 自定义运算符语义（**仅** `运算符X` 可重载——`X` ∈ `+ - * / % == != < > <= >= && || ! & | ^ ~ << >>`；**304 收窄·2026-10-08 用户批「照办」：`[]`/`()` 移出可重载集合**——两者实现从未可用（类体内 `运算符[]`/`运算符()` 解析崩溃实测）·functor 生态位由 lambda+函数指针覆盖·v2 面整面拒绝天然对齐）。**结构体=纯数据聚合（2026-10-26 乙案澄清·1025 采样轮 #1616 用户批）**：结构体体内成员函数**仅限** `函数 运算符X(...)` 重载这一形态（值语义运算符生态位）；**普通成员方法须用 类**——结构体体内 `函数 名(){...}` 普通方法形态双侧编译器同拒（指路诊断「结构体不支持普通成员方法——结构体=纯数据聚合·需要行为请用 类（结构体仅可定义 运算符X 成员·暂未实现）」·E2E 锁面）。结构体的 `运算符X` 重载通道实现欠账另案挂 #1635（本条为立法位·双侧 parse/semantic/IR 发射通道从未实现）。重载决议规则：① 优先精确匹配内置运算符；② 无内置匹配时按左操作数类型查找成员 `运算符X`；③ 仍无匹配则报"类型不兼容"错误。字符串 `+` 拼接由编译器隐式调用 `整数转字符串/浮点转字符串/字符转字符串` 转换 + `字符串连接` 实现，无需用户重载。（v2.1：可重载集合删除 `->`——该运算符已随成员访问统一废除）

### 4.6 语句终止与续行

> **核心事实（2026-09-04 方案B 反转，plans/015 用户裁决）：CN 语言的语句必须以分号 `;` 终结（Rust/C++ 同款「表达式语句必须 `;`」模型）。换行（`\n`/`\r`）在词法层仍与空格、Tab 一样被当作空白直接跳过，不产生换行 token——换行在表达式**内部**仍无语法意义（续行不受影响），但**不再是语句边界**；语句边界唯一由强制分号标记，行尾与下行行首词法可拼导致的静默粘连事故链（本项目实测多起）就此结构性根除。**

#### 4.6.1 三层机制

| 层 | 行为 | 判定位置 |
|----|------|---------|
| 词法层 | 换行 `\n`/`\r` 与空格、Tab 完全当作空白跳过，不产生换行 token（表达式内部续行天然支持） | 词法分析器 |
| 语法层 | 分号 `;` 是**强制**终止符：语句解析完成后必须消费 `;`——缺失即报错「语句缺少分号 ';'」（错误即诊断，杜绝静默粘连），诊断后继续解析保证一次编译报全量位置 | 语法分析器 `consumeSemicolon()` |
| 边界识别 | 语句边界=分号；`}` 自终结（块/如果/当/循环/函数体/结构体/类/接口/枚举体后**不加**分号） | 语法分析器 `parseStmt()` |

#### 4.6.2 EBNF

```
语句 = 表达式语句 | 声明语句 | 返回语句 | 中断语句 | 继续语句
      ";"                              // 分号强制（语句终结符）
控制流语句 = 如果语句 | 当语句 | 循环语句 | 遍历语句 | 选择语句      // 块体 } 自终结，不加分号
```

#### 规则1：语句终止（强制分号）

- 语句**必须**以分号 `;` 终结：变量声明、赋值、自增自减、复合赋值、表达式语句、返回、中断、继续、顶层常量/静态与全局变量声明、导入语句 均须 `;`（顶层全局变量声明分号=2026-10-14 任务569 甲案配套补列）
- `}` 自终结：块/如果/当/循环/选择体、函数体、结构体/类/接口/枚举体后**不加**分号（`}` 即边界）
- 行内块 `{ x = 1; }` 内部语句同样须 `;`
- 缺失分号是**编译错误**（含行列定位的诊断），不再依赖关键字边界推断

#### 规则2：续行（换行≡空格，表达式内部天然续行）

- 换行无语法意义，**表达式内部任何位置换行都天然续行**，不存在"括号未闭合才可续行"的限制
- 括号 `()`/`[]`/`{}` 未闭合时跨行是**结构上安全**的（函数调用参数、下标、表达式分组天然粘合）
- 语句已由分号终结，跨行表达式只需保证行首 token 不与上行行尾粘连出歧义（建议二元运算符留在**行尾**：`a +` 换行 `b;`）

> ⚠️ **注意：行首运算符仍会被并入上一行**（表达式内部换行≡空白）：`变量 a = 1 +` 换行 `2;` 与 `变量 a = 1 + 2;` 等价。若在**语句终结后**行首出现运算符（如上行缺分号），解析器会在语句终结处报「语句缺少分号」而非静默粘连。

#### 规则3：单行多语句（分号分隔）

- 单行多语句由 `;` 分隔：`变量 i = 0; ++i; --i;` 合法
- 每条语句独立终结，行内最后一条语句同样须 `;`

#### 规则4：空语句与空循环体（裸分号非法）

- 裸 `;` 作为空语句**不合法**（报"预期表达式"），CN 语言没有空语句
- `当(x);` 是**语法错误**（循环体强制要求 `{`——语法层显式拒绝，诊断「预期 '{'」；E2E 53/296 锁面），合法空循环体写 `当(x) { }`（空块合法）
- 循环头 `循环(整32 j = 0; j < 10; j++)` 中的分号是**三段分隔符**（与语句终结符语义无关，保持不变）

#### 规则5：模块级声明的分号（2026-09-04 plans/015 裁决）

- 导入语句：`导入 路径;`（对齐 Rust `use ...;`）
- 顶层常量/静态声明：`常量 名 = 值;`（类型推导，实装口径 E2E 96） / `静态 类型 名 = 值;`（对齐 C++ `const`/`static` 声明；238-a 措辞修正——原文「常量 T = 2」易误读为显式类型标注）
- 顶层全局变量声明：`类型 名 [= 常量表达式];`（2026-10-14 任务569 甲案配套补列·对齐 C 全局定义须分号；详见 §5.2a）
- 枚举声明、结构体/类/接口体：`}` 自终结，**不加分号**

#### 示例代码

```
变量 a = 1;        // 分号强制（缺失报错）
变量 b = 2; 整32 c = 3;   // 单行多语句：分号分隔

变量 i = 0; ++i; --i;    // 单行多语句

// 跨行书写长表达式：二元运算符留在行尾（表达式内部换行≡空白，续行不受影响）
变量 总和 = a +
           b +
           c;

当(x) { }        // 合法：空循环体（空块）
// 当(x);        // ❌ 语法错误：循环体强制要求 {
// ;             // ❌ 错误：空语句非法（预期表达式）
// 变量 d = 4    // ❌ 错误：语句缺少分号 ';'

循环(整32 j = 0; j < 10; j++) {   // 循环头分号是三段分隔符（与语句终结无关）
    打印行(j);
}
```

> **注意**：循环头 `循环(初始化; 条件; 更新)` 中的两个分号是语法必需的分隔符，与语句终止符无关；缺失任何一段都会报错。

> 解析层（词法+语法）的输入侧总纲，与 §1.1a①「编译期能证明的必须在编译期拦」同族：
> ① **显式诊断义务**：任何「无法构成合法声明/语句/表达式」的输入终态——缺右花括号/文件截断、调用实参表缺右括号、顶层尾随非法记号、尾随残缺函数声明、嵌套块截断等——必须产出显式诊断并中止编译（不产任何产物）；**禁**静默跳过/静默返回/静默吞记号（969~973 五形态双侧同拒锁面；解析错误=最典型的编译期可判定形态）。
> ② **错误恢复须留痕**：诊断后为继续解析而下读（跳至分号/块边界同步、多错连报）属合法恢复路径，但跳读必须**计数留痕**、由**收尾判定**兜底——753 模式：无法识别的顶层记号=计数漂过（不就地报错），语义检查全绿后收尾守卫判定「无法解析的顶层内容 N 处」中止（语义层已拒绝的形态保留原诊断=不打断既有诊断路径；语义全绿仍漂过=真垃圾拒绝）。
> ③ **「上游已诊断移交语义层」是唯一合法的非就地报错路径**：声明内部失衡吐回顶层、由语义层报既有诊断的形态（271_v2 先例：冒号后置的语义层『未声明的类型』保留以对齐宿主），实现处必须**注释声明**「上游已诊断/保留语义层诊断」，且受 ② 收尾判定约束。
> ④ **与「miss 不可静默」的边界互引（防互相豁免）**：本条管**输入侧**（源码无法构成合法声明的形态→显式诊断/计数收尾）；「miss 不可静默」纪律（AGENTS §3·110 案立法）管**查表侧**（编译器实现内部查表/判定 miss 禁止默认值兜底）——两侧纪律独立、互不豁免：解析层不得以「查表侧有纪律」名义静默吞输入，实现层不得以「上游已诊断」名义保留静默 miss。
>
> 词法层同守本条（§4 章首互引）。

### 5.1 程序结构

```
程序 = 顶层声明*
顶层声明 = 函数声明 | 结构体声明 | 枚举声明 | 类声明 | 接口声明 | 导入声明 | 全局变量声明
```

> **结构闭合与 EOF 截断拒绝（753 族·E2E 969/970/973 锁面）**：块以 `}` 闭合、调用实参表以 `)` 闭合——文件在闭合符前截断（EOF）或嵌套块截断时，解析器**显式诊断拒绝**（诊断「预期 '}'」/「预期 ')'」含行列定位），不静默放行、不产任何产物，收尾判定中止编译。宿主（parser 通用 consume 消费点）与 v2（解析类/解析块与调用实参表消费点）双侧同拒——v2 侧原静默放行（rc=0 无诊断）为 753 根治面。〔基准=019：错误即诊断〕

#### 5.2a 顶层全局变量声明（2026-10-14 任务569 用户裁决「甲+配套」立法）

```
整32 全局计数 = 5;      // 裸全局（无 静态 前缀）——§5.1 文法「全局变量声明」的实体形态
整32 零值计数;           // 无初始化器 = 零初始化（.bss 语义）
字符串 全局名 = "CN";    // 字符串字面量属常量表达式（运行期驻留按 §8.7 同静态通道）
```

> - **合法性**：§5.1 文法 `顶层声明 = … | 全局变量声明` 的实体形态（此前两侧实现分叉：宿主解析层拒、v2 静默吞——2026-10-14 用户裁决甲案定为合法，双侧对齐）。
> - **初始化仅限常量表达式**（C++ `constinit` 思路·防初始化顺序 fiasco）：初始化器须为编译期可求值形态——字面量（整/浮/字符/字符串/布尔）、常量引用与常量算术；函数调用/构造调用/运行期表达式 = **编译错误**（运行期初始化请改用 `静态`——顶层静态=入口注入通道·函数内静态=声明点守卫快照〔§5.2b〕——或在函数体内赋值）。无初始化器 = 零初始化；类/容器类型无初始化器 = 入口默认构造（与静态容器同通道，非「初始化器」故不受本款约束）。
> - **跨模块可见性**（显式化·C 式）：裸全局**默认外部可见**——被导入模块的裸全局无须 `公开:` 标签即跨模块可见（对照：`静态` 变量 = 文件/模块私有，默认不跨模块，`公开:` 显式放行——§5.9.3 之外本形态的显式例外）；跨模块同名裸全局定义 = 重定义编译错误。
> - **写入限制**：可变全局变量的赋值/复合赋值/自增自减 = **仅限 `不安全 函数` 体内**（§747 安全区边界表第 8 条「可变静态/全局变量写」·Rust `static mut` 对照的安全区纪律同构）；安全函数体内写 = 编译错误。读取无限制。
> - **存储**：`.data`（有常量初始化器）/`.bss`（零初始化）段，见 §8.7。

#### 5.2b 函数内静态变量：守卫快照初始化（2026-10-16 任务 852 语义轮落盘·执法锚=E2E 1006 双编译对照全链）

```
函数 标量快照(整32 轮) -> 整32 {
    整32 源 = 轮 * 10;
    静态 整32 甲 = 源;      // 非常量初值：首调经过声明点求值快照
    返回 甲;                // 标量快照(1)/(2)/(3) 恒 10——快照不复求值
}
函数 数组快照(整32 轮) -> 整32 {
    整32[3] 源;
    源[0] = 轮; 源[1] = 轮 + 1; 源[2] = 轮 + 2;
    静态 整32[3] 乙 = 源;   // 数组初值=整块拷贝（非首元素/非标量截断）
    返回 乙[0] * 100 + 乙[1] * 10 + 乙[2];   // 首调 123·再调恒 123
}
```

> - **首调经过声明点求值快照（非入口）**：函数内静态带**非常量初值**（运行期表达式，含引用同函数局部名）时，初值在**声明所在函数**的语句流内、于**首次执行到达声明点**时求值一次（1006 `标量快照`：`源` 首调求值入快照，`标量快照(2)/(3)` 不再求值）——不是程序入口注入（顶层静态通道），也不是每次调用重复求值。
> - **守卫一次性（再调不重初始化）**：每声明以「主槽+已初始化哨兵」双静态槽承载——首触哨兵为零 → 求值写主槽并置哨兵；再调哨兵已置 → 直读主槽、跨调用保持（1006 `计次` 1/2/3）。
> - **数组初值整块拷贝**：静态数组=数组变量初值时按**整块**守卫快照拷贝（按数组类型精确字节数·非标量截断、非首元素；与 259 顶层静态数组赋值同款），后续下标读写经静态符号基址（1006 `数组快照` 首调 123=三元素齐全）。
> - **常量初值=加载期直存**：可折叠常量初值（字面量）由 `.data` 直存、程序加载即生效（与顶层静态变量/类静态字段三形态同通道·§5.6「静态槽字面量域限制」同辖）；守卫通道只承载非常量初值。
> - **守卫快照初始化=非写**：初始化求值不属「可变静态写」执法面（§747 安全区边界表第 8 条只拦赋值/复合赋值/自增自减）——安全函数内的函数内静态照常可带非常量初值（1006 `标量快照/数组快照`=安全函数）；静态变量本身的显式改写仍须 `不安全 函数`（1006 `计次`）。
> - **跨线程初始化口径（如实标注·2026-10-17 用户令）**：当前语义=**单线程语义**——守卫哨兵为普通布尔槽（无锁、非原子），初始化判定=一次哨兵读+分支。多线程并发首触发的竞争语义（对照 C++ magic statics 加锁方案：每次首触原子操作）为**未来扩展项**，本轮不实现、不加锁——需要跨线程初始化保障的场景经显式同步原语（互斥锁·§5.8b）自行组织；安全区口径=①如实写明现状，②扩展项挂号（并发波 027 同域）。

**与顶层面初始化限制对照表（§5.2a/§5.6 ⇔ 本条）**

| 面 | 顶层全局/顶层静态（§5.2a） | 函数内静态（本条） |
|----|--------------------------|--------------------|
| 初始化器形态 | 裸全局仅常量表达式（C++ `constinit` 思路）；`静态` 允许非常量（经入口注入通道） | 常量=加载期直存；非常量表达式=声明点守卫快照 |
| 求值时机 | 加载期 / 入口注入 | 首次执行到达声明点 |
| 引用函数局部名 | 不适用（无函数作用域） | 合法——按首调当时局部值快照 |
| 无初始化器 | 裸全局=零初始化（`.bss`） | **编译拒绝**（#324 甲案·§3.9 def-init 登记面） |
| 可变写限制 | 赋值/复合赋值/自增自减仅限 `不安全 函数`体内（§747 表第 8 条） | 同左（声明点快照初始化=非写不受限） |

#### 参数传递语义（056 甲·2026-09-27 用户裁决落盘）

```
函数 改盒子(盒子 对象) -> 整64 {
    对象.值槽 = 55;      // 经句柄写同一堆对象
    返回 对象.值槽;
}
// 调用方实参 对象.值槽 同步为 55（引用语义·写穿）

函数 改点(点 p) -> 整64 {
    p.x = 99;            // 写在副本上
    返回 p.x;
}
// 调用方实参 p.x 不变（副本语义）
```

> - **类类型按值形参=引用语义（写穿）**：类变量为指针槽模型（见 3.2 取地址语义一致化），形参槽存对象句柄拷贝，体内经句柄对同一堆对象的读写（字段赋值/方法调用）在调用方实参可见。stdlib 容器类（容器/向量/映射/集合）同此。临时实参合法（编译器物化临时槽·句柄指向临时对象）。
> - **结构体/标量按值形参=副本语义**（052 甲值语义）：体内写入落副本，不影响实参。
> - **正交边界（052 甲）**：容器元素读取（元素(i)/获取 等访问器）返回副本（快照语义），对读取副本的写不写穿容器，须 设置 写回；类对象直接形参传递=引用写穿。两者正交并存。
> - **元素引用访问器（第三形态·065 A 账 829 轮实装 2026-09-28）**：`向量<T>.元素引用(整64 位置) -> T&`
>   为**引用返回**零拷贝借用视图（Rust `&v[i]` 同款）——返回左值地址，只读消费与原地写均写穿容器；
>   越界=运行时错误（与 元素 同款 267-a T18）。**`不安全 函数`** 收口（借出视图可绕过值语义别名豁免，
>   责任上移显式审计——AGENTS §3.1 第三句「危险面收口」）；与 元素（副本）/设置（写回）构成
>   读副本/写回/写穿三形态正交并存。宿主 P3-18 引用返回 ABI 与 v2 生成语句 族① 对齐（2026-09-27
>   实测双端一致·78/79_v2 自举链背书）。
> - `T&` 引用参数=编译器取实参左值地址的引用传递（标量/结构体/类均可）；与按值类形参的句柄拷贝机制不同。
> - 实现口径（2026-09-27 实测·双编译对照 535）：宿主与 v2 自举链行为一致（类 ABI 统一背书）〔基准=019：默认路径零规则·写穿即引用语义自然结果，用户无需学新规则〕。
> - **借出视图失效拒绝（77-a 检查器·plans/020 矩阵 A21 格靶子·2026-09-12 立·执法锚=E2E 223）**：字符串元素容器的访问器（元素/读取/栈顶/队首/头部元素/读取头部/读取尾部/获取）返回容器内元素句柄的**浅拷=借出视图**；容器失效方法（删除/设置/清空/弹出/出队/删除头部/删除尾部/释放内部数组）使该元素被释放/移出后，借出视图仍被使用=悬垂——判据=**NLL 顺序近似**（引用活跃区间=绑定点→最后使用点；区间内出现**容器失效点**即拒绝——Rust E0502 同构；CN 无借用类型，靠方法名清单+来源登记达成同一拦截，诚实边界见实现注释）。宿主（semantic_borrowview）与 v2（借出检查.cn）双侧同拒（E2E 223 六形态锁面）〔基准=019：悬垂零容忍〕。

#### 返回值语义（2026-10-29 裁决 #1784·丁案立法）

```
类 货架 {
    公开:
    向量<字符串> 记录;
    函数 货架() { 记录 = 向量<字符串>(); }
    函数 取() -> 货架 { 返回 自身; }     // 值副本：接收方获得独立新对象
    函数 视图() -> 货架& { 返回 自身; }  // 借用：共享同一对象（借用检查约束）
}
```

> - **R1（值副本）**：函数返回类型为类时（`-> T`），返回**值副本**——接收方获得
>   独立拥有的新对象，与来源对象此后互不影响。副本构造按来源三分：
>   ① **本体源**（容器元素、临时对象）：本体逐字段拷贝；
>   ② **句柄源**（成员、变量、形参）：解句柄后逐字段**深拷**（资源字段递归
>      深拷——串/容器各自独立，浅共享共享 = 禁止）；
>   ③ **转移源**（返回局部对象、`转移(表达式)`）：所有权转移，源对象此后
>      不可用（零拷贝移动语义）。
>   与按值形参的句柄写穿语义（见参数传递语义节）**正交并存**：传参写穿、
>   返回副本。容器元素返回（052 甲·630 立法）为 R1① 特例，自然并入。
> - **R2（借用共享）**：`-> T&` 为类借用返回：返回来源对象的句柄视图
>   （零拷贝），受借用检查约束——被借对象生命周期必须覆盖借用使用期；
>   同一对象的可变借用必须独占。执法依托借出视图失效检查同款 NLL 顺序
>   近似（上条），扩展至类返回借用。非借用共享通道（`-> T*` 之外的隐式
>   共享）不存在——共享必须显式写 `&`。
> - **R3（裸指针）**：`-> T*` 仅限不安全函数（B11 空指针执法与借用域规则
>   不变）。
> - **R4（多态禁切片）**：存在继承链（含接口实现）的类，禁止值形态发生
>   "基类格 ← 派生类值"的赋值/传参/返回（对象切片）——多态使用必须经
>   `T&` 或 `T*`。编译期拒绝，诊断指路本条文。
> - **R5（双实现一致）**：宿主与 v2 按本节同法实现（零分叉铁律）。
>   存量补丁面（85-a/914/1501/1737 系）随本立法重写归一。
> 〔裁决 #1784·用户 2026-10-29 批丁：类返回值语义立法——零兜底、零默认、
> 零静默：两侧编译器同法、来源三分显形、切片编译期拦〕

#### lambda 表达式（匿名函数）

```
变量 加倍 = [](整32 x) -> 整32 { 返回 x * 2; };
整32 结果 = 加倍(21);   // 42
```
> lambda 支持 `[捕获]`（`[]` 不捕获 / `[=]` 值捕获 / `[&]` 引用捕获 / `[变量]` 显式捕获）；无返回类型标注时由编译器推导（单一 `返回` 表达式或空类型）。

> **[&] 引用捕获逃逸限制（435·2026-10-11 用户裁决甲+乙组合·悬垂零容忍〔基准=019 §1.1a〕）**：
> 引用捕获（`[&]` 且捕获集非空）的 lambda 持有定义帧局部变量的地址，其生命周期**不得超过
> 被捕获变量的栈帧**。编译器以**保守逃逸分析**编译期强制：①能证明闭包不逃逸定义帧
> （赋给局部变量+同帧调用，706/707 权料面；立即调用 `([&](){...})()` 同面）→ 放行；
> ②检出逃逸形态 → **编译错误**（诊断「逃逸当前栈帧」；文案指路：改 `[=]` 值捕获快照，或改在 `不安全 函数`
> 内定义豁免）——逃逸形态枚举：作返回值（`返回 [&]{...}` 及经局部变量的传播链）；
> 赋给全局变量/对象字段/容器元素等长寿命载体；作函数实参传出。③分析不确定面按逃逸
> 拒绝（永不静默放行——保守方向误拒允许，用户按指路改写即绿）。④**豁免=责任上移**
> （Rust `unsafe` 同款哲学·与 §1.1a④ 不安全区、不安全 函数 先例同构）：`不安全 函数`
> 体内定义的引用捕获 lambda 免检——逃逸悬垂的安全责任由程序员自担（审计面=不安全
> 函数清单）。值捕获（`[=]`/`[变量]`）与空捕获（`[]`）为快照语义无悬垂面，不受限。

#### 显式转移 转移()（2026-09-10，plans/019 阶段1 · 编译期安全）

```
变量 v = 向量<整64>();
变量 u = 转移(v);        // 所有权转移：u 接管 v 的值，v 进入「已转移」状态
打印行(v.大小());        // ✗ 编译错误：'v' 已转移，不能继续使用

变量 p = 分配内存(8);    // 指针交接（零拷贝，槽位值）
变量 q = 转移(p);        // q 持有，p 禁用——释放归属唯一化
```
> `转移(变量)` 为**内置函数**（零新关键字；内置构造器 正常()/错误()/某些() 同位；C++ `std::move` 同构）。规则：①实参须为**变量标识符或成员**（`转移(h.字段)` 成员源 959 起放行——成员地址→句柄交接+成员槽清零·旧名禁用按成员路径在 IR 层清零后读空推导·编译期成员拦截随 LUE 轮精确化；下标/解引用形态编译报错「转移目标须为变量」〔982 条文同步〕）；②实参类型须为**资源语义类型**（指针/字符串/容器/类对象/结构体/结果/可选），**标量（整数/浮点/布尔/字符）拒绝**——复制语义无转移意义（对齐 Rust Copy 类型惯例，诊断「'X' 具有复制语义，无需转移」）；③求值结果=实参的值（交接），**源变量自该点起任何「读性使用」均为编译错误**（读值/复合赋值/自增自减/取地址/解引用/成员与下标对象侧/调用实参/返回/再次转移，对标 Rust E0382），诊断含转移点定位（「'v' 已转移，不能继续使用（转移发生在 行N）」）；④已转移状态不因作用域退出恢复；内层同名**新声明**是新变量不受影响（遮蔽语义）；**⑥赋值复活（2026-10-03 用户裁决甲·981 轮·Rust assign-to-move 同款）**：转移后对源变量的**纯赋值**（`v = 表达式`·赋值目标为标识符）=重新初始化（写不读旧值·无 UAF 风险），赋值点起清除已转移状态（**复活**），此后使用合法；**成员赋值（`v.f = x`）/下标赋值（`v[i] = x`）/复合赋值（`v += x`）/自增自减不豁免**（均需读旧值·仍为编译错误）；⑤第一版运行行为零变更（语义层 AST 改写，指针即值天然零拷贝；容器/类仍按拷贝语义，浅转移零拷贝优化随 plans/019 阶段3）；安全保证=编译期拦截「转移后使用」（UAF 主形态）与「转移后再释放」（双释放主形态）。规格详见 cn-language-spec 04-五。

#### 最后使用消除（LUE·2026-09-28 立；2026-09-29 双端追平，AGENTS §3.1 第四句 (a) 立法承载 · 054 波1 + 083 宿主追平实装）

```
函数 消费(字符串 s) -> 空类型 { 打印行(s); }
函数 主() -> 整32 {
    变量 名 = 字符串复制("甲");
    消费(名);             // 名 在此之后不再出现 → 编译器自动降级为转移（零拷贝）
    返回 0;               // 无需手写 转移(名)——源槽自动清零，深拷省略
}
```
> **拷贝消除是编译器义务**（AGENTS §3.1 第四句 (a)·〔基准=019〕；Rust last-use move elision / C++ NRVO
> 工业对照）：对「源在拷贝后不再被使用」的拷贝，编译器**自动降级为转移**——用户无需手写 `转移()`。
> **触发条件（极保守·不确定即不消除）**：①实参=纯局部标识符（成员链/下标/解引用形态不参与）；
> ②拷贝点之后至函数边界无同名标识符**读**出现（**纯赋值目标=写不算**——赋值复活〔转移条文⑥〕语义下写点即复活点·旧值无人再读；复合赋值/成员链基座/下标基座/取地址=读照算·981 起生效〔基准=019〕第四句(a)）；③**循环跨迭代保守**——拷贝点被
> 循环包围时，源须在同一最内层循环体内声明（每轮重新初始化；否则回边后下一轮读到已清零槽·
> 874 实证修正）；④类型限**字符串/容器**（结构体族 move 发射不完整，扩面随任务 078）。**效果**：
> move 发射（句柄直取+**源槽清零**）跳过深拷——可观察差异=`内存::活动分配数()` 差值 1→0。
> **双端现状（2026-09-29·874 追平）**：v2 自举编译器（854 落地·857 限面收窄）与宿主编译器
> （083 追平·判据同构·含循环保守）**均已实现**——同一源码双端同判：E2E 285 单态断言
> （字符串/容器 增==0；结构体限面 增==1）+ E2E 549 循环回边门禁（回边面不消除／循环内新声明
> 允许消除）。沿革：076（2026-09-28 两态断言承载 v2 独有期）→ 874 收回单态。
> 与显式 `转移()` 的分工：LUE=编译器自动版（默认路径零规则）；`转移()`=用户对热路径的显式控制，
> 二者语义同向（源名禁用），LUE 消除后源变量进入已转移态（同转移条文③⑥：读性使用=未定义读禁·纯赋值可复活）。

#### 不安全 函数 修饰（2026-09-10 立；2026-09-14 清单完整化 plans/023 §九；**2026-09-17 收口——编译硬错误生效**）

```
不安全 函数 裸改(整64* p) -> 整64 {
    整64* q = p + 1;      // 指针算术：不安全函数内合法

> **编译期硬错误**（不属清单，独立于不安全区）；③调用 `不安全 函数` 允许（责任上移；审计面=不安全函数清单）；

#### 外部 函数 声明（FFI，2026-08，C-3）

```

> 调用误编（宿主 retbuf 不预插·类值当指针判空解引用崩）；Rust `extern "C"` 非 FFI-safe

### 5.4 错误处理（替代异常）

```
// 结果类型：正常返回值 或 错误码
函数 除法(整32 a, 整32 b) -> 结果<整32, 整32> {
    如果 b == 0 {
        返回 错误(1)  // 错误码1: 除零错误
    }
    返回 正常(a / b)
}

// 使用时检查
除法结果 = 除法(10, 0)
如果 除法结果.正常 {
    打印行(除法结果.值)
} 否则 {
    打印行("除零错误: ", 除法结果.错误)
}

// 可选类型
函数 查找(整32 键) -> 可选<整32> {
    如果 表.包含(键) {
        返回 某些(表[键])
    }
    返回 无
}
```

> **注意：所有关键字均为保留字，不可用作标识符。**

**内置构造器身份说明：** `正常()`、`错误()`、`某些()` 为内置构造器函数，由编译器预置符号表，非保留关键字，用户不可重定义。

#### 结果/可选强制检查规则
- 规则1：`结果<T,E>` 类型的返回值如果不被检查就丢弃，编译器报**错误**
- 规则2：检查 `结果.正常` 后未处理错误分支，编译器报**警告**
- 规则3：`可选<T>` 类型的值在访问 `.值` 前必须检查 `.有值`，否则编译器报**错误**

#### 错误传播运算符 表达式?（2026-08，C-1）

```
函数 安全除法(整32 a, 整32 b) -> 结果<整32, 整32> {

> **析构体内的释放纪律：摘除 原语 / 析构体手动释放执法 / 手动释放\<T\>（#1674 立·2026-10-26 用户批·执法锚=E2E 1580/1581）**：析构级联（~T 体生成后按字段逆序自动释放 字符串/盒载荷/类字段，对标 C++ 成员析构语义）保证「忘记释放不可能」；但析构体内**手动**释放资源字段（`字符串释放(自身.X)` 等）会与级联构成二次释放。三件同轮立法：
> ①**摘除(槽) 原语**（对标 C++ smart pointer `reset()` / Rust `Option::take` 释放侧内建化）：`摘除(x)` 要求实参=**拥有槽左值**（局部变量/形参/类字段访问，槽类型=字符串或类类型），语义=一步完成「释放旧值+清槽」——字符串槽 `__cn_str_free(旧值)`+槽置零；类类型槽 `DeleteObject(旧对象)`+槽置零；槽已空=空安全无操作。摘除后槽=null，析构级联读到空槽自然跳过——**手动放手与自动级联幂等组合，双释放机械杜绝**。裸指针不纳入（无拥有契约，手动管理继续走 `释放`+不安全 函数）；摘除字符串形参=消耗标记（同 字符串释放 先例·102 甲案）；右值实参=编译期拒（无槽可清）。
> ②**析构体内手动释放资源字段=编译期拒**：析构函数体内对资源字段（字符串/可选$/结果$/类类型字段）调用 `字符串释放` → Error 并引导：改用 `摘除(字段)` 提前放手，或将字段改裸指针类型+析构函数标 `不安全 函数` 自行管理。局部变量手动释放不拦（用户自有槽）。安全函数体内裸释放（A5）既有执法不变。
> ③**手动释放\<T\> 包装类型**（对标 Rust `ManuallyDrop<T>`）：`手动释放<T> 名;` ——类型级显式声明「此槽释放权归用户」：编译器级联**跳过**该槽；**赋值覆盖不释放旧值**（forget 语义——覆盖即忘，责任归用户）；布局=单载荷槽（第一版载荷域=字符串/类类型·句柄槽 8 字节；标量载荷面随泛型克隆协议另批）；经 `.值` 访问载荷（读出=句柄值拷贝）；释放由用户经 `摘除(名.值)` 或不安全函数内手动执行——**摘除+手动释放\<T\> 组合=完全接管+安全放手**。手动释放$ 字段不触发三法则强制（声明即「我不管」·Clone-not-Drop 对标）。宿主与 v2 双侧同构。

> **接口实现三查（413-b 立·2026-10-17 任务 974 补录·执法锚=E2E 717）**：类声明实现接口（`类 X : 接口名`）时逐接口方法校验——①**存在**（缺实现报「未实现接口 'I' 的方法 'M'」）；②**签名一致**（实现方法与接口方法的参数类型与返回类型须精确一致，不一致=编译错误「类 'X' 实现接口 'I' 的方法 'M' 签名不一致」）；③**修饰**（实现方法须 `虚拟` 或 `重写` 修饰，否则报错）。协议不符实现在编译期拦截（防静默错位/截断）；宿主（class_resolver）与 v2 双侧同构（E2E 717 双形态锁面）。

> **抽象成员=纯虚声明（193 立·2026-10-17 任务 974 补录·执法锚=E2E 861）**：`抽象 函数 名(参数) -> 返回类型` 为纯虚声明——**不得带实现体**，带体即编译错误（诊断「抽象方法不得带实现体」；抽象成员声明的接口义务由派生类/实现类承担）。宿主（parser_oop 同点）与 v2（解析方法体 位8）双侧同拒（零分叉）。

### 5.8 函数指针

```
// 声明
整32(*回调)(整32, 整32)

// 赋值
回调 = 加

// 调用
整32 结果 = 回调(10, 20)
```

> **说明：`整32(*回调)(整32, 整32)` 采用C风格声明语法，这是为了与C/C++函数指针语法保持一致，便于底层编程人员理解。**

> **方法作值（P3-23，2026-08）**：静态方法 `类名.静态方法` 可直接作函数指针值（e2e 98）；实例方法 `对象.实例方法` 作值为**绑定 this 的闭包**——经闭包变量调用（`自动 cb = 对象.方法; cb(实参)`，捕获对象地址、引用语义读最新状态，e2e 104），不可直接作裸 fnptr 实参（裸地址无法携带 this，编译报错——诊断「须先赋值给变量」（绑定方法须先落闭包变量再传递），e2e 107 负向双编译对照锁面）。规格详见 cn-language-spec 04-四 方法作值。

> **声明位置全集·字段位与数组元素位（2026-10-05 用户裁决甲案·040/082①② 立法）**：函数指针声明 `返回类型(*名)(参数表)` 支持位全集：①局部变量位 ②形参位 ③函数/方法返回类型位 ④**结构体/联合体字段位**（`整32(*回调)(整32);`）⑤**数组元素位（回调表）**（`整32(*表[2])(整32);`——数组长度置于名字之后、右括号之前，C 同款）⑥全局变量位。字段位/数组元素位宽度=8 字节指针槽（指针族对齐）；数组元素位走既有数组安全通道（编译期常量下标硬错误 §1.1a① + 运行期错误码 2 越界兜底 §1.1a②）。类字段位不在本批（类字段走类布局通道，另域另立）。

> **来源封口（编译期硬错误·§1.1a①）**：函数指针的合法来源仅两种——①**函数名衰减**（含 静态方法 `类名.静态方法`、泛型实例名）②**同签名函数指针**（签名精确兼容：返回类型+参数个数+逐参数类型全等）。整数、空类型*、对象指针等任何其他类型赋给/初始化函数指针 = 编译错误「无法将 'X' 隐式转换为 '函数指针<...>'」。由此函数指针恒指向真实存在的函数，间接调用安全等级与普通调用相同，不安全清单不新增条目（023 域零扩大）。

> **布局与拷贝语义**：函数指针 = 8 字节标量槽（指针族对齐 8）；值语义浅拷贝即安全（指向代码段，复制后新旧值均有效）——无深拷、无析构、无双释放，**非资源字段**（资源字段类别判定豁免）；含函数指针字段的结构体 `转移()` 照常（旧名禁用按结构体整体，零特例）。

> **空调用防线（子案 A·2026-10-05 用户裁决）**：零值（未赋值）函数指针间接调用 = **运行期确定性失败**——编译器在每个间接调用点插入判零检查，零值 → `运行时错误(错误码3): 空指针解引用`（与 093 判空家族同码同文案，§1.1a② 确定性失败·非脏崩溃；Rust 裸 fn pointer 解引用为 UB，CN 安全区更严）。

### 5.8a 可搬运标记（并发安全·027 波2a）

> 〔基准=plans/019 §5.5〕〔对标 Rust Send〕**「可搬运」**＝该类型的值可安全地按值拷贝进入另一线程（`新线程` 实参位）而无数据竞争。并发安全第一版单标记——Sync（共享安全）随未来跨线程共享语法特性另立（021 #201），原子库另立（021 #202），RAII 互斥锁守卫随析构链成熟另立（021 #219）。

> **自动推导规则（用户零负担·Rust auto trait 同构）**：①标量（整N/正M/浮N/布尔/字符）、字符串、函数指针（代码指针·§5.8）恒可搬运；②`结果<T>`/`可选<T>` 可搬运 ⇔ T 可搬运；容器/数组 可搬运 ⇔ 元素类型可搬运；③结构体/类 可搬运 ⇔ **全部字段**可搬运（递归·含继承并入字段）；④**含裸指针字段（`T*`/`空类型*`）的类型默认不可搬运**——裸指针无所有权语义，与「不安全」分区口径一致（§1.1a④），跨线程转移=数据竞争温床。

> **显式豁免（编译期声明·对标 Rust unsafe impl Send）**：确需跨线程的含指针类型，在结构体/类声明位加 `不安全 可搬运` 修饰——声明人自担跨线程安全责任（与 §1.1a④ 不安全哲学同构·编译器不为其插检查）。「可搬运」为**声明位上下文词，非全局保留字**（既有程序以「可搬运」作标识符不受影响·关键字最小化原则）。

> **检查面（第一版单挂点·§1.1a① 编译期硬错误）**：`新线程(入口, 实参)` 实参位——按值拷贝进入新线程的每个值须可搬运；违例=编译错误「类型 'X' 含裸指针字段 'Y'，不可跨线程搬运」（诊断含类型名与字段链）。宿主与 v2 双侧同构（零分叉红线）。

> **内置豁免窗口（sunset 立法·2026-10-06 用户裁决）**：stdlib 线程六函数（线程::新/并入/互斥锁新建/上锁/解锁/释放）的 `空类型*` 句柄形态为过渡 API——**顶层 `空类型*` 实参在 `新线程` 实参位暂放行**（586 既有形态维持零误伤），用户定义类型的指针字段不受此豁免。**本豁免随 021 #218（互斥锁<T> 类型化句柄）集成即作废**，届时六函数签名类型化、顶层指针一并拦截——有到期日的立法过渡，非搁置缺陷。
>
> **〔218 执行·sunset 收窄呈报（2026-10-06）〕**：豁免窗口按到期条款执行，收窄为——**`新线程` 实参位的顶层 `空类型*` 豁免仅限 `不安全` 函数体内**（§1.1a④：线程实参盒=手动管理区 FFI 契约形态；安全区传裸指针值=编译期拒绝·与用户定义指针字段同拦）。stdlib 线程模块六包装函数随批加 `不安全` 修饰（对齐 019 阶段4 stdlib 迁移先例），包装链中转在 不安全 区内自然豁免；586/607 既有用例主函数已为 不安全=零破坏。原条文「六函数签名类型化」以**互斥锁<T> 类替代可用**达成（句柄四函数保留兼容存量·标注过渡），线程实参泛型化（新线程<T>）另域另立。

### 5.8b 互斥锁<T> 类型化句柄（并发安全·027 波2b）

> 〔基准=plans/019 §5.5〕〔对标 Rust Mutex\<T\>〕**互斥锁<T>**=标准库泛型类（纯 CN 源码·`泛型 <类型 T> 类 互斥锁`，与 向量<T> 同通道·零编译器结构改动）——**锁与受护数据类型化绑定**：拿 A 锁护 B 数据的锁错对象错误在类型检查下不可表达（Rust Mutex<T> 字段私有同位）。

> **API（第一版·显式 上锁/解锁 对·2026-10-06 用户裁决）**：`互斥锁(初值: T)` 带参构造（运行时句柄经内置 互斥锁句柄四函数·`~互斥锁()` 析构释放）；`上锁()`/`解锁()` 显式对；受护值经公开字段 `值` 访问（第一版纪律域——未锁直访不拦=诚实边界，**RAII 守卫（021 #219）集成后收紧为编译期拒绝**，条文透明非搁置）。实例=对象句柄语义（与容器实例同模型·共享同一锁实例=跨线程共用正确形态）。

> **可搬运联动**：`互斥锁<T>` 可搬运 ⇔ T 可搬运（Rust `Mutex<T>: Send ⇔ T: Send` 同构）——可搬运判定容器名单含 `互斥锁` 基名（宿主 isPortableType+可搬运判定 v2 双侧同构），句柄私有字段不经字段递归（白名单分支先于用户类递归命中）。

> **过渡与迁移**：句柄四函数（线程::互斥锁新建/上锁/解锁/释放）保留兼容存量 586，标注过渡——新代码用 互斥锁<T>。线程实参泛型化（`新线程<T>(入口, 实参: T)`）另域另立（021 挂行）。

#### 5.9.1 模块声明与路径

```
模块声明 = "模块" 标识符
路径 = 标识符 ("::" 标识符)*
// 示例：网络/传输控制.cn → 模块 网络::传输控制
```

- **定位收紧（2026-09-07 plans/018 裁决，Rust `mod` 对齐）**：`模块` 声明**仅限两种树结构位置**——
  ① **包根成员聚合**（`包.cn` 内 `模块 网络;`，声明包的组成，不引入名字）；
  ② **父模块挂子模块**（`网络.cn` 内 `模块 传输控制;`，建立 `网络::传输控制` 完整路径）。
  **普通源文件使用 `模块` 声明 = 编译诊断**（普通文件即模块，其模块路径由文件名+目录层级唯一决定，无需声明）。
- **自动加载强语义（2026-09-07 宿主实证，plans/018 第 0 步）**：被 `模块` 声明引用的模块文件**恒被加载编译**（Rust `mod foo;` 必编译 `foo.rs` 同款）——哪怕无人 `导入` 它，其内错误也在库自身编译期暴露（fail fast，库完整性保证）；触发源即 `模块` 声明本身，非目录扫描（未声明的同目录杂散 `.cn` 文件不参与编译，封闭树）。
- **循环导入拒绝（2026-10-17 任务 974 补录·执法锚=E2E 325）**：模块导入图（导入声明边）出现环——直接互引或经中间模块的间接互引——=**编译错误**（诊断「模块循环依赖」并打印环路径，如 `循环乙 -> 循环甲 -> 循环乙`）。加载按依赖拓扑序（被依赖者先编译），拓扑排序检出回边即拒绝（不递归展开）；宿主（module.cpp 拓扑 DFS）与 v2 自举链（主.cn 在途模块再入）双侧同拒——环无合法语义，不设豁免通道。〔基准=019：错误即诊断〕

#### 5.9.6 分号模型（2026-09-04 plans/015 方案B 反转）

- 语句强制 `;` 终结（见 §4.6）；模块级声明中：**导入声明 `导入 路径;` 须分号**（Rust `use` 同款）、**顶层常量/静态/全局变量声明须分号**（C++ `const`/`static`/全局定义同款·全局变量=2026-10-14 任务569 甲案补列，见 §5.2a）；模块声明（`模块 名`）与 结构体/类/接口/枚举体 `}` 自终结，不加分号。

- **接口方法签名强制 `;` 终结（2026-10-30 任务1870 立法·1866 同族扩展·执法锚=E2E 1656）**：接口体方法签名「[虚拟|重写] 函数 名(...)[ -> 类型]」后须 `;`——缺失即显式诊断（「接口方法签名缺少分号 ';'」·宿主 parseInterfaceDecl / v2 解析接口.cn 同点同串）。词法层换行已丢，签名间换行分隔自本条起退位——跨签名静默粘连事故链（`虚拟 函数 画() -> 空类型` 直撞下一 `函数 无关()` 被粘连解析成两个方法）就此根除，与字段分号条文（上条）同一立法动机。诊断后不消费当前记号（一次解析报全量缺分号位置·与 1866 类字段纪律同构）。

#### 5.9.7 名称解析（遮蔽与歧义，2026-09-07 plans/018 新增·Rust 对照）

> 此前规范空白（宿主行为是事实标准无条文），本轮立规。Rust 对照：item > named use > glob 三级 +
> E0255（导入与本地定义同名）/E0659（glob 歧义）显式报错、绝不静默选（歧义绝不引入错误绑定）。

**三级优先级**（纯名引用——不带 `::` 的标识符——按此决议唯一绑定）：

| 优先级 | 名字来源 | CN 形式 | Rust 对应 |
|---|---|---|---|
| 1（最高） | 本模块显式定义项 | 函数/结构体/常量/静态声明 | item in current module |
| 2 | 显式导入（具名绑定） | `导入 m::符号`、`导入 m::{a, b}`、`导入 m::符号 作为 别名`（符号以原名/别名绑定纯名） | named `use` |
| 3（最低） | 通配引入 | `导入 m;`（模块整体导入=其公开 API 批量引入）、`导入 m::*` | glob `use m::*` |

> **模块级别名**：`导入 m 作为 别名` / `导入 a::b 作为 别名` 绑定的是**模块路径本身**
> （供 `别名::符号` 限定访问），不引入纯名——等价 Rust `use m as n`。
>
> **限定调用恒明确（2026-09-07 呈报一B 裁决：对齐 Rust「路径恒可用、导入只影响纯名」）**：
> `m::X`（含多级）指向**已加载模块**的公开符号即可用，**不要求先导入**；宿主现行 P1-1
> （未导入限定调用报错）随之废止（✅ 已实施：plans/018 工作流2，第三十一轮下半程，
> E2E 161 正测 + 单测负覆盖锚定）。

**冲突与遮蔽判定矩阵**（同为纯名、签名相同的前提下）：

| 冲突面 | 判定 | 诊断 |
|---|---|---|
| ① × ② 同名 | **编译错误** | 「导入与本地定义同名」（E0255 对应；改名或删其一） |
| ② × ② 同名 | **编译错误** | 「多次显式导入同名」 |
| ③ × ③ 同名 | **使用点歧义错误**（仅当该名字被实际引用时报） | 「符号歧义：来自 模块A/模块B」（E0659 对应） |
| ① 遮蔽 ③ | **合法**（唯一允许的遮蔽） | 无诊断（本模块项优先，glob 项被遮蔽） |
| ② 遮蔽 ③ | 合法 | 无诊断 |
| 重载（同名不同签名） | 不适用本矩阵 | 按函数重载决议（签名精确/字面量宽匹配），歧义同报错 |

- **限定调用恒明确**：`模块::符号(...)`（含多级 `a::b::c`）直接决议到指定模块的公开符号，不参与遮蔽，永无歧义；未导入的模块路径引用=「未声明的标识符」（P1-1 严格化，prelude 内置例外）。
- **跨模块同名同签名合法共存**：链接符号在多模块场景加前缀 `模块全路径$名#参数串`（函数/结构体/常量统一），单文件/主模块不加前缀——编译期一次拼接，运行时零开销。
- **决议失败绝不静默**：歧义/未命中一律编译诊断，禁止「先收集文件赢」式静默绑定（静默吞=错误绑定，违背安全准绳）。

```
// 示例：本模块项遮蔽整体导入（合法）
导入 工具库;                        // ③ 整体导入，工具库 也有 公开 函数 版本()
函数 版本() -> 整32 { 返回 100; }   // ① 本模块项
// 纯名 版本() -> 100（①遮蔽③）；工具库::版本() -> 200（限定调用直达）

// 示例：显式导入与本模块项同名 = 编译错误
导入 工具库::版本;                  // ② 具名绑定与上方 ① 同名 → 编译错误「导入与本地定义同名」
// 对照：导入 工具库; 或 导入 工具库::*;（③ 通配）与本地 版本 同名 = 合法遮蔽
```

> 完整规范见 `.zcode/skills/cn-language-spec/specs/08-模块系统.md`（v2.0）与 `specs/09-包与依赖.md`。

## 六、编译器架构

### 6.1 编译流水线总览

```
CN源代码(.cn)
    │
    ▼
词法分析器(Lexer) -> Token流
    │
    ▼
语法分析器(Parser) -> AST树
    │
    ▼
语义分析器(Semantic) -> 带类型AST + 符号表
    │
    ▼
IR生成器(IRGenerator) -> CN-IR
    │
    ▼
优化器(Optimizer) -> 优化后的CN-IR
    │
    ├─────────────┐
    ▼             ▼
Win x64 Codegen  Linux ARM64 Codegen
    │             │
    ▼             ▼
.asm文件        .asm文件
    │             │
    ▼             ▼
汇编器+链接器 -> 可执行文件
```

### 6.2 各阶段职责

#### 阶段1：词法分析器（Lexer）
- 输入：.cn源文件（UTF-8编码）
- 输出：Token流
- 职责：UTF-8中文字符识别、字面量解析、运算符与分隔符识别、注释剥离、行号/列号追踪
- 关键设计：中文关键字最长匹配，关键字后必须有空格或符号分隔

#### 阶段2：语法分析器（Parser）
- 输入：Token流
- 输出：AST
- 职责：递归下降解析、运算符优先级处理（Pratt parser）、AST节点构建、语法错误报告
- 关键设计：两趟解析——第一趟收集顶层声明，第二趟解析函数体，支持前向引用
- **AST 深度防护（315-a T6 波次3 立·2026-10-17 任务 974 补录·执法锚=E2E 417）**：表达式/语句嵌套统一上限 **128 层**（括号与语句块嵌套统一计数）——超限报「表达式/语句嵌套过深（超过 128 层上限，请重构降低嵌套深度）」并中止（宿主 parser_expr 与 v2 解析表达式 同构同限）。原实装超限=栈溢出崩溃（实测表达式崩点 156 层），防护把崩溃根治为友好诊断（实现限定·非语言语义面；Clang -fbracket-depth 同思路）。

#### 阶段3：语义分析器（Semantic Analyzer）
- 输入：AST
- 输出：带类型标注的AST + 全局符号表
- 职责：符号表构建与作用域管理、类型检查与推断、隐式类型转换验证、继承与接口实现验证、函数重载解析、错误码传播分析（结果/可选强制处理）、常量折叠预计算
- 关键设计：分模块语义分析——名称解析模块（NameResolution）、类型检查模块（TypeChecker）、OOP验证模块（OOPValidator）、错误码分析模块（ErrorAnalysis）；语义错误分级（错误/警告/提示），错误带源码位置与修复建议

#### 阶段4：IR生成器（IR Generator）
- 输入：带类型标注的AST + 符号表
- 输出：CN-IR（静态单赋值形式 SSA）
- 职责：AST降级为CFG基本块、类型化指令生成、虚拟寄存器分配、SSA Phi节点构建、内存访问显式化（指针运算、结构体字段偏移计算）
- 关键设计：每个函数一个控制流图（CFG），指令三地址码形式，类型信息内嵌于每个虚拟寄存器

#### 阶段5：优化器（Optimizer）
- 输入：CN-IR（SSA形式）
- 输出：优化后的CN-IR
- 职责：常量传播、死代码消除、公共子表达式消除、循环优化（不变量外提/强度削减）、内联优化、尾调用优化、指令合并与简化
- 关键设计：优化级别 -O0（无优化，调试用）、-O1（基础优化）、-O2（默认，含循环优化）、-O3（激进优化，含内联）；每个优化Pass独立可插拔，支持打印Pass执行前后IR用于调试

#### 阶段6：代码生成器（Code Generator）
- 输入：优化后的CN-IR
- 输出：平台汇编文件（.asm）
- 职责：指令选择（IR指令映射为目标ISA指令）、寄存器分配（线性扫描/图着色）、指令调度、ABI调用约定处理（Win64/ARM64）、栈帧布局、虚函数表（vtable）生成、全局数据段（.data）与代码段（.text）生成
- 关键设计：后端抽象层（Backend接口）——IR指令通过目标描述文件（TD）映射，Win x64与Linux ARM64共享同一IR与优化器，仅代码生成后端不同；汇编输出经平台汇编器（MASM/GAS）与链接器（link/ld）生成可执行文件

## 七、CN-IR中间表示设计

### 7.1 设计目标
- **可移植性**：与目标平台无关，Win x64 与 Linux ARM64 共享同一 IR 与优化器
- **可优化性**：采用静态单赋值（SSA）形式，Phi 节点统一汇合点，便于数据流分析
- **可调试性**：IR 保留源码位置信息（文件/行/列），支持 -emit-ir 选项导出可读 IR 文本
- **类型化**：每个虚拟寄存器带类型标注，代码生成时无需回查符号表

### 7.2 IR 结构

```
模块(Module)
├── 全局变量表
├── 函数列表(Function)
│   ├── 函数签名（名称/参数/返回值/链接属性）
│   ├── 基本块列表(BasicBlock)
│   │   ├── 入口标签
│   │   ├── 指令序列(Instruction)
│   │   │   ├── 操作码
│   │   │   ├── 源操作数列表（虚拟寄存器/常量/全局符号）
│   │   │   ├── 目标虚拟寄存器
│   │   │   ├── 类型标注
│   │   │   └── 源码位置
│   │   └── 终止指令（跳转/条件跳转/返回/选择跳转表）
│   └── Phi 节点集合
└── 全局字符串常量池
```

### 7.3 指令分类

| 类别 | 指令 | 说明 |
|------|------|------|
| 算术 | 加/减/乘/除/取余 | 整型与浮点变体（加浮32/加浮64等） |
| 位运算 | 位与/位或/位异或/位非/左移/右移 | 整型专用 |
| 比较 | 相等/不等/小于/小于等于/大于/大于等于 | 结果为布尔，整型与浮点变体 |
| 逻辑 | 逻辑与/逻辑或/逻辑非 | 短路求值语义 |
| 内存 | 加载/存储/取地址 | 含原子性标注（预留） |
| 转换 | 扩展/截断/浮整转换/位重解释 | 显式类型转换 |
| 控制 | 跳转/条件跳转/返回/选择表跳转 | CFG 终止指令 |
| 调用 | 直接调用/间接调用（函数指针） | 含调用约定与返回约定标注 |
| 对象 | 虚调用/新建对象/删除对象/字段加载/字段存储 | OOP 相关，虚调用经 vtable 间接跳转 |
| 错误 | 结果构造/结果检查/可选构造/可选检查 | 错误处理类型降级 |

### 7.4 虚拟寄存器与 SSA

- 虚拟寄存器编号：`%v0`、`%v1`、`%v2`...
- 每个虚拟寄存器恰好赋值一次（SSA 性质）
- 汇合点使用 Phi 指令合并多个入边值
- 基本块 ID：`块0`、`块1`、`块2`...
- IR 文本示例：

```
函数 加(整32 %v0, 整32 %v1) -> 整32 {
块0:
    %v2 = 加 整32 %v0, %v1
    返回 %v2
}
```

### 7.5 类型表示

| IR类型 | 对应CN类型 | 大小 |
|--------|-----------|------|
| i8/i16/i32/i64/i128 | 整8/整16/整32/整64/整128 | 1/2/4/8/16字节 |
| u8/u16/u32/u64/u128 | 正8/正16/正32/正64/正128 | 1/2/4/8/16字节 |
| f32/f64 | 浮32/浮64 | 4/8字节 |
| i1 | 布尔 | 1字节 |
| ptr | 指针/字符串/字符* | 8字节（64位平台） |
| struct | 结构体/类 | 布局后大小 |
| void | 空类型 | 0字节 |

### 7.6 结果/可选类型降级约定
- `结果<正常, 错误>` 降级为 `结构体 { 布尔 是否正常; 联合体 { 正常类型 值; 错误类型 错误值 } }`
- `可选<类型>` 降级为 `结构体 { 布尔 是否某些; 类型 值 }`
- 检查成员 `.正常`/`.某些` 对应结构体首字段读取，未检查即访问 `.值` 由语义分析器在阶段3提前拦截
- **联合体仅用于编译器内部IR降级，源语言层面也可使用**（见3.5节复合类型定义）

## 八、代码生成

### 8.1 目标平台与ABI

| 目标 | 汇编器 | 链接器 | ABI规范 | 备注 |
|------|--------|--------|---------|------|
| Win x64 | MASM（ml64） | link.exe | Microsoft x64 ABI | 初期主目标 |
| Linux ARM64 | GNU as（GAS） | ld | AAPCS64 | 初期次目标 |
| Linux x64 | GNU as（GAS） | ld | System V AMD64 ABI | 预留 |
| macOS x64/ARM64 | 预留 | 预留 | Apple ABI | 预留 |

### 8.2 指令选择策略
- IR指令与目标指令的映射采用**模式匹配**：针对常见IR模式（如"加法+比较+条件跳转"）匹配目标平台的组合指令
- 乘除/取余等复杂运算：整型宽度 ≤ 64 位映射为原生指令；整128位宽用运行时辅助函数（如 `__cn_mul_i128`）模拟
- 浮点运算映射为SSE/NEON指令集指令

### 8.3 寄存器分配
- **Win x64**：采用线性扫描寄存器分配器（针对-O2），-O0/-O1时全栈帧分配（调试友好）
- 预留寄存器：`rbx/rbp/r12~r15` 为被调用者保存寄存器，`rax/rcx/rdx/r8~r11` 为调用者保存寄存器
- **Linux ARM64**：x19~x28为被调用者保存，x0~x18为调用者保存；浮点寄存器 d0~d31
- 溢出（spill）：临时值溢出到栈槽，栈帧统一管理
- **阶段C 实现（2026-08-14，Task 4.3/4.4）**：
  - 线性扫描寄存器分配器 `codegen/reg_alloc.cpp`：活跃区间计算（def-use + 跨块活跃传播）、
    区间按 start 线性扫描分配、溢出到栈槽
  - 仅对 **i64/u64/ptr** 虚拟寄存器参与分配（保守：浮点/i128/小位宽保持栈槽，避免与发射器宽度假设冲突）
  - 仅分配**被调用者保存寄存器**（x64 rbx/r12~r15；arm64 x19~x28），序言保存、尾声恢复
  - -O2 起启用（`--no-regalloc` 可关）；-O0/-O1 全栈帧不变
  - 调试信息 `codegen/debug_info.cpp`：汇编嵌入源码位置注释（`; src:` / `// src:`），
    DWARF 节生成接口预留（`mappings()` + `dwarfLineProgram()`）

### 8.4 栈帧布局（Win x64）

```
高地址
┌─────────────────────────┐
│ 返回地址（调用者压栈）      │
├─────────────────────────┤
│ 被调用者保存寄存器区        │
├─────────────────────────┤
│ 局部变量区（含溢出槽）      │
├─────────────────────────┤
│ 参数栈传递区（>4个参数）    │
├─────────────────────────┤
│ 影子空间（32字节，预留）    │
└─────────────────────────┘
低地址  ← rsp
```

### 8.5 调用约定
- 参数传递：前4个整型参数用 `rcx/rdx/r8/r9`，前4个浮点参数用 `xmm0~xmm3`（Win x64）
- 返回值：整型/指针用 `rax`，浮点用 `xmm0`
- 大于8字节的结构体：调用方在栈上分配并传入指针
- 栈对齐：调用前栈16字节对齐

### 8.6 OOP运行时布局
- 类实例布局：`[vtable指针 | 父类成员区 | 自身成员区]`（单继承）
- 虚函数表（vtable）：函数指针数组，子类重写时覆盖对应槽位；接口实现采用附加vtable（B1 全局槽位，P3-19 已实现：对象首 8 字节虚表指针后接接口分派区）。接口类型可作函数参数/返回（C2 多态传参，P3 收尾已锁定）；A1 同地址语义（值/指针零指针调整，经接口方法修改即写回原对象）。
- 构造/析构：构造函数返回对象指针；析构函数内联清理资源后调用父类析构
- **类→基类指针/引用隐式转换（234·2026-10-06 用户批准甲案·91303 采样实锤）**：派生类对象/指针可隐式转换为其基类链上任一祖先类的**指针或引用**形态——同地址语义（接口 A1 扩展：装的是原对象，零拷贝零指针调整；经基类引用修改即写回原对象）；经基类指针/引用调用虚拟函数按**动态类型虚表分派**（§5.6）；成员可见性按**静态类型**（基类）视角检查（保护/私有照常拦截）。**基类值形态编译期拒绝（防切片）**：值拷贝会截掉派生类字段（C++ 经典事故源），专用诊断提示改用基类指针/引用。〔基准=019 分层安全四条·悬垂/借用由既有编译期检查体系接管，零新增安全债〕

### 8.7 全局数据与字符串常量
- 全局变量进入 `.data`/`.bss` 段
- 字符串常量合并去重后进入 `.rdata`/`.rodata` 段
- 全局符号命名：源码中文符号经内部名字修饰（mangling）后生成唯一汇编符号，规则见附录C

### 8.8 汇编输出示例（Win x64）

```asm
; 函数 加(整32 a, 整32 b) -> 整32
.code
?加@@YAHHH@Z PROC
    ; prologue
    push    rbp
    mov     rbp, rsp
    ; 参数：ecx = a, edx = b
    mov     eax, ecx
    add     eax, edx
    ; epilogue
    pop     rbp
    ret
?加@@YAHHH@Z ENDP
END
```

## 九、优化器

### 9.1 优化级别

| 级别 | 说明 | 适用场景 |
|------|------|---------|
| -O0 | 无优化，全栈帧分配，保留调试信息 | 开发调试 |
| -O1 | 基础优化（常量折叠、死代码消除） | 快速构建 |
| -O2 | 默认级别，含循环优化与内联 | 生产发布 |
| -O3 | 激进优化，含激进内联与向量化预留 | 性能敏感场景 |

### 9.2 优化Pass清单

| Pass | 类别 | 说明 |
|------|------|------|
| 常量折叠与传播 | 基础 | 编译期常量计算与传播 |
| 死代码消除（DCE） | 基础 | 删除无副作用且结果未使用的指令 |
| 公共子表达式消除（CSE） | 基础 | 相同表达式复用 |
| 复写传播 | 基础 | 消除冗余复制指令 |
| 指令合并 | 基础 | 合并可组合指令 |
| 循环不变量外提（LICM） | 循环 | 将循环内不变量移到循环前 |
| 强度削减 | 循环 | 乘法/除法替换为移位/加法 |
| 循环展开（预留） | 循环 | 小循环体展开减少分支开销 |
| 函数内联 | 函数 | 小函数内联展开（启发式阈值） |
| 尾调用优化（TCO） | 函数 | 尾递归转为循环 |
| 选择表生成 | 控制 | 密集选择语句生成跳转表 |
| 空块合并 | 控制 | 合并空基本块、消除冗余跳转 |

### 9.3 Pass框架设计
- 每个Pass实现统一接口：`Pass::运行(IR模块) -> 是否修改`
- Pass管理器按依赖顺序调度，重复运行直至收敛（fixpoint）
- 每个Pass可通过 `-打印ir=pass名` 输出执行前后IR对比

> **栈溢出防线（错误码 9·〔476 收口·2026-10 立法补录〕）**：深度递归等耗尽线程栈时，
> CN 程序以**确定性失败**替代段错误脏崩（§1.1a② 兜底·Rust guard page 被动捕获同型）——
> stdout 打印 `运行时错误(错误码9): 栈溢出`（文案锚附录B 错误码 9 消息表；打印前先 flush
> 保住溢出前用户已缓冲的输出）后**退出码 1** 终止（对齐本表首行运行时错误契约）。
> - **防线性质=进程级信号兜底，非编译期插入检查**：运行时入口 `entry()` 启动时一次性安装，
>   **零热路径开销**（函数体内不插任何栈检查代码）。linux（x64/arm64）=SIGSEGV 处理器＋
>   `sigaltstack` 64KiB 备用栈（`SA_ONSTACK`——溢出信号必须在备用栈上处理；主线程用静态
>   备用栈，子线程由线程入口 trampoline 各自安装独立备用栈、随线程退出回收）；win=VEH/UEF
>   按 `EXCEPTION_STACK_OVERFLOW` 专用异常码拦截（处理器在内核提供的受控备用栈上执行退出，
>   无二次故障）。宿主与 v2 发射的程序共用同一运行时入口（双侧零分叉）。故本防线与
>   §1.1a④「不安全 函数=真零运行期检查」不冲突：④ 禁止的是**编译器向函数体插入运行期检查**，
>   本防线为进程级信号兜底（纵深防御面），**`不安全` 函数内同样生效**——信号兜底面向整个
>   进程，不区分安全区/不安全区代码。
> - **保证范围=「典型栈边界溢出形态」·指纹覆盖率<100%（宁漏勿误）**：linux 判据纯函数
>   `__cn_stack_overflow_match(故障地址, 故障时SP, si_code)` 三条件**全满足**才判栈溢出——
>   ① `si_code` ∈ {SEGV_MAPERR, SEGV_ACCERR}（地址类故障）；② 故障地址不高于故障时 SP 一页
>   （栈访问必在 SP 附近——压栈/帧内访问）；③ 故障地址不低于 SP 以下 64MiB（覆盖巨型栈帧；
>   空指针/野指针与 SP 相距地址空间级，由此排除）。win 侧 `EXCEPTION_STACK_OVERFLOW` 为栈
>   保护专用异常码，判定精确、无地址判定面。**指纹匹配不到=不拦截**：恢复平台默认崩溃行为
>   （linux 段错误 rc=139、win 常规崩溃路径），本防线对该形态**不作任何承诺**；备用栈或
>   处理器安装失败同样降级为无防护（宁缺毋误报）。E2E 锚=`tests/e2e/818_栈溢出确定性失败/`
>   （非尾递归深递归→错误码 9 rc=1＋健康深度对照防误伤·宿主+v2 双编译对照）。

> **扩展（2026-08 自举前置 C-1/C-3）：分配计数 + 进程竞技场**
> - `内存::活动分配数()` -> 整64：当前未释放块数（原子计数，泄漏检测基线）；
>   `内存::总分配次数()` -> 整64：累计分配次数。分配/释放/重新分配 全路径
>   计数（含字符串/时间/文件 API 内部 malloc，统一经计数辅助）。
> - `内存::竞技场分配(大小)` -> 空类型*：一次性进程竞技场 bump 分配（8 字节
>   对齐，块链 64KB，超块自动扩容）；`内存::竞技场重置()`：一次性释放全部块；
>   `内存::竞技场活动字节()` -> 整64：已分配总字节（含块头）。
>   适配编译器内存模式（长生命周期 + 一次分配）：自举源码无需逐对象释放，
>   杜绝泄漏/双重释放；智能指针可后置（plans/004 C 组判定）。

### 10.2b 线程备用栈安装 API（2026-10-14 登记实装面·任务 728k）

| API（运行时符号） | 说明 | 平台行为 |
|-------------------|------|---------|
| `cn_install_thread_stack_guard()` | 为**当前线程**安装栈溢出备用栈（476 防护的显式线程侧入口·§1.1a②） | linux=`sigaltstack` 安装本线程备用栈（每线程独立·pthread key 析构回收·重复调用=空操作）；win=空操作（VEH/UEF 进程级过滤器覆盖全部线程·x64 内核为栈溢出提供受控栈） |

> **用法（手工线程场景）**：经运行时创建线程（`线程::新`）由运行时 trampoline
> 自动安装，无需调用；用户以 FFI **绕过运行时**、手工 `pthread_create` 的线程——
> 须在**线程入口函数处显式调用一次**（CN 侧 FFI 形态：
> `外部 函数 cn_install_thread_stack_guard() -> 空类型`），否则该线程栈溢出时
> 信号处理器在耗尽栈上运行=二次故障（脏崩），476 的错误码 9 输出不成立。
> 安装后行为：该线程栈溢出 → 处理器在备用栈上判定 → `运行时错误(错误码9): 栈溢出`
> 确定性终止 rc=1。E2E 锚：929_手工线程栈守卫（双编译对照）。

### 10.3 字符串表示
- 字符串采用UTF-8编码，以`\0`结尾
- 字符串字面量在编译期进入只读数据段，字符串变量为指针
- 字符串连接等操作调用运行时API完成
- **拥有型字符串（2026-09-10 plans/019 阶段4' 方案A 用户裁决，替代 Task 2.8 值语义）**：
  `字符串` 局部变量为**拥有类型**——①字面量/标识符拷贝初始化经 `__cn_str_copy` 落堆
  （变量一律拥有堆串，Rust `"x".to_string()` 同款）；②赋值=free 旧值再拥有化新值
  （drop 旧+move 新）；③函数返回块自动注入 `__cn_str_free`（RAII 空安全；返回字符串
  变量=所有权移出跳过释放）；④`转移()` 零拷贝衔接（句柄直拷+源清零）；⑤裸指针视图
  用 `字符*`（FFI/只读降级）。**拥有判定白名单**（第一版）：字面量/标识符/内置分配族
  调用（复制/连接/拼接/子串/大写/小写/修剪/反转）；其余调用形态（`驻留文本` 返回驻留表
- **返回拥有契约（A2 2026-09-11 方案甲 用户批准）**：返回类型 `字符串`=拥有（调用方按返回类型登记 RAII 自动释放——用户函数返回堆串泄漏根治，Rust `fn f() -> String` 同款）；返回类型 `字符*`=借用（调用方零拷贝不释放，`&str` 同款）。返回位借用形态（参数直传/成员/下标/解引用/字符* 调用/全局静态）编译错误——须 字符串复制(...) 或改 字符* 返回。隐式转换收紧：拥有→借用自动；借用→拥有（字符* 初始化/赋值 字符串 变量）须显式 字符串复制(...)。返回 字符串 函数的字面量返回由编译器自动 copy 落堆。
  指针=借用、用户函数可能返回借用包装）整变量退出 RAII（宁可不自动释放保安全——
  用户函数返回拥有语义随第二批类型区分落地）。参数=借用（被调方不释放）；
  顶层静态字符串=只读语义不 RAII。
- **静态源拥有返回禁令（#1614·2026-10-26 用户批·甲案·1025 采样轮）**：函数返回
  类型=拥有契约；返回源为 全局/静态/类字段 的拥有型变量须显式 `字符串复制(...)`
  或借用类型——静态变量=借用语义，禁止隐式拷贝。函数内静态局部同受此约束
  （静态槽=静态存储期，拥有返回链会搬空槽——宿主修前产物实测输出 `AB/空/空`；
  判据=480 静态局部表，遮蔽语义 865-a 双侧同构），诊断名=解析期合成名
  `名$静态$函数名` 口径（双侧文案逐字一致·E2E 1566 负例固化/1567 正例对照
  ——`字符串复制(...)` 落堆与 `字符*` 借用视图两合法形态双侧绿）。
  本条执法面=字符串返回类型（`字符串`/`字符串&`）；容器/结构体/类 等拥有型
  返回的静态源泛化收口=#1636（双侧现状一致放行·容器面宿主运行崩溃实证）。
- **比较语义（Task 2.8·962 轮修订·用户裁决 2026-10-02）**：比较运算符
  （`==`/`!=`/`<`/`>`/`<=`/`>=`）定义于整型、浮点与**字符串**——字符串 `==`/`!=`
  为**内容比较**（等价 `字符串比较(a,b)`），`<`/`<=`/`>`/`>=` 为**字典序**
  （等价 `字符串字典序(a,b)` 与 0 比较）——对齐 Rust/Go/Python/C++ std::string
  主流语义（旧版「字符串不参与运算符比较」废止）；显式函数 `字符串比较`/
  `字符串字典序` **保留**（显式通道·泛型体内分派用）。判空 `s == 无` 走指针
  通道不受影响；`字符*×字符*` 维持真指针语义（比较地址）；地址/同一性判定
  收 `不安全` 域（内核::字符串同址·随需提供）。〔基准=019 第一句：默认路径
  零规则——「字符串不能用 ==」即一条必学规则，与基准冲突故立法〕
- **跨类型拼接语义（增强）**：`字符串 + 数值` 表达式触发隐式拼接——右操作数为整数/浮点/布尔/字符/枚举时，
  编译器自动插入 `整数转字符串`/`浮点转字符串`/`字符转字符串` 转换后再 `字符串连接`；
  布尔转换为 `"真"`/`"假"`。多操作数左结合：`"a" + 1 + 2` 等价 `(("a" + 1) + 2)`，结果为 `"a12"`。
  混合类型拼接结果由调用方负责 `字符串释放`。
- **字符串驻留（2026-08-25 用户批准，自举重建 P1；对标 rustc Symbol / LLVM StringPool）**：
  `驻留(字符串)` -> 整64：字符串内容加入全局驻留表并返回唯一整数 ID（Symbol）。
  相同内容返回同一 ID，字符串内容只存一份；`驻留文本(整64 ID)` -> 字符*：ID 反查文本（调试/错误消息；A2 2026-09-11 方案甲——驻留表指针=借用视图，持有须 字符串复制(...) 落堆）；`驻留计数()` -> 整64：驻留唯一内容数。
  驻留表生命周期为编译器进程级，不随 内存::释放全部() 释放（防 reset 破坏符号引用）。
  用途：Token/AST/IR/符号表文本字段一律用整型 ID（O(1) 比较/哈希），消除百万级重复字符串分配。
- **字符串构建器（2026-10-10 用户批准立法+立项实施·#366·Rust `String::push_str` 同款）**：
  字符串不可变，`字符串连接` 每次新分配+整串拷贝，拼接 k 段均摊 O(k²) 字节拷贝——
  循环/大批量拼接须走构建器：预分配缓冲+追加尾插（摊还倍增）+终态出串，一趟 O(L)。
  **内建层**（限定名直调·全局注册无需导入）：`字符串构建器::新建() -> 整64`（空缓冲，
  初始容量 64）；`字符串构建器::追加(整64 句柄, 字符串 段) -> 空类型`（尾插）；`字符串构建器::追加字节(整64 句柄, 整64 字节) -> 空类型`（单字节·取低 8 位，UTF-8 字节直通）；
  `字符串构建器::完成(整64 句柄) -> 字符串`（返回新分配串+释放缓冲）；
  `字符串构建器::弃置(整64 句柄) -> 空类型`（不取串仅释放——错误路径中途放弃防泄漏）。
  **stdlib 门面层**（`导入 字符串扩展::{...}` 纯名通道）：`字符串构建器新建/追加/追加字节/
  追加整数/完成/弃置` 与内建一一对应，另附 `字符串构建器追加整数` 便利函数（内部经
  `整数转字符串`，便利通道非性能通道）。
  **句柄契约**：句柄=整64 不透明值，完成/弃置后一次性（不可再用）；完成返回串所有权
  归调用方（RAII 自动释放）；追加均摊 O(段长)，完成 O(L)。示例：
  `整64 句 = 字符串构建器::新建(); 循环 (...) { 字符串构建器::追加(句, 段); }
  字符串 大串 = 字符串构建器::完成(句);`
  **用法警示（2026-10-14 补位·#728i）**：加号链 `甲 + 乙 + 丙`（编译为 `字符串连接` 逐段调用）
  仅适合**少量短拼接**；循环体内拼接与大段文本组装（段数 k 较大）一律走构建器——每次连接
  都是新分配+整串拷贝，k 段累计拷贝 O(k²) 字节（见本条上句「拼接 k 段均摊 O(k²) 字节拷贝」），
  k 稍大即数量级退化（b1 基准 8192 段≈1GB 拷贝实证·#366）。编译期不设性能诊断（静态不可知
  运行时循环规模与段长·误报噪音大于收益）=本警示为唯一提示通道：少量短链随意用加号，
  循环内/大段拼接必换构建器。

### 10.6 格式化与输入输出API

> **打印函数族（方案C 2026-08-14 ✅ 已修复）**：打印函数族**只有 `打印` / `打印行` 两个变参函数**（外加 `格式化`），

> - **"行" 的语义统一为：不追加换行符**（`打印行` 名称中"行"表示逐行连续输出语义）。
> - 遗留函数 `打印行整数(整64)`（`printf "%lld\n"`，换行）与 `打印行`（不换行）语义**恰好相反**，
>   造成命名二义性——已彻底删除，统一用变参 `打印`/`打印行` 表达：
>   `打印行整数(42)` → `打印(42)`（输出 `42\n`，换行行为完全一致）；
>   `打印行浮点(3.5)` → `打印(3.5)`（输出 `3.500000\n`）。
> - 整128/正128 打印同样由 `打印` 变参展开（`__cn_print_i128`/`__cn_print_u128`，完整128位）。

| API | 说明 | 对应C库 |
|-----|------|---------|
| 打印(任意值...) | 变参打印，`字符串 + 数值` 拼接或逐参展开为打印序列，末尾**自动换行** | printf（子集） + "\n" |
| 打印行(任意值...) | 同 `打印` 但末尾**不自动换行**（名称中"行"表示逐行连续输出语义，不追加换行符） | printf（子集） |
| 格式化(格式字符串, 参数...) | sprintf 风格格式化，返回新字符串（调用方释放） | sprintf |
| 读取行() | 从标准输入读取一行，返回字符串（不含换行，调用方释放） | fgets |
| 读取整数() / 读取浮点() | 从标准输入读取数值 | scanf（子集） |

> **`格式化()` 占位符**：`%d`（整型）、`%u`（无符号）、`%f`（浮点）、`%s`（字符串）、`%c`（字符）、`%x`/`%X`（十六进制）、`%o`（八进制）、`%p`（指针）。变参 ABI 在 IR 层展开为运行时 `__cn_format` 调用。

### 10.4 程序入口约定
- 入口函数名：`主`，签名：`函数 主() -> 整32`（返回0表示成功）
- **入口签名恒为无参**：带参偏离形态（如 C 风格 `主(整32 参数个数, 字符** 参数值)`）不合成匹配的无参入口符号 `cn_main`（编译器按无参约定合成、runtime 启动代码引用）——**链接期拒绝**（诊断「链接失败」）；宿主与 v2 自举链双侧同拒（2026-10-17 任务 974 补录·E2E 372 双编译对照锁面）。
- 运行时启动代码负责：初始化堆、调用全局构造器、调用`主`、传递返回值给操作系统
- 命令行参数经内置 `系统::参数个数`/`系统::参数` 获取（stdlib 系统模块；本节原「预留」带参形态表述以本条取代——现行口径=编译/链接期拒绝）

### 10.5 128位整数运算辅助
- 整128/正128的乘除取余等运算由运行时辅助函数实现
- 命名约定：`__cn_mul_i128`、`__cn_div_i128`、`__cn_div_u128` 等
- 与目标平台无关，统一用C++实现并随编译器分发

### 12.2 E2E测试原则（遵循项目规范）
- **E2E先行**：每个功能必须先写E2E测试，测试通过后才算完成
- **禁止.skip()**：所有测试必须真正运行，不使用跳过
- **真实配置**：所有测试使用真实配置，不使用Mock
- **渐进式**：分阶段实施，每阶段独立交付价值
- **全链路验证**：E2E测试必须通过真实编译流程（源文件 → cn编译 → 汇编 → 链接 → 运行 → 检查输出），禁止绕过生产代码直接实例化组件

### 附录B：错误码约定（结果<正常, 错误>的错误值）

| 错误码 | 含义 |
|--------|------|
| 1 | 除零错误 |
| 2 | 数组越界 |
| 3 | 空指针解引用 |
| 4 | 内存分配失败 |
| 5 | 文件打开失败 |
| 6 | 无效参数 |
| 7 | 资源未初始化 |
| 8 | 溢出错误 |
| 9 | 栈溢出（典型栈边界溢出形态·指纹匹配判据·未命中不拦截——详见 §10.2a 栈溢出防线〔476 收口·2026-10 立法补录〕；不经 `结果` 通道返回·不入 `核心错误码` 枚举——2026-10-17 用户裁决） |

> **错误码 4（内存分配失败）的处置语义〔#1012 批甲·2026-10-29 用户裁决〕**：运行期任何内存
> 分配失败（字符串族/竞技场/构建器缓冲等运行时分配点）= **打印诊断后立即终止程序**
> （`__cn_runtime_error(4)`·退出码 4）——**不以空指针/空句柄哨兵返回**、不进入 `结果` 通道、
> 不存在「调用方处理分配失败」的合法程序形态。理由：分配失败是机器级资源异常而非业务
> 分支（与 Rust 分配失败 abort 同构）；运算符形态（`a + b`）无失败处理语法位；「下游记得
> 检查」依赖人工纪律无机械保证（违反「禁止静默错误/禁止兜底」）。谓词与业务失败（如文件
> 打开失败=错误码 5）不属此条——业务失败仍走各自显式通道。

**入口函数返回 `结果<T, 整32>` 的进程退出码（2026-09-16 新增·246-a 用户裁决·Rust Termination 同构）：**

- `主` 返回 `结果<整32, E>`（E 为整型）时：正常 → 退出码取 `.值`（截断为 int）；错误 → 退出码取 `.错误` 码
- 与运行时错误码（上表）同一契约——用户态与运行态退出码语义全线统一
- 实现方式：编译器自动合成整32 包装入口（调 主 后按分支取值），调用约定与运行时入口对齐
- 其他聚合类型（可选/结构体等）与 `.值` 非数值的 `结果` 暂不支持（编译期诊断——退出码语义待规范定义）

### 附录C：名字修饰规则（mangling）
- 源码中文符号名统一转换为 UTF-8 字节序列的十六进制编码，前缀 `?`，后缀按函数签名编码
- 全局变量：`?变量名@@3A` 形式
- 函数：`?函数名@@Y<返回编码><参数编码>@Z` 形式（Win x64 MSVC风格）
- 静态/局部符号：模块内唯一即可，不参与全局修饰
- 设计目标：保证同名不同签名的函数可共存（重载支持），避免符号冲突
