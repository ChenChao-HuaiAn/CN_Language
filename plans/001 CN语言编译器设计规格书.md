# CN语言编译器设计规格书

> 版本：v1.0  
> 日期：2026-08-12  
> 状态：待审批  
> 基准：以本规格书定义的语法风格为准，参考C++编程范式，用C++从零编写编译器

## 一、语言设计概述

### 1.1 语言定位
CN语言是一门全中文语法的系统级编程语言，参考C++的编程范式，面向需要底层控制力的应用场景。语言设计遵循"中文优先、手动控制、零成本抽象"的原则。

### 1.2 设计决策汇总

| # | 决策项 | 确认结果 |
|---|--------|---------|
| 1 | 语法基准 | 以本规格书定义的语法风格为准，Rust参考仅作技术借鉴 |
| 2 | 编译器实现 | 从零用C++重写，不依赖现有C代码 |
| 3 | 代码生成后端 | 直接生成汇编代码，无外部依赖 |
| 4 | 目标平台 | 设计考虑全平台，初期实现 Win x64 + Linux ARM64 |
| 5 | 内存管理 | 指针+手动内存管理（malloc/free式），运行时API |
| 6 | 错误处理 | 错误码+可选值，去掉异常关键字，语法风格参照本规格书 |
| 7 | OOP | 完整保留（类/接口/继承/保护/虚拟/重写/抽象/实现/自身/父类） |
| 8 | 模块系统 | **v2.0**：文件即模块 + 包=crate，`导入`/`模块`/`作为`/`包`/`货舱`，`::` 路径，导入全形式（花括号/通配符/重命名），公开:/私有:标签式 + **默认私有** + 可见性交集 |
| 9 | 构建系统 | CMake |
| 10 | 编译器架构 | 方案C（多趟+自定义IR），包含IR层和优化器 |
| 11 | 开发路径 | 参考 Rust参考/003 路线图，直到自举 |
| 12 | 类型命名 | 中文位宽命名（整8/正8/整16/正16...整128/正128/浮32/浮64） |
| 13 | 字面量增强 | 增加Unicode字符转义、原始字符串、多行字符串（不增加数字下划线） |

> **重要：本规格书为编译器实现的唯一基准文档。**

### 3.6B 类型大小 内建（2026-08，A-3）

```
类型大小(类型)    // 编译期字节数常量（整64），C++ sizeof 等价物
```
> **内建表达式而非函数**：编译器直接求值，不产生调用、不可取地址、不可作函数指针；参数可为基础类型/结构体/数组/指针/限定类型/泛型参数（按实例化实参求值）。典型用途：容器按元素真实大小分配（`容量 * 类型大小(T)`）。

### 3.7 隐式类型转换

- 字符 ↔ 整数
- 字符* ↔ 字符串
- 字符串 ↔ 字符*
- 空类型* ↔ 任意指针
- 整数 -> 整64（宽化）
- 浮32 -> 浮64（宽化）
- **数值 -> 字符串（仅 `+` 拼接上下文）**：当 `+` 左操作数为 `字符串`/`字符*` 时，右操作数为整数/浮点/布尔/字符/枚举，自动隐式转换为字符串后再拼接（等价于 `整数转字符串/浮点转字符串/字符转字符串` 运行时转换）。布尔转换结果为 `"真"`/`"假"`。此转换**仅**在字符串拼接语境触发，不参与其他算术/比较上下文。

## 四、词法结构

### 4.1 源文件
- 扩展名：.cn
- 编码：UTF-8（必须）
- 入口文件：主.cn
- **说明：入口文件命名为 `主.cn` 仅为约定，其内部须定义 `主` 函数作为程序入口。文件名与函数名无强制绑定关系。**

### 4.2 注释
- `//` 单行注释
- `/* */` 块注释（支持嵌套）

### 4.3 字面量

**整数字面量：**
- 十进制：`42`
- 十六进制：`0xFF`
- 二进制：`0b1010`
- 八进制：`0o777`
- 类型后缀与中文位宽类型的映射：
  - `f` -> 浮点（浮32）
  - `L` -> 整64
  - `LL` -> 整128
  - `U` -> 正32
  - `UL` -> 正64
  - `ULL` -> 正128
- 不支持数字下划线分隔

**浮点字面量：**
- 小数形式：`3.14`
- 科学计数法：`1.5e10`

**字符字面量：**
- 普通字符：`'A'`、`'中'`
- 转义字符：`'\n'`、`'\t'`、`'\0'`
- Unicode转义（新增）：`'\u{4E2D}'`（等同于'中'）

**字符串字面量：**
- 普通字符串：`"你好"`
- 原始字符串（新增）：`原始"^\d+\.\d+$"`（反斜杠不需转义）
- 多行字符串（新增）：`多行"""第一行\n第二行\n第三行"""`
- 转义语义规则：多行字符串内部仍处理 `\n`、`\t` 等转义字符。如需完全原始的多行文本，可组合使用 `原始` 和 `多行` 前缀：`原始多行"""..."""`

### 4.4 运算符

**算术运算符：** `+` `-` `*` `/` `%`
**比较运算符：** `==` `!=` `<` `>` `<=` `>=`
**逻辑运算符：** `&&` `||` `!`
**位运算符：** `&` `|` `^` `~` `<<` `>>`
**赋值运算符：** `=` `+=` `-=` `*=` `/=` `%=` `&=` `|=` `^=` `<<=` `>>=`
**指针运算符：** `&`（取地址）`*`（解引用）`->`（成员访问）
**其他：** `.`（成员访问）`[]`（下标）
**条件运算符（三元）：** `条件 ? 真值 : 假值`（右结合，惰性求值，仅对选中分支求值）

> **成员包含判断使用标准库函数 `包含()` 而非运算符**（如 `表.包含(键)`），"在"不是运算符。

> **运算符重载**：类/结构体可定义成员 `函数 运算符X(参数) -> 返回类型` 自定义运算符语义（`X` ∈ `+ - * / % == != < > <= >= && || ! & | ^ ~ << >> [] () ->`）。重载决议规则：① 优先精确匹配内置运算符；② 无内置匹配时按左操作数类型查找成员 `运算符X`；③ 仍无匹配则报"类型不兼容"错误。字符串 `+` 拼接由编译器隐式调用 `整数转字符串/浮点转字符串/字符转字符串` 转换 + `字符串连接` 实现，无需用户重载。

### 4.5 运算符优先级（13级，从高到低）

| 优先级 | 运算符 | 说明 |
|--------|--------|------|
| 13（最高） | `()` `[]` `.` `->` `?`（后缀错误传播，2026-08 C-1） | 后缀 |
| 12 | `!` `~` `-`（负）`*`（解引用）`&`（取地址） | 一元 |
| 11 | `*` `/` `%` | 乘除 |
| 10 | `+` `-` | 加减 |
| 9 | `<<` `>>` | 移位 |
| 8 | `<` `<=` `>` `>=` | 比较 |
| 7 | `==` `!=` | 相等 |
| 6 | `&` | 按位与 |
| 5 | `^` | 按位异或 |
| 4 | `|` | 按位或 |
| 3 | `&&` | 逻辑与 |
| 2 | `||` | 逻辑或 |
| 1.5 | `条件 ? 真值 : 假值` | 三元条件（右结合） |
| 1（最低） | `=` `+=` `-=` 等 | 赋值 |

### 4.6 语句终止与续行

> **核心事实：CN 语言的语句既不是"换行结尾"也不是"分号结尾"。换行（`\n`/`\r`）在词法层与空格、Tab 一样被当作空白直接跳过，不产生换行 token，因此换行没有语法意义，等同空格。语句的真正边界由"表达式自然解析停止 + 下一条语句的起始关键字"识别。**

#### 4.6.1 三层机制

| 层 | 行为 | 判定位置 |
|----|------|---------|
| 词法层 | 换行 `\n`/`\r` 与空格、Tab 完全当作空白跳过，不产生换行 token | 词法分析器（换行无语法意义，等同空格） |
| 语法层 | 分号 `;` 是**可选**终止符："有就吃、没有不报错" | 语法分析器 `consumeSemicolon()` |
| 边界识别 | 语句结束靠"表达式自然解析停止 + 下一条语句起始关键字（返回/如果/当/循环/中断/继续/变量/常量/静态/类型关键字）" | 语法分析器 `parseStmt()` |

#### 4.6.2 EBNF

```
语句 = 表达式语句 | 声明语句 | 控制流语句 | 返回语句 | ...
      [";"]                            // 分号可选，有就吃、没有不报错
```

#### 规则1：语句终止（无终止符 + 可选分号 + 关键字边界）

- 语句**无需终止符**，分号 `;` 可选（兼容 C 习惯写法，如 `变量 a = 1;`）
- 语句边界由"下一条语句起始关键字/类型关键字"识别
- 无分号时依赖关键字边界，`变量 x = 1 整32 y = 2` 合法（`整32` 触发新声明）

#### 规则2：续行（换行≡空格，天然无条件续行）

- 换行无语法意义，**任何位置换行都天然续行**，不存在"括号未闭合才可续行"的限制
- 括号 `()`/`[]`/`{}` 未闭合时跨行是**结构上安全**的（函数调用参数、下标、表达式分组天然粘合）

> ⚠️ **警告：行首运算符会被并入上一行**。因为换行≡空格，`返回 a` 换行 `- b` 实际解析为 `返回 a - b`（与 C 语言行首续行效果相同但无文档说明）。建议跨行书写长表达式时把二元运算符留在**行尾**（`a +` 换行 `b`）而非行首，避免歧义。

#### 规则3：单行多语句（显式分号支持）

- 显式 `;` 分隔多条语句是**稳定支持**的：`变量 i = 0; ++i; --i;` 合法
- 无分号依赖关键字边界是**偶然可行但未定义**，规范建议统一使用分号表达单行多语句

#### 规则4：空语句与空循环体（裸分号非法）

- 裸 `;` 作为空语句**不合法**（报"预期表达式"），CN 语言没有空语句
- 连续分号 `;;` 会报错
- `当(x);` 是**语法错误**（循环体强制要求 `{`），合法空循环体写 `当(x) { }`（空块合法）
- 循环头 `循环(整32 j = 0; j < 10; j++)` 中的分号是**唯一强制分号**（三段分隔符，缺了报错）

#### 示例代码

```
变量 a = 1;        // 分号可选（C 习惯）
变量 b = 2         // 无分号合法
变量 x = 1 整32 y = 2   // 合法：整32 触发新声明 y

变量 i = 0; ++i; --i;    // 单行多语句：显式分号分隔（稳定支持）

// 推荐：跨行书写长表达式时二元运算符留在行尾
变量 总和 = a +
           b +
           c

当(x) { }        // 合法：空循环体（空块）
// 当(x);        // ❌ 语法错误：循环体强制要求 {
// ;             // ❌ 错误：空语句非法（预期表达式）
// ;;            // ❌ 错误：连续分号

循环(整32 j = 0; j < 10; j++) {   // 分号是唯一强制分号（三段分隔符）
    打印行(j)
}
```

> **注意**：循环头 `循环(初始化; 条件; 更新)` 中的两个分号是语法必需的分隔符，与语句终止符无关；缺失任何一段都会报错。

## 五、语法规范

### 5.1 程序结构

```
程序 = 顶层声明*
顶层声明 = 函数声明 | 结构体声明 | 枚举声明 | 类声明 | 接口声明 | 导入声明 | 全局变量声明
```

### 5.2 变量声明（类型前置）

```
变量 x = 10           // 类型推断
整数 y = 20           // 显式类型
整32 z = 30           // 位宽类型
常量 PI = 3.14        // 常量
静态 整32 计数 = 0    // 静态变量
```

### 5.3 函数定义

```
函数 加(整32 a, 整32 b) -> 整32 {
    返回 a + b
}

// 无返回值时省略 -> 类型
函数 打印问候() {
    打印行("你好")
}

// 函数原型声明（前向引用）
函数 计算(整32 n) -> 整32
```

#### 函数重载

```
函数 加(整32 a, 整32 b) -> 整32 { 返回 a + b }
函数 加(浮64 a, 浮64 b) -> 浮64 { 返回 a + b }
函数 加(字符串 a, 字符串 b) -> 字符串 { 返回 a + b }
```
> 同名函数按**参数类型与个数**区分（重载决议）；仅返回类型不同不构成重载。名称修饰（mangling）按签名编码（规格书附录C）。

#### 默认参数

```
函数 问候(字符串 名字 = "世界") -> 空类型 {
    打印行("你好，" + 名字)
}
问候()          // 你好，世界
问候("张三")    // 你好，张三
```
> 默认参数从右向左连续声明；调用时按位置补缺省实参；默认参数在原型声明中给出（避免重复）。

#### lambda 表达式（匿名函数）

```
自动 加倍 = [](整32 x) -> 整32 { 返回 x * 2 }
整32 结果 = 加倍(21)   // 42
```
> lambda 支持 `[捕获]`（`[]` 不捕获 / `[=]` 值捕获 / `[&]` 引用捕获 / `[变量]` 显式捕获）；无返回类型标注时由编译器推导（单一 `返回` 表达式或空类型）。

#### 强制类型转换

```
浮64 比例 = 浮64(3) / 4        // 显式转浮点
整32 截断 = 整32(3.99)         // 浮点转整（截断）
指针 原始 = 指针(地址)          // 整数转指针
整64 地址 = 整64(指针)          // 指针转整数
```
> 提供 C 风格构造转换 `类型名(表达式)`，语义同 static_cast/位重解释组合；宽化/窄化/浮整转换/指针↔整数 均显式触发，避免隐式危险转换。

#### 引用参数（2026-08，A-1）

```
函数 交换(整32& a, 整32& b) -> 空类型 {
    整32 临时 = a
    a = b
    b = 临时
}

泛型 <类型 T>
函数 引用交换(T& a, T& b) -> 空类型 {
    T 临时 = a
    a = b
    b = 临时
}
```
> `类型& 参数名` 为引用参数（C++ 引用语义）：实参传左值地址，读取自动解引用、赋值经指针写回调用方；引用仅支持函数参数（含泛型 `T&`），引用变量声明/引用返回/引用默认值编译报错；实参须为左值；支持友元引用参数访问私有成员。规格详见 cn-language-spec 04-一F。

#### 外部 函数 声明（FFI，2026-08，C-3）

```
外部 函数 strlen(字符串 s) -> 整64
外部 函数 toupper(整32 c) -> 整32
外部 函数 GetTickCount64() -> 正64
```
> FFI 最小集：声明 C 链接外部函数（无函数体），链接符号 = 函数名本身（无重载 mangling/模块前缀）；声明带函数体报错；同名同签名重复声明允许（C 语义）；附加链接库用 `--链接 <库>`（别名 `--link-lib`）。规格详见 cn-language-spec 04-一G。

### 5.4 错误处理（替代异常）

```
// 结果类型：正常返回值 或 错误码
函数 除法(整32 a, 整32 b) -> 结果<整32, 整32> {
    如果 b == 0 {
        返回 错误(1)  // 错误码1: 除零错误
    }
    返回 正常(a / b)
}

// 使用时检查
除法结果 = 除法(10, 0)
如果 除法结果.正常 {
    打印行(除法结果.值)
} 否则 {
    打印行("除零错误: ", 除法结果.错误)
}

// 可选类型
函数 查找(整32 键) -> 可选<整32> {
    如果 表.包含(键) {
        返回 某些(表[键])
    }
    返回 无
}
```

> **注意：所有关键字均为保留字，不可用作标识符。**

**内置构造器身份说明：** `正常()`、`错误()`、`某些()` 为内置构造器函数，由编译器预置符号表，非保留关键字，用户不可重定义。

#### 结果/可选强制检查规则
- 规则1：`结果<T,E>` 类型的返回值如果不被检查就丢弃，编译器报**错误**
- 规则2：检查 `结果.正常` 后未处理错误分支，编译器报**警告**
- 规则3：`可选<T>` 类型的值在访问 `.值` 前必须检查 `.有值`，否则编译器报**错误**

#### 错误传播运算符 表达式?（2026-08，C-1）

```
函数 安全除法(整32 a, 整32 b) -> 结果<整32, 整32> {
    如果 b == 0 { 返回 错误(1) }
    返回 正常(a / b)
}

// 传播：正常取 .值，失败沿调用链上抛（Rust ? 同语义）
函数 除法传播(整32 a, 整32 b) -> 结果<整32, 整32> {
    整32 商 = 安全除法(a, b)?
    返回 正常(商)
}
```
> 后缀 `?` 错误传播（优先级13，与三元 `?` 按后随 token 区分）：操作数须为 `结果<T,E>`/`可选<T>`，正常/有值 → 取 .值；失败 → 构造错误结果并从当前函数返回。当前函数返回类型须兼容（结果值类型 T 精确一致、错误类型 E 可转换；可选 T 一致）。规格详见 cn-language-spec 07-一B。

}

// 遍历...中每个 迭代（2026-08，C-2，对标 C++ range-for）

遍历 数据 中 每个 x {

}
向量<整32> 数表 = 向量<整32>()

| 模块公开 | 类内公开 | ✅ | ✅ | ✅ |
| 模块公开 | 类内私有 | ✅ | ❌ | ❌ |
| 模块私有 | 类内公开 | ✅ | ❌ | ❌ |
| 模块私有 | 类内私有 | ✅ | ❌ | ❌ |

## 六、编译器架构

### 6.1 编译流水线总览

```
CN源代码(.cn)
    │
    ▼
词法分析器(Lexer) -> Token流
    │
    ▼
语法分析器(Parser) -> AST树
    │
    ▼
语义分析器(Semantic) -> 带类型AST + 符号表
    │
    ▼
IR生成器(IRGenerator) -> CN-IR
    │
    ▼
优化器(Optimizer) -> 优化后的CN-IR
    │
    ├─────────────┐
    ▼             ▼
Win x64 Codegen  Linux ARM64 Codegen
    │             │
    ▼             ▼
.asm文件        .asm文件
    │             │
    ▼             ▼
汇编器+链接器 -> 可执行文件
```

### 6.2 各阶段职责

#### 阶段1：词法分析器（Lexer）
- 输入：.cn源文件（UTF-8编码）
- 输出：Token流
- 职责：UTF-8中文字符识别、字面量解析、运算符与分隔符识别、注释剥离、行号/列号追踪
- 关键设计：中文关键字最长匹配，关键字后必须有空格或符号分隔

#### 阶段2：语法分析器（Parser）
- 输入：Token流
- 输出：AST
- 职责：递归下降解析、运算符优先级处理（Pratt parser）、AST节点构建、语法错误报告
- 关键设计：两趟解析——第一趟收集顶层声明，第二趟解析函数体，支持前向引用

#### 阶段3：语义分析器（Semantic Analyzer）
- 输入：AST
- 输出：带类型标注的AST + 全局符号表
- 职责：符号表构建与作用域管理、类型检查与推断、隐式类型转换验证、继承与接口实现验证、函数重载解析、错误码传播分析（结果/可选强制处理）、常量折叠预计算
- 关键设计：分模块语义分析——名称解析模块（NameResolution）、类型检查模块（TypeChecker）、OOP验证模块（OOPValidator）、错误码分析模块（ErrorAnalysis）；语义错误分级（错误/警告/提示），错误带源码位置与修复建议

#### 阶段4：IR生成器（IR Generator）
- 输入：带类型标注的AST + 符号表
- 输出：CN-IR（静态单赋值形式 SSA）
- 职责：AST降级为CFG基本块、类型化指令生成、虚拟寄存器分配、SSA Phi节点构建、内存访问显式化（指针运算、结构体字段偏移计算）
- 关键设计：每个函数一个控制流图（CFG），指令三地址码形式，类型信息内嵌于每个虚拟寄存器

#### 阶段5：优化器（Optimizer）
- 输入：CN-IR（SSA形式）
- 输出：优化后的CN-IR
- 职责：常量传播、死代码消除、公共子表达式消除、循环优化（不变量外提/强度削减）、内联优化、尾调用优化、指令合并与简化
- 关键设计：优化级别 -O0（无优化，调试用）、-O1（基础优化）、-O2（默认，含循环优化）、-O3（激进优化，含内联）；每个优化Pass独立可插拔，支持打印Pass执行前后IR用于调试

#### 阶段6：代码生成器（Code Generator）
- 输入：优化后的CN-IR
- 输出：平台汇编文件（.asm）
- 职责：指令选择（IR指令映射为目标ISA指令）、寄存器分配（线性扫描/图着色）、指令调度、ABI调用约定处理（Win64/ARM64）、栈帧布局、虚函数表（vtable）生成、全局数据段（.data）与代码段（.text）生成
- 关键设计：后端抽象层（Backend接口）——IR指令通过目标描述文件（TD）映射，Win x64与Linux ARM64共享同一IR与优化器，仅代码生成后端不同；汇编输出经平台汇编器（MASM/GAS）与链接器（link/ld）生成可执行文件

## 七、CN-IR中间表示设计

### 7.1 设计目标
- **可移植性**：与目标平台无关，Win x64 与 Linux ARM64 共享同一 IR 与优化器
- **可优化性**：采用静态单赋值（SSA）形式，Phi 节点统一汇合点，便于数据流分析
- **可调试性**：IR 保留源码位置信息（文件/行/列），支持 -emit-ir 选项导出可读 IR 文本
- **类型化**：每个虚拟寄存器带类型标注，代码生成时无需回查符号表

### 7.2 IR 结构

```
模块(Module)
├── 全局变量表
├── 函数列表(Function)
│   ├── 函数签名（名称/参数/返回值/链接属性）
│   ├── 基本块列表(BasicBlock)
│   │   ├── 入口标签
│   │   ├── 指令序列(Instruction)
│   │   │   ├── 操作码
│   │   │   ├── 源操作数列表（虚拟寄存器/常量/全局符号）
│   │   │   ├── 目标虚拟寄存器
│   │   │   ├── 类型标注
│   │   │   └── 源码位置
│   │   └── 终止指令（跳转/条件跳转/返回/选择跳转表）
│   └── Phi 节点集合
└── 全局字符串常量池
```

### 7.3 指令分类

| 类别 | 指令 | 说明 |
|------|------|------|
| 算术 | 加/减/乘/除/取余 | 整型与浮点变体（加浮32/加浮64等） |
| 位运算 | 位与/位或/位异或/位非/左移/右移 | 整型专用 |
| 比较 | 相等/不等/小于/小于等于/大于/大于等于 | 结果为布尔，整型与浮点变体 |
| 逻辑 | 逻辑与/逻辑或/逻辑非 | 短路求值语义 |
| 内存 | 加载/存储/取地址 | 含原子性标注（预留） |
| 转换 | 扩展/截断/浮整转换/位重解释 | 显式类型转换 |
| 控制 | 跳转/条件跳转/返回/选择表跳转 | CFG 终止指令 |
| 调用 | 直接调用/间接调用（函数指针） | 含调用约定与返回约定标注 |
| 对象 | 虚调用/新建对象/删除对象/字段加载/字段存储 | OOP 相关，虚调用经 vtable 间接跳转 |
| 错误 | 结果构造/结果检查/可选构造/可选检查 | 错误处理类型降级 |

### 7.4 虚拟寄存器与 SSA

- 虚拟寄存器编号：`%v0`、`%v1`、`%v2`...
- 每个虚拟寄存器恰好赋值一次（SSA 性质）
- 汇合点使用 Phi 指令合并多个入边值
- 基本块 ID：`块0`、`块1`、`块2`...
- IR 文本示例：

```
函数 加(整32 %v0, 整32 %v1) -> 整32 {
块0:
    %v2 = 加 整32 %v0, %v1
    返回 %v2
}
```

### 7.5 类型表示

| IR类型 | 对应CN类型 | 大小 |
|--------|-----------|------|
| i8/i16/i32/i64/i128 | 整8/整16/整32/整64/整128 | 1/2/4/8/16字节 |
| u8/u16/u32/u64/u128 | 正8/正16/正32/正64/正128 | 1/2/4/8/16字节 |
| f32/f64 | 浮32/浮64 | 4/8字节 |
| i1 | 布尔 | 1字节 |
| ptr | 指针/字符串/字符* | 8字节（64位平台） |
| struct | 结构体/类 | 布局后大小 |
| void | 空类型 | 0字节 |

### 7.6 结果/可选类型降级约定
- `结果<正常, 错误>` 降级为 `结构体 { 布尔 是否正常; 联合体 { 正常类型 值; 错误类型 错误值 } }`
- `可选<类型>` 降级为 `结构体 { 布尔 是否某些; 类型 值 }`
- 检查成员 `.正常`/`.某些` 对应结构体首字段读取，未检查即访问 `.值` 由语义分析器在阶段3提前拦截
- **联合体仅用于编译器内部IR降级，源语言层面也可使用**（见3.5节复合类型定义）

### 8.1 目标平台与ABI

| 目标 | 汇编器 | 链接器 | ABI规范 | 备注 |
|------|--------|--------|---------|------|
| Win x64 | MASM（ml64） | link.exe | Microsoft x64 ABI | 初期主目标 |
| Linux ARM64 | GNU as（GAS） | ld | AAPCS64 | 初期次目标 |
| Linux x64 | GNU as（GAS） | ld | System V AMD64 ABI | 预留 |
| macOS x64/ARM64 | 预留 | 预留 | Apple ABI | 预留 |

### 8.2 指令选择策略
- IR指令与目标指令的映射采用**模式匹配**：针对常见IR模式（如"加法+比较+条件跳转"）匹配目标平台的组合指令
- 乘除/取余等复杂运算：整型宽度 ≤ 64 位映射为原生指令；整128位宽用运行时辅助函数（如 `__cn_mul_i128`）模拟
- 浮点运算映射为SSE/NEON指令集指令

### 8.3 寄存器分配
- **Win x64**：采用线性扫描寄存器分配器（针对-O2），-O0/-O1时全栈帧分配（调试友好）
- 预留寄存器：`rbx/rbp/r12~r15` 为被调用者保存寄存器，`rax/rcx/rdx/r8~r11` 为调用者保存寄存器
- **Linux ARM64**：x19~x28为被调用者保存，x0~x18为调用者保存；浮点寄存器 d0~d31
- 溢出（spill）：临时值溢出到栈槽，栈帧统一管理
- **阶段C 实现（2026-08-14，Task 4.3/4.4）**：
  - 线性扫描寄存器分配器 `codegen/reg_alloc.cpp`：活跃区间计算（def-use + 跨块活跃传播）、
    区间按 start 线性扫描分配、溢出到栈槽
  - 仅对 **i64/u64/ptr** 虚拟寄存器参与分配（保守：浮点/i128/小位宽保持栈槽，避免与发射器宽度假设冲突）
  - 仅分配**被调用者保存寄存器**（x64 rbx/r12~r15；arm64 x19~x28），序言保存、尾声恢复
  - -O2 起启用（`--no-regalloc` 可关）；-O0/-O1 全栈帧不变
  - 调试信息 `codegen/debug_info.cpp`：汇编嵌入源码位置注释（`; src:` / `// src:`），
    DWARF 节生成接口预留（`mappings()` + `dwarfLineProgram()`）

### 8.4 栈帧布局（Win x64）

```
高地址
┌─────────────────────────┐
│ 返回地址（调用者压栈）      │
├─────────────────────────┤
│ 被调用者保存寄存器区        │
├─────────────────────────┤
│ 局部变量区（含溢出槽）      │
├─────────────────────────┤
│ 参数栈传递区（>4个参数）    │
├─────────────────────────┤
│ 影子空间（32字节，预留）    │
└─────────────────────────┘
低地址  ← rsp
```

### 8.5 调用约定
- 参数传递：前4个整型参数用 `rcx/rdx/r8/r9`，前4个浮点参数用 `xmm0~xmm3`（Win x64）
- 返回值：整型/指针用 `rax`，浮点用 `xmm0`
- 大于8字节的结构体：调用方在栈上分配并传入指针
- 栈对齐：调用前栈16字节对齐

### 8.6 OOP运行时布局
- 类实例布局：`[vtable指针 | 父类成员区 | 自身成员区]`（单继承）
- 虚函数表（vtable）：函数指针数组，子类重写时覆盖对应槽位；接口实现采用附加vtable（预留）
- 构造/析构：构造函数返回对象指针；析构函数内联清理资源后调用父类析构

### 8.7 全局数据与字符串常量
- 全局变量进入 `.data`/`.bss` 段
- 字符串常量合并去重后进入 `.rdata`/`.rodata` 段
- 全局符号命名：源码中文符号经内部名字修饰（mangling）后生成唯一汇编符号，规则见附录C

### 8.8 汇编输出示例（Win x64）

```asm
; 函数 加(整32 a, 整32 b) -> 整32
.code
?加@@YAHHH@Z PROC
    ; prologue
    push    rbp
    mov     rbp, rsp
    ; 参数：ecx = a, edx = b
    mov     eax, ecx
    add     eax, edx
    ; epilogue
    pop     rbp
    ret
?加@@YAHHH@Z ENDP
END
```

### 9.2 优化Pass清单

| Pass | 类别 | 说明 |
|------|------|------|
| 常量折叠与传播 | 基础 | 编译期常量计算与传播 |

| 公共子表达式消除（CSE） | 基础 | 相同表达式复用 |
| 复写传播 | 基础 | 消除冗余复制指令 |
| 指令合并 | 基础 | 合并可组合指令 |
| 循环不变量外提（LICM） | 循环 | 将循环内不变量移到循环前 |

| 尾调用优化（TCO） | 函数 | 尾递归转为循环 |
| 选择表生成 | 控制 | 密集选择语句生成跳转表 |

### 9.3 Pass框架设计
- 每个Pass实现统一接口：`Pass::运行(IR模块) -> 是否修改`

- 每个Pass可通过 `-打印ir=pass名` 输出执行前后IR对比
- 优化前后正确性验证（预留）：`-验证-ir` 检查SSA性质不变量（支配关系、Phi节点合法性）

## 十、运行时设计

### 10.1 运行时库结构

```
cnrt（CN Runtime）
├── 内存管理：分配/释放/重新分配/复制
├── 字符串操作：长度/比较/连接/复制/查找
│   （Task 2.8 补充：子串/字典序/大小写/前缀/后缀/包含/修剪/反转/
│     整数转字符串/浮点转字符串/字符转字符串/释放——按常见字符串库补充，动态分配，调用方负责释放）
├── 格式化与IO：格式化输出/标准输出/标准错误/文件IO
├── 数学库：浮点运算辅助/128位整数运算辅助
├── OOP支持：vtable辅助/类型信息（预留RTTI）
└── 程序入口：启动代码（crt0风格，调用主函数）
```

### 10.2 内存管理API

| API | 说明 | 对应C库 |
|-----|------|---------|
| 分配(大小) | 分配内存块 | malloc |
| 释放(指针) | 释放内存块 | free |
| 重新分配(指针, 新大小) | 调整内存块大小 | realloc |
| 复制内存(目标, 源, 大小) | 内存复制 | memcpy |
| 置零内存(目标, 大小) | 内存置零 | memset |

> **扩展（2026-08 自举前置 C-1/C-3）：分配计数 + 进程竞技场**
> - `内存::活动分配数()` -> 整64：当前未释放块数（原子计数，泄漏检测基线）；
>   `内存::总分配次数()` -> 整64：累计分配次数。分配/释放/重新分配 全路径
>   计数（含字符串/时间/文件 API 内部 malloc，统一经计数辅助）。
> - `内存::竞技场分配(大小)` -> 空类型*：一次性进程竞技场 bump 分配（8 字节
>   对齐，块链 64KB，超块自动扩容）；`内存::竞技场重置()`：一次性释放全部块；
>   `内存::竞技场活动字节()` -> 整64：已分配总字节（含块头）。
>   适配编译器内存模式（长生命周期 + 一次分配）：自举源码无需逐对象释放，
>   杜绝泄漏/双重释放；智能指针可后置（plans/004 C 组判定）。

### 10.3 字符串表示
- 字符串采用UTF-8编码，以`\0`结尾
- 字符串字面量在编译期进入只读数据段，字符串变量为指针
- 字符串连接等操作调用运行时API完成
- **值语义（Task 2.8）**：字符串变量为指针，`字符串 t = s` 共享同一指针（与C一致，不深拷贝）；
  显式深拷贝用 `字符串复制`；动态分配结果（连接/子串/大写/小写/修剪/反转/整数转字符串/浮点转字符串/字符转字符串）
  由调用方负责用 `字符串释放` 释放
- **比较语义（Task 2.8）**：比较运算符（`==`/`!=`/`<`/`>`/`<=`/`>=`）仅定义整型与浮点变体
  （见运算符表），字符串不参与运算符比较；等价能力由 `字符串比较`（相等）与
  `字符串字典序`（全序比较，返回 <0/0/>0）提供
- **跨类型拼接语义（增强）**：`字符串 + 数值` 表达式触发隐式拼接——右操作数为整数/浮点/布尔/字符/枚举时，
  编译器自动插入 `整数转字符串`/`浮点转字符串`/`字符转字符串` 转换后再 `字符串连接`；
  布尔转换为 `"真"`/`"假"`。多操作数左结合：`"a" + 1 + 2` 等价 `(("a" + 1) + 2)`，结果为 `"a12"`。
  混合类型拼接结果由调用方负责 `字符串释放`。

### 10.6 格式化与输入输出API

> **打印函数族（方案C 2026-08-14 ✅ 已修复）**：打印函数族**只有 `打印` / `打印行` 两个变参函数**（外加 `格式化`），
> 旧版遗留的 `打印行整数` / `打印行浮点` **已删除（缺陷修复）**。
> - **"行" 的语义统一为：不追加换行符**（`打印行` 名称中"行"表示逐行连续输出语义）。
> - 遗留函数 `打印行整数(整64)`（`printf "%lld\n"`，换行）与 `打印行`（不换行）语义**恰好相反**，
>   造成命名二义性——已彻底删除，统一用变参 `打印`/`打印行` 表达：
>   `打印行整数(42)` → `打印(42)`（输出 `42\n`，换行行为完全一致）；
>   `打印行浮点(3.5)` → `打印(3.5)`（输出 `3.500000\n`）。
> - 整128/正128 打印同样由 `打印` 变参展开（`__cn_print_i128`/`__cn_print_u128`，完整128位）。

| API | 说明 | 对应C库 |
|-----|------|---------|
| 打印(任意值...) | 变参打印，`字符串 + 数值` 拼接或逐参展开为打印序列，末尾**自动换行** | printf（子集） + "\n" |
| 打印行(任意值...) | 同 `打印` 但末尾**不自动换行**（名称中"行"表示逐行连续输出语义，不追加换行符） | printf（子集） |
| 格式化(格式字符串, 参数...) | sprintf 风格格式化，返回新字符串（调用方释放） | sprintf |
| 读取行() | 从标准输入读取一行，返回字符串（不含换行，调用方释放） | fgets |
| 读取整数() / 读取浮点() | 从标准输入读取数值 | scanf（子集） |

> **`格式化()` 占位符**：`%d`（整型）、`%u`（无符号）、`%f`（浮点）、`%s`（字符串）、`%c`（字符）、`%x`/`%X`（十六进制）、`%o`（八进制）、`%p`（指针）。变参 ABI 在 IR 层展开为运行时 `__cn_format` 调用。

### 10.4 程序入口约定
- 入口函数名：`主`，签名：`函数 主() -> 整32`（返回0表示成功）
- 运行时启动代码负责：初始化堆、调用全局构造器、调用`主`、传递返回值给操作系统
- 命令行参数（预留）：`函数 主(整32 参数个数, 字符** 参数值) -> 整32`

### 10.5 128位整数运算辅助
- 整128/正128的乘除取余等运算由运行时辅助函数实现
- 命名约定：`__cn_mul_i128`、`__cn_div_i128`、`__cn_div_u128` 等
- 与目标平台无关，统一用C++实现并随编译器分发

## 十二、测试策略

### 12.1 测试层级

| 层级 | 范围 | 工具 | 目标 |
|------|------|------|------|
| 单元测试 | 单个模块（词法/语法/IR等） | C++单元测试框架（如GoogleTest） | 模块级正确性 |
| 集成测试 | 多阶段组合（词法+语法+语义） | 自定义测试框架 | 阶段间接口正确性 |
| E2E测试 | 完整编译运行（源文件→可执行→运行→输出验证） | 脚本驱动 | 端到端功能可用性 |
| 回归测试 | 全量测试集 | CI集成 | 防止功能回退 |

### 12.2 E2E测试原则（遵循项目规范）
- **E2E先行**：每个功能必须先写E2E测试，测试通过后才算完成
- **禁止.skip()**：所有测试必须真正运行，不使用跳过
- **真实配置**：所有测试使用真实配置，不使用Mock
- **渐进式**：分阶段实施，每阶段独立交付价值
- **全链路验证**：E2E测试必须通过真实编译流程（源文件 → cn编译 → 汇编 → 链接 → 运行 → 检查输出），禁止绕过生产代码直接实例化组件

### 附录C：名字修饰规则（mangling）
- 源码中文符号名统一转换为 UTF-8 字节序列的十六进制编码，前缀 `?`，后缀按函数签名编码
- 全局变量：`?变量名@@3A` 形式
- 函数：`?函数名@@Y<返回编码><参数编码>@Z` 形式（Win x64 MSVC风格）
- 静态/局部符号：模块内唯一即可，不参与全局修饰
- 设计目标：保证同名不同签名的函数可共存（重载支持），避免符号冲突
