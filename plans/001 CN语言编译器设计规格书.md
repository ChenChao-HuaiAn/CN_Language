# CN语言编译器设计规格书

> 版本：v1.0  
> 日期：2026-08-12  
> 状态：待审批  
> 基准：以本规格书定义的语法风格为准，参考C++编程范式，用C++从零编写编译器

---

## 一、语言设计概述

### 1.1 语言定位
CN语言是一门全中文语法的系统级编程语言，参考C++的编程范式，面向需要底层控制力的应用场景。语言设计遵循"中文优先、手动控制、零成本抽象"的原则。

### 1.2 设计决策汇总

| # | 决策项 | 确认结果 |
|---|--------|---------|
| 1 | 语法基准 | 以本规格书定义的语法风格为准，Rust参考仅作技术借鉴 |
| 2 | 编译器实现 | 从零用C++重写，不依赖现有C代码 |
| 3 | 代码生成后端 | 直接生成汇编代码，无外部依赖 |
| 4 | 目标平台 | 设计考虑全平台，初期实现 Win x64 + Linux ARM64 |
| 5 | 内存管理 | 指针+手动内存管理（malloc/free式），运行时API |
| 6 | 错误处理 | 错误码+可选值，去掉异常关键字，语法风格参照本规格书 |
| 7 | OOP | 完整保留（类/接口/继承/保护/虚拟/重写/抽象/实现/自身/父类） |
| 8 | 模块系统 | 保持本规格书设计（文件即模块，导入/从，.路径，公开:/私有:标签式） |
| 9 | 构建系统 | CMake |
| 10 | 编译器架构 | 方案C（多趟+自定义IR），包含IR层和优化器 |
| 11 | 开发路径 | 参考 Rust参考/003 路线图，直到自举 |
| 12 | 类型命名 | 中文位宽命名（整8/正8/整16/正16...整128/正128/浮32/浮64） |
| 13 | 字面量增强 | 增加Unicode字符转义、原始字符串、多行字符串（不增加数字下划线） |

> **重要：本规格书为编译器实现的唯一基准文档。**

## 二、关键字体系

本规格书定义共53个有效关键字（控制流10 + 类型20 + 声明7 + 常量3 + OOP9 + 错误处理2 + 字面量前缀2）。

### 2.1 关键字分类表

**类型关键字(20个)：**
- 默认类型(2个)：整数（=整32别名）、小数（=浮64别名）
- 有符号整数(5个)：整8、整16、整32、整64、整128

- 浮点(2个)：浮32、浮64
- 其他(6个)：布尔、字符、字符串、空类型、结构体、枚举

**声明(7个)：**
函数、变量、导入、从、公开、私有、静态

**常量(3个)：**
真、假、无

**OOP(9个)：**
类、接口、保护、虚拟、重写、抽象、实现、自身、父类

**错误处理(2个，新增)：**
结果、可选

**字面量前缀(2个，新增)：**
原始、多行

### 2.2 移除的关键字
- ~~尝试~~、~~捕获~~、~~抛出~~、~~最终~~（异常机制，改用错误码+可选值）

**变更记录：**

## 四、词法结构

### 4.1 源文件
- 扩展名：.cn
- 编码：UTF-8（必须）
- 入口文件：主.cn
- **说明：入口文件命名为 `主.cn` 仅为约定，其内部须定义 `主` 函数作为程序入口。文件名与函数名无强制绑定关系。**

### 4.2 注释
- `//` 单行注释
- `/* */` 块注释（支持嵌套）

### 4.3 字面量

**整数字面量：**
- 十进制：`42`
- 十六进制：`0xFF`
- 二进制：`0b1010`
- 八进制：`0o777`
- 类型后缀与中文位宽类型的映射：
  - `f` -> 浮点（浮32）
  - `L` -> 整64
  - `LL` -> 整128
  - `U` -> 正32
  - `UL` -> 正64
  - `ULL` -> 正128
- 不支持数字下划线分隔

**浮点字面量：**
- 小数形式：`3.14`
- 科学计数法：`1.5e10`

**字符字面量：**
- 普通字符：`'A'`、`'中'`
- 转义字符：`'\n'`、`'\t'`、`'\0'`
- Unicode转义（新增）：`'\u{4E2D}'`（等同于'中'）

**字符串字面量：**
- 普通字符串：`"你好"`
- 原始字符串（新增）：`原始"^\d+\.\d+$"`（反斜杠不需转义）
- 多行字符串（新增）：`多行"""第一行\n第二行\n第三行"""`
- 转义语义规则：多行字符串内部仍处理 `\n`、`\t` 等转义字符。如需完全原始的多行文本，可组合使用 `原始` 和 `多行` 前缀：`原始多行"""..."""`

### 4.4 运算符

**算术运算符：** `+` `-` `*` `/` `%`
**比较运算符：** `==` `!=` `<` `>` `<=` `>=`
**逻辑运算符：** `&&` `||` `!`
**位运算符：** `&` `|` `^` `~` `<<` `>>`
**赋值运算符：** `=` `+=` `-=` `*=` `/=` `%=` `&=` `|=` `^=` `<<=` `>>=`
**指针运算符：** `&`（取地址）`*`（解引用）`->`（成员访问）
**其他：** `.`（成员访问）`[]`（下标）

> **成员包含判断使用标准库函数 `包含()` 而非运算符**（如 `表.包含(键)`），"在"不是运算符。

### 4.5 运算符优先级（13级，从高到低）

| 优先级 | 运算符 | 说明 |
|--------|--------|------|
| 13（最高） | `()` `[]` `.` `->` | 后缀 |
| 12 | `!` `~` `-`（负）`*`（解引用）`&`（取地址） | 一元 |
| 11 | `*` `/` `%` | 乘除 |
| 10 | `+` `-` | 加减 |
| 9 | `<<` `>>` | 移位 |
| 8 | `<` `<=` `>` `>=` | 比较 |
| 7 | `==` `!=` | 相等 |
| 6 | `&` | 按位与 |
| 5 | `^` | 按位异或 |
| 4 | `|` | 按位或 |
| 3 | `&&` | 逻辑与 |
| 2 | `||` | 逻辑或 |
| 1（最低） | `=` `+=` `-=` 等 | 赋值 |

## 五、语法规范

### 5.1 程序结构

```
程序 = 顶层声明*
顶层声明 = 函数声明 | 结构体声明 | 枚举声明 | 类声明 | 接口声明 | 导入声明 | 全局变量声明
```

### 5.2 变量声明（类型前置）

```
变量 x = 10           // 类型推断
整数 y = 20           // 显式类型
整32 z = 30           // 位宽类型
常量 PI = 3.14        // 常量
静态 整32 计数 = 0    // 静态变量
```

### 5.3 函数定义

```
函数 加(整32 a, 整32 b) -> 整32 {
    返回 a + b
}

// 无返回值时省略 -> 类型
函数 打印问候() {
    打印行("你好")
}

// 函数原型声明（前向引用）
函数 计算(整32 n) -> 整32
```

### 5.4 错误处理（替代异常）

```
// 结果类型：正常返回值 或 错误码
函数 除法(整32 a, 整32 b) -> 结果<整32, 整32> {
    如果 b == 0 {
        返回 错误(1)  // 错误码1: 除零错误
    }
    返回 正常(a / b)
}

// 使用时检查
除法结果 = 除法(10, 0)
如果 除法结果.正常 {
    打印行(除法结果.值)
} 否则 {
    打印行("除零错误: ", 除法结果.错误)
}

// 可选类型
函数 查找(整32 键) -> 可选<整32> {
    如果 表.包含(键) {
        返回 某些(表[键])
    }
    返回 无
}
```

> **注意：所有关键字均为保留字，不可用作标识符。**

**内置构造器身份说明：** `正常()`、`错误()`、`某些()` 为内置构造器函数，由编译器预置符号表，非保留关键字，用户不可重定义。

#### 结果/可选强制检查规则
- 规则1：`结果<T,E>` 类型的返回值如果不被检查就丢弃，编译器报**错误**
- 规则2：检查 `结果.正常` 后未处理错误分支，编译器报**警告**
- 规则3：`可选<T>` 类型的值在访问 `.值` 前必须检查 `.有值`，否则编译器报**错误**

### 5.5 控制流

```
// 条件
如果 x > 0 {
    打印行("正数")
} 否则 如果 x < 0 {
    打印行("负数")
} 否则 {
    打印行("零")
}

// 当循环
整数 i = 0
当 i < 10 {
    打印行(i)
    i++
}

// 循环（for风格）
循环 (整32 j = 0; j < 10; j++) {
    打印行(j)
}

// 选择语句
选择(值) {
    情况 1:
        打印行("一")
        中断
    情况 2:
        打印行("二")
        中断
    默认:
        打印行("其他")
}

// 中断和继续
循环 (整32 k = 0; k < 100; k++) {
    如果 k % 2 == 0 {
        继续
    }
    如果 k > 50 {
        中断
    }
    打印行(k)
}
```

## 六、编译器架构

### 6.1 编译流水线总览

```
CN源代码(.cn)
    │
    ▼
词法分析器(Lexer) -> Token流
    │
    ▼
语法分析器(Parser) -> AST树
    │
    ▼
语义分析器(Semantic) -> 带类型AST + 符号表
    │
    ▼
IR生成器(IRGenerator) -> CN-IR
    │
    ▼
优化器(Optimizer) -> 优化后的CN-IR
    │
    ├─────────────┐
    ▼             ▼
Win x64 Codegen  Linux ARM64 Codegen
    │             │
    ▼             ▼
.asm文件        .asm文件
    │             │
    ▼             ▼
汇编器+链接器 -> 可执行文件
```

### 6.2 各阶段职责

#### 阶段1：词法分析器（Lexer）
- 输入：.cn源文件（UTF-8编码）
- 输出：Token流
- 职责：UTF-8中文字符识别、字面量解析、运算符与分隔符识别、注释剥离、行号/列号追踪
- 关键设计：中文关键字最长匹配，关键字后必须有空格或符号分隔

#### 阶段2：语法分析器（Parser）
- 输入：Token流
- 输出：AST
- 职责：递归下降解析、运算符优先级处理（Pratt parser）、AST节点构建、语法错误报告
- 关键设计：两趟解析——第一趟收集顶层声明，第二趟解析函数体，支持前向引用

#### 阶段3：语义分析器（Semantic Analyzer）
- 输入：AST
- 输出：带类型标注的AST + 全局符号表
- 职责：符号表构建与作用域管理、类型检查与推断、隐式类型转换验证、继承与接口实现验证、函数重载解析、错误码传播分析（结果/可选强制处理）、常量折叠预计算
- 关键设计：分模块语义分析——名称解析模块（NameResolution）、类型检查模块（TypeChecker）、OOP验证模块（OOPValidator）、错误码分析模块（ErrorAnalysis）；语义错误分级（错误/警告/提示），错误带源码位置与修复建议

#### 阶段4：IR生成器（IR Generator）
- 输入：带类型标注的AST + 符号表
- 输出：CN-IR（静态单赋值形式 SSA）
- 职责：AST降级为CFG基本块、类型化指令生成、虚拟寄存器分配、SSA Phi节点构建、内存访问显式化（指针运算、结构体字段偏移计算）
- 关键设计：每个函数一个控制流图（CFG），指令三地址码形式，类型信息内嵌于每个虚拟寄存器

#### 阶段5：优化器（Optimizer）
- 输入：CN-IR（SSA形式）
- 输出：优化后的CN-IR
- 职责：常量传播、死代码消除、公共子表达式消除、循环优化（不变量外提/强度削减）、内联优化、尾调用优化、指令合并与简化
- 关键设计：优化级别 -O0（无优化，调试用）、-O1（基础优化）、-O2（默认，含循环优化）、-O3（激进优化，含内联）；每个优化Pass独立可插拔，支持打印Pass执行前后IR用于调试

#### 阶段6：代码生成器（Code Generator）
- 输入：优化后的CN-IR
- 输出：平台汇编文件（.asm）
- 职责：指令选择（IR指令映射为目标ISA指令）、寄存器分配（线性扫描/图着色）、指令调度、ABI调用约定处理（Win64/ARM64）、栈帧布局、虚函数表（vtable）生成、全局数据段（.data）与代码段（.text）生成
- 关键设计：后端抽象层（Backend接口）——IR指令通过目标描述文件（TD）映射，Win x64与Linux ARM64共享同一IR与优化器，仅代码生成后端不同；汇编输出经平台汇编器（MASM/GAS）与链接器（link/ld）生成可执行文件

## 七、CN-IR中间表示设计

### 7.1 设计目标
- **可移植性**：与目标平台无关，Win x64 与 Linux ARM64 共享同一 IR 与优化器
- **可优化性**：采用静态单赋值（SSA）形式，Phi 节点统一汇合点，便于数据流分析
- **可调试性**：IR 保留源码位置信息（文件/行/列），支持 -emit-ir 选项导出可读 IR 文本
- **类型化**：每个虚拟寄存器带类型标注，代码生成时无需回查符号表

### 7.2 IR 结构

```
模块(Module)
├── 全局变量表
├── 函数列表(Function)
│   ├── 函数签名（名称/参数/返回值/链接属性）
│   ├── 基本块列表(BasicBlock)
│   │   ├── 入口标签
│   │   ├── 指令序列(Instruction)
│   │   │   ├── 操作码
│   │   │   ├── 源操作数列表（虚拟寄存器/常量/全局符号）
│   │   │   ├── 目标虚拟寄存器
│   │   │   ├── 类型标注
│   │   │   └── 源码位置
│   │   └── 终止指令（跳转/条件跳转/返回/选择跳转表）
│   └── Phi 节点集合
└── 全局字符串常量池
```

### 7.3 指令分类

| 类别 | 指令 | 说明 |
|------|------|------|
| 算术 | 加/减/乘/除/取余 | 整型与浮点变体（加浮32/加浮64等） |
| 位运算 | 位与/位或/位异或/位非/左移/右移 | 整型专用 |
| 比较 | 相等/不等/小于/小于等于/大于/大于等于 | 结果为布尔，整型与浮点变体 |
| 逻辑 | 逻辑与/逻辑或/逻辑非 | 短路求值语义 |
| 内存 | 加载/存储/取地址 | 含原子性标注（预留） |
| 转换 | 扩展/截断/浮整转换/位重解释 | 显式类型转换 |
| 控制 | 跳转/条件跳转/返回/选择表跳转 | CFG 终止指令 |
| 调用 | 直接调用/间接调用（函数指针） | 含调用约定与返回约定标注 |
| 对象 | 虚调用/新建对象/删除对象/字段加载/字段存储 | OOP 相关，虚调用经 vtable 间接跳转 |
| 错误 | 结果构造/结果检查/可选构造/可选检查 | 错误处理类型降级 |

### 7.4 虚拟寄存器与 SSA

- 虚拟寄存器编号：`%v0`、`%v1`、`%v2`...
- 每个虚拟寄存器恰好赋值一次（SSA 性质）
- 汇合点使用 Phi 指令合并多个入边值
- 基本块 ID：`块0`、`块1`、`块2`...
- IR 文本示例：

```
函数 加(整32 %v0, 整32 %v1) -> 整32 {
块0:
    %v2 = 加 整32 %v0, %v1
    返回 %v2
}
```

### 7.5 类型表示

| IR类型 | 对应CN类型 | 大小 |
|--------|-----------|------|
| i8/i16/i32/i64/i128 | 整8/整16/整32/整64/整128 | 1/2/4/8/16字节 |
| u8/u16/u32/u64/u128 | 正8/正16/正32/正64/正128 | 1/2/4/8/16字节 |
| f32/f64 | 浮32/浮64 | 4/8字节 |
| i1 | 布尔 | 1字节 |
| ptr | 指针/字符串/字符* | 8字节（64位平台） |
| struct | 结构体/类 | 布局后大小 |
| void | 空类型 | 0字节 |

### 7.6 结果/可选类型降级约定
- `结果<正常, 错误>` 降级为 `结构体 { 布尔 是否正常; 联合体 { 正常类型 值; 错误类型 错误值 } }`
- `可选<类型>` 降级为 `结构体 { 布尔 是否某些; 类型 值 }`
- 检查成员 `.正常`/`.某些` 对应结构体首字段读取，未检查即访问 `.值` 由语义分析器在阶段3提前拦截
- **联合体仅用于编译器内部IR降级，源语言层面也可使用**（见3.5节复合类型定义）

## 八、代码生成

### 8.1 目标平台与ABI

| 目标 | 汇编器 | 链接器 | ABI规范 | 备注 |
|------|--------|--------|---------|------|
| Win x64 | MASM（ml64） | link.exe | Microsoft x64 ABI | 初期主目标 |
| Linux ARM64 | GNU as（GAS） | ld | AAPCS64 | 初期次目标 |
| Linux x64 | GNU as（GAS） | ld | System V AMD64 ABI | 预留 |
| macOS x64/ARM64 | 预留 | 预留 | Apple ABI | 预留 |

### 8.2 指令选择策略
- IR指令与目标指令的映射采用**模式匹配**：针对常见IR模式（如"加法+比较+条件跳转"）匹配目标平台的组合指令
- 乘除/取余等复杂运算：整型宽度 ≤ 64 位映射为原生指令；整128位宽用运行时辅助函数（如 `__cn_mul_i128`）模拟
- 浮点运算映射为SSE/NEON指令集指令

### 8.3 寄存器分配
- **Win x64**：采用线性扫描寄存器分配器（针对-O1/-O2），-O0时全栈帧分配（调试友好）
- 预留寄存器：`rbx/rbp/r12~r15` 为被调用者保存寄存器，`rax/rcx/rdx/r8~r11` 为调用者保存寄存器
- **Linux ARM64**：x19~x28为被调用者保存，x0~x18为调用者保存；浮点寄存器 d0~d31
- 溢出（spill）：临时值溢出到栈槽，栈帧统一管理

### 8.4 栈帧布局（Win x64）

```
高地址
┌─────────────────────────┐
│ 返回地址（调用者压栈）      │
├─────────────────────────┤
│ 被调用者保存寄存器区        │
├─────────────────────────┤
│ 局部变量区（含溢出槽）      │
├─────────────────────────┤
│ 参数栈传递区（>4个参数）    │
├─────────────────────────┤
│ 影子空间（32字节，预留）    │
└─────────────────────────┘
低地址  ← rsp
```

### 8.5 调用约定
- 参数传递：前4个整型参数用 `rcx/rdx/r8/r9`，前4个浮点参数用 `xmm0~xmm3`（Win x64）
- 返回值：整型/指针用 `rax`，浮点用 `xmm0`
- 大于8字节的结构体：调用方在栈上分配并传入指针
- 栈对齐：调用前栈16字节对齐

### 8.6 OOP运行时布局
- 类实例布局：`[vtable指针 | 父类成员区 | 自身成员区]`（单继承）
- 虚函数表（vtable）：函数指针数组，子类重写时覆盖对应槽位；接口实现采用附加vtable（预留）
- 构造/析构：构造函数返回对象指针；析构函数内联清理资源后调用父类析构

### 8.7 全局数据与字符串常量
- 全局变量进入 `.data`/`.bss` 段
- 字符串常量合并去重后进入 `.rdata`/`.rodata` 段
- 全局符号命名：源码中文符号经内部名字修饰（mangling）后生成唯一汇编符号，规则见附录C

### 8.8 汇编输出示例（Win x64）

```asm
; 函数 加(整32 a, 整32 b) -> 整32
.code
?加@@YAHHH@Z PROC
    ; prologue
    push    rbp
    mov     rbp, rsp
    ; 参数：ecx = a, edx = b
    mov     eax, ecx
    add     eax, edx
    ; epilogue
    pop     rbp
    ret
?加@@YAHHH@Z ENDP
END
```

## 九、优化器

### 9.1 优化级别

| 级别 | 说明 | 适用场景 |
|------|------|---------|
| -O0 | 无优化，全栈帧分配，保留调试信息 | 开发调试 |
| -O1 | 基础优化（常量折叠、死代码消除） | 快速构建 |
| -O2 | 默认级别，含循环优化与内联 | 生产发布 |
| -O3 | 激进优化，含激进内联与向量化预留 | 性能敏感场景 |

### 9.2 优化Pass清单

| Pass | 类别 | 说明 |
|------|------|------|
| 常量折叠与传播 | 基础 | 编译期常量计算与传播 |
| 死代码消除（DCE） | 基础 | 删除无副作用且结果未使用的指令 |
| 公共子表达式消除（CSE） | 基础 | 相同表达式复用 |
| 复写传播 | 基础 | 消除冗余复制指令 |
| 指令合并 | 基础 | 合并可组合指令 |
| 循环不变量外提（LICM） | 循环 | 将循环内不变量移到循环前 |
| 强度削减 | 循环 | 乘法/除法替换为移位/加法 |
| 循环展开（预留） | 循环 | 小循环体展开减少分支开销 |
| 函数内联 | 函数 | 小函数内联展开（启发式阈值） |
| 尾调用优化（TCO） | 函数 | 尾递归转为循环 |
| 选择表生成 | 控制 | 密集选择语句生成跳转表 |
| 空块合并 | 控制 | 合并空基本块、消除冗余跳转 |

### 9.3 Pass框架设计
- 每个Pass实现统一接口：`Pass::运行(IR模块) -> 是否修改`
- Pass管理器按依赖顺序调度，重复运行直至收敛（fixpoint）
- 每个Pass可通过 `-打印ir=pass名` 输出执行前后IR对比
- 优化前后正确性验证（预留）：`-验证-ir` 检查SSA性质不变量（支配关系、Phi节点合法性）

## 十、运行时设计

### 10.1 运行时库结构

```
cnrt（CN Runtime）
├── 内存管理：分配/释放/重新分配/复制
├── 字符串操作：长度/比较/连接/复制/查找
├── 格式化与IO：格式化输出/标准输出/标准错误/文件IO
├── 数学库：浮点运算辅助/128位整数运算辅助
├── OOP支持：vtable辅助/类型信息（预留RTTI）
└── 程序入口：启动代码（crt0风格，调用主函数）
```

### 10.2 内存管理API

| API | 说明 | 对应C库 |
|-----|------|---------|
| 分配(大小) | 分配内存块 | malloc |
| 释放(指针) | 释放内存块 | free |
| 重新分配(指针, 新大小) | 调整内存块大小 | realloc |
| 复制内存(目标, 源, 大小) | 内存复制 | memcpy |
| 置零内存(目标, 大小) | 内存置零 | memset |

### 10.3 字符串表示
- 字符串采用UTF-8编码，以`\0`结尾
- 字符串字面量在编译期进入只读数据段，字符串变量为指针
- 字符串连接等操作调用运行时API完成

### 10.4 程序入口约定
- 入口函数名：`主`，签名：`函数 主() -> 整32`（返回0表示成功）
- 运行时启动代码负责：初始化堆、调用全局构造器、调用`主`、传递返回值给操作系统
- 命令行参数（预留）：`函数 主(整32 参数个数, 字符** 参数值) -> 整32`

### 10.5 128位整数运算辅助
- 整128/正128的乘除取余等运算由运行时辅助函数实现
- 命名约定：`__cn_mul_i128`、`__cn_div_i128`、`__cn_div_u128` 等
- 与目标平台无关，统一用C++实现并随编译器分发

```
├── tools/                  # 辅助工具（E2E脚本等）
├── plans/                  # 设计文档
└── target/                 # 编译输出（E2E测试产物）
```

### 13.2 模块依赖约束
- `frontend` → `ir` → `opt` → `codegen`（单向依赖，禁止反向）
- `driver` 依赖所有模块，是唯一组合入口
- 每个源文件不超过1000行，每个函数不超过100行（遵循项目规范）
- 模块可拆分为子模块目录，旧文件及时删除

### 附录C：名字修饰规则（mangling）
- 源码中文符号名统一转换为 UTF-8 字节序列的十六进制编码，前缀 `?`，后缀按函数签名编码
- 全局变量：`?变量名@@3A` 形式
- 函数：`?函数名@@Y<返回编码><参数编码>@Z` 形式（Win x64 MSVC风格）
- 静态/局部符号：模块内唯一即可，不参与全局修饰
- 设计目标：保证同名不同签名的函数可共存（重载支持），避免符号冲突
