## 三、方法论（与 lessons 第七十二轮互补）

1. **探针实测优先于读代码推断**：泄漏/悬垂用 `内存::活动分配数()` 差值与搅动复现量化；生成物层对照（IR/asm 有无 `__cn_str_free`）；与 clang/gcc 输出对照（ABI 契约）。
2. **静态审查与探针两条腿**：探针测得出泄漏/悬垂，测不出死代码/命名失准/注释不符/状态清理不对称——后者靠 diff 审读（本轮 4+1 瑕疵全由静态审查发现，其中顺带揪出类方法返回路径真缺陷=探针 87 实证）。
3. **修前先实证、修后看归零**：每处修复先跑探针拿到非零残留，修复后归零，证据入提交信息。
4. **矩阵空白=靶子**：每轮收尾扫一遍第一节，未填格与「靶子」标记即下一轮立案候选。

### 方法论补充（本轮新证）

- **「无条件释放」与「不接管所有权」是一对必须同时成立或同时不成立的假设**：容器析构假定元素归容器（逐元素 free），而入容器位不接管所有权——两个半截机制各自「看起来正常」，合起来产生一族静默缺陷（悬垂/双释放/UAF）。**修复方式不是给任一侧打补丁，而是让「所有权」在两侧成为同一个事实**（编译器在入口接管）。举凡「A 处假定 X 成立、B 处负责建立 X」的设计，先问「X 由谁建立、在哪一行建立、建立失败会怎样」。
- **容器元素释放必须按元素模型分派**：平铺数组（向量/栈）与链式槽（链表/队列）的「有效元素集合」不同——链式容器的 出队/删除头部 把元素所有权转移给调用方，槽序号可能 < 元素数量，按计数平铺释放会释放已移交的串（UAF）。**新增容器类型时先问「有效元素怎么枚举」**。
- **v2 侧实施的两个不变量（v2 特有，非宿主同款）**：①**调用发射时序**——v2 代码生成的调用展开是「收集 IR_调用实参，遇 IR_调用参数化 统一展开」，任何插入式调用必须在此收集开始**之前**发射（否则其 IR_调用参数化 会把已收集实参一并展开，位数错乱）；②**节点池后缀序**——实参根节点在调用节点**前一位置**，不可用 子起点+1+序（那是实参子树的起始节点，复合实参时指向最内层子节点，判定失真；探针 74-H 实证：误判借用→多一次复制+原值泄漏）。
- **移植纪律 9 的第二个对照用例价值实证**：219 覆盖六形态（含两侧共有的容器模型差异面），宿主与 v2 侧任一形态分叉即退出码不同——比 217（块级 RAII）覆盖面更广（所有权语义 + 四容器模型 + 借用来源）。

### 诚实边界（74-a）

- **v2 侧 `转移(拥有局部)` 入容器未走真 move**：判定「源是否拥有」需 函数信息.字符串变量们/污染们，而 归一化入容器实参 位于 生成表达式求值（深层），拿不到 函数信息——穿透需改 表达式生成族 12 函数 + 22 调用点签名，风险大于收益。现统一复制，**语义安全等价**（容器独立拥有、源照常释放，无悬垂无泄漏），仅多一次分配；真 move 优化登记为后续项。

### 机制说明（v2 真 move 的三重判定）

v2 侧实施难点：`归一化入容器实参` 位于 `生成表达式求值`（深层），拿不到 `函数信息`（穿透需改表达式生成族 12 函数 + 22 调用点，风险大于收益）。方案：**污染名单镜像**（v2 已有 `已装箱名们`/`当前函数变量类型` 同款惯例）——
- 静态 `当前串污染们` + `登记串污染(函数信息, 名ID)` 唯一写入入口（5 处污染登记点收口）+ `是当前串污染(名ID)` 查询 + `清空函数级槽表()` 函数级重置；
- **同生同灭**不变量：镜像只能经唯一入口写入（漏项方向不保守 → 误判拥有 → 容器接管借用句柄=UAF，故以代码注释为强制契约）；
- 真 move 判定 = 实参形态为 `转移(标识符)` ∧ 源在**局部槽**命中 ∧ 源**不在参数槽**（形参=借用视图）∧ 源不在污染镜像；任一不满足回落复制。
- 实测：真 move 分配增量 **0**（预分配后）；借用形参转移走复制（调用方串经搅动完好）=安全方向。

- **容器元素释放的第三种模型**：向量/栈=平铺数组；链表/队列=链式槽（按链游）；**映射=交换式删除的前缀数组**（删除与末元素交换 → 有效元素恒为 `[0,元素数量)`，平铺安全）。新增容器类型时先确认它的删除策略，据此选释放遍历方式。
- **注入到容器方法体的释放覆盖嵌套场景**：映射的字符串释放注入在 `~映射`/`清空` 方法体内，因此 `向量<映射<…,字符串>>` 的元素析构（注入的 `Call ~映射`）自动受益——比"调用点插入"覆盖面更广（调用点插入需枚举所有持有者）。

### 边界① 跨函数别名（探针 A 实证 → 实现「调用点同源互斥」）

| 真根因 | **池索引 0 哨兵冲突**：入口文件**首个入池节点**（首个函数体首条语句的最早叶子，如 `返回 错误(5);` 的 错误）恰为被调标识符时 `子起点 == 0`，而语义/IR 多处守卫 `子起点 > 0` 把 0 当「无」哨兵 → 识别整段跳过。结构体声明只是把首叶推离索引 0 | 诊断注入：dbg（语义层）——P10c 打印 `调用名=[错误] 附加=1 语境=63`，P10b **无此行**（调用节点未进构造器分支）；dbg2（返回语句区间）——`区间节点 0 类型=10 文本=错误`；dbg3 实测二元/赋值节点字段协议（`子起点`=右值起点，佐证可达性判定） |

### 可达性判定（哪些守卫的 0 可达）

- **可达（活缺陷）＝调用族**：被调标识符是**首次出现的新引用**，且实参可为字面量/
  类型名（无前置依赖）→ 可成为池索引 0。
  - 语义层 `检查调用表达式` 的 `调用起点 > 0`（★缺陷点：构造器/转移/类型大小/
    类型转换/借用纪律/决议登记整段跳过）
  - IR 层 `生成调用` 三特判 `n.子起点 > 0`（构造器装箱 21 / 转移 36 / 类型大小 61）
- **不可达（写法脆弱但当前无害）**：下标/成员对象、赋值左值末、二元左末——其索引
  对象**必为已声明变量**（声明节点/参数节点必在其前；参数实测入池）或右值起点 ≥1；
  P23（转移实参=参数）、P26/P27（全局引用形态）探针均未命中索引 0。
- 全树审计：`子起点 > 0` 23 处 + `子起点 <= 0` 4 处 + `附加 <= 0` 1 处；
  `池.元素(0)` 直接访问与全池遍历（`当 (i < 池.大小())`）**零命中**——哨兵槽方案的
  可行性前提（池仅随机访问，无第二处池创建）。

### 方案裁决（三案，乙实施）

| 案 | 内容 | 代价 | 判定 |
|---|---|---|---|
| 甲 | 调用/下标/成员族 24 处守卫逐处改 `>= 0` | 分散修改；「0 歧义」隐患留存（未来新代码写 `> 0` 即复发）；残缺节点误读索引 0 风险上升 | 落选 |

**Rust 对照**：rustc `NodeId` 0 保留（`CRATE_NODE_ID = NodeId::from_u32(1)`）——

两写法同时正确**（哨兵永不为任何真实节点的子），同族缺陷整族一次收口、未来新代码

## 十四、第八十二轮：v2 帧尾共享 retbuf 根治（82-a，2026-09-12）

**立案**：HANDOFF 第八十一轮「下一轮任务 #1（第一优先，数据损坏级）」——v2 帧尾共享
retbuf × 嵌套结构体返回实参。用户令：遵守 AGENTS.md 第3项开发纪律、参考 Rust 经验给

### 缺陷实证（探针 P15/P17/P19/P20 + E2E 172 回归，/tmp/p81probe 不入库）

| 形态 | 宿主 | v2（修复前） | 触发条件 |
|---|---|---|---|
| `表.追加(造盒())`（单实参） | 0 | 残留 **1**（句柄泄漏） | 外层调用的返回值也用 retbuf（结果返回） |
| `取大(a, 造点(1,2))`（标识符+返回混合） | 7 ✓ | 7 ✓ | 外层调用返回标量 → 无覆盖（本轮探明） |
| **`合并(造盒(1),造盒(2))`（双返回实参）** | 1 ✓ | **0（数据损坏）** | 第二次返回覆盖第一次 |
| E2E 172 跨模块 `甲::记录 甲记录 = 甲::造甲(42,99);` | 141 ✓ | **84（数据损坏）** | 跨模块返回类型按纯名解析到当前模块同名异布局类型（4B vs 16B） |

**根因（三步收敛）**：
1. **共享单缓冲**：v2 全部结构体/结果返回共用帧尾 retbuf（`retbuf序号` + `累计retbuf字节数`）；
   宿主相反——每次调用独立 `__retbufN` Alloca 槽。任何「返回值跨越另一次返回调用」形态被覆盖。
2. **首版失败（槽基址约定）**：v2 的结构体基址槽 = **`槽起 + 槽数 - 1`**（最大槽号=最低
   地址=结构体基址，②b B1 约定）——首版误用 `槽起` 当基址 → 写穿相邻变量槽
   （P20 实测：物化槽 -704 与 t 槽 -696 重叠 8 字节）；且只发一条 `IR_分配`（扫描函数
   漏统计 → 帧尺寸不足）。
3. **跨模块返回类型**：v2 的函数符号键格式为 `模块$名#参数串`；返回类型表存**纯名**
   （「记录」）→ 在调用方模块上下文解析到**同名异布局类型**（E2E 172：主 4B vs 甲 16B）
   → retbuf 尺寸/物化长度错。

### 方案（甲案 = LLVM sret 各自分配语义；性能第一）

| 案 | 内容 | 判定 |
|---|---|---|
| **甲（实施）** | **返回物化到独立槽**：结构体返回调用发射后**立即** memcpy 到新分配的生成期临时槽，返回寄存器（压栈值）换成槽地址；实参位置的物化槽其串字段在外层调用发射后释放；跨模块返回类型按定义模块限定 | **采纳**：每返回值独立（与 LLVM sret 一致）；+1 memcpy/返回调用（正确性必要）；零运行时元数据 |
| 乙 | retbuf 全量独立（每次返回分配独立缓冲） | 落选：帧尺寸=Σ 返回尺寸（v2 自举树调用点数千 → 膨胀） |
| 丙 | 所有返回调用后物化（不限实参位置） | 与甲实质等价——甲即「每次真结构体返回都物化」（非实参位置不释放=句柄归接收方，零泄漏） |

### 实施（v2 树 3 文件）

- `IR容器.cn`：`物化返回值到独立槽`（槽起/基址=槽起+槽数-1、逐槽 IR_分配、memcpy、
  返回槽地址寄存器并登记）+ `清理调用实参临时`（实参寄存器命中登记表 → 释放串字段 +
  匹配即删除）+ `发射串字段释放顺序`（纯串字段结构体，无块结构体版）+ `是纯串字段结构体` +
  `限定返回类型ID`（跨模块：键文本首 `$` 前=模块前缀，重查结构体大小命中才用限定名）+
  `子串位置`（"::" 检测）+ 静态 `结构体返回临时们`。
- `生成表达式求值.cn`：`发射普通函数调用`/`生成方法调用`（签名加 `整64* 槽计数`）在
  `IR_调用参数化` 后物化真结构体返回、以槽地址压栈；`生成调用` 两处调用点在外层调用
  发射后 `清理调用实参临时`。
- `IR生成.cn`：`清空函数级槽表` 加 `结构体返回临时们.清空()`（防跨函数寄存器号误命中）。

### 槽分配纪律（**独立于预扫预分配槽区**，本轮订立）

1. **预扫**分配参数槽 + 变量槽（槽 1=retbuf 指针保留）；
2. **生成期临时槽**（本机制的物化槽）只用同一 `槽计数` 继续递增——不回溯、不复用已分配
   槽号、不与参数/变量槽区交错；
3. **retbuf 区**由代码生成动态计算（`扫描函数` 的 `槽基数 = 最大槽`，retbuf 区在其上）→
   任何 `IR_分配`（含物化槽）都使该区上移，**两者不可能重叠**；
4. 结构体**基址槽 = 槽起 + 槽数 − 1**（最大槽号=最低地址=结构体基址）；逐槽 `IR_分配`
   （扫描函数 按 `附加` 统计最大槽——只登记基槽会致帧尺寸不足）。

## 十六、第八十三轮：链表/队列 槽分配与回收（空闲链，83-a，2026-09-12）

**立案**：81-a 登记的既有缺陷「stdlib 链表 `追加` 槽复用缺陷」（探针 P5④/P22 实证）——

### 缺陷实证（探针 P22，宿主基线）

| 形态 | 修复前 | 期望 |
|---|---|---|
| `链表<整64>`：追加 11/22/33 + 删除头部 + 追加 44 | 大小=3、头部=22、尾部=44（**33 被 44 覆盖** + `next` 自环） | [22,33,44] |
| `队列<整64>`：入队 11/22/33 + 出队 + 入队 44 | 出队序 **22/44/44**（**33 丢失**） | 22/33/44 |
| `链表<字符串>`：追加 2 + 删头 + 追加 1 | 头部=[丙串]（应 [乙串]，**内容错**）+ **残留 1**（泄漏） | 头部=[乙串]、残留 0 |

**根因**：`新索引 = 元素数量` 假设「槽 0..元素数量-1 全被占用」——删除头部/尾部 后该
不变量破坏（被摘槽仍占槽号但不在计数内）→ 新槽号与在链槽冲突（**覆盖旧元素 + `next`
自环**）。

## 十七、待用户裁决：B35 字段容器接收者——容器字段赋值语义（move vs 深拷）

> **本节为呈报项（AGENTS.md §2.3「新增语法规范须审批」+ §3「报告类产出必须等用户批阅」）**：
> 涉及**语言级语义裁决**，AI 不自行实施；其余登记项（已完成的 81-a/82-a/82-b/83-a）不涉此。

### 现象（探针 P4⑨⑩ / P5①，宿主与 v2 同缺）

```cn
结构体 货架 { 向量<字符串> 记录; 整32 号; }
货架 甲;
甲.记录 = 向量<字符串>();
甲.记录.追加(转移(值));       // 或 甲.记录.追加(值)
// 块出口后 内存::活动分配数() 差值 = 2（容器对象内存 + 元素串）
```
**结构体容器字段的「消亡位」无释放面**（对象与元素串都不释放）——根源是**语义未定**：
CN 的结构体赋值是**深拷**（79-a 对字符串字段的裁决），但**容器字段的赋值当前是浅拷**
（共享对象指针）→ 若只加释放面，两端共享句柄即 double free；若不加深拷，释放面无从谈。

### 三方案（性能第一、安全第二；Rust 对照）

| 案 | 内容 | 性能 | 安全 | 语义影响 |
|---|---|---|---|---|
| **甲：move 语义**（Rust 原生） | 容器字段赋值 = 浅拷 + **源字段清零**（`转移`/`自身` 来源零拷贝）；借用来源 → 复制落堆 | **最优**（零拷贝） | 高（唯一持有者） | **语言级语义变更**：结构体容器字段赋值 ≠ 深拷（与字符串字段分叉）；须用户批准 |
| **乙（推荐）：深拷（拷贝构造）** | 容器字段赋值 = `NewObject` + 调用拷贝构造（`向量(向量&)` 既有 ✓）+ 目标旧字段释放（DeleteObject + 元素释放） | 中（O(n) 拷贝，= Rust `Clone` 由编译器代写） | 高（每字段独立拥有，与 79-a 字符串字段同哲学） | 零语义变更（延续「结构体赋值=深拷」契约） |
| 丙：维持现状 + 诊断 | 不改语义（保持泄漏=宁漏勿错），编译器对可疑赋值给观察期警告 | 最优（无改动） | 中（泄漏持续） | 零语义变更；安全面靠使用者纪律 |

**推荐：乙**——与 79-a「字符串字段 drop glue」同一套三件套（写入位归一化 + 拷贝位深拷 +
消亡位释放）在容器字段上的自然延伸，零语言级语义变更、安全闭环；甲的零拷贝收益可作为
**后续优化**（若用户批准 move 语义，再在乙之上切换，改动集中在一处）。

**请裁决**：采用 乙（深拷，零语义变更）/ 甲（move，性能最优但语义变更）/ 丙（维持 + 诊断），
或指定其它口径。裁决前 B35 保持登记状态（不实施）。

   + 收尾 节点_结构体构造（后缀序：字段初值节点在值表达式之后，与 v2 池惯例一致）。
3. **IR 生成**（新函数 `生成结构体构造`，挂 `生成表达式.cn` 分派）：**临时槽**

## 二十四、第八十四轮后续：未初始化槽 preFree 隐患核验（84-f，2026-09-12）

**立案**：79-a 登记 / 81-a 再登记的观察项「未初始化槽 preFree 隐患」——stdlib 的
`数据[n] = 值` 结构体写入走 79-a 深拷（preFree 释放目标旧字段串）→ 对**扩容后的新槽**
（未初始化内存）会「释放」**垃圾句柄**；依赖 `cn_free_tracked`（仅在册释放）空安全，
但**若垃圾值恰为某个在册串地址 → 误释放活动串（UAF）**。本轮核验该隐患的可构造性。

### 机制复核（静态）

- `cn_free_tracked(ptr)`（`src/runtime/io_api.cpp:121`）：`ptr != nullptr && trackedUnregister(ptr)`
  → **仅在册释放**，不在册**静默忽略**（78 段错误加固的产物）✓
- 误释放成立需**三重条件同时满足**：①新槽内存含**句柄值**；②该值对应**当前在册**的串；
  ③该槽在本轮写入时被 preFree 读到。

### 构造尝试（探针 P32，两版）

| 版 | 构造手法 | 结果 |
|---|---|---|
| P32-1 | `栈<字符串>`（容量 8 → 数组块 64 字节）→ 压入 5 个 + **弹出 1 个**（句柄移交调用方=**在册**、槽内保留句柄值）→ 栈析构（弹出槽不在有效范围 → **不释放**、数组块归还且**含在册句柄**）→ 新建 `向量<盒子>`（16 字节/元素 ×4 = 64 字节，同尺寸）→ 追加 1 次（写槽 0=偏移 0） | 未触发（`到手` 内容完好） |
| P32-2 | 同上 + **三追加**（覆盖偏移 0/16/32 —— 偏移 32 恰对位旧块的「弹出槽」） | 未触发（内容完好、长度 33 不变） |

**未能构造的机制原因（如实登记）**：
1. **对位耦合**：旧块中「在册句柄」的槽位（弹出槽=偏移 32）需与新容器的**写入槽 2** 精确
   对齐——追加顺序/元素数/扩容时序任一变化即错位；
2. **在册性耦合**：旧块其余槽多为**已释放**句柄（不在册 → 静默忽略）；弹出的句柄**无其他
   持有者**时即使命中，后果是**泄漏方向**而非 UAF；
3. **`realloc` 搬移**：glibc 对**扩大**请求常直接搬移（新块新页 → 内容为新内存 = 非旧句柄），
   复用仅发生在可原地扩展/同尺寸链命中时。

### 结论与登记

- **核验结论：未能构造**（探针两版均未触发；维持**观察项**，优先级低）；
- **加固方向登记**（若未来确认风险）：①`cn_free_tracked` 加**代际/类型校验**（成本高，需
  分配元数据扩展——Rust 的「类型化指针」同族思路）；②为「新槽写入」增设编译器挂点
  （**无 preFree 的纯写入**，语义=构造新元素而非赋值旧元素——Rust `ptr::write` 同款）；
  ③stdlib 写入前清零目标槽的串字段（泛型层不可表达字段名 → 需编译器注入挂点，与②同根）。
- **附带观察**：探针 P32-2 三追加的分配增量 = +7（3 串副本 + 数组 + 3 额外）——额外 3 个
  分配来源未定位（疑与 84-a 表达式位字面量的临时/或 preFree 相关路径），**登记为下一轮
  观察项**（非所有权缺陷·不影响正确性）。

### 诚实边界（84-f）

- **本轮零代码改动**（核验轮）：验证链沿用 84-e 终值（零警告 / 单测 1306/1306 / E2E 268
  用例 264 过 0 失败 / 固定点 326126 / 对拍 34/34）——**E2E 234~241 门禁保持全绿**（无改动，
  无需重跑）；

## 二十六、第八十五轮：聚合返回位所有权链断裂根治（85-a，2026-09-12）

**本轮线索**：84-g 登记的「宿主字面量实参每字段多一次 `__cn_str_copy`（性能项）」。复核该登记项时
发现它与 v2 的差异实为**释放时机**（登记项**证伪**），而在复核过程中**揪出真缺陷**——「聚合返回位
所有权链断裂」（宿主与 v2 两侧同现，数据正确性/安全级 UAF）。

### 一、84-g 登记项复核：**证伪**（探针 P36/P37）

| 口径 | 宿主 | v2 | 结论 |
|---|---|---|---|
| 构造后净增量（P34/P36） | +9 | +6 | 差 3 ≠ 复制次数差 |
| **分配事件数**（逐项分解） | 9 | 9 | **完全相同** |
| 分解式 | 4×`字符串复制` + 4×元素深拷 + 1 数组 | 同 | 元素槽各持独立副本，语义两侧一致 |
| 差 3 的来源 | 实参临时字段串**推迟到块出口**释放（79-a 名单） | 调用后**立即**释放（`清理调用实参临时`） | **释放时机差异**，非冗余复制 |
| 汇编核对 | `cn_main` 4 处 `__cn_str_copy`（=4 次 `字符串复制`）+ 容器方法 4 处（元素深拷 ×4） | v2asm.s 4 处 + 供给 obj 同 4 处 | 运行时复制次数两侧同为 8 |

⇒ 84-g 的「宿主优化项（字段写入归一化改走接管分支）」**不成立**（没有冗余复制可消除）；真正的
差异（实参临时的释放时机）属**生命周期**差异：v2 更贴近 Rust「临时值在语句末释放」，宿主为块出口。
宿主若跟进「调用后立即释放」会**加剧**下节缺陷（同块内即悬垂）——故本轮**不动**该路径，仅在本文登记。

### 二、缺陷：聚合返回位所有权链断裂（**宿主与 v2 同现**）

**现象**（探针 P38，两侧同一份源码）：

```
函数 收盒(盒子 b) -> 盒子 { 返回 b; }
盒子 收一; { 收一 = 收盒(盒子{ 名 = 字符串复制("…") , 号 = 7 }); }   // 源 place 退出作用域
搅动();                                                              // 覆盖已释放内存
打印(收一.名);   // 修复前：宿主 [乱码] / v2 [乱码]；修复后：内容完好 ✓
```

**根因**：返回类型含拥有型串字段（结构体/结果/可选）时，**聚合返回契约**规定返回值的句柄归
**调用方**（调用方各接收位一律按 owned 处理：声明/赋值=浅拷接管、入容器=元素槽独立、实参位=
调用后清理），但 `返回 <借用来源>` 只做按位 memcpy → 返回值的句柄与**调用方实参 place / 全局 /
容器元素**共享 → 调用方（或其 place 持有者）释放后，返回值字段**悬垂**。
Rust 对照：`fn f(b: 盒子) -> 盒子 { b }` 中 `b` 是**拥有**的（按值传入=move in），返回即 move out；
CN 的按值形参是「调用方 place 的浅拷副本（借出视图）」——被调方**不拥有**该句柄，故返回值必须先
拥有化（clone / 深拷），否则所有权链断裂。

**形态矩阵**（探针 P40）：

| 形态 | 宿主（修复前） | v2（修复前） | 归属 | 本轮 |
|---|---|---|---|---|
| ① 返回按值形参（实参=字面量临时） | 乱码 | 乱码 | 借用来源 | 深拷 ✓ |
| ② 返回全局静态结构体 | 段错误 | — | 借用来源 | 深拷 ✓（宿主；静态面另有缺陷，见下） |
| ③ 返回形参的嵌套成员链 | 乱码 | 乱码 | 借用来源 | 深拷 ✓ |
| ④ 返回拥有局部的成员链 | 乱码 | 乱码 | 借用来源 | 深拷 ✓ |
| ⑤ 返回指针解引用 `*p` | **基线段错误 rc=139** | 乱码 | 借用来源 | 深拷 ✓（并修基线段错误） |
| ⑥ 返回拥有局部（move） | 正常 | 正常 | 拥有来源 | 零拷贝不变 |
| ⑦ 返回结构体字面量 / 调用返回 | 正常 | 正常 | 拥有来源 | 零拷贝不变 |
| ⑧ 容器读出接口（元素/读取/获取…） | 正常 | 正常 | **借出视图（豁免）** | 不拥有化 ✓ |

**附带揪出的两个独立缺陷**：

- **④ 基线段错误（rc=139）**：`返回 *p` 在修复前即崩溃——`genExpr` 对解引用 place 的读值降级为
  「把结构体首字段当地址」（汇编实证 `mov r9,[r10]; mov r10,r9; mov [rbx],…`）。修法=源地址一律取
  **左值地址**（`lvalueAddress`，左值地址单一事实源，与 引用返回 路径同款）→ 已同轮修复。
- **② 静态结构体不支持**（登记，独立面）：`.data` 段静态槽恒为 8 字节（`.quad 0`，未按类型尺寸分配），
  且 `静态盒 = 盒子{…}` 被编译为 `store 0`（字面量赋值丢值）→ 结构体静态变量整体不可用。
  登记为下一轮靶子（三方案见「登记项」）。

## 二十九、第八十八轮：v2 实参位短路栈失衡根治（88-a，2026-09-12，深度机 linux-x86_64）

**立案来源**：87-a 登记项「v2 实参位短路栈失衡」（**下一轮第一优先**，附探针与诊断链）。
87-a 诚实边界原文：「`f(a || b)`（短路运算在**调用实参位**）→ `生成调用` 弹实参后被调取到
残留寄存器 → `[ir2] 调用被调对象非函数名/方法` + 运行时错误6；根治方向=统一「表达式求值
净栈 +1」不变量契约为单一事实源（先做栈模型普查）」。

### 一、栈模型普查（先做，再动手）

**契约（普查结论）**：`生成表达式(区间)` 的**净栈增量恒为 +1**（求值结果=栈顶元素；无值
形态返回 0 且净 0）。全部消费点分两类工作：

- **相对栈顶消费**：`生成调用` 弹（实参数 + 被调）/二元弹 2/下标弹 2/方法接收者弹对象；
- **弹到进入前深度归位**：三元/一元/取地址/结构体构造字段（既有正确形态）。

**破坏者定位（两处叠加）**：

| # | 层 | 缺陷 | 实证 |
|---|---|---|---|
| S1 | 语法层 | `解析二元链` → `解析二元层` 的「左起点」= `池.大小()`（左操作数**之后**——左操作数已由 `解析表达式` 前段解析）→ `\|\|`（层1）/`&&`（层2）节点的左操作数区间 `[子起点, 附加)` **恒为空** | 探针 dbg：`标 \|\| 假` 收集短路 `子起点=28=附加`（左操作数在 27） |
| S2 | IR 层 | `生成短路求值` 「只压不弹」——左递归 +1/右递归 +1/末尾结果 +1（净 **+3**） | 弹前栈 `[1 2 -30 3 4 8]`：实参弹 2 后被调取到 `3`（应为 `-30`） |
| S3 | 消费端 | 两处叠加 → `f(a \|\| b)` 弹栈错位 → `[ir2] 调用被调对象非函数名/方法` + 运行时错误6 | 探针 P88：`取值(甲, 甲 + 2, 判(甲) \|\| 标)` 双侧对照（宿主 ✓ rc=0 / v2 中止） |

### 三、实施（性能第一、安全第二；v2 单侧）
