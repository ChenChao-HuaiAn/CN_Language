## 三、方法论（与 lessons 第七十二轮互补）

1. **探针实测优先于读代码推断**：泄漏/悬垂用 `内存::活动分配数()` 差值与搅动复现量化；生成物层对照（IR/asm 有无 `__cn_str_free`）；与 clang/gcc 输出对照（ABI 契约）。
2. **静态审查与探针两条腿**：探针测得出泄漏/悬垂，测不出死代码/命名失准/注释不符/状态清理不对称——后者靠 diff 审读（本轮 4+1 瑕疵全由静态审查发现，其中顺带揪出类方法返回路径真缺陷=探针 87 实证）。
3. **修前先实证、修后看归零**：每处修复先跑探针拿到非零残留，修复后归零，证据入提交信息。
4. **矩阵空白=靶子**：每轮收尾扫一遍第一节，未填格与「靶子」标记即下一轮立案候选。

### 三-B、移植纪律（73-a 订立，**每轮触碰所有权语义时逐条执行**）

> 背景：宿主与 v2 是**两套独立实现**（v2 为重实现，非移植）——同一语义机制两侧常各自重写，
> 「各自功能测试全绿」**不能**推出「行为等价」。73-a 的 P0 缺陷正是分叉产物：v2 块级 RAII
> 从未生效而用例全绿（那些用例只断言内容，泄漏不改内容）。

7. **移植清单两件套（主体 + 不变量）**：凡从宿主向 v2（或反向）移植机制，先写明两行再动手——
   - **机制主体**：如「跳出前按基线释放」（73-a 的 drop-on-jump）
   - **依赖不变量**：如「释放后槽清零（`emitStringFreeFor` / `零寄存器`）——多路径共享槽的幂等前提」

   不变量**必须逐条验证落地，禁止凭「看起来像冗余」跳过**。73-a 首版 SIGSEGV 的直接原因就是读宿主实现时把清零当成防御性冗余而只搬了主体（`free <- cn_free <- ~向量` 双释实证）。
   移植完成的自检问句：**「这个机制假设的另一半在哪里？」**

8. **释放路径两侧对照（每轮改释放路径必做）**：`bash scripts/cn_release_parity.sh` 拉出两侧
   释放挂点清单（宿主 `genStringFrees`/`genClassDestructorCalls`/`genJumpDestructFrom`/`genBlockExitDestruct`/`emitStringFreeFor`/`emitClassDeleteFor` ↔ v2 `发射字符串释放`/`发射容器析构`/`发射容器字段析构`/`循环跳出析构`/`块出口析构`），逐条人工核对三列：

   | 核对列 | 问句 |
   |---|---|
   | **时机** | 释放发生在 块出口 / 跳出前 / 函数尾 的哪一种？两侧一致吗？ |
   | **条件** | 跳过名单（返回移出 / 装箱 move / 污染名 / 已装箱名）两侧一致吗？ |
   | **不变量** | 是否依赖「释放后槽清零」？两侧都搬了吗？ |

   脚本末尾有「释放+槽清零」两测非零计数（单侧为 0 即报警）。**清单是核对入口，不是结论**——语义等价性须人工阅读，机械对比会漏掉「时机」这类差异（73-a 的缺陷正是时机差异）。

9. **同结构双编译器对照（发现重实现分叉的唯一系统性手段）——已门禁化（217）**：同一段小程序在宿主与 v2 **各编一次**，
   比对**生成物层**（asm 中有无 `__cn_str_free` / `~类` / `__cn_object_delete`）与**运行级**（`内存::活动分配数()` 差值），而非仅比对程序输出。

   **门禁用法（首选，无需手工）**：用例目录放 `双编译对照.txt`（键与 `v2闭环.txt` 同格式）+ 源码（自带内存断言、折入退出码校验和）——runner 自动走「双编译对照」编排：
   - 宿主侧真实管线编译运行 → 断言退出码 == 用例期望值（**宿主语义锚定**，防两侧同错反而"对照通过"）
   - v2 侧以宿主实测值为期望走既有 v2 闭环 → 断言两侧退出码一致（**等价性判据**）
   - 两侧任一形态的释放机制失效（不释放/晚释放/双释）→ 该校验位丢失 → 退出码变化 → 对照失败

   首个用例：**E2E 217_双编译对照块级RAII**（五形态：继续跳出/中断跳出/自然回边/如果体/容器跳出，退出码 31）。反证实证（73-a 订立时）：故意注入「缺 继续 drop-on-jump」→ v2 侧退出码 31→0（探针残留 974）；故意注入「释放点缺清零」→ 同样 31→0——两类缺陷形态门禁均可捕获。

   **手工手法（补充场景）**：写最小 CN 源两侧各 `build` 一次 → `grep -c` 释放调用 → 差值对照；需运行级数字时用 `LD_PRELOAD` + `__attribute__((destructor))` 读 `__cn_alloc_live`（手法见 /tmp 探针历史）。
   连带原则：**防线不对称本身即缺陷候选**（宿主有内存回归用例而 v2 无对应件时同轮补建，213 ↔ 216_v2 为第一对）；**文档声明须带验证状态**——矩阵格只能写「实测通过（证据）」或「未验证（靶子）」，禁止把读代码的推断写成事实（73-a 的 A1 格原载「v2 已有块出口析构」即此类误载，已回改）。

10. **两侧同缺的修复要一次修全**：lessons 第七十二轮预防⑥已载，73-a 仍复发（宿主 72-a 的 drop-on-jump v2 侧隔一轮才补）。改动任一侧释放机制时，**当场核对另一侧是否有同族缺口**（用第 8 条对照清单），不留给下一轮。
