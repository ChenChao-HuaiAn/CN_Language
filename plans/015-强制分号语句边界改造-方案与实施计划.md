# plans/015 — 强制分号语句边界改造（方案B·Rust 式）方案与实施计划

> **状态：呈报件——等用户批阅后方可实施（AGENTS.md「报告类产出必须等用户批阅」纪律）**
> 立项时间：2026-09-04（第十一轮，用户裁决方案B）
> 级别：**规范级变更**（plans/001 与 cn-language-spec 01a/03 条目反转）+ 全库存量迁移

## 一、背景与裁决

CN 现规范是「可选分号 + 换行≡空格」——语句边界无任何词法标记，本项目实测粘连事故链：
`泛深--` 换行 `类型文本 = ...` 粘连成非左值赋值（本轮簇③）、`&v` 换行 `(*q)++` 粘成调用（lessons 一日三踩）、`p.y = 3` 换行 `--p.y` 粘成 `3--`、复合赋值解析缺口静默截断（冒烟假绿）。共同模式：**行尾与下行行首词法可拼时，解析器无从知晓两条语句的意图**，只能靠检查器事后拦截（运气非设计保证）。

2026-09-04 用户裁决：**方案B 强制分号（Rust 式）**——Rust/C++ 同款「表达式语句必须 `;` 终结」（Rust 唯一免分号场景=块尾表达式；CN 是语句式语言、无块尾表达式语义，故全强制）。方案A（Swift 式换行敏感 ASI）与方案C（Python 式换行即终结）已被裁决排除。

## 二、规范变更明细（plans/001 + cn-language-spec 双侧）

| 条目 | 现行 | 变更后 |
|------|------|--------|
| 01a「语句终止与续行」 | 换行≡空格（换行与空格同为空白） | **语句必须 `;` 终结**；换行在表达式内部仍≡空白（`整64 x = 1 +` 换行 `2;` 合法——运算符悬挂续行不受影响）；括号/方括号/花括号包围上下文内换行≡空白不变 |
| 03「语句终止」 | 显式 `;` 为「稳定支持」的可选项（单语句换行免分号） | **显式 `;` 为强制项**：变量声明/赋值/自增自减/复合赋值/表达式语句/返回/中断/继续/顶层常量与静态声明 须 `;`；`}` 自终结（块/如果/当/循环/函数体/结构体/类体后不加）；**行内块 `{ x = 1; }` 内部语句同样须 `;`** |
| 循环头三段分号 | 唯一强制分号（三段分隔符） | 保持不变（与语句终结符语义无关） |
| 导入语句 | 无分号 | `导入 路径;`（对齐 Rust `use ...;`）——**待用户确认**（或对齐 C 预处理惯例免分号，见 §五-3） |

## 三、实现变更（宿主 + v2 双侧对称）

### 宿主（src/cn_compiler）
1. parser：语句级解析（parseStatement 及各分支）消费语句后**要求 `;`**——缺失报错「语句缺少分号 ';'+ 行列定位」（错误即诊断，杜绝静默粘连）；`}` 前 token 若为语句结尾同样要求。
2. 词法零改动（`;` token 已有——显式分号「稳定支持」现状）。
3. 错误恢复：缺分号诊断后可继续（按行号推断边界），保证一次编译报全量缺分号位置。

### v2（CN语言编译器v2）
1. 语法分析.cn：解析语句 各分支返回前消费 `;`（缺失=诊断计数+按行界推进——v2 无行号诊断惯例则 运行时错误(303) 行号码或诊断数组）；解析块 循环按分号切分。
2. **块截断静默家族整体消亡**：孤儿 token 即缺分号诊断——「复合赋值假绿」类事故结构性根除。
3. 词法零改动。

## 四、存量迁移（自动化脚本 + 全量门禁）

1. **迁移脚本**（python，一次性工具，用后删除）：解析 .cn 源码（词法级：注释/字符串/嵌套块感知），在「语句结尾 token（标识符/字面量/`)`/`]`/`++`/`--`）后跟语句边界（`}`/换行后的语句起点/EOF）」处补 `;`。风险点：换行≡空格的既有续行写法（运算符悬挂行尾）不会被误判（其行尾 token 是运算符）。
2. 迁移范围：`tests/e2e/*/主.cn`+`.expected`（146 用例）、`CN语言编译器v2/*.cn`（12 文件）、`stdlib/*.cn`（10 文件）、单测源码 `tests/unit/` 嵌入源码字符串、`plans/` 文档内代码示例（可选）。
3. 门禁：迁移后全量 E2E（146）+ 单测（1216+）+ v2p 冒烟 5 组件 0 错——三重验证逐行比对 expected 零漂移。
4. **回退保护**：git 分支操作，迁移单独一个提交（可整体 revert）。

## 五、待用户确认项

1. **导入语句分号**：`导入 路径;`（Rust use 同款，推荐——一致性）或免分号（C #include 惯例）？
2. **顶层 常量/静态声明**：`常量 T = 2;`（推荐——C++ const 同款）确认？
3. **实施时机**：本轮（第十一轮）收尾后立即专项实施；或与 IR生成.cn 冒烟 96 错消化轮并行（建议**专项独占轮**——万行级迁移不宜与其他改动混提交）。
4. 迁移脚本产出的用例 diff（尤其 expected 逐行比对）作为迁移正确性证据随轮呈报。

## 六、风险与代价

- 迁移量：万行级（自动化为主，人工复核 `expected` 与语义敏感处）。
- 写法变化：无分号源码（现有全部 CN 代码）将编译失败——**规范反转的必然代价**，一次迁移终身受益（Rust 十年生产验证的模型）。
- 对拍链路：v2p 编译 v2 组件（自举冒烟）同规则——迁移后 v2 组件即符合新规范。
- 星号歧义（`a * b` 乘法 vs 声明）等**单行内歧义不受本方案影响**（独立观察项，另行裁决）。
