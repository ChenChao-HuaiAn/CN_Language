## 一、总体判断：三项是一个体系的三块拼图

| 项 | 维度 | 缺口本质 |
|---|---|---|
| B3 | 资源**字段** | 字符串字段已有「三件套」（写入位归一化／拷贝位深拷／消亡位释放，79-a），容器字段只有浅拷共享＋无释放面——**设施是类型专用的，未通用化** |
| B4 | 跨函数**边界** | `转移()` 第一版只是编译期标记（运行行为仍深拷），零拷贝只在入容器位落地；表达式位转移未支持、聚合真 move 未落地——**「真 move 设施」缺位** |
| B5 | 安全**边界** | 观察期五类检查：宿主有、v2 侧未实现；迁移面（stdlib 泛型体 / tests / v2 树）实际未清零；且存在宿主误报缺陷——**收口前置未就绪** |

因此最完美的做法是：**一次把底层设施做成类型无关的统一体系**（资源字段设施通用化 ＋ 真 move 设施
落地），三项缺口随同一设施一次性关闭；安全边界（B5）在同一设施之上收口为硬错误。

## 二、目标蓝图：CN 所有权模型五层（性能打满、安全打平 Rust、体验优于 Rust）

| 层 | 机制 | 语义 / 性能 | 现状 |
|---|---|---|---|
| ① 默认层（零规则） | 值语义深拷 ＋ RAII | 不学所有权也能写出安全代码（CN 相对 Rust 的体验优势，**保留**）；代价是拷贝 | ✅ 已有 |
| ② 显式层（零拷贝） | `转移(x)` 真 move：IR 槽位交接 ＋ 源槽禁用 ＋ 析构跳过已转移槽 | 用户显式声明，O(1) 交付所有权；编译器保证 moved-from（E0382 对标） | ⚠️ **半成品**：第一版=纯编译期标记（实测 `盒子 移 = 转移(甲);` 仍 +1 次深拷）；零拷贝仅入容器位（74-a/75-a） |
| ③ 借用层（只读零拷贝） | `T&` 引用 ＋ `字符*` 借用视图（A2 已裁决） | 零拷贝观察；生命周期由编译期检查器保证（77-a 借出检查、内联/跨函数形态） | ✅ 主体已有 |
| ④ 显式克隆层 | `字符串复制` 已有；**新增统一 `复制(x)`**（结构体/容器/结果可选） | 拷贝意图可见（性能可见性）；为「A2 式显式政策」留门 | ⚠️ 聚合克隆缺失（85-a 丙案因此不可行） |
| ⑤ 编译器省略 | 活性分析证明源 place 已死时，自动把深拷降级为 move（语义不变） | **免费性能**（NRVO 的推广版）；与 3b「跨语句 NLL 活跃区间」共享基础设施 | ⚠️ 仅「返回拥有局部」单点 |

**为什么这是最完美而不是妥协**：C++ 的性能来自「拷贝/移动构造 ＋ RVO」；Rust 的安全来自
「move 唯一所有权 ＋ 借用检查」。本方案两者各取所长——默认路径比 C++ 更安全（无浅拷别名），
显式路径与 C++ 同级（真 move 零拷贝），并有 C++ 没有的编译期 moved/借用拦截；体验上用户不写
任何标注也能安全，想快时写一个 `转移()` 即可。**这是同时满足「性能超 C++、安全接近 Rust」的
唯一自洽形态**，完全延续 plans/019 立项时用户认可的三句设计哲学（默认零规则／显式放弃安全=显式
获得性能／危险面收口而非全语言戒严）。

## 三、B3 最完美方案：资源字段统一化（容器字段纳入三件套）

### 3.1 现象（实测，全部为完整可编译用例，`cn.exe build` rc=0、运行 rc=0）

```cn
导入 容器::向量;

结构体 货架 {
    向量<字符串> 记录;
    整32 号;
}

函数 主() -> 整32 {
    整64 起 = 内存::活动分配数();
    {
        货架 甲;
        甲.记录 = 向量<字符串>();
        结果<空类型, 整32> 加 = 甲.记录.追加(字符串复制("值"));
    }
    打印("形一 结构体块出口后增量 = ", 内存::活动分配数() - 起);
    返回 0;
}
```

实测输出（探针 `b3_字段容器.cn`，五形态）：

| 形态 | 代码要点 | 实测 | 含义 |
|---|---|---|---|
| 形一 | 上例：成员位赋值＋块出口 | 增量 **2** | 容器对象与元素串都不释放（**消亡位缺失**） |
| 形二 | `货架 乙 = 甲;` 后读 `乙.记录.大小()` | **2** | 结构体整体拷贝时容器字段**浅拷共享**同一容器（**拷贝位未深拷**） |
| 形三 | `甲.记录 = 向量<字符串>();` 覆盖旧值 | 增量 **4** | 旧容器不释放（旧新两份都占着） |
| 形四 | `乙.记录 = 甲.记录;`（来源=另一字段） | **2（共享）** | 字段位赋值来源无归一化（**写入位缺失**） |
| 形五（对照） | **类**字段容器 `账本 甲 = 账本();` 块出口 | 增量 **0** | **类**的容器字段已正常释放（析构级联，79-a/83-a 已闭环） |

**缺口只限结构体侧**；形二/形四同时证明：浅拷共享下**不能只加释放面**（两端共享句柄，谁释放谁制造
悬垂）——所以必须三件套同时做。

### 3.2 最完美形态（语义取「深拷」，性能靠 B4 真 move——不做甲/乙二选一）

1. **语义**：容器字段走与字符串字段同一套「资源字段三件套」——**零语义变更**（延续「结构体赋值＝
   深拷」契约）。**不采纳「甲：容器字段 move」**：同一结构体里字符串字段深拷、容器字段 move 会产生
   「部分 move 的结构体」（`货架 乙 = 甲;` 后 `甲.记录` 失效但 `甲.号` 仍可用），与 Rust 的
   「整体 move」不一致，是不可接受的语义分叉。
2. **性能**：容器字段的拷贝点同时接入 B4 真 move 设施——`甲.记录 = 转移(乙.记录)`、`转移(局部容器)`
   走 O(1) 槽位交接，零拷贝由用户显式获得。
3. **设施升级（推倒重来清单第 2 项）**：把三件套从「字符串专用」抽象为**所有拥有型资源通用**
   （字符串 / 容器 / 结果 / 可选 / 类对象 / 嵌套结构体 / 数组；含递归深度防御与联合体条件释放），
   单点事实源，宿主与 v2 双侧同构。
4. **一并关闭历史尾巴**：H7/H11「字段容器接收者入容器位归一化保守分支」（残留 1）——字段容器
   接收者走拥有契约接管。
5. **验收**：结构体容器字段全形态（本值/整体拷贝/成员覆盖/字段位赋值/入容器/嵌套/循环/跳出/
   函数尾）残留归零；E2E 双编译对照 ＋ 反证 ＋ 搅动内容校验；plans/020 矩阵「资源字段」相关格
   全部从「靶子」转为「已实现＋有门禁」。

## 四、B4 最完美方案：真 move 设施（阶段 3 补完）＋ 统一克隆内置

### 4.1 现象（实测）

完整可编译对照（探针 `b4_返回形参_规范构造.cn`，五点测量＝逐段读 `内存::活动分配数()`；
对象创建一律使用 **CN 规范构造字面量** `盒子{ 字段 = 值 }`——`创建盒子` 是示例自定义的**普通辅助函数**，
非语言构造语法，仅用于第⑤段「返回拥有局部」零拷贝对照）：

```cn
结构体 盒子 {
    字符串 名;
}

函数 转发(盒子 参) -> 盒子 {
    返回 参;
}

// 示例辅助函数（普通函数，非语言构造语法）：供第⑤段「返回拥有局部」对照
函数 创建盒子(字符串 内容) -> 盒子 {
    盒子 b;
    b.名 = 字符串复制(内容);
    返回 b;
}

函数 主() -> 整32 {
    整64 基点 = 内存::活动分配数();
    盒子 甲 = 盒子{ 名 = 字符串复制("内容甲乙丙丁戊己庚辛") };   // 规范构造字面量
    整64 p1 = 内存::活动分配数();
    盒子 借转 = 转发(甲);
    整64 p2 = 内存::活动分配数();
    盒子 移转 = 转移(甲);
    整64 p3 = 内存::活动分配数();
    盒子 副本 = 借转;
    整64 p4 = 内存::活动分配数();
    盒子 直返 = 创建盒子("内容甲乙丙丁戊己庚辛");
    整64 p5 = 内存::活动分配数();
    打印("①构造字面量（含 字符串复制） = ", p1 - 基点);
    打印("②转发(借用实参) 返回       = ", p2 - p1);
    打印("③声明位转移 转移(甲)        = ", p3 - p2);
    打印("④结构体整体拷贝             = ", p4 - p3);
    打印("⑤工厂函数返回（拥有局部）    = ", p5 - p4);
    打印("读回长度: ", 字符串长度(借转.名), "/", 字符串长度(移转.名), "/", 字符串长度(副本.名), "/", 字符串长度(直返.名));
    返回 0;
}
```

| 段（五点测量，实测输出 1/1/1/1/1） | 实测增量 | 判读 |
|---|---|---|
| ① 构造字面量（含 `字符串复制`） | 1 | 字面量字段值的拥有化复制 |
| ② `转发(甲)`（借用实参） | **1** | 返回借用来源=深拷归一化（85-a 乙：安全但每次转发 O(n)） |
| ③ `盒子 移转 = 转移(甲);` | **1** | **转移对聚合目前不是零拷贝**（第一版=纯编译期标记） |
| ④ `盒子 副本 = 借转;`（整体拷贝） | 1 | 值语义深拷（79-a） |
| ⑤ 工厂函数返回（拥有局部） | 1 | 函数内 `字符串复制`；返回位本身零成本（拥有局部零拷贝） |

另有**编译期实证**——表达式位转移当前被拒绝。实证方式＝下面这份**完整合规程序**（除标注行外全部编译通过），
在标注行实测得到拒绝诊断（诊断原文）：

```cn
// 目标形态（本方案批准实施后）：转移实参 → 形参获得拥有归属，返回直移零拷贝。
// 当前实测：本程序在「盒子 丁 = 转发(转移(甲));」行被编译期拒绝，诊断原文——
//   错误: 变量 '甲'（类型 '盒子'）的转移仅支持声明初始化位（类型 名 = 转移(变量);），
//         表达式位转移随 plans/019 阶段3 浅拷贝优化支持
结构体 盒子 {
    字符串 名;
}

函数 转发(盒子 参) -> 盒子 {
    返回 参;
}

函数 主() -> 整32 {
    盒子 甲 = 盒子{ 名 = 字符串复制("内容") };   // 规范构造字面量
    盒子 丁 = 转发(转移(甲));                    // ← 当前被拒绝行（缺口实证）
    打印(字符串长度(丁.名));
    返回 0;
}
```

### 4.2 最完美形态（把「真 move」做成完整设施，而非让用户在「深拷」与「改语义」之间选）

| # | 内容 | 说明 |
|---|---|---|
| 1 | **转移全位置支持** | 声明位 / 赋值位 / **表达式位（实参）** / 返回位 / 成员位 / 下标位——实测上述「表达式位」被拒绝，是最大缺口 |
| 2 | **IR 真槽位交接** | 句柄直拷（O(1)）＋ 源槽清零；`源槽禁用标记` 传 IR；**RAII 析构路径跳过已转移槽**（plans/019 阶段 3 原设计已标风险点，须反证） |
| 3 | **拥有形参归属** | `f(转移(x))`：形参获得拥有归属——被调方负责析构（或其 `返回 参` 直移零拷贝）；未写转移时维持现状「借用视图＋返回位深拷归一化」 |
| 4 | **返回位政策** | 借用来源=深拷归一化（乙已实施，保留：安全默认、零破坏）；拥有来源=零拷贝（已有）；形参拥有=直移（新增） |
| 5 | **新增统一克隆内置 `复制(x)`** | 覆盖字符串/结构体/容器/结果可选；与 `转移(x)` 构成显式「复制/移动」双内置（C++ copy/move 对照物）。这也是 85-a 登记的「丙：返回位拒绝」将来可重估的前置条件（届时聚合返回位可对齐 A2 字符串的显式契约） |
| 6 | **推倒第一版实现（清单第 1 项）** | 删除「语义层把转移 AST 改写为标识符」的临时手法，按 IR 槽位交接重做，宿主＋v2 双侧同构 |

**为什么不做「甲的完整语义」（形参全拥有、隐式 move）**：那等于把 CN 变成 Rust——所有按值实参在
调用后失效，除非用户学借用；牺牲第①层「零规则」的体验优势；且实测表明它依赖的基础设施（表达式位
转移、聚合真 move）恰好都还没落地。**正确顺序恰是先建真 move 设施**：建成后「甲」的全部性能收益
都能通过 `f(转移(x))` 显式获得，而存量语义变更代价为零。

### 4.3 验收

`转移` 六位置零拷贝实证（分配增量 0 探针）；moved-from 全链拦截（含再转移/成员/下标/实参/返回）；
析构跳过已转移槽的反证（注入失败即 double free，须被门禁捕获）；**性能锚**（大聚合/大容器转发路径
分配次数从 N 到 0）；全树零误伤。

### 5.2 现象示例（合规完整代码）

观察期现状（E2E 204 用例同款语义面）：

```cn
联合体 数值 {
    整32 甲;
    浮64 乙;
}

函数 主() -> 整32 {
    数值 u;
    u.甲 = 3;                     // 观察期警告（不阻断）：
                                  // [安全区边界·观察期] 联合体字段访问应在 不安全 函数 内（数值.甲）
    打印(u.甲);
    返回 0;
}
```

收口后：该形态在安全函数中＝**编译错误**（须包进 `不安全 函数`，或改写为安全抽象）。

v2 树误报实例（宿主缺陷，取自 v2 源码实测警告）：

```cn
函数 函数签名键(整64 名ID, 字符串 参数串) -> 整64 {
    如果 (字符串长度(参数串) == 0) { 返回 名ID; }
    返回 驻留(驻留文本(名ID) + "#" + 参数串);   // 误报「指针算术」——这是字符串拼接，非指针运算
}
```

### 5.3 收口本体与「立即收口会发生什么」

收口＝警告切硬错误＋删除「观察期／分批收口后变错误」字样＋204 用例迁移为负测＋反证实验
（收口后原形态编译失败）。若立即收口的后果（实测推演）：① v2 自举链断裂（75 处误报变错误，
宿主编译不出 v2p）；② stdlib 容器不可用（实例化即错）；③ 约 40 个 E2E 用例编译失败。

**收口时点修正建议**：不再以「无期限反馈期」为唯一等待理由——改为「**迁移面清零 ＋ 不安全清单
实现完毕 ＋ v2 侧检查上线**之后立即收口」；反馈期改为与迁移并行执行的「误报观察」，不阻塞收口。
