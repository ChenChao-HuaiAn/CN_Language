### 四、技术方案

#### 4.1 自举侧后端接口设计（CN语言，参考spec 06 OOP规范）

```cn
// 后端接口.cn — 抽象后端接口
接口 后端接口 {
    虚拟 函数 目标平台() -> 字符串
    虚拟 函数 段头(字符串 段名) -> 空类型
    虚拟 函数 段尾() -> 空类型
    虚拟 函数 函数头(字符串 名, 整数 槽数) -> 空类型
    虚拟 函数 函数尾() -> 空类型
    虚拟 函数 发射指令(整数 行类型, 字符串 行文本) -> 空类型
    虚拟 函数 发射加载(整数 槽, 整数 类型) -> 空类型
    虚拟 函数 发射存储(整数 槽, 整数 类型) -> 空类型
    虚拟 函数 发射运算(整数 运算类型, 整数 类型) -> 空类型
    虚拟 函数 发射调用(字符串 符号, 整数 参数数) -> 空类型
    虚拟 函数 发射字面量(字符串 值, 整数 类型) -> 空类型
    虚拟 函数 发射外部声明(字符串 符号) -> 空类型
    虚拟 函数 符号修饰(字符串 名) -> 字符串
    虚拟 函数 寄存器名(整数 索引) -> 字符串
}
```

#### 4.2 x64后端实现（从现有代码提取）

从 [`代码生成.cn`](CN语言编译器/代码生成.cn) 971行中提取x64 MASM特定代码：
- 寄存器名：`rax`/`rdx`/`rcx`/`r12`/`rbp`/`rsp`
- 指令：`mov`/`add`/`sub`/`imul`/`idiv`/`cqo`/`sete`/`setne`/`setl`/`setle`/`setg`/`setge`/`shl`/`sar`/`and`/`or`/`xor`/`neg`/`not`/`movsx`/`lea`/`jmp`/`jnz`/`jz`/`call`/`ret`/`test`/`cmp`
- 段声明：`.data`/`.code`/`END`
- 符号修饰：`?UTF8hex@@Y码@Z`
- EXTERN声明：`EXTERN printLine:PROC` 等19+个
- Win x64调用约定：`rcx`/`rdx`/`r8`/`r9` + 影子空间32字节 + 栈参 + 16字节对齐
- `__chkstk`三段式栈探测（帧大小 > 4096时）

#### 4.3 arm64后端实现（新增，镜像C++ ARM64后端）

参考C++ ARM64后端（[`arm64_codegen.cpp`](src/cn_compiler/codegen/arm64/arm64_codegen.cpp) 等）实现：
- 寄存器名：`x0`-`x30`、`sp`、`xzr`、`v0`-`v31`
- 指令：`mov`/`add`/`sub`/`mul`/`sdiv`/`udiv`/`ldr`/`str`/`bl`/`ret`/`cmp`/`b.eq`/`b.ne`/`b.lt`/`b.le`/`b.gt`/`b.ge`/`lsl`/`lsr`/`asr`/`and`/`orr`/`eor`/`neg`/`mvn`/`sxtw`/`adrp`/`add`/`str`
- 段声明：`.text`/`.data`/`.section .rodata`
- 符号修饰：`_` + UTF-8 hex（无`?..@@Y`装饰）
- AAPCS64调用约定：`x0`-`x7`参数、`x0`返回值、`x19`-`x28`被调用者保存
- 16字节栈对齐：`stp x29, x30` / `ldp x29, x30` 帧设置
- 隐藏返回指针：`x19`保存（与C++ ARM64后端对齐）
- 接口分派区填充：遍历`classInterfaces`，`adrp + add + str`写入接口分派表地址（lessons教训）

#### 4.4 IR遍历引擎

平台无关的IR指令遍历逻辑（从现有`代码生成`、`发射函数`、`发射指令`等函数提取）：
- 遍历IR模块的所有函数
- 对每个函数，调用后端接口的`函数头`/`函数尾`
- 对每条IR指令，根据类型调用后端接口的相应方法
- 处理常量池、外部声明、字符串常量等

### 五、风险评估与缓解

#### 5.1 GS栈cookie崩溃风险（⚠️ 高）
- **风险**：拆分`代码生成.cn`可能触发0xC0000409 GS崩溃（lessons记录：拆分为门面+6子模块时78/79运行期崩溃）
- **缓解**：
  1. 新拆分结构（5组件）与原拆分（门面+6子模块）不同，可能不触发相同崩溃
  2. 先在Windows x86上验证，如崩溃则调查C++后端栈帧生成缺陷
  3. 备选方案：在单文件内实现抽象（使用CN语言的类/继承特性），控制行数

#### 5.2 ARM64无法本地测试（中）
- **风险**：用户在Windows x86上，无法运行ARM64汇编
- **缓解**：
  1. ARM64后端镜像C++ ARM64后端实现（已验证通过E2E 28/28）
  2. 通过代码审查验证正确性
  3. 生成的ARM64 GAS可通过`as --dry-run`验证语法（如有ARM64工具链）

#### 5.3 1000行限制（中）
- **风险**：新文件可能超过1000行
- **缓解**：每个文件控制在1000行以内，必要时进一步拆分

#### 5.4 自举用例功能对齐（中）
- **风险**：重构后自举用例75/76/78可能因功能差异失败
- **缓解**：保持x64后端与原`代码生成.cn`行为完全一致，逐字节比对输出
