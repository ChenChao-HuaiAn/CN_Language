## 〇、摘要（一页纸）

**问题**：当前 `对象.实例方法` 作值只有两条路——①裸作 fnptr 实参=编译报错（806/107 拦截，
诊断「须先赋值给变量」）；②先赋值给变量=同帧直调绿（e2e 104），但**经函数参数转发=段错误**
（#943 主病灶·p82d 探针 rc=139）。正路目前只有闭包捕获包装（`[对象](整32 x)->整32{...}`·
p82g 实证转发安全），与用户「已写明对象」的直觉差一层倒手。

**提议**：新增语言语义——`对象.方法` 求值直接得**绑定方法值**（Python 绑定方法 / C# 委托 /
Go method value 流派），运行时载体=**栈上两字值**：`{对象引用, 方法代码指针}`，值语义拷贝、
零堆分配、零运行期检查；调用语法与现存完全一致（`cb(5)`）；不可（隐式或显式）转裸 fnptr。

**六问结论一览**：

| # | 问题 | 结论（详见 §二） |
|---|------|------------------|
| ① | 运行时表示 | **甲案：栈上两字值**（16 字节纯标量对·IR 层降低为两个 8 字节标量·零堆分配）；乙案堆小对象、丙案蹦床统一均否决/推后（§二·①） |
| ② | 类型语法与调用语法 | 类型=`方法值<类名, 返回类型(参数表)>`（形参/局部位可写；第一版存字段/返回禁用）；调用 `cb(实参)` 零新语法，与 fnptr 调用按静态类型消歧（§二·②） |
| ③ | fnptr 兼容面 | 方法值→裸 fnptr **全形态编译拒绝**（赋值/实参/返回/字段；对象丢失=静默错行为）；#943 的 `整32(*绑)(整32)=对象.方法` 过渡路径**废弃**（显式 fnptr 声明位改拒+新指路）；lambda 蹦床值↔fnptr 现状（8 字节）保持不动（§二·③） |
| ④ | 生命周期安全 | **推荐路线 a（静态作用域限制·保守逃逸检查）为主 + 路线 b（运行期存活检查）仅作 debug 纵深（不作为安全依据）**；路线 c（引用计数/共享）否决（与 CN 手动堆模型/ABI/性能冲突·未来另立 `共享<T>` 专型）（§二·④） |
| ⑤ | 双侧实现+三后端 ABI | 被调方协议零新增（this 恒为首参·与实例方法 ABI 完全一致）；调用点两形态（fnptr 间接 / 方法值注入 this 间接）；两槽传参=IR 层展开为两个连续 8 字节标量（win rcx/rdx·linux rdi/rsi·arm64 x0/x1——复用既有整型参数通道，codegen 零新协议）；双侧改动面清单见 §二·⑤ |
| ⑥ | 001 条文草案+用例规划 | §5.8c 全文草案 + dual 锁用例清单（正/边界/负三类·含 ABI 矩阵与悬垂负测）（§二·⑥） |

**推荐路线一句话**：方法值=两槽栈值 + this 首参间接调用（复用实例方法调用协议）+ 静态借用规则
（R1~R6：局部持有可拷贝/不返回/不存长寿命载体/传参=调用期借用/不安全函数豁免/转移联动失效），
性能路径与现状同帧快径同级（一次间接跳转、两个寄存器装载、零分配、零运行期检查）。

**待用户批阅决策点**：七件（§四，含两件 P3 级 AI 可自裁候选——类型写法与诊断文案）。

3. **闭包捕获正路（真跑安全）**：`变量 闭 = [对象](整32 x) -> 整32 { 返回 对象.双倍(x); };`

**本设计轮现场复核（#970 工作树·linux-x86_64·target/ 暂存探针已删）**——两条路径真跑对照
（stdbuf 无缓冲以保留崩溃前输出）：

| 探针 | 源码形态 | 输出 | 退出码 |
|------|----------|------|--------|
| p970a | `变量 cb = 对象.双倍;` 直调 + 经 `整32(*f)(整32)` 形参转发 | `直调: 105` → `转发前` → 崩溃于转发调用（两次复跑一致） | **139（段错误）** |
| p970b | `变量 闭 = [对象](整32 x)->整32{返回 对象.双倍(x);};` 直调 + 同形转发 | `直调: 105` / `转发: 105` | 0 |

结论：现状「方法值变量=裸方法符号+编译期旁路」在转发语境下**静默错行为→脏崩溃**（违 §1.1a②
「确定性失败非脏崩溃」纪律），而闭包捕获路径两形态皆安全。补充根因（核准）：闭包安全来自
「载体自带数据」——p970b 的 `[对象]` **值捕获=定义处深拷独立副本**（940 通道·
`src/cn_compiler/ir/ir_lambda.cpp:169-176`「容器/类经 evalValueCaptureCopy 深拷独立副本」），
`[&对象]` 引用捕获则受 435 逃逸限制（`plans/001 CN语言编译器设计规格书.md:676-688`）——
两条子路各自在定义处消解悬垂面。本设计轮的甲案（值自带对象引用）从根上消除旁路依赖——
转发后两槽一起走，与 p970b 同等的安全性、比 p970b 更低的包装成本。

### 1.2 三大流派对照（设计取舍的坐标系）

| 流派 | 代表 | 载体 | 生命周期保障 | 调用代价 |
|------|------|------|--------------|----------|
| 一等公民派（本设计轮对齐） | Python 绑定方法 / C# 委托 / Go method value | self+func / target+method | GC（Python/C#）·逃逸分析升格堆（Go） | 1 次间接跳转 |
| 类型区分派 | C++ 成员函数指针 | 裸指针「待配对」（`obj.*pmf` 显式配对） | 无（UB 自担） | 1 次间接跳转（虚=2 次） |
| 闭包包装派 | Rust 闭包 / Swift | 捕获环境（栈或 Box）+ 代码 | 借用检查 / ARC | 1 次间接跳转 |
| **反面教员** | JavaScript | 裸函数值 | 无——**静默丢 this**（`setTimeout(obj.method)` 报 undefined） | 1 次间接跳转 |

CN 现状=「闭包包装派的内部机制 + 一等公民派的表面拦截」：内部把 `对象.方法` 表达为绑定 this 的
闭包（spec 04-四:399-406），但对外拦掉裸用、只留「先赋值给变量」一条窄路。本设计轮=把表面
语义升为一等公民，内部机制换成**两槽值**（比闭包包装更直接的载体，性能与语义双赢）。

### 1.3 设计原则（本呈报取舍之依据）

1. **性能第一**（自举双目标①）：零堆分配优先、零运行期检查优先（§1.1a④ 哲学）——凡「优雅但
   每次创建/调用有常数或分配开销」的方案降级为备选。
2. **安全接近 Rust**（双目标②·悬垂零容忍）：方法值持有对象引用=潜在悬垂面，必须有静态或
   运行期确定性防线，禁「放行+脏崩溃」（#943 现状即反例；§1.1a 分层安全总则）。
3. **宿主与 v2 零分叉**：全部语义双侧同构落地（AGENTS §3 红线），诊断文案逐字一致。
4. **复用既有设施、不发明新机制**：调用协议复用「this 首参」（`src/cn_compiler/ir/ir_oop_call.cpp:676/736`
   this 为参数位 0）；静态检查复用 435 逃逸检查的保守传播集模式
   （`src/cn_compiler/semantic/semantic_lambda_escape.cpp:14-20`）；「转移后原名禁用」复用仿射检查。
5. **不破坏既有语义**：lambda 蹦床闭包（8 字节·作 fnptr 自由传递·e2e 1002/1044）不动；
   104 用例行为（引用语义读最新 this）保持；107/806 负测按新语义**重定义**而非删除。

## 二、六问逐答

### ① 运行时表示

**现状表示（问题根源）**：lambda 值与实例方法作值共用「单槽 + 旁路/静态槽」模型——
lambda 值 = 蹦床函数地址（8 字节·签名=用户签名），捕获快照固化 .data 静态槽
（`src/cn_compiler/ir/ir_lambda.cpp:7-12`：「?gstatic_cap$?lambdaN$<捕获名>」）；实例方法作值
= 裸方法链接符号（`src/cn_compiler/ir/ir_oop_field.cpp:632-664`），this 走编译期旁路
（同函数快径 expand captureArgs）。该模型对方法值的三大失效：
(a) **跨函数转发丢绑定**（#943：旁路表是编译期键=变量源码名，转发后不可达→段错误）；
(b) **静态槽多实例覆盖**（482/1044 与 lambda 同病已修——载体槽机制只为 lambda 设计，
    方法值走独立通道无此修复）；
(c) **递归/重入污染**（静态槽非值实例私有）。结论：对象引用必须装进**值本身**——
单槽不可救，两槽是正解。

**候选甲（推荐）：栈上两字值 `{对象指针 this, 方法代码指针 code}`**

- 形态：16 字节纯标量对（对齐 8）；值语义拷贝（两条 8 字节复制）；IR 层降低为两个 8 字节标量
  （见 §二·⑤——此为「codegen 零新协议」的关键）。
- 创建：`对象.方法` 求值 = `{Load 对象槽（对象指针）, FuncAddr 方法符号}`——两条已有指令
  （`src/cn_compiler/ir/ir_oop_field.cpp:632-664` 现在只发第二条，补第一条即得两槽）。
- 调用 `cb(5)`：`CallIndirect(code)(this, 5)`——this 注入参数位 0，与实例方法直调
  （`src/cn_compiler/ir/ir_oop_call.cpp:676`：`args.push_back(thisArg); // operand[0] = this`）
  **协议完全一致**——被调方（方法符号）零特例。
- 性能：创建=1 次 Load + 1 次符号装载（无分配）；调用=1 次间接跳转+1 次额外寄存器装载
  （this）——与 Go method value / Python bound method 同级，优于堆对象方案一个分配的数量级。
- 「逃逸升格」辨析（立项六问原文关注点）：**两槽值本身无升格问题**——它是纯标量对，被拷贝进
  任何载体（局部槽/形参/（未来）字段）都只是 16 字节复制，不存在「栈值逃逸需搬堆」的情形。
  真正的「升格」对象是 **this 指向的类的生命周期**（CN 类对象恒为堆对象·变量槽存指针——
  `src/cn_compiler/ir/ir_oop_call_release.cpp:19`「类对象在 CN 中为堆对象（NewObject 分配），
  变量槽存对象指针」）——即「对象亡、方法值存」的悬垂面，归 §二·④ 生命周期处理。
- 虚方法：`对象.虚方法` 的方法值——**创建时快照**（对对象 vtable 解析出当前实现的代码地址
  存入 code 槽）。语义无损性论证：CN 对象创建后类终生不变（无 JS 原型改写类特性），
  快照结果与「每次调用时动态分派」恒等价，且省一层 vtable 间接——采用快照。
  （对照：C++ 成员函数指针调用虚函数=调用时分派、Go 接口 method value=创建时快照；CN 取 Go 式。）

**候选乙（否决）：堆小对象（方法值=单指针句柄，指向 {对象,代码} 堆块）**

- 需要引用计数/所有权确定堆块析构时机——CN 无 GC，块的生命周期管理立刻退化为候选丙的
  全部难题；即使只分配不回收=每次创建一次 malloc（性能第一不可接受）+ 拷贝语义歧义
  （浅拷共享 vs 深拷）。
- 对照：Rust `Box<dyn Fn>` 靠所有权单一化（方法值即失去原对象引用）——与「方法值引用语义
  读最新状态」（e2e 104 断言 205）冲突。

**候选丙（推后·非本专项）：与闭包蹦床统一表示（环境指针+蹦床地址）**

- 即把一切闭包升级为 16 字节 {捕获环境, 蹦床}，方法值=环境为单对象指针的特例。
- 理论统一性最好，但破坏面巨大：lambda 值现有 8 字节形态承载「可作 fnptr 自由传递/返回」
  （e2e 1002 借调形参、1044 返回闭包、`整32(*)()` 返回类型）——16 字节化后全部用例族
  （1002/1038/1044/1046/485 等）重测重立法，且 lambda→fnptr 互操作面要重定义。
- 裁决：**本专项不动 lambda**（U1 独立表示·§二·②）；统一化作为长期演进留档（U2·非本专项批）。

**性能对比（创建+调用，相对量级）**：

| 方案 | 创建开销 | 调用开销 | 逃逸/存储开销 | 悬垂防线 |
|------|----------|----------|----------------|----------|
| 甲：栈上两字值 | 2 条装载 | 1 次间接跳转+2 寄存器 | 16 字节拷贝 | 静态借用规则（§二·④a） |
| 乙：堆小对象 | 1 次 malloc+写 | 1 次间接跳转+1 解引用 | 指针拷贝（析构时机难题） | 引用计数（丙）或静态 |
| 丙：蹦床统一 | 2 条装载+静态槽写 | 1 次间接跳转 | 16 字节拷贝+蹦床帧 | 同甲（若两槽化） |
| 现状（#943 快径） | 2 条装载 | 直调（同帧）/**转发崩溃** | 旁路表丢失 | 无（缺陷） |

### ② 类型语法与调用语法

**类型书写（候选与推荐）**：

- 候选 A（**推荐**）：`方法值<类名, 返回类型(参数表)>`——泛型风格与 `结果<T,E>`/`向量<T>` 一致。
  示例：
  ```
  函数 应用(方法值<计数器, 整32(整32)> 回调, 整32 v) -> 整32 { 返回 回调(v); }
  变量 cb = 对象.双倍;              // 推导得 方法值<计数器, 整32(整32)>
  ```
- 候选 B：`绑定 整32(计数器::*)(整32)`（C++ 成员函数指针风格）——否（与 CN 中文/后缀类型
  风格割裂，且 `::` 在表达式位是「类::静态方法」限定名符号，类型位复用易混）。
- 候选 C：`闭包<整32(整32)>`（不带类名）——否（this 类型必须进类型，跨类错调不可表达；
  且与 lambda 蹦床值（8 字节）混淆——同为「闭包」却不同宽度/不同调用协议）。
- 类型系统内部串（实现锚·供宿主/v2 共用）：`方法值<类名,函数指针<返回类型>(参数表)>`
  （对齐现有 fnptr 内部串形态 `函数指针<整32>(整32)`——`src/cn_compiler/semantic/semantic_expr_access.cpp:306-312`）。

**调用语法**：零新增——`cb(实参)`（与 fnptr 变量调用、e2e 104 现写法完全同形）。
调用点消歧=**静态类型驱动**（编译期已知 cb 是方法值类型还是 fnptr 类型）：
- 方法值：`CallIndirect(code, this, 用户实参...)`（this 注入位 0）；
- fnptr：`CallIndirect(code, 用户实参...)`（现状不动）。
用户零学习成本：两种形态语法一模一样，差异只在非法转换处（§二·③）。

**与闭包（lambda 值）的统一性——两案呈报**：

- **U1（推荐·本专项采用）**：语义统一、表示独立——两者都「值语义拷贝、`f(实参)` 调用、
  可作实参/（方法值第一版限形参）」，但 lambda 保持 8 字节蹦床（可作 fnptr 传递·现状用例
  全绿），方法值 16 字节两槽（不可转 fnptr）。代价：用户可见「两种函数值类型」概念区分
  （文档与诊断文案需讲清：lambda 蹦床值=无对象引用、可裸传；方法值=自带对象、不可裸传）。
  收益：lambda 全家族零回归 + 性能最优 + 风险隔离（新语义新通道，旧通道冻结）。
- **U2（推后·长期演进）**：闭包全面 16 字节化（{环境,代码}）并统一类型名——须连带重立法
  fnptr 互操作（lambda→fnptr 的面）、全量回归 1002/1044/1038/485 族；列为**后续专项**
  候选（非本设计轮范围）。

**第一版可写位置**（保守面·呈报）：局部变量（推导+显式）、形参；**不可写**：函数返回类型、
类字段、容器元素、全局/静态——即「禁长寿命载体」（与 §二·④ 规则 R1/R2 同源，
语法面与语义面单一裁决点）。

### ③ fnptr 兼容面

**方法值→裸 fnptr：全形态编译拒绝**（对象丢失=静默错行为，JS 反面教员）：统一诊断覆盖
初始化/赋值（如 `整32(*绑)(整32) = 对象.方法`）、实参（现状 107 已拦）、返回（`返回 对象.方法`
且返回类型为 fnptr）、字段写（`结.回调 = 对象.方法`）。新诊断候选文案（双侧逐字）：
「绑定方法值不能转换为函数指针（对象引用无处安放）——改用 `变量 cb = 对象.方法;` 携带对象
（或写闭包捕获 `[对象](...)`）」。

**#943 过渡路径的重定义**：#943 修复期保留的「先赋值给变量」指路，在方法值落地后
**废弃原「赋给裸 fnptr 变量」形态**（显式 `整32(*绑)(整32)=对象.方法` 由放行改为拒绝——
它与「全形态拒绝」单一规则对齐，消除「赋值能过、转发崩溃」的假安全通道）；同时段新指路
=「`变量 cb = 对象.方法;`（推荐）或闭包捕获」。**不保留过渡双轨**（一步到位·尽善尽美纪律）。

**fnptr→方法值：拒绝**（来源封口延续·001 §5.8 现有条文「合法来源仅函数名衰减+同签名
函数指针」（`plans/001 CN语言编译器设计规格书.md:1200`）——方法值类型不进 fnptr 来源，
fnptr 也不进方法值来源）。

**lambda 蹦床值（8 字节）↔ fnptr：现状保持**——按值捕获 lambda 可作 fnptr 传递/返回
（e2e 1002/1044 已立法安全·`plans/001 CN语言编译器设计规格书.md:676-688` 435 条文面）；
本专项不改。**lambda 值不自动成为方法值**（类型不同·宽度不同），方法值作 lambda 实参=
类型不匹配（除非形参声明为方法值类型）。

**诊断文案过渡链（双侧同改·#943 记录在案）**：
1. 现状（#943 修复前）：「须先赋值给变量」——且赋值后转发不安全（缺陷期）。
2. #943 修复中（家机分支）：「建议闭包捕获」。
3. 本设计轮批准实施后：拦截点文案改为**指路绑定方法值**（推荐）+闭包捕获（备选）——
   与 001 §5.8c 新条文同步（§二·⑥）。

### ④ 生命周期安全（最大难点·与 GC 语言的分水岭）

**问题陈述**：方法值持有 this=**堆对象指针**。CN 类对象恒为编译器 `NewObject` 分配、变量槽存
指针（`src/cn_compiler/ir/ir_oop_call_release.cpp:19`），对象由 RAII 在块出口析构释放
（同文件 :489「块出口析构：释放本块新增的拥有串/类对象」）。对象释放后调用方法值=悬垂/
UAF——本语言「悬垂零容忍」（双目标②）与 §1.1a 分层安全总则（`plans/001 CN语言编译器设计
规格书.md:15-30`）禁止静默放行；#943 的段错误正是无防线放行的代价实证。

**对照坐标系（为什么是「分水岭」）**：
- Python / C# / Go：GC 持有引用关系，对象活到无引用为止——方法值携带引用天然安全
  （代价：GC 停顿、内存峰值、运行时复杂度——CN 明确拒绝此路线）。
- C++ 成员函数指针：无任何检查（对象亡后 `obj.*pmf` 调用=UB 自担）。
- JavaScript：（无 this 语义保护）裸传静默丢 this——反面教员。
- Rust：借用检查在编译期证明；跨函数需生命周期标注或 move 捕获（Box<dyn Fn>）。
- **CN**：无 GC、对象生命周期=词法块 RAII——只能以「静态作用域规则」或「运行期检查」补上
  GC 语言由运行时免费提供的那一环；这一环的选型即本问。

#### 路线 a：静态作用域限制（编译器保守逃逸检查）——**推荐主体**

**机制**：编译期跟踪「方法值变量 → 绑定对象变量」的关联（方法值类型自带类名=关联锚），
强制规则「**方法值的持有域不得超过绑定对象的持有域**」；判定方式沿用 435 逃逸检查的保守
传播集模式（`src/cn_compiler/semantic/semantic_lambda_escape.cpp:14-20`：声明/赋值位收集
持有变量名集 → 使用位树扫描命中逃逸形态即拒绝；不确定面按逃逸拒绝·永不静默放行）。

**规则集（第一版·呈报草案）**：

| 规则 | 内容 | 违反处置 |
|------|------|----------|
| R1 | 方法值可作局部变量、可值拷贝（两槽整拷）、可在本作用域直调 | — |
| R2 | **不可作函数返回值**（对象也不同步返回时） | 编译错误+指路 |
| R3 | **不可存入长寿命载体**：类字段/容器元素/全局变量/静态变量 | 编译错误+指路 |
| R4 | 可作实参传入（**调用期借用**）——被调函数体内该形参同样受 R1~R3 约束（被调方不可再返回/存储它） | 被调体内逃逸=编译错误 |
| R5 | `不安全 函数` 体内全豁免（责任上移·审计面=不安全函数清单·§1.1a④ 先例） | — |
| R6 | **转移联动**：绑定对象被 `转移()`/提前释放后，其方法值禁用（复用仿射检查「旧名禁用」通道） | 编译错误 |

**关键设计点**：
- R4 的跨函数安全性不依赖调用者分析：形参方法值在**被调方体内**即受 R2/R3 约束——无论谁调用，
  被调函数都不可能把它存到长寿命载体或返回（函数体是静态检查单元）——「单向借入、禁止留用」
  自洽成立。这使 R4 无需 Rust 式生命周期标注（零新语法）。
- 直调（`应用(cb, 5)` 中 f(v)）在新规则下天然合法：调用是「使用」而非「存储」。
- 与 435 的差异：435 检查的是「[&] 捕获变量地址」；本规则检查「方法值变量引用对象变量」——
  同模式扩展，检查器基础设施（传播集/树扫描/诊断指路/函数入口清空）可复用。
- 演进留档（第 3 期候选）：R2 放开为「**方法值可携带对象所有权返回**」（对象随方法值走、
  析构归属随之转移——与 019 `转移()` 哲学合流）；本设计轮不批，保守禁返回。

**性能**：零运行期开销（纯编译期判定）——「性能第一」首选路线。
**代价**：保守误拒伤害部分写法（须指路改写：闭包捕获/把对象一起传/不安全区）；诊断文案质量
决定体验（违规必须给出可操作的改写指路——435 先例同款纪律）。

#### 路线 b：运行期存活检查——**仅作 debug 纵深（不作为 release 安全依据）**

**机制候选与逐条否决分析**：

- **b1 对象头存活位/毒化魔法数**（free 时写毒）：释放后调用=读头判死→确定性失败。
  缺陷：①free 后内存可被 allocator 复用/复用为任意数据——「假活」窗口（ABA）；②读已释放
  内存理论 UB（页归还 OS 时可能直接崩）——防线本身不可靠。
- **b2 对象头代际计数器（gen）**：对象头加 gen，释放时自增；方法值需记住创建时 gen——
  载体变 **24 字节三槽**（this/code/gen），每次调用多一次读头+比较（1 访存+1 分支）；
  全局单调发号可防复用假活，但「释放路径写头」要求**所有**释放路径可控——用户可在
  `不安全` 区手动释放（023 不安全清单内的既有通道），防线有洞；且 24 字节破坏 §二·①
  两槽简洁性。
- **b3 全局存活注册表**（对象登记/注销，方法值调用查表）：每次对象创建/销毁+每次调用都
  过哈希表（性能第一=否），且需跨线程同步——与「默认路径零规则/零开销」哲学冲突。

**定位**：上述三变体都不能做到「既可靠又零/常数低开销」，且 §1.1a 的精髓是「编译期能证明的
必须编译期拦、证不了的才运行期兜底」——路线 a 已覆盖全部可证明面；b 的残余价值仅在
**debug/审计构建**（`不安全` 区内专家代码的辅助测试），列为**可选后波**
（可随未来安全构建模式专项一并做），本设计轮不为它付 ABI 代价（say no to 24 字节）。

#### 路线 c：所有权转移/共享（对象装箱引用计数）——**否决**

**机制**：对象升级为引用计数对象；创建方法值 +1、方法值亡 -1；最后引用亡时释放。

**否决理由（逐条）**：
1. **ABI 全破坏**：所有类对象布局加 RC 头 → vtable 槽位/接口附加区分派区/字段偏移全动——
   既有千级用例、FFI 面（对象跨 C 边界）、CN-OS 蓝图（029）全部波及；「不轻易破坏既有 ABI」
   是性能第一的物质基础。
2. **性能**：每次方法值创建/销毁 ±1；跨线程需原子（更贵）或非原子（线程不安全）；GC 语言的
   「免费引用」在 CN 变成显式计数税——与性能目标反向。
3. **模型冲突**：CN 的语言卖点=值语义深拷贝「默认路径零规则、无别名」（plans/019 §二 设计
   哲学 1）——隐式 RC 共享引入可变别名写（两个持有者经同一对象互相影响），与安全模型
   （019 借用互斥/转移）纠缠。
4. **正确定位**：共享语义应是**显式类型**（未来 `共享<T>`/智能指针·与 019 阶段 4'「智能指针
   与拥有型字符串」方向合流），由需要者显式选择——而非把「全部对象」隐式升级为 RC。
   对照：Rust `Rc<T>`/`Arc<T>` 显式（不是所有类型）；Python 隐式（CN 不取）。

#### 推荐路线与理由（性能第一裁决）

**推荐=路线 a 为主体（零运行期开销）+ 路线 b 仅 debug 纵深（可选后波）+ 路线 c 否决。**

1. **性能**：a 纯编译期零开销；b 每次调用 +1 访存；c 每次创建/销毁原子操作+全 ABI 破坏——
   a 完胜（性能第一）。
2. **安全等级与既有防线同构**：a 与 435（[&] 逃逸）、仿射（转移后禁用）、借用互斥同族——
   用户已学习的「保守拒绝+指路改写」规则不变，安全责任边界清晰（`不安全` 豁免先例统一）。
3. **直觉写法可达**：目标形态 `变量 cb = 对象.方法; 应用(cb, 5)` **全绿**（转发=调用期借用）；
   仅「悬垂形态」（返回/存长寿命载体/对象转移后调用）拒绝——第一版保守面正是这些**本就
   危险**的写法，符合「默认路径零规则、危险面收口」哲学。
4. **分水岭回答**：GC 语言用运行时免费换安全；CN 用编译期规则+保守拒绝换零开销——
   路线 a 是 CN 在无 GC 前提下「安全接近 Rust」的唯一可持续形态（b 只能兜底、c 即承认 GC 模型）。

### ⑤ 双侧实现+三后端 ABI

**值布局**：16 字节两槽（**this 在前、code 在后**·对齐 8）。IR 表示=**两个 8 字节标量成对**
（`ptr` 槽×2）——这是全设计的关键降维：两槽方法值在 IR/后端里从来不是「聚合类型」，而是
「总是成对出现的两个标量」，从而**复用全部既有整型装载/存储/传参通道，codegen 零新协议**。

**参数传递（方法值作实参）**：IR 层展开为两个**连续** 8 字节整型实参——
`应用(cb, 5)` → IR `Call 应用(cb.this, cb.code, 5)`；被调方声明 `方法值<…> 回调` →
prologue 摊平为两个连续形参槽（回调.this/回调.code）。三后端落位：

| 后端 | 实参寄存器（两槽占 2 位） | 依据 |
|------|--------------------------|------|
| win-x64 | 前 4 整型参数 rcx/rdx/r8/r9，第 5 起栈 | `src/cn_compiler/codegen/x64/x64_instructions_call.cpp:19` |
| linux-x86_64 | SysV：rdi/rsi/rdx/rcx/r8/r9 起（struct 按值地址/隐藏返回同通道） | `src/cn_compiler/codegen/linux_x64/linux_x64_instructions_call.cpp:18-19` |
| linux-arm64 | x0~x7（GP/FP 独立换代·404 单点分配） | `src/cn_compiler/codegen/arm64/arm64_instructions_call.cpp:10-15` |

对照：结构体按值参数现有通道=**传地址**（linux 注释「结构体按值地址」同款）——本设计
**不复用**该通道（避免「地址指向调用者栈槽」的间接+被调拷贝协议），两槽走真寄存器直传，
与「性能第一」一致。

**调用点两形态（IR 层）**：
- 方法值调用 `cb(5)`：`CallIndirect(code槽, this槽, 用户实参...)`——this 注入参数位 0，
  与实例方法直调 ABI **完全一致**（`src/cn_compiler/ir/ir_oop_call.cpp:676`「operand[0] = this」、
  :736「this 为第一个实参（参数位 0）」、:795「参数位 0（rcx）」）——被调方符号=普通方法符号
  （`methodSymbolKey`·`src/cn_compiler/ir/ir_oop_field.cpp:638` 现成），**被调方零特例、
  零蹦床、零静态槽**。
- fnptr 调用：现状不动（`src/cn_compiler/ir/ir_call.cpp:926/938/967` CallIndirect + 空调用
  判零防线·001:1204）。
- 同帧快径（优化，非必需）：方法值变量在本函数内调用可保留现状 closureInfo_ 式直调优化
  （`src/cn_compiler/ir/ir_call.cpp:191`）——但**正确性不再依赖它**（转发路径两槽自足），
  快径仅是性能补充（缺失时走 CallIndirect 语义等价）。

**返回位**：第一版方法值**禁返回**（规则 R2）→ **无新返回 ABI**（省 sret/寄存器对返回的
全部复杂度）。演进放开时复用既有 structReturn 隐藏指针通道（三后端已成熟·
`src/cn_compiler/codegen/x64/x64_instructions_call.cpp:26-58`）。

### ⑥ 001 条文草案 + dual 锁用例规划

#### 001 §5.8c 条文草案（拟插于 §5.8 函数指针之后·**待批**）

> **§5.8c 绑定方法值（一等公民化·2026-10-17 用户批准立项 #970·待批条文）**
>
> **求值**：`对象.实例方法` 求值为**绑定方法值**——自带绑定对象的函数值（两槽载体：
> 对象引用+方法代码；Python 绑定方法/C# 委托/Go method value 流派）。绑定=**引用语义**：
> 调用读对象当前状态（e2e 104 断言「改态后 205」不变）。静态方法作值（`类::静态方法`·
> e2e 98）维持裸函数指针语义不变。
>
> **类型与调用**：类型写作 `方法值<类名, 返回类型(参数表)>`；`cb(实参)` 直调——调用协议=
> 「this 注入首参的间接调用」，与实例方法直调 ABI 一致（被调方零特例）。可作实参传递
> （调用期借用·见生命周期）、可值拷贝（两槽整拷·无析构/非资源字段）。
>
> **fnptr 隔离**：绑定方法值**不可**转裸函数指针（对象引用无处安放）——初始化/赋值/实参/
> 返回/字段写全形态编译错误（诊断指路 `变量 cb = 对象.方法;` 或闭包捕获）。反之 fnptr
> 亦不可转方法值（来源封口延续 §5.8）。
>
> **生命周期（零悬垂纪律·〔基准=019 §1.1a〕）**：方法值的持有域不得超过绑定对象的持有域——
> ①可局部持有/值拷贝/直调/传参（被调方体内不得将其返回或存入类字段/容器元素/全局/静态）；
> ②返回=编译错误（第一版）；③绑定对象被 `转移()` 后其方法值禁用；④`不安全 函数` 体内
> 豁免（责任上移·审计面=不安全函数清单）。违反=编译错误+改写指路（保守方向：不确定按
> 逃逸拒绝·永不静默放行——对齐 435 纪律）。
>
> **禁用面（第一版保守）**：方法值类型不可写于函数返回类型/类字段/容器元素/全局/静态声明位
> （配合生命周期规则；演进放开随「所有权随方法值转移」另案）。
>
> **实现与验证**：宿主 C++ 与 v2 双侧同构（零分叉红线）；E2E dual 全形态锁（见 #970 规划
> 清单）；三后端（win-x64/linux-x86_64/linux-arm64）产出一致。
