### 5.1 「原始」作字段名的精确机制（缺陷定位）

`src/cn_compiler/lexer/lexer.cpp:235-247`：

```cpp
if (lookupKeyword(text, type)) {
    // 原始/多行字符串前缀：关键字后紧跟引号才是字符串字面量
    if ((type == TokenType::Kw_Raw || type == TokenType::Kw_MultiLine) &&
        peek() == U'"') {
        return readPrefixedString(text, loc);
    }
    return Token(type, text, loc);   // ← 缺陷：不跟引号时仍返回 Kw_Raw/Kw_MultiLine token
}
```

注释即意图（「后紧跟引号**才是**字符串字面量」——否则应回退标识符），实现漏了回退分支。
组合前缀 `原始多行`/`多行原始`（lexer.cpp:244）走文本分支、**已正确回退**为 Identifier ✓（无需改动）。

**对照实测（T 系列）**：`点 位置;`（结构体成员）✅、`点* 位置;` ✅、`字符串 名字;` ✅、`整64[4] 数据;` ✅
——复合类型成员全部放行；`整64 原始;` ❌ 且在**结构体**下同样报错（t3/t4）→ 与联合体、与成员类型无关。

### 7.3 `原始`/`多行` 非保留化（裁决 2②）

目标：**功能零变化、保留字身份移除**。

```cpp
// 目标形态（lexer.cpp readIdentifierOrKeyword）
if (lookupKeyword(text, type)) {
    if (type == TokenType::Kw_Raw || type == TokenType::Kw_MultiLine) {
        if (peek() == U'"') return readPrefixedString(text, loc);
        // 前缀后仅空白再跟引号 = 前缀误用 → 保留友好诊断（原 readPrefixedString 诊断位）
        if (前缀后跳过空格/制表为 '"') reportError(loc, "字符串前缀后必须紧跟引号");
        return Token(TokenType::Identifier, text, loc);   // 非前缀语境=普通标识符
    }
    return Token(type, text, loc);
}
```

- 删除 `Kw_Raw`/`Kw_MultiLine` 两个 TokenType（token.hpp/token.cpp；零使用已成事实）。
- **保持不变**：组合前缀 `原始多行"..."`/`多行原始"..."`（文本分支，已正确）；`原始"..."`、
  `多行"""..."""` 字面量行为；`tests/e2e/06_string/字符串.cn:16` 的 `原始多行"""A\nB"""` 用例。
- 诊断保留要求：`原始 "x"`（前缀后空格再引号）→ 明确报「字符串前缀后必须紧跟引号」（不得退化为
  普通语法错误）；实现纳入单测。
- 影响：`原始`/`多行` 可作变量名/字段名/函数名（消除 135-a 误判的土壤）。

## 十、阶段 3（**已批准**）——6 词上下文化改造设计

> **裁决**：2026-09-14 用户 userselect 批准（§六 裁决 3；144-a 补正落盘）。目标=释放 6 个常用词的
> 命名空间占用，语法与语义**零变化**。原则（规范 §2.2 已立先例）：凡只在固定语法位置出现的关键字，
> 一律走**上下文识别**（非保留字）——`运算符`/`遍历`/`每个`/`属于`/`对` 即此模式。

### 10.1 六词与识别位置

| 词 | 出现位置（唯一） | 识别判据（parser） |
|---|---|---|
| `保护` | 类体内可见性标签：`保护:` | 类体内 `Identifier("保护")` + 紧跟 `:` → 标签；否则按普通声明解析 |
| `虚拟` | 类/接口成员声明前缀：`虚拟 函数 …` | 成员声明起始位：`Identifier("虚拟")` 后接 `函数` 等修饰序列 |
| `重写` | 同上：`重写 函数 …` | 成员声明起始位：`Identifier("重写")` 后接 `函数` |
| `抽象` | 类声明 / 成员前缀：`抽象 类 …` / `抽象 函数 …` | 类声明起始位或成员声明起始位 |
| `作为` | 重命名导入：`导入 路径 作为 别名;` | `parseImport` 内：路径解析完成后 `Identifier("作为")` → 别名段 |
| `模块` | 顶层模块声明：`模块 名;` | 顶层：`Identifier("模块")` + `Identifier` + `;`（无 `=`/`(`——与顶层变量声明 `类型 名 = …` 区分） |

### 10.2 实现方式（推荐甲·与先例一致）

- **甲（推荐）**：`keywordTable` 删除六词 + parser 在各识别点按 `Identifier` + 文本判定
  （与「遍历」现实现同款：`check(TokenType::Identifier) && current().getValue() == "遍历"`；
  `parser_stmt.cpp:57`）。收益=真正不占命名空间；代价=六处识别点改造 + 歧义判据显式化。
- **乙（对照，不推荐）**：词法保留 token、语法层按位置校验——token 仍占标识符空间，不彻底。

### 10.3 歧义与边界（逐词）

- 作标识符的新语义：`整64 保护 = 1;`、`整64 虚拟 = 1;`、`整64 作为 = 1;`、`整64 模块 = 1;` 全部合法；
  原语法形态判据唯一（类体内 `保护:` 冒号；成员起始 `虚拟 函数`；导入内 `作为`；顶层 `模块 名;`）。
- `模块` 作路径段：`导入 模块::向量;` 仍按路径段解析 ✓（判据=首 token 为 `导入`）。
- `模块 名;`（模块声明）与顶层无初值变量声明的区分判据须在规范中显式化（`模块` 后仅 `标识符 ;`）。
- 负测须覆盖：六词作变量/字段/函数名 + 原形态 + 相邻歧义形态（如类体内 `保护: 整64 保护;`——
  标签与字段名同名同时出现）。
