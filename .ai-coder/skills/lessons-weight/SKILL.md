# lessons.md 权重管理技能

## 概述

本技能为 AI Agent 提供 lessons.md 的权重管理能力，确保 AI 在任务开始时优先关注高频、高影响的历史问题，避免重复犯错。

---

## 何时使用此技能 / When to Use

**强制触发场景：**
1. **任务开始时** - 读取 lessons.md 必须应用权重规则
2. **记录错误时** - 写入错误记录必须计算权重
3. **发现重复错误** - 相同类型错误出现时必须检查历史

**不要使用：**
- 与错误记录无关的任务
- 纯代码编写任务（无错误发生）

---

## 核心规则

### 一、权重计算规则

**公式**：
```
权重 = 基础权重 × 类型系数 × 新鲜度系数 × 解决状态系数
```

**基础权重表**：

| 问题类型 | 基础权重 | 说明 |
|---------|---------|------|
| 设计缺陷 | 10 | 架构或设计层面问题 |
| 任务未完成 | 9 | 任务被遗漏或未完成 |
| 逻辑错误 | 8 | 代码逻辑错误 |
| 集成问题 | 7 | 模块间集成问题 |
| 配置错误 | 6 | 配置问题 |
| 工具执行错误 | 2 | 临时性工具错误 |

**类型系数**：

| 内容特征 | 系数 |
|---------|------|
| 有详细分析 | ×2.0 |
| 有解决方案 | ×1.5 |
| 有预防措施 | ×1.3 |
| 模板化内容 | ×0.3 |

**新鲜度系数**：
```
新鲜度 = 1 / (1 + log10(天数 + 1))
```

**解决状态系数**：

| 状态 | 系数 |
|------|------|
| 未解决 | ×2.0 |
| 部分解决 | ×1.2 |
| 已解决 | ×1.0 |

### 二、读取优先级规则

**AI 读取 lessons.md 时必须遵循以下顺序：**

```markdown
## 读取流程

Step 1: 读取"⚠️ 高权重问题"部分
        └── 重点关注权重 ≥ 15 的问题（🔴 红色标记）
        └── 其次关注权重 10-14 的问题（🟡 黄色标记）

Step 2: 检查"问题类型统计"
        └── 了解各类问题分布
        └── 识别高频问题类型

Step 3: 根据当前任务类型，匹配相关历史问题
        └── 代码编写 → 查找"逻辑错误"、"设计缺陷"
        └── 配置修改 → 查找"配置错误"
        └── 集成开发 → 查找"集成问题"

Step 4: 低权重历史记录仅在需要时查阅
        └── 权重 < 5 的内容可跳过
```

### 三、写入规范规则

**记录错误时必须包含：**

| 字段 | 必填 | 说明 |
|------|------|------|
| 日期时间 | ✅ | 格式：YYYY-MM-DD HH:mm |
| 问题类型 | ✅ | 从基础权重表选择 |
| 描述 | ✅ | 简明扼要描述问题 |
| 原因分析 | 推荐 | 分析根本原因 |
| 解决方案 | 推荐 | 提供解决方案 |
| 预防措施 | 推荐 | 如何避免同类问题 |

**禁止行为：**
- ❌ 禁止写入无意义的模板内容
- ❌ 禁止重复记录相同的错误
- ❌ 禁止遗漏高权重问题的记录

### 四、清理维护规则

**定期执行（建议每周）：**

1. **合并重复错误**
   - 同一天内相同错误 → 合并为一条，记录次数
   - 跨天相同错误 → 保留首末记录

2. **压缩低价值内容**
   - 权重 < 3 的模板化错误 → 压缩为表格
   - 超过 30 天的工具执行错误 → 归档

3. **更新权重摘要**
   - 重新计算所有记录权重
   - 更新高权重问题列表

## 检查清单

### 任务开始前检查

```markdown
## lessons.md 读取检查

- [ ] 已读取"⚠️ 高权重问题"部分
- [ ] 已关注权重 ≥ 15 的问题
- [ ] 已检查当前任务相关的历史问题
- [ ] 已识别可能影响当前任务的问题

**确认**：我已了解历史教训，将避免重复犯错。
```

### 错误记录检查

```markdown
## 错误记录检查

- [ ] 已选择正确的问题类型
- [ ] 已填写问题描述
- [ ] 已分析根本原因（推荐）
- [ ] 已提供解决方案（推荐）
- [ ] 已计算权重

**确认**：错误记录符合规范。
```
