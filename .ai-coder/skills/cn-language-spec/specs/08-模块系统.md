## 一、设计原则：文件即模块 + 包 = crate

### EBNF

```
模块 = 源文件（每个 .cn 文件是一个模块）
模块名 = 文件名（不含 .cn 扩展名）
包（crate）= 一个编译单元根（主.cn 或 包.cn）+ 其引用的模块树
```

### 原则说明

| 原则 | 说明 |
|------|------|
| 文件即模块（保留） | 每个 `.cn` 文件就是一个模块，模块名为文件名（不含扩展名）；`网络/传输控制.cn` → 模块 `网络::传输控制` |
| 包 = crate（新增） | 包（crate）是**命名空间边界与编译单元边界**：一个可执行程序或库 = 一个 crate。跨包同名符号互不冲突（crate 隔离） |
| crate 根 | 可执行程序根 = `主.cn`；库根 = `包.cn`（聚合模块并再导出公共 API） |
| 顶层声明 | 函数/结构体/枚举/类/接口/导入/模块/常量/静态/全局变量均为模块级声明 |
| 模块边界 | 模块间可见性通过 `公开:`/`私有:` 标签控制，**默认私有**（见第四节） |

### 设计决策

- **文件即模块**（保留自 v1.0）：无块式模块语法（`模块 名 { }`），模块必须以独立文件存在。
- **包 = crate**（v2.0 新增）：crate 隔离是模块系统 v2.0 的核心决策之一——每个包是独立的命名空间，`包A::工具` 与 `包B::工具` 是两个不同符号，互不冲突。
- **v1.0 差异**：路径分隔由 `.` 改为 `::`；删除 `从` 导入语法；可见性由默认公开改为**默认私有**。

## 二、模块声明

### EBNF

```
模块声明 = "模块" 标识符
```

### 规则说明

| 规则 | 说明 |
|------|------|
| 形式 | `模块 网络`（声明引用模块 `网络.cn`，编译器自动加载同名文件） |
| 无强制分号 | 声明以换行终止，`;` 可选（兼容 C 习惯），见第八节 |
| 不引用文件内容 | `模块 名` 仅建立模块树引用关系；具体符号需通过 `导入` 引入作用域 |
| 唯一形式 | CN 语言**不支持内联模块**（`模块 名 { }` 花括号形式），所有模块必须以独立文件存在 |

### 示例代码

```
// 主.cn：声明引用同级文件模块
模块 网络
模块 工具

函数 主() -> 整32 {
    导入 网络::连接
    网络::连接()
    返回 0
}
```

## 三、路径与导入语法

### 3.1 路径（`::` 分隔）

```
路径 = 标识符 ("::" 标识符)*
```

- 路径用 `::` 分隔，**对应目录层级与模块树**：`网络/传输控制.cn` → `网络::传输控制`。
- 路径首段可以是：当前包内的模块名、`核心`（核心包）、或货舱.toml 中声明的依赖包名。

### 3.2 导入语法（全形式）

```
导入声明 = "导入" 路径 ["作为" 标识符]
          | "导入" 路径 "::" "{" 导入项 ("," 导入项)* "}"
          | "导入" 路径 "::" "*"
导入项 = 标识符 ["作为" 标识符]
```

### 3.3 四种导入形式

| 形式 | 语法 | 语义 | 示例 |
|------|------|------|------|
| 路径导入 | `导入 路径` | 导入模块（其后可用 `路径::符号` 限定访问） | `导入 核心::集合` |
| 重命名导入 | `导入 路径 作为 标识符` | 导入模块/符号并绑定别名 | `导入 核心::列表 作为 动态数组` |
| 花括号导入 | `导入 路径::{项列表}` | 选择性导入多个符号，可逐个重命名 | `导入 核心::可选::{某些, 无}` |
| 通配符导入 | `导入 路径::*` | 导入模块全部公开符号（谨慎使用） | `导入 核心::集合::*` |

### 3.4 示例代码

```
导入 核心::可选::{某些, 无}      // 花括号：选择性导入
导入 核心::集合                   // 路径：导入整个模块
导入 核心::列表 作为 动态数组     // 重命名：别名绑定
导入 核心::集合::*               // 通配符：全部公开符号（不推荐滥用）
导入 包::网络::连接              // 跨包：包名::模块::符号
```

### 3.5 设计决策

- **`::` 路径分隔**（v2.0）：替代 v1.0 的 `.`，与 Rust 路径习惯一致；`::` 使模块限定与成员访问 `.` 在词法上清晰区分。
- **删除 `从`**（v2.0）：v1.0 的 `从 模块 导入 名` 语法删除，统一由 `导入 路径::{名1, 名2}` 花括号形式承担。
- **保留 `导入`**：`导入` 是唯一导入关键字，不引入 `使用`。
- **再导出**：`公开 导入 路径` 可将导入的符号再导出（crate 公共 API 聚合，见第五节）。

## 四、可见性（标签式 + 默认私有 + 交集规则）

### 4.1 EBNF

```
可见性标签 = "公开:" | "私有:"
可见性段 = 标签, 声明*
```

### 4.2 标签式语义

| 标签 | 语义 | 对应C++ |
|------|------|---------|
| `公开:` | 模块外可访问（可被导入使用） | public |
| `私有:` | 仅模块内部可访问 | 匿名命名空间/static |

- **标签式**：`公开:`/`私有:` 为块级标签，标签后所有声明继承该可见性直到下一个标签。
- **默认私有**（v2.0 变更）：文件顶部**无任何标签时，声明默认为私有**（v1.0 为默认公开）。标准库模块须在文件顶部显式写 `公开:` 以导出 API。

### 4.3 可见性交集规则（重点章节，v2.0 新增）

> **核心规则：符号的最终可见性 = 各层级可见性的交集（取最严格）。**
>
> 模块级 `私有:` 块内的类，即使类内标了 `公开:`，**跨文件导入时整个类（含公开成员）不可见**。类内 `公开:` 仅在本模块内有效（允许本模块代码访问该类公开成员），**不赋予类跨模块可见性**。

### 四象限可见性矩阵

| 类层级 | 成员层级 | 同文件 | 同包跨文件（导入后） | 跨包（导入后） |
|--------|---------|--------|-------------------|--------------|
| 模块公开 | 类内公开 | ✅ | ✅ | ✅ |
| 模块公开 | 类内私有 | ✅ | ❌ | ❌ |
| 模块私有 | 类内公开 | ✅ | ❌ | ❌ |
| 模块私有 | 类内私有 | ✅ | ❌ | ❌ |

### 4.4 示例代码

```
// 模块甲.cn
公开:
    函数 公开函数() { }          // 模块公开：可跨模块导入
    类 公开类 {                  // 模块公开类
        公开:
        函数 公开方法() { }      // 类内公开 + 模块公开 → 交集=公开
    }

私有:
    函数 私有函数() { }          // 模块私有：仅本模块可见
    类 私有类 {                  // 模块私有类
        公开:
        函数 公开方法() { }      // 类内公开 + 模块私有 → 交集=私有（整个类跨文件不可见）
    }

    函数 默认私有() { }          // 无标签 → 默认私有
```

```
// 模块乙.cn
导入 模块甲::{公开类}

函数 使用() {
    公开类 实例                        // ✅ 模块公开类可导入
    实例.公开方法()                    // ✅ 类内公开 + 模块公开 → 可访问
    // 模块甲::私有类 实例2             // ❌ 模块私有类跨文件不可见（即使类内标了公开）
    // 模块甲::私有函数()              // ❌ 模块私有函数不可见
}
```

### 4.5 设计决策

- **默认私有**（v2.0 变更）：模块级与类内均默认私有。理由：默认私有是信息隐藏的最佳实践，显式 `公开:` 声明公共 API，避免"忘了写私有导致意外暴露"。
- **可见性交集**（v2.0 新增）：模块级可见性与类内可见性取交集（最严格），杜绝"类内公开成员绕过模块私有边界"的漏洞。
- 与旧版 Rust 风格差异：旧版为逐项修饰（`公开 函数`），v2.0 保留 C++ 风格标签式（`公开:`）。

## 五、crate 模型（包 = crate）

### 5.1 包.cn 根文件

库包以 `包.cn` 为 crate 根，聚合模块树并再导出公共 API：

```
// 包.cn（crate 根，聚合模块）
模块 网络
模块 存储

公开 导入 网络::连接      // 再导出：外部通过 包名::连接 使用
公开 导入 存储::存储器
```

### 5.2 子目录模块树

```
网络/
├── 网络.cn                 // 模块 网络（目录内同名文件 = 模块本身）
├── 传输控制.cn             // 模块 网络::传输控制
└── 用户数据报.cn           // 模块 网络::用户数据报
```

- 目录层级对应 `::` 路径：`网络/传输控制.cn` → `网络::传输控制`。
- `模块 网络` 引用 `网络.cn`；`网络/传输控制.cn` 作为 `网络` 的子模块树。

### 5.3 跨包导入

```
// 货舱.toml 已声明依赖 网络库 = "1.2"
导入 网络库::连接            // 导入依赖包中的模块符号
导入 网络库::请求::获取      // 多级路径：包名::模块::符号
```

- 包名 = crate 名（货舱.toml 中 `[货舱] 名称`）。
- crate 隔离：`包A::工具` 与 `包B::工具` 是两个独立符号，互不冲突。

### 5.4 示例：完整 crate 布局

```
项目/
├── 货舱.toml               // 包元数据 + 依赖
├── 主.cn                   // 可执行程序 crate 根（或 包.cn 库根）
├── 网络.cn                 // 模块 网络
└── 网络/
    └── 传输控制.cn         // 模块 网络::传输控制

// 主.cn
模块 网络
导入 网络::传输控制
导入 网络库::连接           // 跨包导入

函数 主() -> 整32 {
    网络::传输控制::发送()
    连接()
    返回 0
}
```

## 六、核心包 prelude

### 6.1 规则

- **核心包基础项默认可见**：编译器隐式提供 `导入 核心::*` 级别的 prelude——核心包中的基础项（打印行/整型/布尔/结果/可选 等构造器与基础函数）无需显式导入即可使用。
- **显式扩展**：`导入 核心::*` 或 `导入 核心::{符号列表}` 可显式引入更多核心包符号。
- **内置函数归属**：内置函数（打印行/运行时函数族）归入 `核心` 包 prelude，不再作为无前缀硬编码扁平表。

### 6.2 示例代码

```
// 无需导入即可使用 prelude 基础项
函数 主() -> 整32 {
    打印行("你好")            // 打印行 来自核心包 prelude
    整32 n = 42                // 整32 类型默认可见
    结果<整32, 字符串> 结果值 = 正常(42)   // 结果/正常 来自 prelude
    返回 0
}

// 显式扩展：导入核心包更多符号
导入 核心::数学::平方根
```

## 七、货舱.toml

### 7.1 规范

```
[货舱]
名称 = "我的程序"          // 包（crate）名称，必填
版本 = "0.1.0"            // 语义化版本，必填

[依赖]
核心 = "内置"             // 内置核心包
网络库 = "1.2"            // 外部依赖（名称 = 版本约束）
```

### 7.2 规则

| 节 | 键 | 说明 |
|----|----|------|
| `[货舱]` | `名称` | crate 名，用于跨包导入路径首段（`导入 名称::模块::符号`），必填 |
| `[货舱]` | `版本` | 语义化版本（`主.次.修订`），必填 |
| `[依赖]` | `名称 = "版本"` | 声明依赖包；`核心 = "内置"` 表示内置核心包；版本支持 `"1.2"`（>=1.2 <2.0）等约束 |

### 7.3 使用示例

```
// 货舱.toml
[货舱]
名称 = "我的程序"
版本 = "0.1.0"

[依赖]
核心 = "内置"
网络库 = "1.2"

// 代码中使用依赖
导入 网络库::连接
导入 网络库::请求::获取

函数 主() -> 整32 {
    连接()
    返回 0
}
```

完整规范见 [09-包与依赖.md](09-包与依赖.md)。

## 八、无强制分号

- **声明以换行终止**：模块声明、导入声明、顶层声明**均无需分号**，换行即终止。
- **`;` 仅同行多语句分隔**：`;` 为可选终止符（兼容 C 习惯），在单行书写多条语句时作为显式分隔符使用。
- **与全语言一致**：本规则与 [01a-词法结构-总览与关键字.md](01a-词法结构-总览与关键字.md) 第三节「语句终止与续行」、[03-语句与控制流.md](03-语句与控制流.md) 第零节完全一致——换行无语法意义（等同空格），语句边界由关键字识别，分号可选。

```
模块 网络                     // 无分号合法
导入 网络::传输控制           // 无分号合法
导入 网络::传输控制;          // 分号可选（兼容 C 习惯）
公开 导入 网络::连接          // 再导出：无分号合法
```

## 九、迁移说明（v1.0 → v2.0）

| v1.0（旧语法） | v2.0（新语法） | 说明 |
|---------------|---------------|------|
| `导入 数学.平方根` | `导入 数学::平方根` | `.` → `::` |
| `从 数学 导入 正弦, 余弦` | `导入 数学::{正弦, 余弦}` | `从...导入` → 花括号导入 |
| `导入 网络协议.HTTP.请求` | `导入 网络协议::HTTP::请求` | 多级路径 `.` → `::` |
| `导入 数学`（默认公开） | `导入 数学`（导入语义不变）+ 文件内显式 `公开:` | 默认私有：模块文件顶部需显式 `公开:` 导出 API |
| 类内无标签默认公开 | 类内无标签默认私有 | 类内默认私有：需显式 `公开:` 标注公共成员 |
| （无） | `模块 网络` | v2.0 新增：模块声明引用 |
| （无） | `导入 核心::{某些, 无}` | 删除 `从` 后花括号形式承担选择性导入 |
| （无） | `导入 路径 作为 别名` | v2.0 新增：重命名导入 |
| （无） | `导入 路径::*` | v2.0 新增：通配符导入 |
| （无） | `公开 导入 网络::连接` | v2.0 新增：再导出（包.cn 聚合 API） |
| （无） | `货舱.toml` `[货舱]`/`[依赖]` | v2.0 新增：包元数据与依赖管理 |
| （无） | 默认私有 + 可见性交集 | v2.0 变更：可见性默认值改变，跨文件/跨包可见性取最严格交集 |

### 迁移速查（标准库模块）

```
// v1.0：默认公开，无需标签
函数 平方根(浮64 x) -> 浮64 { ... }

// v2.0：文件顶部必须显式 公开:
公开:
函数 平方根(浮64 x) -> 浮64 { ... }
```
