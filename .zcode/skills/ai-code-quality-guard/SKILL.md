# AI代码质量保障技能 (AI Code Quality Guard)

## 概述

本技能为AI Agent提供代码质量保障能力，确保每次代码交付都符合质量标准。基于四维度质量保障机制：

1. **预防机制** - 任务设计阶段的粒度控制和规范预检
2. **检测机制** - 代码编写阶段的禁区规则检测
3. **审批机制** - 代码交付前的自检报告
4. **反馈迭代** - 违规记录和经验沉淀

**代码结构三大纪律**（2026-10-10 增补）：针对 AI 写码三大病史（依赖混乱解耦差/重复
不归纳/文件过大不拆），规则挂在动作路径上（写前三问/写中两触发/写后三自查）而非停留
条文。出处对照见文末附录（LLVM/Google/Chromium/Linux 内核/Fowler/SonarQube）。

---

## 何时使用此技能 / When to Use

**使用场景：**
- 用户请求编写新代码或修改现有代码
- 功能实现任务开始前
- 代码重构任务开始前
- Bug修复任务开始前
- 任何涉及代码产出的任务

**不要使用：**
- 纯文档编写任务
- 项目规划或架构设计任务
- 仅阅读和分析代码的任务

## 代码结构三大纪律（写前/写中/写后三检查点）

> 本节是本技能的**强制动作面**：任何代码产出任务，三大纪律的三检查点逐项过，
> 缺一不可。条文出处见文末附录；本项目执法脚本见各纪律末行。

### 纪律一·依赖纪律（写前声明·越界即停）〔Chromium DEPS / LLVM·Google include 最小化〕

| 动作 | 要求 |
|------|------|
| **写前定归属** | 新文件落笔前先定归属层（查 AGENTS.md「新代码归属速查」：类型/AST→model（宿主）/语法树（v2）；词法→lexer/词法；语法→parser/语法；语义→semantic/语义；AST→IR→ir；优化→opt；发射→codegen；CLI→driver/主） |
| **写前查白名单** | 查 `scripts/check_layer_deps.py`（CPP_ALLOW/CN_ALLOW）确认本层允许依赖面；白名单外的依赖需求→**停下呈报用户裁决，禁「顺手 include」** |
| **最小依赖面** | 只依赖直接依赖，禁搭车 include 上游实现头（下游只可依赖中立层接口）；跨层共性优先下沉中立层（model/协议常量先例） |
| **写后过账** | 交付前将本次新增 include/import 逐条对照依赖面自述一遍，越界即撤 |

执法：`python scripts/check_layer_deps.py`（gate_quick 已接入）。

### 纪律二·重复归纳（先查再写·事不过三）〔Fowler Rule of Three / LLVM avoid duplication〕

| 动作 | 要求 |
|------|------|
| **先查再写** | 写任何功能前先 grep 已有实现（同目录+近义关键词，跨模块搜）；宿主与 v2 双侧是本项目常态，v2 落笔前先看宿主同构先例（反之亦然），禁闭眼重写 |
| **事不过三** | 第 1 处正常写；第 2 处重复允许复制但必须留标记注释（如 `// 与 XX 重复·待归纳`）；**第 3 处出现前必须提炼公共函数**，禁出现第 4 处 |
| **当场归纳** | 提炼是一劳永逸义务，禁以「留给下轮重构/保守起见先复制」搁置；公共函数按「新代码归属速查」落正确层，不随手堆当前文件 |

执法：无机械门禁（按 v5「门禁尽量少」方针）——靠写前 grep 动作+写后 diff 自查。

### 纪律三·体量红线（先拆再加）〔Linux 内核单一职责/函数单屏 + 本项目既有红线〕

| 检查点 | 红线 | 动作 |
|--------|------|------|
| 文件行数 | ≤1000 硬红线；**>900 行=警戒线** | 改动前 `wc -l` 目标文件；警戒线上新增功能**先拆再加**（禁只加不拆） |
| 函数行数 | ≤100 行 | 超限当场拆；`python scripts/check_fn_length.py` 报告可核对 |
| 拆分信号 | 嵌套 >3 层；一文件混入第二职责 | 当场按职责切子模块（先例：semantic_call 拆族、genVarDecl 拆族），新文件先查归属 |

执法：`python scripts/check_file_length.py`（gate_quick 已接入）。

### 三检查点（核心机制——把规则挂上动作路径）

```
写前三问：① 这段代码归属哪一层（查「新代码归属速查」）？
          ② grep 过已有实现没有（含宿主↔v2 对侧先例）？
          ③ 目标文件现在多少行（>900 先拆再加）？

写中两触发：第三次重复出现 → 立即提炼公共函数；
            函数过 100 行 / 嵌套过 3 层 → 立即拆分。

写后三自查：wc -l 新旧文件 ≤ 红线？
            diff 里有没有该归纳而未归纳的复制块？
            新增 include/import 全部在本层依赖面内？
```

三自查任一不过=返工，不带病交付；自查通过后进入下方四阶段流程并写入自检报告。

**闸门两态挂点（纪律五）**：写前三问加问「本轮新增/交接语义闸门吗？坏样本与好对照
各是什么」；写后自查加查「两态现场证据齐否（诊断原文+退出码+好样本对照绿——禁以注释
声称代替），负测锚对账过否（`python scripts/check_diag_negtest.py --diff`）」。无闸门
改动轮此二问空过即可（零成本）。

### 纪律四·miss 处置（查表/判定失败不可静默）〔2026-10-14 用户令·648·110 案立法化·rustc/LLVM 内部错误显形〕

> 适用面：编译器实现代码（宿主 C++ 与 v2 CN 两侧同规），以及一切「查不到就给默认值继续跑」的
> 判定代码。110 实录：FFI 返回类型查表 miss 静默默认整32→三平台全错值；同族静默兜底曾致
> 常量 0、8 字节过写邻槽、虚表 0 号槽误调——静默错误比显式报错危险一个数量级。

| 动作 | 要求 |
|------|------|
| **miss 终态三选一** | ①报内部错误诊断（编译器 bug 显形——宿主 `diagnostics_.report(Error,…)`·v2 T3 收集-收尾报先例）；②显式哨兵+消费点强制检查分流；③穷举断言证明不可达。三之外皆禁 |
| **合法 miss 须显式声明·登记制（882 升格）** | 一切静默终态（查表/判定 miss、默认值散写）豁免面**禁散写**：统一登记 [`scripts/miss_registry.json`](../../../scripts/miss_registry.json)（文件/函数/锚文本/类别/来源/静默风险/原因/登记人）+代码侧协议化注释 **`// 静默豁免<类别>: 原因`**（同行行尾或上一行·类别枚举=上游已诊断/闭集穷举/运行时API/业务值（确权不求值）/待裁决——对齐 Google TODO(username) 强制格式先例）。三红 L1 硬拦无逃生门（`scripts/check_miss_gate.py`·gate_quick 静态段）：漏登记（注释无条）/陈旧（条锚消失）/红旗词面无登记；唯一合法通道=补条+协议注释 |
| **红旗注释** | 「防御性兜底」「保守回退」「miss 即默认」「查不到按 X 处理」类注释=审查红旗，新代码出现即驳回（存量冻结基线只减不增·新位置无登记=L1 红） |
| **修面修全** | 修 miss 面**禁止只扩已知形态覆盖面而保留静默终态**（110/861-a 同一教训：修了已知面，miss 终态留雷） |

写前三问增补：④ 这段代码的 miss 路径终态是什么？静默默认值=当场改三选一；
增补：⑤ 若确需保留豁免面，写登记表条+协议注释了吗（三红硬拦，无逃生门）。

**else 新规（2026-10-17 用户裁决·机械无判别空间）**：条件语句必须 `如果`+`否则如果` 显式枚举
全部合法区间（枚举须含上界——分数场景补 `否则如果(分数<=100)`），**`else`/`否则` 块内禁止业务
代码**（赋值/打印结果/返回业务值），只许报错/警告/断言终止——else 从「兜底处理分支」降格为
「非法输入拦截分支」（布尔完备≠业务完备：`分数>=60` 的 else 拦不住 1000 分的非法输入）。
机械抓捕=check_miss_gate「else业务」面（块内容非 {报错调用/打印到错误/返回错误码/断言/负数码}
即红·存量进基线）。

**单边开区间禁令（2026-10-17 用户裁决二）**：分支条件（`如果`/`否则如果`/`if`/`else if` 条件位）
对业务数值的比较必须**双边界闭区间**（`分数>=90 且 分数<=100`），禁止单边无限区间
（`>=`/`>`/`<`/`<=` 一侧字面量且无反向第二比较·`>=90` 向 +∞ 开口=红）；相邻区间允许冗余
复写边界。排除：指针判空（nullptr/空指针/`*` 前缀操作数）、循环头、常量布尔。
机械抓捕=check_miss_gate「单边比较」面。

### 纪律五·闸门验收两态（新增/交接语义闸门必做正反两态）〔728n 立·教训 #146 同族/193 病根·Clang 诊断验证实践〕

> 病根（193 实录）：宿主编译器某处注释写着「语义层已报错、此处防御跳过」——注释声称
> 检查存在，实际语义层零检查，防线交接断链存活很久才被探针戳穿。审计结论：**「检查点
> 交接」没有验收环节**。本纪律将其制度化：任何**新增/交接的语义闸门**（编译期拒绝、
> 诊断、防线——含宿主与 v2 双侧）验收必须含「真实拦截一个坏样本」的两态证据。
> 核心一句：**禁以代码/注释/文档的声称代替现场证据**——注释说拦住了不算拦住，跑出来的才作数。

| 态 | 要求 | 证据形态（缺一不可） |
|----|------|----------------------|
| **① 坏样本被真实拦截（正态）** | 拿一个真实坏样本（违反新闸门的代码/输入）喂进真实生产链路（真编译/真运行，非静态推断、非「按理应该」），确认真被拦 | 诊断**原文**+退出码/拒绝行为实录；有负测用例则附用例名（诊断锚与实测输出逐字一致） |
| **② 好样本零误伤（反态）** | 同族合法形态的健康对照样本必须照常通过（闸门过紧=误伤正常程序，同属缺陷） | 编译通过+运行输出对照绿；正测用例或最小对照样本实录 |
| **③ 交接型·注释声称已拦** | 任何「上游已报错/已检查，此处防御跳过」形态的防线=交接防线 | **现场证明上游真报了**（探针实测/负测用例实证）；注释、文档、他人转述一律不足以验收——193 病根即注释声称而实际零检查 |

动作挂点（挂上编码路径）：
- **写前**：本轮若新增/交接语义闸门 → 预算两态样本（坏样本+好对照各一，通常=一条负测+一条正测，诊断锚同步登记覆盖矩阵）。
- **写后**：跑一次真实链路（本地定向 `python tests/e2e/run_e2e.py --filter <用例>` 或手动编译坏/好样本），把两态证据写进交付说明；再做机械对账
  `python scripts/check_diag_negtest.py --diff [基线]`——新增诊断须能在 tests/e2e 负测锚中找到着落（强=锚为静态段子串、run_e2e 必然命中；近似=疑跨拼接缝待判；弱=短锚/短共享段；缺口=无着落应补负测）。
- **工具边界（诚实·不假装全覆盖）**：对账只证明「有负测锚着落」，不证明运行期真拦截（那正是两态现场证据的职责）；跨变量缝的锚与「注释声称」型交接机械无判据（列人工清单项）；v2 `IO::打印到错误` 通道混有进度日志（[p6h]/[ir1]/[cg1] 等），工具不作文本语义分类。

验收记录模板（交付说明/提交信息内三行照抄·728n 演示实例）：

```
闸门：<一句话闸门名>（宿主 <文件/函数> + v2 <文件/函数>）
① 坏样本 <用例目录/探针>：<命令> → rc≠0，诊断原文「……」〔逐字〕
② 好样本 <正测用例/对照>：<命令> → rc=0，输出对照绿（主.expected 逐行一致）
③ 交接型注释：有/无 → 有则现场证明结论〔上游真报=<探针实录> / 伪=已修+负测〕
对账：check_diag_negtest.py --diff <基线> → 新增诊断 N 条 强 x/近似 y/弱 z/缺口 0
```

执法：`scripts/check_diag_negtest.py`（--diff 增量对账 + --selftest 探测器自测；收工自查手动跑·报告式默认 rc=0；973 起另挂 ci_daemon 兜底轮周期段〔ci_reconcile.py·每周到期 --diff --strict·红步骤播报〕）——与 §4 E2E 纪律（负测登记/覆盖矩阵）互为表里。

## 核心规则

### 一、任务预检规则（Phase 1）

在开始编写代码之前，必须进行以下预检：

| 检查项 | 限制值 | 超限处理 |
|--------|--------|----------|
| **代码量预估** | ≤500行 | 超过则建议拆分为多个子任务 |
| **文件数预估** | ≤10个 | 超过则建议拆分为多个子任务 |
| **复杂度评估** | 明确输入/输出/边界 | 未明确则先澄清需求 |

#### 预检清单模板

```markdown
## 任务预检清单

### 任务信息
- 任务名称：[填写任务名称]
- 预估代码量：[X] 行（限制：500行）
- 预估文件数：[X] 个（限制：10个）

### 复杂度评估
- 输入定义：[明确输入数据/参数]
- 输出定义：[明确输出结果/返回值]
- 边界条件：[列出边界场景]

### 预检结果
- [ ] 代码量符合限制
- [ ] 文件数符合限制
- [ ] 复杂度已评估明确

**预检结论**：通过 / 需拆分
```

### 二、代码编写禁区（Phase 2）

以下行为严格禁止，检测到将自动驳回：

| 禁区规则 | 说明 | 检测方式 |
|----------|------|----------|
| **禁止TODO占位** | 方法内禁止写 `// TODO` 或 `// 待实现` 后直接返回 | 正则扫描 |
| **禁止空方法体** | 方法体不能为空或只抛出 `NotImplementedException` | AST分析 |
| **禁止省略校验** | 必须进行参数校验和边界处理 | 代码审查 |
| **禁止魔法值** | 禁止硬编码数字、字符串等魔法值 | 正则扫描 |
| **禁止依赖越界** | include/import 不得超出本层白名单（`check_layer_deps.py`）；白名单外需求呈报而非顺手加 | 写前查表+写后对照 |
| **禁止无查复制** | 复制既有代码块前必须先 grep 已有实现；第二处重复须留标记注释，第三处前必须提炼 | 代码审查 |
| **禁止警戒线增行** | >900 行文件新增功能前先拆分；函数 >100 行/嵌套 >3 层当场拆 | `wc -l`+check 脚本 |
| **禁止 miss 静默** | 查表/判定 miss 终态不得静默取默认值继续；合法处置仅三选一（见纪律四）：报内部错误诊断/显式哨兵+强制检查/穷举断言 | 代码审查+红旗注释扫描 |
| **禁止无两态验收的新闸门** | 新增/交接语义闸门（编译期拒绝/诊断/防线）必须附正反两态现场证据（坏样本被拦实录+好样本对照绿）；「注释声称已拦」必须现场证明上游真报（见纪律五） | 交付说明证据核对+`check_diag_negtest.py --diff` 对账 |

#### 禁区检测清单

```markdown
## 禁区检测清单

### 静态扫描项
- [ ] 无 TODO/FIXME/XXX 注释
- [ ] 无空方法体
- [ ] 无 NotImplementedException
- [ ] 无注释掉的代码块

### 代码质量项
- [ ] 参数校验完备
- [ ] 边界处理覆盖
- [ ] 无硬编码魔法值
- [ ] 错误处理完整

### 检测结果
**状态**：合格 / 不合格
**问题清单**：[列出发现的问题]
```

### 三、必须检查项（Phase 3）

代码编写完成后，必须进行以下检查：

| 检查项 | 要求 | 说明 |
|--------|------|------|
| **单元测试** | 覆盖核心逻辑 | 测试覆盖率 ≥80% |
| **错误处理** | 异常捕获和日志记录 | 关键路径必须有错误处理 |
| **代码风格** | 符合项目规范 | 遵循项目已有代码风格 |
| **注释说明** | 复杂逻辑必须有注释 | 解释"为什么"而非"是什么" |

### 四、自检报告格式（Phase 4）

代码交付前必须生成自检报告：

```markdown
## 代码交付自检报告

### 基本信息
- 任务名称：[任务名称]
- 涉及文件：[文件列表]
- 代码行数：[X] 行
```

## 附录·成熟大项目对照（三大纪律出处）

| 本项目纪律 | 成熟项目出处 | 原文要点 |
|------------|--------------|----------|
| 依赖纪律·白名单 | Chromium DEPS 文件 | 模块间依赖显式声明，越界依赖构建即拒；下层禁依赖上层 |
| 依赖纪律·最小 include | LLVM Coding Standards / Google C++ Style Guide | 只 include 直接依赖，能用前置声明就不 include，降低耦合与编译时间 |
| 重复归纳·避免复制 | LLVM Coding Standards | 写可复用库代码而非复制粘贴；重复=双倍维护面 |
| 重复归纳·事不过三 | Fowler《重构》Rule of Three | 第三次重复必须提炼，否则提炼成本超过重复成本 |
| 体量红线·单一职责 | Linux 内核编码规范 | 一个文件一件事；函数长到单屏放不下即拆分信号 |
| 体量红线·量化口径 | SonarQube 质量门默认值 | 认知复杂度阈值；10+ 行重复块判为 clone 入质量门 |
| 闸门验收两态 | Clang/LLVM 测试套件（lit 诊断验证） | 每个新诊断须带负测样本（`expected-error {{…}}` 逐字锚定）；LLVM 综述——「没有回归测试的补丁不算修好」 |

本项目执法差异：依赖与行数两条已有机械脚本（check_layer_deps / check_file_length），
重复归纳无机械门禁（clone 检测误报天然偏高·v5「门禁尽量少」方针），靠三检查点动作自查承担。
