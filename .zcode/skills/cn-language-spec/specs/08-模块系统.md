## 一、设计原则：文件即模块 + 包 = crate

### EBNF

```
模块 = 源文件（每个 .cn 文件是一个模块）
模块名 = 文件名（不含 .cn 扩展名）
包（crate）= 一个编译单元根（主.cn 或 包.cn）+ 其引用的模块树
```

### 原则说明

| 原则 | 说明 |
|------|------|
| 文件即模块（保留） | 每个 `.cn` 文件就是一个模块，模块名为文件名（不含扩展名）；`网络/传输控制.cn` → 模块 `网络::传输控制` |
| 包 = crate（新增） | 包（crate）是**命名空间边界与编译单元边界**：一个可执行程序或库 = 一个 crate。跨包同名符号互不冲突（crate 隔离） |
| crate 根 | 可执行程序根 = `主.cn`；库根 = `包.cn`（聚合模块并再导出公共 API） |
| 顶层声明 | 函数/结构体/枚举/类/接口/导入/模块/常量/静态/全局变量均为模块级声明 |
| 模块边界 | 模块间可见性通过 `公开:`/`私有:` 标签控制，**默认私有**（见第四节） |

### 设计决策

- **文件即模块**（保留自 v1.0）：无块式模块语法（`模块 名 { }`），模块必须以独立文件存在。
- **包 = crate**（v2.0 新增）：crate 隔离是模块系统 v2.0 的核心决策之一——每个包是独立的命名空间，`包A::工具` 与 `包B::工具` 是两个不同符号，互不冲突。
- **v1.0 差异**：路径分隔由 `.` 改为 `::`；删除 `从` 导入语法；可见性由默认公开改为**默认私有**。

## 二、模块声明

### EBNF

```
模块声明 = "模块" 标识符
```

### 规则说明

| 规则 | 说明 |
|------|------|
| 形式 | `模块 网络`（声明引用模块 `网络.cn`，编译器自动加载同名文件） |
| 分号 | `模块 名` 无分号（声明即引用，无体）；`导入 路径;` **须分号**（2026-09-04 plans/015 裁决，Rust use 同款），见第八节 |
| 不引用文件内容 | `模块 名` 仅建立模块树引用关系；具体符号需通过 `导入` 引入作用域 |
| 唯一形式 | CN 语言**不支持内联模块**（`模块 名 { }` 花括号形式），所有模块必须以独立文件存在 |
| **定位收紧**（2026-09-07 plans/018 裁决，Rust `mod` 对齐） | `模块` 声明**仅限两种树结构位置**：① 包根成员聚合（`包.cn` 内 `模块 网络;`）；② 父模块挂子模块（`网络.cn` 内 `模块 传输控制;`，建立 `网络::传输控制` 完整路径）。**普通源文件使用 `模块` 声明 = 编译诊断**（普通文件的模块路径由文件名+目录层级唯一决定，无需声明） |
| **自动加载强语义**（2026-09-07 宿主实证，plans/018 第 0 步） | 被 `模块` 声明引用的模块文件**恒被加载编译**（Rust `mod foo;` 必编译 `foo.rs` 同款）——哪怕无人 `导入`，其内错误也在库自身编译期暴露（fail fast，库完整性保证）；触发源即 `模块` 声明本身而非目录扫描：未声明的同目录杂散 `.cn` 文件不参与编译（封闭树） |
| **自包导入**（2026-09-09 plans/018 立规，见 5.5） | 目录包成员 `导入 自包名;`（如 `IR/IR布局.cn` 内 `导入 IR;`）= **合法的自包引用**：包内公开符号经合并阶段全局可见，自包引用是包内符号解析而非跨包依赖——**不构成循环依赖**，加载器与依赖图必须豁免该依赖边（Rust 同构：crate 内路径引用无需跨 crate 依赖边） |

### 示例代码

```
// 主.cn：声明引用同级文件模块
模块 网络
模块 工具

函数 主() -> 整32 {
    导入 网络::连接
    网络::连接()
    返回 0
}
```

## 三、路径与导入语法

### 3.1 路径（`::` 分隔）

```
路径 = 标识符 ("::" 标识符)*
```

- 路径用 `::` 分隔，**对应目录层级与模块树**：`网络/传输控制.cn` → `网络::传输控制`。
- 路径首段可以是：当前包内的模块名、`核心`（核心包）、或货舱.toml 中声明的依赖包名。

### 3.2 导入语法（全形式）

```
导入声明 = "导入" 路径 ["作为" 标识符]
          | "导入" 路径 "::" "{" 导入项 ("," 导入项)* "}"
          | "导入" 路径 "::" "*"
导入项 = 标识符 ["作为" 标识符]
```

### 3.3 四种导入形式

| 形式 | 语法 | 语义 | 示例 |
|------|------|------|------|
| 路径导入 | `导入 路径` | 导入模块（其后可用 `路径::符号` 限定访问） | `导入 核心::集合` |
| 重命名导入 | `导入 路径 作为 标识符` | 导入模块/符号并绑定别名 | `导入 核心::列表 作为 动态数组` |
| 花括号导入 | `导入 路径::{项列表}` | 选择性导入多个符号，可逐个重命名 | `导入 核心::可选::{某些, 无}` |
| 通配符导入 | `导入 路径::*` | 导入模块全部公开符号（谨慎使用） | `导入 核心::集合::*` |

### 3.4 示例代码

```
导入 核心::可选::{某些, 无}; // 花括号：选择性导入
导入 核心::集合; // 路径：导入整个模块
导入 核心::列表 作为 动态数组; // 重命名：别名绑定
导入 核心::集合::*; // 通配符：全部公开符号（不推荐滥用）
导入 包::网络::连接; // 跨包：包名::模块::符号
```

### 3.5 设计决策

- **`::` 路径分隔**（v2.0）：替代 v1.0 的 `.`，与 Rust 路径习惯一致；`::` 使模块限定与成员访问 `.` 在词法上清晰区分。
- **删除 `从`**（v2.0）：v1.0 的 `从 模块 导入 名` 语法删除，统一由 `导入 路径::{名1, 名2}` 花括号形式承担。
- **保留 `导入`**：`导入` 是唯一导入关键字，不引入 `使用`。
- **再导出**：`公开 导入 路径` 可将导入的符号再导出（crate 公共 API 聚合，见第五节）。

### 3.6 名称解析（遮蔽与歧义，2026-09-07 plans/018 新增·Rust 对照）

> 此前规范空白（宿主行为是事实标准无条文），plans/018 立规。Rust 对照：item > named use > glob
> 三级 + E0255（导入与本地定义同名）/ E0659（glob 歧义）显式报错，**绝不静默选**（歧义绝不引入错误绑定）。

**三级优先级**（纯名引用——不带 `::` 的标识符——按此决议唯一绑定）：

| 优先级 | 名字来源 | CN 形式 | Rust 对应 |
|---|---|---|---|
| 1（最高） | 本模块显式定义项 | 函数/结构体/常量/静态声明 | item in current module |
| 2 | 显式导入（具名绑定） | `导入 m::符号`、`导入 m::{a, b}`、`导入 m::符号 作为 别名`（符号以原名/别名绑定纯名） | named `use` |
| 3（最低） | 通配引入 | `导入 m;`（模块整体导入=其公开 API 批量引入）、`导入 m::*` | glob `use m::*` |

> **模块级别名**：`导入 m 作为 别名` / `导入 a::b 作为 别名` 绑定的是**模块路径本身**
> （供 `别名::符号` 限定访问），不引入纯名——等价 Rust `use m as n`。
>
> **限定调用恒明确（2026-09-07 plans/018 呈报一B 裁决：对齐 Rust「路径恒可用、导入只影响
> 纯名」）**：`m::X`（含多级）指向**已加载模块**的公开符号即可用，**不要求先导入**；宿主
> 现行 P1-1（未导入限定调用报错）随之废止（✅ 已实施：plans/018 工作流2，第三十一轮下半程）。

**冲突与遮蔽判定矩阵**（同为纯名、签名相同的前提下）：

| 冲突面 | 判定 | 诊断 |
|---|---|---|
| ① × ② 同名 | **编译错误** | 「导入与本地定义同名」（E0255 对应；改名或删其一） |
| ② × ② 同名 | **编译错误** | 「多次显式导入同名」 |
| ③ × ③ 同名 | **使用点歧义错误**（仅当该名字被实际引用时报） | 「符号歧义：来自 模块A/模块B」（E0659 对应） |
| ① 遮蔽 ③ | **合法**（唯一允许的遮蔽） | 无诊断（本模块项优先，glob 项被遮蔽） |
| ② 遮蔽 ③ | 合法 | 无诊断 |
| 重载（同名不同签名） | 不适用本矩阵 | 按函数重载决议（签名精确/字面量宽匹配），歧义同报错 |

- **限定调用恒明确**：`模块::符号(...)`（含多级 `a::b::c`）直接决议到指定模块的公开符号，不参与遮蔽，永无歧义；指向**已加载模块**的公开符号即可用，**不要求先导入**（2026-09-07 呈报一B 裁决废止 P1-1，Rust「路径恒可用」对齐，✅ 已实施）。
- **跨模块同名同签名合法共存**：链接符号在多模块场景加前缀 `模块全路径$名#参数串`（函数/结构体/常量统一），单文件/主模块不加前缀——编译期一次拼接，运行时零开销。
- **决议失败绝不静默**：歧义/未命中一律编译诊断，禁止「先收集文件赢」式静默绑定。

```
// 示例：本模块项遮蔽整体导入（合法）
导入 工具库;                        // ③ 模块级通配，工具库 也有 公开 函数 版本()
函数 版本() -> 整32 { 返回 100; }   // ① 本模块项
// 纯名 版本() -> 100（①遮蔽③）；工具库::版本() -> 200（限定调用直达）

// 示例：具名导入与本模块项同名 = 编译错误
导入 工具库::版本;                  // ② 与上方 ① 同名 → 编译错误「导入与本地定义同名」
// 对照：导入 工具库; 或 导入 工具库::*;（③ 通配）与本地 版本 同名 = 合法遮蔽
```

## 四、可见性（标签式 + 默认私有 + 交集规则）

### 4.1 EBNF

```
可见性标签 = "公开:" | "私有:"
可见性段 = 标签, 声明*
```

### 4.2 标签式语义

| 标签 | 语义 | 对应C++ |
|------|------|---------|
| `公开:` | 模块外可访问（可被导入使用） | public |
| `私有:` | 仅模块内部可访问 | 匿名命名空间/static |

- **标签式**：`公开:`/`私有:` 为块级标签，标签后所有声明继承该可见性直到下一个标签。
- **默认私有**（v2.0 变更）：文件顶部**无任何标签时，声明默认为私有**（v1.0 为默认公开）。标准库模块须在文件顶部显式写 `公开:` 以导出 API。

### 4.3 可见性交集规则（重点章节，v2.0 新增）

> **核心规则：符号的最终可见性 = 各层级可见性的交集（取最严格）。**
>
> 模块级 `私有:` 块内的类，即使类内标了 `公开:`，**跨文件导入时整个类（含公开成员）不可见**。类内 `公开:` 仅在本模块内有效（允许本模块代码访问该类公开成员），**不赋予类跨模块可见性**。

### 四象限可见性矩阵

| 类层级 | 成员层级 | 同文件 | 同包跨文件（导入后） | 跨包（导入后） |
|--------|---------|--------|-------------------|--------------|
| 模块公开 | 类内公开 | ✅ | ✅ | ✅ |
| 模块公开 | 类内私有 | ✅ | ❌ | ❌ |
| 模块私有 | 类内公开 | ✅ | ❌ | ❌ |
| 模块私有 | 类内私有 | ✅ | ❌ | ❌ |

### 4.4 示例代码

```
// 模块甲.cn
公开:
    函数 公开函数() { }          // 模块公开：可跨模块导入
    类 公开类 {                  // 模块公开类
        公开:
        函数 公开方法() { }      // 类内公开 + 模块公开 → 交集=公开
    }

私有:
    函数 私有函数() { }          // 模块私有：仅本模块可见
    类 私有类 {                  // 模块私有类
        公开:
        函数 公开方法() { }      // 类内公开 + 模块私有 → 交集=私有（整个类跨文件不可见）
    }

    函数 默认私有() { }          // 无标签 → 默认私有
```

```
// 模块乙.cn
导入 模块甲::{公开类};

函数 使用() {
    公开类 实例                        // ✅ 模块公开类可导入
    实例.公开方法()                    // ✅ 类内公开 + 模块公开 → 可访问
    // 模块甲::私有类 实例2             // ❌ 模块私有类跨文件不可见（即使类内标了公开）
    // 模块甲::私有函数()              // ❌ 模块私有函数不可见
}
```

### 4.5 设计决策

- **默认私有**（v2.0 变更）：模块级与类内均默认私有。理由：默认私有是信息隐藏的最佳实践，显式 `公开:` 声明公共 API，避免"忘了写私有导致意外暴露"。
- **可见性交集**（v2.0 新增）：模块级可见性与类内可见性取交集（最严格），杜绝"类内公开成员绕过模块私有边界"的漏洞。
- 与旧版 Rust 风格差异：旧版为逐项修饰（`公开 函数`），v2.0 保留 C++ 风格标签式（`公开:`）。

## 五、crate 模型（包 = crate）

### 5.1 包.cn 根文件

库包以 `包.cn` 为 crate 根，聚合模块树并再导出公共 API：

```
// 包.cn（crate 根，聚合模块）
模块 网络
模块 存储

公开 导入 网络::连接; // 再导出：外部通过 包名::连接 使用
公开 导入 存储::存储器;
```

### 5.2 子目录模块树

```
网络/
├── 网络.cn                 // 模块 网络（目录内同名文件 = 模块本身）
├── 传输控制.cn             // 模块 网络::传输控制
└── 用户数据报.cn           // 模块 网络::用户数据报
```

- 目录层级对应 `::` 路径：`网络/传输控制.cn` → `网络::传输控制`。
- `模块 网络` 引用 `网络.cn`；`网络/传输控制.cn` 作为 `网络` 的子模块树。

### 5.3 跨包导入

```
// 货舱.toml 已声明依赖 网络库 = "1.2"
导入 网络库::连接; // 导入依赖包中的模块符号
导入 网络库::请求::获取; // 多级路径：包名::模块::符号
```

- 包名 = crate 名（货舱.toml 中 `[货舱] 名称`）。
- crate 隔离：`包A::工具` 与 `包B::工具` 是两个独立符号，互不冲突。

### 5.4 示例：完整 crate 布局

```
项目/
├── 货舱.toml               // 包元数据 + 依赖
├── 主.cn                   // 可执行程序 crate 根（或 包.cn 库根）
├── 网络.cn                 // 模块 网络
└── 网络/
    └── 传输控制.cn         // 模块 网络::传输控制

// 主.cn
模块 网络
导入 网络::传输控制;
导入 网络库::连接; // 跨包导入

函数 主() -> 整32 {
    网络::传输控制::发送()
    连接()
    返回 0
}
```

### 5.5 目录包（阶段目录包形态，2026-09-09 plans/018 立规）

> 背景：库包的物理组织在 5.1/5.2（`包名.cn` + `包名/` 子目录）之外新增**目录包**形态：
> 包 = 目录，包根 = 目录内 `包.cn`，成员 = 包目录同级 `.cn` 文件。形态于 2026-09-08
> plans/018 千行拆分轮用户裁决（阶段目录包形态A，自举编译器 `CN语言编译器v2/` 即此
> 形态：词法/语法/语义/IR/代码生成/货舱解析 六目录包）；语义边界于 2026-09-08
> 第三十八轮「单文件入口组件编译」根治中全链钉死（宿主与自举编译器双侧实现一致，
> 组件对拍 30/30 逐字节 + 发射级等价实证），本节随即将其立规。

**物理形态**：

```
包名/
├── 包.cn            // 包根：成员聚合声明（每成员一行 模块 成员名）
├── 成员一.cn        // 包成员（模块路径 = 包名::成员一）
└── 成员二.cn        // 包成员
```

**规则**：

| 规则 | 说明 |
|------|------|
| 包根 | 包目录内的 `包.cn`；包根模块名 = 包目录名。包根仅含成员聚合 `模块` 声明与（可选）`公开 导入` 再导出，不含函数/类型等实体声明 |
| 成员聚合 | 包根内 `模块 成员名;` 声明成员（第二节定位收紧形态①）；**声明序 = 加载序**（依赖先解析：基础模块在前），成员文件在包目录同级解析（`成员名.cn`） |
| 成员模块路径 | 成员路径 = `包名::成员名`（目录层级对应 `::` 路径，5.2 同款规则）；同包内兄弟符号经合并阶段全局可见——成员互相引用**无需** `导入` |
| **自包导入** | 包成员 `导入 自包名;` = 引用本包公开符号，**不构成循环依赖**（见第二节规则表；宿主曾因自包依赖边与包根聚合边构成图环而假报「模块循环依赖」，2026-09-08 第三十八轮根治：依赖图对自包边豁免） |
| **编译单元不变式** | 包 = 完整编译单元：以任一**成员文件**为编译入口（组件级编译）时，其所属包根的聚合语义仍生效——兄弟成员自动纳入编译（**包上下文恢复**）；以 `包.cn` 为入口 = 编译整包。保证「包内符号互相可见」不因入口选择而破坏 |
| 非成员文件 | 恰好位于包目录内、但未被包根 `模块` 声明引用的 `.cn` 文件**不是**包成员（封闭树，第二节自动加载强语义同源）——以其为入口编译不触发包聚合 |
| 依赖查找 | 目录包经依赖查找链命中（自引用方文件目录逐级上溯探测 `<名>/包.cn`）；货舱 `[依赖]` 本地依赖的 `依赖/名/包.cn` 为同款目录形态（完整查找顺序见 [09-包与依赖.md](09-包与依赖.md)） |
| 链接键 | 目录包成员的链接符号键形态由编译器实现定义，但**同一编译器内必须自洽且由唯一公式确定**（3.6 链接符号契约「注册/定义/调用三处同源」原则延伸）；不同实现（宿主/自举）键形态细节允许各自定义，产物各自自洽 |

**示例**（自举编译器真实形态节选）：

```
CN语言编译器v2/
├── 主.cn                    // 可执行程序 crate 根
├── 词法/
│   ├── 包.cn                // 包根：模块 词法分析
│   └── 词法分析.cn          // 成员（模块路径 = 词法::词法分析）
└── IR/
    ├── 包.cn                // 包根：模块 IR布局（声明序=加载序）
    │                        //        模块 IR容器
    │                        //        ...
    ├── IR布局.cn            // 成员；文件内 `导入 IR;`（自包导入 = 合法）
    └── IR容器.cn            // 成员，可纯名引用 IR布局 的公开符号（同包免导入）

// 主.cn（crate 根）
导入 词法;                      // 目录包按包名导入
导入 IR;                        // IR 包（语法/语义 依赖其布局与判定，依赖先解析）
导入 语法;
导入 语义;
导入 代码生成;
```

## 六、核心包 prelude

### 6.1 规则

- **核心包基础项默认可见**：编译器隐式提供 `导入 核心::*` 级别的 prelude——核心包中的基础项（打印行/整型/布尔/结果/可选 等构造器与基础函数）无需显式导入即可使用。
- **显式扩展**：`导入 核心::*` 或 `导入 核心::{符号列表}` 可显式引入更多核心包符号。
- **内置函数归属**：内置函数（打印行/运行时函数族）归入 `核心` 包 prelude，不再作为无前缀硬编码扁平表。

### 6.2 示例代码

```
// 无需导入即可使用 prelude 基础项
函数 主() -> 整32 {
    打印行("你好")            // 打印行 来自核心包 prelude
    整32 n = 42                // 整32 类型默认可见
    结果<整32, 字符串> 结果值 = 正常(42)   // 结果/正常 来自 prelude
    返回 0
}

// 显式扩展：导入核心包更多符号
导入 核心::数学::平方根;
```

## 七、货舱.toml

### 7.1 规范

```
[货舱]
名称 = "我的程序"          // 包（crate）名称，必填
版本 = "0.1.0"            // 语义化版本，必填

[依赖]
核心 = "内置"             // 内置核心包
网络库 = "1.2"            // 外部依赖（名称 = 版本约束）
```

### 7.2 规则

| 节 | 键 | 说明 |
|----|----|------|
| `[货舱]` | `名称` | crate 名，用于跨包导入路径首段（`导入 名称::模块::符号`），必填 |
| `[货舱]` | `版本` | 语义化版本（`主.次.修订`），必填 |
| `[依赖]` | `名称 = "版本"` | 声明依赖包；`核心 = "内置"` 表示内置核心包；版本支持 `"1.2"`（>=1.2 <2.0）等约束 |

> **v2 自举编译器同样须支持**（2026-09-07 plans/018 用户裁决：货舱.toml 纳入 v2 范围）——
> v2 加载器实现纯 CN 的 TOML 子集解析（`[货舱]`/`[依赖]` 两节）+ 包发现 + 依赖查找链，
> 与宿主 cargo_parser 语义一致（入口同目录 → 货舱 `[依赖]`：内置→stdlib、本地→`依赖/名/`）。

### 7.3 使用示例

```
// 货舱.toml
[货舱]
名称 = "我的程序"
版本 = "0.1.0"

[依赖]
核心 = "内置"
网络库 = "1.2"

// 代码中使用依赖
导入 网络库::连接;
导入 网络库::请求::获取;

函数 主() -> 整32 {
    连接()
    返回 0
}
```

完整规范见 [09-包与依赖.md](09-包与依赖.md)。

## 八、分号模型（2026-09-04 plans/015 方案B 反转）

- **导入声明须分号**：`导入 路径;`（对齐 Rust `use ...;`）——含重命名/花括号/通配符全形式与 `公开 导入`（再导出）。
- **模块声明无分号**：`模块 名` 仅建立引用关系（无体、无初始化表达式），保持换行即止。
- **顶层常量/静态声明须分号**：`常量 T = 2;` / `静态 类型 名 = 值;`（C++ const/static 同款）；结构体/类/接口/枚举体 `}` 自终结。
- **与全语言一致**：本规则与 [01a-词法结构-总览与关键字.md](01a-词法结构-总览与关键字.md) 第三节「语句终止与续行」、[03-语句与控制流.md](03-语句与控制流.md) 第零节完全一致——语句强制 `;` 终结，表达式内部换行仍≡空白（续行不受影响）。

```
模块 网络                     // 模块声明：无分号（声明即引用）
导入 网络::传输控制;          // 导入声明：须分号
导入 网络::{连接, 断开};      // 花括号导入：须分号
导入 网络::*;                 // 通配符导入：须分号
公开 导入 网络::连接;         // 再导出：须分号
常量 上限 = 100;              // 顶层常量：须分号（C++ const 同款）
静态 整32 计数 = 0;           // 顶层静态：须分号
```

## 九、迁移说明（v1.0 → v2.0）

| v1.0（旧语法） | v2.0（新语法） | 说明 |
|---------------|---------------|------|
| `导入 数学.平方根` | `导入 数学::平方根` | `.` → `::` |
| `从 数学 导入 正弦, 余弦` | `导入 数学::{正弦, 余弦}` | `从...导入` → 花括号导入 |
| `导入 网络协议.HTTP.请求` | `导入 网络协议::HTTP::请求` | 多级路径 `.` → `::` |
| `导入 数学`（默认公开） | `导入 数学`（导入语义不变）+ 文件内显式 `公开:` | 默认私有：模块文件顶部需显式 `公开:` 导出 API |
| 类内无标签默认公开 | 类内无标签默认私有 | 类内默认私有：需显式 `公开:` 标注公共成员 |
| （无） | `模块 网络` | v2.0 新增：模块声明引用 |
| （无） | `导入 核心::{某些, 无}` | 删除 `从` 后花括号形式承担选择性导入 |
| （无） | `导入 路径 作为 别名` | v2.0 新增：重命名导入 |
| （无） | `导入 路径::*` | v2.0 新增：通配符导入 |
| （无） | `公开 导入 网络::连接` | v2.0 新增：再导出（包.cn 聚合 API） |
| （无） | `货舱.toml` `[货舱]`/`[依赖]` | v2.0 新增：包元数据与依赖管理 |
| （无） | 默认私有 + 可见性交集 | v2.0 变更：可见性默认值改变，跨文件/跨包可见性取最严格交集 |

### 迁移速查（标准库模块）

// v1.0：默认公开，无需标签
函数 平方根(浮64 x) -> 浮64 { ... }
