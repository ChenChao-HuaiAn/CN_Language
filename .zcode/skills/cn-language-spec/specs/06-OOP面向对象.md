## 一、类定义与继承

### EBNF

```
类定义 = "类", 标识符, [":", 父类列表], "{", 类体, "}"
父类列表 = 父类名 | 接口名
类体 = 访问标签段*
访问标签段 = ("公开:" | "保护:" | "私有:"), 成员声明*
成员声明 = 字段声明 | 方法声明 | 构造函数声明 | 析构函数声明
```

### 示例代码

```
类 动物 {
公开:
    字符串 名称
    虚拟 函数 叫声() -> 字符串 {
        返回 "..."
    }
保护:
    整32 年龄
私有:
    整32 内部ID
}

类 狗 : 动物 {        // 单继承：冒号后跟父类名
公开:
    重写 函数 叫声() -> 字符串 {
        返回 "汪汪"
    }
}
```

### 设计决策

- **完整OOP**（决策7）：类/接口/继承/保护/虚拟/重写/抽象/实现/自身/父类全部保留。
- 继承语法 `类 狗 : 动物` 与C++一致（冒号后父类）。
- 与旧版Rust风格的关键差异：旧版无类继承概念（使用结构+特征），新版为完整面向对象。

## 二、访问控制（标签式 + 默认私有）

### EBNF

```
访问控制 = "公开:" | "保护:" | "私有:"
```

### 访问控制表

| 标签 | 访问范围 | 对应C++ |
|------|---------|---------|
| `公开:` | 所有代码可访问 | public |
| `保护:` | 自身与子类可访问 | protected |
| `私有:` | 仅自身可访问 | private |
| （无标签） | **默认私有**（v2.0 变更，原默认公开） | 默认 private |

### 示例代码

```
类 账户 {
    字符串 用户名              // 无标签 → 默认私有（v2.0）
    函数 内部函数() { }        // 无标签 → 默认私有
公开:
    函数 存款(整32 金额) -> 空类型 {
        余额 += 金额
    }
保护:
    整32 余额
私有:
    整32 密码哈希
}
```

### 设计决策

- **标签式可见性**：`公开:`/`保护:`/`私有:` 为块级标签，标签后的所有成员继承该可见性，直到下一个标签出现。
- **默认私有**（v2.0 变更）：类体开头无任何标签时，成员默认私有。公共 API（字段/方法/构造/析构）须显式 `公开:` 标注。
- **可见性交集**（v2.0）：类内 `公开:` 仅赋予"成员在类层级可见的前提下的公开访问"——若类本身是模块私有（模块级 `私有:` 或无标签默认私有），则类内公开成员跨文件也不可见（取交集最严格），见[08-模块系统.md](08-模块系统.md) 第四节。
- 与旧版Rust风格的逐项修饰（`公开 函数`）不同：新版为C++风格的标签式，更简洁。

## 三、构造函数与析构函数

### EBNF

```
构造函数 = "函数", 类名, "(", 参数列表, ")", 函数体
析构函数 = "函数", "~", 类名, "(", ")", 函数体
```

### 示例代码

```
类 狗 : 动物 {
公开:
    // 构造函数（与类同名）
    函数 狗(字符串 名) {
        名称 = 名
    }
    
    // 析构函数（~类名）
    函数 ~狗() {
        // 清理资源
    }
}
```

### 设计决策

- 构造函数 `函数 类名(...)`，析构函数 `函数 ~类名()`，与C++同名构造/析构语义一致。
- 构造函数返回对象指针；析构函数内联清理资源后调用父类析构（见编译器架构-运行时布局）。

## 三A、构造器三语境判定规则

> 任务 1642 条文（第160审计①·与双侧实现对读一致；内置构造器 正常/错误/某些 的语境细则见 [07-错误处理.md](07-错误处理.md) 五A）

### 规则

**类构造调用 `类名(实参)` 的三个合法语境**（判定规则统一：被调名匹配已注册类名
——含泛型 `类名<实参>` 先实例化为 `类名$实参`——即按类构造调用检查；构造函数
匹配按重载决议「精确优先」）：

| 语境 | 形态 | 语义 |
|------|------|------|
| ①声明初始化位 | `类名 变量 = 类名(实参);` | 声明即构造：先按默认构造建立对象槽，显式构造实参覆盖初始化（含字段初始化器）；无匹配构造函数且无实参=隐式默认构造 |
| ②赋值位 | `变量 = 类名(实参);` | **覆盖前释放旧对象**（析构+释放·单发删除指令），再构造新对象并深拷/接管字段（类=堆句柄语义，禁止指针直接 Store 导致双变量共享同一堆地址） |
| ③表达式右值位 | `用形状(方(3));` / `返回 方(3);` / `表.追加(方(3));` | 临时对象：实参/返回/容器元素位按返回槽（sret/retbuf）语义物化，由消费点析构（语句边界统一结算） |

**判定细则**：

- 被调名命中已注册类名（含泛型实例化）→ 构造调用检查（实参个数/类型按构造函数
  重载集校验）；类构造调用与普通函数调用在名字解析上互斥（类名登记于类表、
  函数名登记于函数表，命中即定族）。
- **抽象类构造调用编译期拒绝**（含抽象类名直调与抽象类名作返回类型实例化）。
- 父类构造不经 `父类.构造名()` 限定调用（编译期拒·见第七节），须经初始化列表
  `: 父类(实参)`；未写列表=自动调用基类默认构造。

### 示例代码

```
类 方 : 形状 {
公开:
    整32 边;
    函数 方(整32 b) { 边 = b; }
    重写 函数 面积() -> 整32 { 返回 边 * 边; }
}

函数 主() -> 整32 {
    方 a = 方(3);            // 语境①：声明初始化位
    a = 方(4);               // 语境②：赋值位（旧对象先析构释放，再接管新对象）
    打印(a.面积());           // 16
    返回 0;
}

函数 造方() -> 方 {
    返回 方(5);              // 语境③：返回位临时对象（消费点接管）
}
```

### 设计决策

- 三语境共用同一构造调用检查入口（判定一次、语境分流），避免「声明位一套规则、
  赋值位一套规则」的实现分叉（v2 曾因赋值位缺语境设置点漏检查——#1591 根治，
  本条即其规范面）。
- 赋值位「先析构旧再接管新」是 RAII 语义的完整闭环（095 立法）；声明位
  「声明即默认构造」使对象槽恒有效（无未初始化对象面·994 隐式默认构造配套）。

## 四、虚函数与重写

### EBNF

```
虚函数 = "虚拟", "函数", 标识符, "(", 参数列表, ")", ["->", 返回类型], 函数体
重写函数 = "重写", "函数", 标识符, "(", 参数列表, ")", ["->", 返回类型], 函数体
```

### 示例代码

```
类 动物 {
公开:
    虚拟 函数 叫声() -> 字符串 {      // 虚函数声明
        返回 "..."
    }
}

类 狗 : 动物 {
公开:
    重写 函数 叫声() -> 字符串 {      // 重写父类虚函数
        返回 "汪汪"
    }
}

类 猫 : 动物 {
公开:
    重写 函数 叫声() -> 字符串 {
        返回 "喵喵"
    }
}
```

### 设计决策

- `虚拟` 声明多态函数（vtable分发），`重写` 显式标注子类覆盖（编译期校验签名匹配）。
- 调用虚函数经vtable间接跳转（`调用 虚调用` IR指令）。

## 五、虚表内存布局

### 内存布局

```
类实例内存布局（单继承）：
┌─────────────────────────────┐
│ vtable指针（8字节）            │ ← 实例首地址
├─────────────────────────────┤
│ 父类成员区                     │
├─────────────────────────────┤
│ 自身成员区                     │
└─────────────────────────────┘
```

### 虚函数表（vtable）

- vtable为函数指针数组，子类重写时覆盖对应槽位。
- 接口实现采用附加vtable（预留）。
- 虚调用指令经vtable间接跳转分发。

### 示例代码

```
类 形状 {
公开:
    虚拟 函数 面积() -> 浮64 {
        返回 0.0
    }
}

类 圆形 : 形状 {
公开:
    浮64 半径
    重写 函数 面积() -> 浮64 {
        返回 3.14159 * 半径 * 半径
    }
}
```

## 六、接口定义与实现

### EBNF

```
接口定义 = "接口", 标识符, "{", 虚拟函数签名列表, "}"
接口实现 = "类", 类名, ":", 接口名, "{", 类体, "}"
```

### 示例代码

```
// 接口定义：只含虚拟函数签名（无实现）
接口 可绘制 {
    虚拟 函数 绘制() -> 空类型
}

// 接口实现：类冒号后实现接口
类 圆形 : 可绘制 {
公开:
    浮64 半径
    重写 函数 绘制() -> 空类型 {
        // 实现绘制逻辑
    }
}

类 矩形 : 可绘制 {
公开:
    重写 函数 绘制() -> 空类型 {
        // 实现绘制逻辑
    }
}
```

### 设计决策

- 接口只包含虚函数签名（无实现体），由实现类通过 `重写` 提供实现。
- 接口实现采用附加vtable（B1 全局槽位：对象首 8 字节虚表指针后接接口分派区，槽=8+全局槽*8），支持多接口实现。
- **接口类型可作函数参数/返回（多态传参，C2）**：`函数 用形状(形状* 图形)` / `函数 用形状(形状 图形)` / `函数 造圆() -> 形状`；类→接口隐式转换（A1 同地址，值/指针）覆盖实参/返回位，任何实现类（含继承实现类）经接口传参多态分派。
- 接口变量/参数为**同地址语义**（A1）：经接口方法修改对象状态即写回原对象（非拷贝）。

## 六B、类→基类指针/引用隐式转换（234·2026-10-06 用户批准甲案）

### EBNF

```
基类转换 = 派生类表达式 -> 基类指针 | 派生类表达式 -> 基类引用
```

### 规则

- **指针/引用形态放行**（同地址语义·接口 A1 扩展）：`形状* p = 方(3);`、`形状& r = a;`、函数传参 `用形状(a)`（形参 `形状*`/`形状&`）——装/绑的是**原对象**，零拷贝零指针调整；经基类形态调用虚拟函数按**动态类型**虚表分派；成员可见性按**静态类型**（基类）视角。
- **基类值形态编译期拒绝（防切片）**：`形状 s = 方(3);` 报「禁止类切片」——值拷贝截掉派生类字段（C++ 经典事故源），提示改用基类指针/引用。

### 示例代码

```
类 形状 {
公开:
    虚拟 函数 面积() -> 整32 { 返回 0; }
}
类 方 : 形状 {
公开:
    整32 边;
    函数 方(整32 b) { 边 = b; }
    重写 函数 面积() -> 整32 { 返回 边 * 边; }
}
函数 印(形状& s) -> 整32 { 返回 s.面积(); }
函数 主() -> 整32 {
    方 a = 方(3);
    形状* p = a;       // 同地址上行转换
    打印(p.面积());     // 9（动态分派）
    打印(印(a));        // 9（引用多态）
}
```

### 设计决策

- **与接口 A1 对仗**：类继承与接口实现同一条多态路——语法一致（`基类* p = 派生对象`），语义一致（同地址·虚表分派）。
- **切片零容忍**：值形态拒绝（Rust 不提供该形态同款哲学；宁严勿松）。
- **安全接管**：悬垂/借用由既有编译期检查体系（§1.1a 分层安全）照常生效，零新增安全债。

## 六C、多接口同名方法归类与接口签名权威

> 任务 1642 条文（第171反思②④·与双侧实现对读一致）

### 规则

- **接口签名是引用位方法解析的唯一权威**：接口方法签名（返回类型+参数类型串）
  在**接口声明处**一次性登记（签名表）；接口变量/接口形参（引用位）上的方法调用
  一律按该签名表解析与分派（全局槽 `接口名::方法名` → 槽号），**不以实现类的
  方法签名表为准**。类实现接口时逐方法校验「类实现签名 == 接口声明签名」
  （返回类型与参数类型完全一致）+「实现须 `虚拟`/`重写` 修饰」，不一致=编译期拒绝。
- **多接口同名方法归类**：一个类实现多个含同名方法的接口时，类体只写**一份实现**
  （类方法表按名索引）；各接口的同名方法在编译期各占**独立全局槽**
  （`接口甲::叫` 与 `接口乙::叫` 槽号不同），实现时**两槽填入同一实现函数**
  ——「一份实现，多槽指入」。同名方法签名在两个接口间不一致时，该类无法同时
  满足两接口（签名校验逐接口独立报错），须拆分实现类或更名接口方法。
- 继承链并入：接口实现验证接受「本类或继承得到的」实现（父类已实现则子类免重写）；
  接口分派区按跨继承链收集的接口全集填充。

### 示例代码

```
接口 可叫 {
    虚拟 函数 叫() -> 字符串
}
接口 可描述 {
    虚拟 函数 叫() -> 字符串        // 与 可叫.叫 同名同签名
    虚拟 函数 描述() -> 字符串
}

类 狗 : 可叫, 可描述 {
公开:
    重写 函数 叫() -> 字符串 {       // 一份实现：可叫.叫 与 可描述.叫 共用
        返回 "汪汪"
    }
    重写 函数 描述() -> 字符串 {
        返回 "家犬"
    }
}

函数 声(可叫 c) -> 空类型 {
    打印行(c.叫());                  // 引用位解析：按 可叫.叫 的签名表分派
}

函数 主() -> 整32 {
    狗 d = 狗{};
    声(d);                            // 汪汪（可叫 槽 → 狗.叫）
    可描述 p = d;
    打印行(p.叫());                   // 汪汪（可描述 槽 → 同一 狗.叫·多槽指入）
    打印行(p.描述());                 // 家犬
    返回 0;
}
```

> 反例：`接口 甲 { 虚拟 函数 叫() -> 字符串 }` 与 `接口 乙 { 虚拟 函数 叫() -> 整32 }`
> 被 `类 猫 : 甲, 乙` 同时实现——同名方法签名不一致，逐接口签名校验编译期拒绝。

### 设计决策

- 「一份实现，多槽指入」：同型同名方法不强迫用户写两份委托代码（C# 显式接口实现
  的分身机制 CN 不采用）；签名不一致=真语义冲突，直接拒绝（宁严勿松）。
- 引用位权威归接口声明：接口分派槽的签名依据与实现校验依据同源（同一签名表），
  实现类签名漂移在实现点即被拦截，不会渗漏到调用点。

## 七、自身和父类访问

### EBNF

```
自身访问 = "自身", ".", 成员名
父类访问 = "父类", ".", 方法名, "(", 实参列表, ")"
```

### 示例代码

```
类 父类 {
公开:
    整32 字段 = 10
    函数 方法() -> 空类型 {
        打印行("父类方法")
    }
}

类 子类 : 父类 {
公开:
    重写 函数 方法() -> 空类型 {
        自身.字段 = 20       // 访问自身成员（this->字段）
        父类.方法()          // 调用父类方法（父类::方法()）
    }
}
```

### 设计决策

- `自身` 对应C++的 `this`，`父类` 对应C++的 `父类::` 限定调用。
- 2026-08-12变更：`基类` 更名为 `父类`，更符合中文面向对象表达习惯。
- `父类.`/`自身.` 限定仅用于**方法与字段**——构造函数不能经限定名调用（`父类.构造名()` 编译期拒绝·2026-10-01 用户裁决）：父类构造须经**初始化列表**（`: 父类(实参)`）显式调用，未写列表时编译器自动调用基类默认构造（与C++构造语义一致，见第三节）。

## 八、抽象类（抽象关键字）

### EBNF

```
抽象成员 = "抽象", 函数签名      // 纯虚函数，子类必须实现
```

## 九、运算符重载（成员）

### 示例代码

```
类 复数 {
公开:
    浮64 实部
    浮64 虚部

    函数 运算符+(复数 右) -> 复数 {
        返回 复数{实部 + 右.实部, 虚部 + 右.虚部}
    }

    函数 运算符==(复数 右) -> 布尔 {
        返回 实部 == 右.实部 且 虚部 == 右.虚部
    }
}

复数 a = 复数{1.0, 2.0}
复数 b = 复数{3.0, 4.0}
复数 c = a + b        // 调用 复数.运算符+
布尔 相同 = a == b    // 调用 复数.运算符==
```

### 设计决策

- 重载运算符仅限成员函数，左操作数必须是本类实例；单目运算符（`-`/`!`/`~`）无参数，双目运算符单参数（右操作数）。
- `运算符` 为**上下文关键字**（非保留字）：仅当后随运算符符号且处于类/结构体函数定义上下文时识别。
- 字符串 `+` 拼接由编译器隐式转换，不与用户重载冲突。

## 十、静态成员

### 示例代码

```
类 计数器 {
公开:
    静态 整32 总数 = 0        // 类静态字段（全类共享）

    函数 计数器() {
        总数++               // 类内直接访问
    }

    静态 函数 获取总数() -> 整32 {
        返回 总数
    }
}

计数器.总数 = 10              // 类外通过 类名.静态成员 访问
整32 当前 = 计数器.获取总数()
```

### 设计决策

- 静态成员全类共享（`.data` 段分配）；静态方法无 this，不可访问非静态成员。
- 类外访问用 `类名.静态成员`。

## 十一、常量成员函数

### 示例代码

```
类 只读包装 {
私有:
    整32 值
公开:
    函数 只读包装(整32 v) { 值 = v }

    常量 函数 获取() -> 整32 {   // 常量成员：不修改任何成员
        返回 值
    }
}
```

### 设计决策

- `常量` 修饰的成员函数承诺不修改成员；常量对象仅能调用常量成员函数；违反时编译器报错。

## 十二、友元

### 示例代码

```
类 账户 {
私有:
    整64 余额
公开:
    友元 函数 审计(账户& 账)   // 声明友元函数，可访问私有成员
}

函数 审计(账户& 账) -> 整64 {
    返回 账.余额                // 友元可访问私有
}
```

### 设计决策

- `友元` 授予外部函数或类访问本类私有/保护成员的权限（最小授权原则，谨慎使用）。

## 十三、泛型 / 模板

### 示例代码

```
泛型 <类型 T>
类 向量 {
私有:
    T* 数据
    整64 长度
公开:
    函数 向量(整64 容量) { 数据 = 分配(T 大小 * 容量); 长度 = 0 }
    函数 推入(T 值) { 数据[长度] = 值; 长度++ }
    函数 获取(整64 索引) -> T { 返回 数据[索引] }
}

向量<整32> 整数列表 = 向量<整32>(10)
整数列表.推入(42)

泛型 <类型 T>
函数 交换(T& a, T& b) -> 空类型 {
    T 临时 = a
    a = b
    b = 临时
}
```

### 设计决策

- 泛型采用**编译期单态化**（每实例化生成一份具体类型代码）。
- `泛型 <类型 T>` 声明类型参数，`类型名<实参>` 实例化；支持泛型类与泛型函数；类型参数可约束为接口（`泛型 <类型 T : 接口>`）。

## 十三A、泛型静态局部（克隆体独立性）

> 任务 1642 条文（与双侧实现对读一致·E2E 1539 锁面）

### 规则

- 泛型函数/泛型类方法内的**静态局部变量**，按**单态化实例**各自独立一份：
  `造<整32>` 与 `造<字符串>` 各有独立静态槽，互不共享状态（每实例计数从 1 起）。
- 实现形态（实现者参考）：静态局部符号在克隆体上按
  `名$静态$实例$函数名`（v2）/同语义合成键（宿主）重写，保证每实例唯一
  `.data` 符号；克隆区间内的静态声明须补登静态表（声明/读写/取地址三通道同规）。
- 静态局部初值仍走守卫快照初始化（[03-语句与控制流.md](03-语句与控制流.md) 1.1b），
  每实例各一套守卫槽。

### 示例代码

```
泛型 <类型 T>
函数 造(T 样) -> T {
    静态 整32 计数 = 0;
    计数++;
    打印行(计数);
    返回 样;
}

函数 主() -> 整32 {
    造<整32>(1);       // 1
    造<整32>(2);       // 2   ← 同实例：状态延续
    造<字符串>("甲");  // 1   ← 新实例：独立状态（不接续 2）
    造<整32>(3);       // 3
    返回 0;
}
```

> 反例（已根治的缺陷形态·任务 1176）：所有实例共享同一 `名$静态$函数名` 符号
> ——`造<整32>` 与 `造<字符串>` 交替调用输出 1 2 3 1 2 3（状态串扰）。

### 设计决策

- 「每实例独立」与 C++ 模板语义对齐（每实例化一份静态变量）；这是单态化语义的
  自然延伸，不是额外特性。

---

## 十三B、单态化不改借用深度

> 任务 1642 条文（第170审计①·与双侧实现对读一致）

### 规则

- 单态化=**纯类型参数替换**：类型参数 T 被替换为实参类型文本，替换机制本身
  **不增删任何 `&`/`*` 修饰层**——
  - `T&` 实例化=`实参&`（模板位写一层引用，实例化后恰一层引用）；
  - `T*` 实例化=`实参*`（指针同理）；
  - `结果<T,E>`/`可选<T>`/容器模板位内部递归替换，外层修饰符不动。
- 实参类型**自带**的修饰符深度**原样并入**：`T=整32*` 时 `T&` 实例化为 `整32*&`
  （指针的引用·两层）——并入是实参文本的忠实携带，不是替换机制加了层。
- 「借用深度」(`&` 深度) 由此在单态化前后恒可静态计数：模板位显式写出的层数 +
  实参自带层数，无隐藏增减点。借用纪律（[plans/019] 借用登记面）按替换后的
  最终文本计层，无需对单态化做特判。

### 示例代码

```
泛型 <类型 T>
函数 首个(T& 引用) -> T& {
    返回 引用;              // 返回类型=T&：对 整32 实例化为 整32&；
}                            //   对 整32* 实例化为 整32*&（自带深度并入）

函数 主() -> 整32 {
    整32 a = 5;
    整32& r = 首个<整32>(a);     // T& → 整32&：一层引用
    r = 7;
    打印行(a);                    // 7
    返回 0;
}
```

### 设计决策

- 「单态化不改借用深度」在实现中是替换算法的直接性质（尾字符 `&`/`*` 剥一层、
  替换、原样接回），本条把它从「推导隐含」升格为**条文**：任何后续实现（含
  自举版）不得引入「实例化时智能增删引用」的行为——那会改变借用纪律的计层基础。
