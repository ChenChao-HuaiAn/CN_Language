# v2 自举推进计划：ARM64 GAS 后端（阶段A）→ ②b 结构体元素容器全量（阶段B）

## 背景与裁决

- 现状：P7b 容器全链路完成（E2E 126 用例基线、单测 1196/1196），HANDOFF 下一步为 ②b 结构体元素容器（③ v2 自举对拍前最大缺口）。
- 本机 Linux ARM64，无 MSVC/ml64/wine：v2 现只产 win-x64 MASM，本机无法运行时验证 v2 产物。
- **用户裁决①**：先做 v2 的 Linux ARM64 GAS 后端（兼合项目双后端终极目标），使 v2 闭环本机全程可运行时验证，②b 随后。
- **用户裁决②**：②b 一步到位，含资源字段结构体（追加深拷贝、删除(i) 字段析构注入、整体 RAII），不止 POD。
- 诚实门禁纪律（lessons「E2E 119 门禁基线造假」）：本机验证不到的绝不写成结论；win-x64 运行时门禁明确标注「待 Windows 会话」。

## 阶段0：本机基线摸底（先摸清再动手）

1. GCC 构建宿主编译器：`cmake -S . -B target/build && cmake --build target/build -j`（`-Wall -Wextra -Werror` 零警告）。
2. 单测全量跑通（基线 1196）。
3. `python3 tests/e2e/run_e2e.py --target linux-arm64 --cn <宿主>` 全量：预期 62/65/69/79 平台跳过，**119/120/123 当前按代码逻辑会「失败」而非跳过**（win-x64 only）——如实记录，作为阶段A的验收对照（阶段A后这三例应在 linux-arm64 真实通过）。

## 阶段A：v2 Linux ARM64 GAS 后端 + E2E 闭环双平台化

**目标**：v2 可选目标平台产出 AArch64 GAS 汇编，本机 as+g++ 汇编链接运行，E2E 119/120/123 在 linux-arm64 真实跑通。

### A1. 新组件 `CN语言编译器v2/代码生成ARM64.cn`（新文件，理由：单一职责 ≤1000 行 + 后端组件化惯例，对齐宿主 x64/arm64 分离结构）
- IR→AArch64 GAS 全量操作码发射，**逐项对齐宿主 `src/cn_compiler/codegen/arm64/` 实现**（ABI/指令选择不自创）：
  - 函数骨架 `.text/.globl/标签`、prologue/epilogue（stp x29,x30、sub sp，帧大小 16 字节对齐）、虚拟寄存器→栈槽（对齐 v2 现有 [rbp-8r-8] 栈槽模型的 ARM64 等价）；
  - 参数 x0-x7、>8 参走栈参数区（复用 v2 已有的 64+63 双向参数 IR 位号标注）；结构体按值 ABI 按**宿主 arm64 实现为准**；
  - 算术/比较/跳转（mov/add/sub/mul/sdiv/cmp/b.cond/cbz）、返回 ret；
  - 字符串常量 `.section .rodata`/`.ascii`、静态数据 `.data`；
  - 符号修饰复用 nameMangle 规则（中文 `?XX@@Y`+类型编码，与宿主 stdlib 符号一致才能链接）；
  - 空安全删除 cbz（宿主已有先例）；窄加载符号扩展坑（lessons 16.8：ldrsb xN 等）。
- 结构体拷贝：ARM64 无 rep movsb，对齐宿主做法（ldp/stp 序列或 memcpy 调用）。

### A2. `主.cn` 目标平台参数
- 现仅有 1 个参数（入口文件，默认 target/v2src.cn）；增加可选第 2 参数：目标平台，默认 `win-x64`（既有 run_e2e.py win-x64 路径行为完全不变），`linux-arm64` 时分派到新后端，输出 `target/v2asm.s`（GAS 惯例后缀；MASM 路径维持 target/v2asm.asm）。

### A3. E2E 运行器 v2 闭环双平台化（`tests/e2e/run_e2e.py`）
- `执行v2闭环` 从 win-x64-only 扩展：linux-arm64 分支用 `as` 汇编 v2asm.s → `g++` 链接（对齐宿主 `cn_main.cpp:502-515` 工具链探测与链接编排：v2p(arm64) 对象提供 stdlib 符号实现 + 宿主运行时），运行断言退出码；
- 编排细节按现有 win-x64 六步闭环等价移植（构建 v2p → v2p 编译测试源 → 汇编 → 链接 → 运行）。

### A4. 阶段A验收（本机真实运行）
- E2E 119/120/123 在 linux-arm64 全绿（退出码 14/62/21333）；
- 全量 E2E linux-arm64：除平台跳过清单（62/65/69/78/79）外全绿；
- win-x64 路径行为不回退（本机只能 asm 文本级核对 119 入口产物与改动前基线 diff——**改动前先存基线 asm** 到 target/dbg/，不入库）。

## 阶段B：②b 结构体元素容器（全量，双后端）

**目标**：v2 支持 `向量<结构体>` 全链路——布局/视图/传参/深拷贝/析构注入，验收载体 E2E 125（新用例），linux-arm64 本机真实运行 + win-x64 asm 级核对（运行时待 Windows 门禁）。

### B1. 结构体布局对齐宿主 typeSizeOf（`语法分析.cn`、新组件 `IR结构体.cn`）
- 现状缺陷：字段偏移按 8 字节平铺、语义层成员类型一律按整64（语义分析.cn:129,201）；
- 改为按声明类型真实大小+自然对齐（整32=4/整64=8/指针=8），结构体表记录 sizeof/对齐/逐字段类型与偏移（参照 E2E 124 节点：4+4+8+4+4=24，偏移 0/4/8/16/20，对齐 8）——供容器元素步长、拷贝大小、传参 ABI 使用；
- IR生成.cn 已 977 行，超出部分拆入新文件 `IR结构体.cn`（结构体布局表/元素视图/深拷贝/析构注入，与 IR容器.cn/IR签名.cn 同惯例）。

### B2. 元素(i) 视图语义（`语义分析.cn`、`IR生成.cn`）
- 对齐宿主 `ir_expr.cpp:1707,1762`：结构体元素返回**地址**（供 `.字段` 读写、按值传参、整体拷贝）；标量/字符串元素维持值装载；
- 链式 `池.元素(19).类型` 读、算术参与、`设置(i,v)` 后读回（E2E 124 全形状）。

### B3. 结构体按值传参 ABI（双后端 `代码生成.cn` + `代码生成ARM64.cn`）
- 追加(n)/设置(i,v) 实参按值：MASM 路径对齐宿主 Win x64 约定（>8 字节传引用+调用方拷贝、rep movsb sizeof）、ARM64 路径对齐宿主 arm64 实现；
- 与宿主编译的 stdlib 符号/ABI 必须毫厘一致（链接同一实现）；MASM 247 符号限制纪律：v2 组件函数参数 ≤8、类型信息走语法层预标注。

### B4. 深拷贝与析构注入（`IR生成.cn` RAII 扩展、`IR容器.cn`）
- **POD 结构体**：删除(i)/收缩 memmove 语义、无析构直通；
- **资源字段结构体**（用户裁决②，一步到位）：追加 深拷贝（字符串字段所有权对齐宿主方案A/113/115/116/117 语义）、删除(i)/清空/整体 RAII 时元素字段析构注入。

### B5. E2E 125_v2_结构体元素容器（新用例，先写用例再实现到绿）
- 覆盖：POD 结构体（E2E 124 形状：追加20+链式读首/中/末字段+算术+设置+读回+大小）+ 资源字段结构体（字符串字段：追加/读/删除/作用域退出 RAII）+ 删除(i) 中间位置；
- run_e2e.py 注册（V2闭环用例 dict：["主.cn"], 期望退出码, 链接 v2 对象），win-x64 与 linux-arm64 双平台编排；
- 本机：linux-arm64 真实运行验证；win-x64 产物 asm 文本级核对（偏移/拷贝大小/ABI 寄存器/mangled 符号逐项清单）。

## 风险与对策

- **宿主 ARM64 ABI/链接细节不一致**（v2 产物链接即崩）：逐项对齐宿主 arm64 后端实现，闭环 E2E 实测收敛；无法收敛即视为发现缺陷，按「缺陷零容忍」暂停汇报三方案；
- **MASM 路径改动回退**：改动前存 119/120/123 三入口基线 asm（target/dbg/），改动后 diff；
- **文件超 1000 行**：IR生成.cn 拆出 IR结构体.cn、新后端独立 代码生成ARM64.cn（计划内新文件仅此两个，理由如上）；
- **发现宿主编译器新缺陷**：立即暂停当前任务，汇报现象/根因/影响面+≥3 方案，经用户选择后继续。

## 纪律合规
