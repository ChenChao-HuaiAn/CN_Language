> **📌 文档状态（2026-09-28 第 866 轮更新·活文档）**：本指南与当前 runner 对齐——编号约定（2~3 位）、
> 参数表（`--target`/`--jobs`/`--max-mem-mb`）、内存与互斥防线、超时与退出码口径、用例级控制文件
> （`编译选项.txt`/`期望编译失败.txt`/`双编译对照.txt`）；当轮口径=**全量 544 用例：542 过 / 0 败 / 2 跳过**
> （linux 平台限制跳，见 §四）。**历史**：291-a（09-17）对齐 423 用例口径；其 --jobs/--max-mem-mb 默认值
> 与 v1 用例描述已由 604-a/746-a/797-a/e387f316/601-a 演进，本轮追平。

E2E（端到端）测试用于验证CN语言编译器的完整链路：**编译源文件 → 链接生成可执行文件 → 运行 → 比对输出**。

遵循"E2E先行"原则：每个功能必须先写E2E测试，测试通过后才算完成。

---

## 一、目录结构

```
tests/e2e/
├── run_e2e.py                  # E2E测试运行器（Python 3）
├── README.md                   # 本文档
├── 01_hello/                   # 第一个用例：Hello World
│   ├── hello.cn                # CN语言源文件
│   └── hello.expected          # 预期输出（逐行比对）
├── 02_xxx/                     # 后续用例（阶段一之后逐步添加）
│   ├── xxx.cn
│   └── xxx.expected
└── ...
```

### 用例目录命名约定

- 目录名：`<编号>_<名称>`（如 `01_hello`、`423_名称`）——编号 2~3 位数字，**全局唯一递增**
- 运行器识别**目录名前两位为数字**的目录作为用例（`d.name[:2].isdigit()`）
- 源文件名：`<用例>.cn`（目录内第一个 `.cn` 文件即源码）
- 期望文件名：与源文件**同名**的 `.expected` 文件（`hello.cn` ↔ `hello.expected`）
- 可选控制文件（用例级）：
  - `编译选项.txt`：每行一个编译旗标（如 `-O3`、`--验证-ir`），
  - `期望编译失败.txt`：**负测**——断言编译失败；文件内容可写期望诊断子串（逐条断言出现在 stderr/stdout），
  - `双编译对照.txt`：双编译对照上架标记（宿主 + v2 双侧均须通过，C20 口径），
  - `v2锚定链.txt`：v2 自举锚定链配置（键：`阶段=链构建|闭环`），
  - `.input` / `.args`：标准输入与命令行参数（每行一个）。

## 二、如何添加新测试

1. 在 `tests/e2e/` 下创建目录 `NN_名称`（NN为下一个可用编号）
2. 编写CN语言源文件 `tests/e2e/NN_名称/名称.cn`：

   ```cn
   // 示例：两数相加
   函数 主() -> 整32 {
       整32 a = 1
       整32 b = 2
       打印行(a + b)
       返回 0
   }
   ```

3. 创建同名期望输出文件 `名称.expected`，内容为程序运行后的预期输出（UTF-8编码）：

   ```
   3
   ```

4. 运行验证（见下节）。

> 注意：`hello.expected` 最后一行应有换行；比对时逐行比较并忽略行尾空白差异。

## 三、如何运行测试

### 运行子集（日常开发·354 护栏推荐路径）

```bash
python3 tests/e2e/run_e2e.py --filter <用例编号|名称>   # 定向族（秒~分钟级）
python scripts/gate_quick.py --l2                       # 按写集自动推导影响面子集
```

### 全量（本地须给理由·CI 脚本自动带）

```bash
python3 tests/e2e/run_e2e.py --full-reason "<任务号+理由>"
```

编译器路径自动按序探测：`target/Debug/cn.exe` → `target/Release/cn.exe` → `target/cn.exe`
（或显式 `--cn <路径>` 指定）。

裸全量（约 600 例·本机 30~90 分钟）无理由会被护栏拒绝（exit 2）——全量默认交云端
（`python scripts/integrate.py` 预验·池并行 8~16 分钟·AGENTS §4 三档阶梯）。

### 常用参数

| 参数 | 说明 |
|------|------|
| `--cn <路径>` | 指定编译器可执行文件路径（默认自动探测 `target/Debug` 等） |
| `--target <平台>` | 目标平台：`win-x64` / `linux-x86_64` / `linux-arm64`（缺省按本机） |
| `--verbose` / `-v` | 详细输出（显示编译/运行命令） |
| `--filter <模式>` | 仅运行目录名包含指定模式的用例（如 `--filter 01_hello`） |
| `--target-dir <目录>` | 可执行文件输出目录（默认 `target/`） |
| `--jobs <N>` / `-j <N>` | **并行度（默认=本机 CPU 核数·604-a 落地，串行路径已删，`-j 1`=单 worker 等效；进程池隔离=每用例独立 worker 进程）** |
| `--max-mem-mb <N>` | 单用例重负载内存上限（MB，**默认 4096**·917 由 32768 收紧——v2p 全树编译峰值已被内存治理压至 227.8MB；746-a 由 4096 演进沿革见源码注释；v2 锚定链等重负载用例启用轮询，超限=该用例判红） |
| `--stall-timeout <秒>` | **整池看门狗（917）**：全池连续 N 秒无任何用例完成=停摆判定→终止池+未完成用例诚实红+诊断（默认 1800s·0=禁用；arm64 79_v2 尾部合法静默 ~20 分钟，勿调低） |

#### 内存与互斥防线（797-a / e387f316·linux 生效；917 更新）

- **地址空间硬顶**：非 win 平台 runner 对**全部子进程**注入 `RLIMIT_AS=8GB`（`--max-as-mb` 可调）——失控
  进程在顶处 malloc 失败，该用例诚实判红，不再连坐整机（926 三连 OOM 实证后立）。
- **v2 全树编译 flock 互斥（917 已退役摘除）**：其前提「双 14GB 全树编译并行＝28GB OOM」已被内存治理
  消灭（v2p 全树编译峰值 RSS 20.75GB→**227.8MB**·885 轮实测）——78/79 三跳串行长尾（arm64 单跳
  ~8 分钟）并入并行；win 侧本就未启用（跑 jobs 8 数百轮零事故=现成实证）。回取=git 历史。
- **全树编译内存上限自适应**：全树编译用例上限=**物理内存 × 0.55**（下限 4096MB；e387f316·824 轮），
  非「无上限豁免」——深度机 32GB → 约 17.5GB。
- **超时进程树终止（917 根治孤儿管道·021 任务 108）**：普通路径超时由「subprocess.run 只杀直接子进程」
  改为显式 Popen+`终止进程树`（win `taskkill /T /F`·POSIX `killpg`）——孙进程持 stdout 管道写端
  致 worker 永挂的形态根除。
- **整池看门狗（917）**：`--stall-timeout`（默认 1800s·0=禁用）——治「按序 get 卡死全员白等 N×30 分钟」
  的停摆形态；触发=未完成用例诚实红+停摆诊断（判真挂死=子进程 CPU 时间零增长〔教训 0930 判据〕）。

#### 超时与退出码口径（651 轮扩面 / 609-a）

- 默认超时：编译 600 秒 / 构建（锚定链全树）900 秒 / 运行 180 秒 / 检查 60 秒——超时进程被终止、该用例判失败
  （挂死用例不再拖死门禁；31 个调用点全覆盖）。
- **退出码比对平台分派（609-a）**：POSIX 退出码 8 位截断——linux 侧比对 `预期退出码 % 256`；
  win-x64 侧为 32 位全值精确比对（退出码 >255 的负测两平台 PASS/FAIL 判定可不同，属平台事实非缺陷）。
| `--strict` | 严格模式：将"未实现"用例视为失败 |

## 四、输出与状态说明

每个用例输出三种状态之一（彩色文本：PASS绿 / FAIL红 / SKIP黄）：

| 状态 | 含义 | 退出码影响 |
|------|------|-----------|
| `PASS` | 编译→运行→输出比对全部通过 | 无 |
| `FAIL` | 编译失败 / 运行失败 / 输出不一致 / 用例结构错误 | 最终返回1 |
| `SKIP` | 平台限制跳过（如 `62_ffi`〔Windows API〕/`69_memory_management` 在 linux 两平台各 2 跳，win-x64 无跳）或编译器返回"尚未实现" | 默认不计数，`--strict` 时返回1 |

退出码约定：

- `0`：全部通过（或仅存在"未实现"用例且未启用 `--strict`）
- `1`：存在失败用例（或 `--strict` 下有未实现用例）
- `2`：参数错误（如指定的编译器不存在）

> **当前口径（2026-09-17，第 291-a 轮实测·linux-x86_64）**：全量 **423 用例：421 过 / 0 败 / 2 跳过**
> （跳过为平台限制，见上表）；运行器已支持并行池（`--jobs`）、负测诊断断言、用例级编译旗标通道、
> 双编译对照与 v2 自举锚定链（见 §六）。历史「阶段零 SKIP 未实现」说明已作废。

## 五、测试原则

- **E2E先行**：每个功能必须先写E2E测试，测试通过后才算完成
- **禁止跳过**：所有测试必须真正运行，不使用Mock
- **真实配置**：测试使用真实编译器与真实可执行文件
- **编译产物**：可执行文件统一输出到 `target/` 目录，不污染源码目录
