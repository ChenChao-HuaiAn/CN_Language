E2E（端到端）测试用于验证CN语言编译器的完整链路：**编译源文件 → 链接生成可执行文件 → 运行 → 比对输出**。

遵循"E2E先行"原则：每个功能必须先写E2E测试，测试通过后才算完成。

## 一、目录结构

```
tests/e2e/
├── run_e2e.py                  # E2E测试运行器（Python 3）
├── README.md                   # 本文档
├── 01_hello/                   # 第一个用例：Hello World
│   ├── hello.cn                # CN语言源文件
│   └── hello.expected          # 预期输出（逐行比对）
├── 02_xxx/                     # 后续用例（阶段一之后逐步添加）
│   ├── xxx.cn
│   └── xxx.expected
└── ...
```

### 用例目录命名约定

- 目录名：`<编号>_<名称>`（如 `01_hello`、`423_名称`）——编号 2~3 位数字，**全局唯一递增**
- 运行器识别**目录名前两位为数字**的目录作为用例（`d.name[:2].isdigit()`）
- 源文件名：`<用例>.cn`（目录内第一个 `.cn` 文件即源码）
- 期望文件名：与源文件**同名**的 `.expected` 文件（`hello.cn` ↔ `hello.expected`）
- 可选控制文件（用例级）：
  - `编译选项.txt`：每行一个编译旗标（如 `-O3`、`--验证-ir`），
  - `期望编译失败.txt`：**负测**——断言编译失败；文件内容可写期望诊断子串（逐条断言出现在 stderr/stdout），
  - `双编译对照.txt`：双编译对照上架标记（宿主 + v2 双侧均须通过，C20 口径），
  - `v2锚定链.txt`：v2 自举锚定链配置（键：`阶段=链构建|闭环`），
  - `.input` / `.args`：标准输入与命令行参数（每行一个）。

## 二、如何添加新测试

1. 在 `tests/e2e/` 下创建目录 `NN_名称`（NN为下一个可用编号）
2. 编写CN语言源文件 `tests/e2e/NN_名称/名称.cn`：

   ```cn
   // 示例：两数相加
   函数 主() -> 整32 {
       整32 a = 1
       整32 b = 2
       打印行(a + b)
       返回 0
   }
   ```

3. 创建同名期望输出文件 `名称.expected`，内容为程序运行后的预期输出（UTF-8编码）：

   ```
   3
   ```

4. 运行验证（见下节）。

> 注意：`hello.expected` 最后一行应有换行；比对时逐行比较并忽略行尾空白差异。

## 三、如何运行测试

### 直接运行（自动探测编译器）

```bash
python3 tests/e2e/run_e2e.py
```

自动按顺序探测：`target/Debug/cn.exe` → `target/Release/cn.exe` → `target/cn.exe`

### 指定编译器路径

```bash
python3 tests/e2e/run_e2e.py --cn target/Debug/cn.exe
```

### 常用参数

| 参数 | 说明 |
|------|------|
| `--cn <路径>` | 指定编译器可执行文件路径（默认自动探测 `target/Debug` 等） |
| `--target <平台>` | 目标平台：`win-x64` / `linux-x86_64` / `linux-arm64`（缺省按本机） |
| `--verbose` / `-v` | 详细输出（显示编译/运行命令） |
| `--filter <模式>` | 仅运行目录名包含指定模式的用例（如 `--filter 01_hello`） |
| `--target-dir <目录>` | 可执行文件输出目录（默认 `target/`） |
| `--jobs <N>` / `-j <N>` | **并行度（默认 1；全量建议显式 `--jobs 8`）** |
| `--max-mem-mb <N>` | 单用例内存上限（MB，默认 4096；锚定链等大内存用例自动豁免） |
| `--strict` | 严格模式：将"未实现"用例视为失败 |

### 通过CMake运行

```bash
cmake --build target/build --target e2e     # 自定义目标（自动携带编译器路径）
ctest --test-dir target/build -R e2e        # CTest集成
```

## 四、输出与状态说明

每个用例输出三种状态之一（彩色文本：PASS绿 / FAIL红 / SKIP黄）：

| 状态 | 含义 | 退出码影响 |
|------|------|-----------|
| `PASS` | 编译→运行→输出比对全部通过 | 无 |
| `FAIL` | 编译失败 / 运行失败 / 输出不一致 / 用例结构错误 | 最终返回1 |
| `SKIP` | 平台限制跳过（如 `62_ffi`〔Windows API〕/`69_memory_management` 在 linux 两平台各 2 跳，win-x64 无跳）或编译器返回"尚未实现" | 默认不计数，`--strict` 时返回1 |

退出码约定：

- `0`：全部通过（或仅存在"未实现"用例且未启用 `--strict`）
- `1`：存在失败用例（或 `--strict` 下有未实现用例）
- `2`：参数错误（如指定的编译器不存在）

> **当前口径（2026-09-17，第 291-a 轮实测·linux-x86_64）**：全量 **423 用例：421 过 / 0 败 / 2 跳过**
> （跳过为平台限制，见上表）；运行器已支持并行池（`--jobs`）、负测诊断断言、用例级编译旗标通道、
> 双编译对照与 v2 自举锚定链（见 §六）。历史「阶段零 SKIP 未实现」说明已作废。

## 五、测试原则

- **E2E先行**：每个功能必须先写E2E测试，测试通过后才算完成
- **禁止跳过**：所有测试必须真正运行，不使用Mock
- **真实配置**：测试使用真实编译器与真实可执行文件
- **编译产物**：可执行文件统一输出到 `target/` 目录，不污染源码目录
