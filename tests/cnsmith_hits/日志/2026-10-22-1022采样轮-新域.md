### D1〔#1393·P0·v2〕类型名宽度缺枚举分支 → 枚举宽度 0 全链静默错值/中止

**现象矩阵（全部实测）**：

| 探针 | 形态 | 宿主 | v2 |
|---|---|---|---|
| m09 | `色[3] 表 = {色.红, 色.绿, 色.蓝}` 循环读 | 0 1 2 | **0 0 0** |
| m08 | 逐个赋值 `表[0]=上;表[1]=中;表[2]=下` | -1 0 1 | **1 1 1** |
| m10 | `{-2, 5, -1}` 初始化列表 | -2 5 -1 | **-2 -2 -2** |
| b01 | 负数枚举数组 | -1 0 1 | **-1 -1 -1** |
| m16 | `类型大小(色)` | 4 | IR 中止「类型大小: 未知类型 色」 |
| m12/m21/g01 | 类方法返回枚举（字段/字面量） | 正常 | IR 中止「表达式净栈契约违反(吞外层): 增量=-1」 |
| m23 | 枚举数组形参 `色[3] a` | 3 | **503313744（垃圾值）** |

**根因（asm 铁证）**：m09 汇编数组下标寻址：
```
; op=1  mov rax, 0        ← 元素步进=0
; op=12 mov rax, [rbp-128] ; i
        imul rax, [rbp-160] ; ×0
```
`IR/IR布局尾.cn:295 类型名宽度` 全函数**无枚举分支**，末尾 `返回 查结构体大小(类型名ID)` →
枚举不是结构体 → **0**。而同文件 `类型大小与对齐` 有枚举 4/4 分支（279 行，注释明言
C 枚举布局）——两表分叉（1033 注称两表口径已归一，枚举遗漏）。
`类型名宽度` 的 0 被三类消费点静默使用：数组元素步进（`数组元素布局宽` 尾部）、
`类型大小` 折叠（宽度 0 → IR 诊断中止）、类方法返回槽（宽度 0 → 净栈契约 -1）。
**同族**：#1327（泛型实例方法体内 类型大小(枚举) 报未知）、#1129（布局全类型矩阵）、
#1203/#961（类数组步进族，不同根因）。**联想**：`向量<枚举>` 元素注入、枚举数组返回、
联合体含枚举、`类型大小` 的数组/嵌套形态均走同一宽度表——修复须补锁用例矩阵。

### D2〔#1394·P1·v2〕查枚举成员值 -1 哨兵与合法负枚举值重叠

- b04：`枚举 方向 { 上=-1, 中=0 }` + `选择(d){情况 上:…}` → v2 **编译中止**
  「[sem5] 枚举 '方向' 无成员 '上'」；宿主输出「上」。
- 根因：`IR/IR布局尾.cn:660 查枚举成员值` 未命中 `返回 0-1`；`语义/语义检查选择.cn:238/262`
  以 `!= -1` 判命中、`== -1` 判 miss → 合法成员值 -1 被判「无成员」。
- 附带：`IR/生成表达式尾.cn:684`（生成枚举成员常量）**无 miss 判定**，查不到成员时静默发 -1。
- **同族**：#1239 哨兵禁令、#1360 结果化、#1147（v2 哨兵消费点批量核验）、#1374 批5 清单
  （须核对 查枚举成员值 是否在结果化清单内，防双改）。
- **联想**：同文件 `查函数签名个数` 等 41 处返回 0 哨兵、33 处返回 -1 哨兵的消费点
  （#1147 在案）——本件是「-1 落进合法值域」的最强活案例（枚举定义本身允许 -1）。

### D3〔#1395·P1·双侧〕默认参数非常量/常量表达式：宿主静默 0，v2 常量算式发射中止

| 探针 | 默认值形态 | 宿主 | v2 |
|---|---|---|---|
| a03 | 字面量链 `10`/`"尾"` | 正确 | 正确 |
| a08 | 常量算式 `1 + 2` | **0（应 3）** | 「[992守卫] 非法寄存器槽号: 0」中止 |
| a09 | 全局常量 `基`（=5） | **0（应 5）** | **5（正确）** |
| a11 | 类构造 `2 + 3` | **0（应 5）** | 非法寄存器槽号中止 |
| a04 | 引用前参 `a + 1`（非法） | 0（应拒） | 非法寄存器槽号中止 |
| a13 | `真` / `'甲'` | 30002 | 30002 |

- 宿主根因：`semantic_builtins.cpp checkDefaultParams` 只查「从右向左连续」与「引用参数无默认」，
  **无常量性校验**；`ir_call_direct.cpp evalDefaultExpr` 的 `default:` 分支注释假设
  「语义层已报错，此处补 0」→ 直接补 0（#648 同族静默）。parser 注释与 `ast_decl.hpp:29`
  均明文「默认值须编译期常量」。
- v2 根因：`IR/生成函数.cn 补默认参数实参` 查默认根节点后直接 `生成表达式`（调用点上下文），
  常量算式/标识符进入运行期生成路径 → 寄存器槽契约崩。
- **同族**：#1196（默认参数值域未校验）、#1197（正128 默认值域）、#233/#314（补缺机制，已修）。
- **联想**：`1+2` 是规范承诺的合法常量表达式（应折叠 3）；全局常量同理；类构造/父构造初始化列表
  共用 `evalDefaultExpr`（ir_oop.cpp:75/280/437）——修复须四消费位同源。

### D4〔#1396·P1·v2〕重载决议实参类型推导忽略字面量后缀

- a01 `取(1L)`：宿主选整64 重载（4），v2 **选整32 重载**（3）。
- a02/m05 `述(1.5f)` / `取(1.5f)`：v2 推导为浮64 → 选浮64 重载，且浮32 实参按浮64 ABI
  读出 **0**（2.0 vs 3.5）；`取(1.5)`/浮32 变量实参均正确。
- 根因：`IR/IR生成类型辅助.cn:565 推导实参类型文本`——整数字面量只判「无后缀十进制超 i32 域」
  → 整64，否则**一律整32（不读 L/LL/U/UL/ULL）**；浮点字面量**一律浮64（不读 f）**。
- **同族**：#1264（`取(4000000000L)` 选整32 静默截断·巨值形态）、#1263（混合字面量歧义）、#745。
  本件是 #1264 的低值/浮点扩面（#1264 只处理值域失守，低值 1L 仍错选）。
- **联想**：`1UL`/`1LL`/`1.5f`/字面量负号（`-1` 推导空段→通配）全部同通道；
  修复须与 001 §3.7a「带后缀字面量按后缀定级」和宿主 `literalTypeOf` 同源。

### D5〔#1397·P1·v2〕字符串 NUL 转义被删除 + 空串驻留哨兵致解析中止

- d01 `"a\0b"`：宿主长度 1（C 串截断，s[1] 越界 rc=2）；v2 长度 **2**（NUL 被删除，非 3）；
- m13 四形态：`"ab"`/`"a\0"`/`"\0"`/`"a\0b"` 同句 → v2 **解析中止**
  「函数调用实参表缺少右括号 ')'」；宿主可编译。
- 根因：`词法/词法分析.cn 解码字符串内容` 的 `\0` 分支 `内容 + 字符串子串("\0", 0, 1)`——
  该字面量的有效 C 串长度为 0 → 子串返回空串 → **NUL 被静默删除**；空串 `驻留` 返回 0
  （哨兵）→ token 文本 0 → 语法层 token 流截断（m13 的错误由此而来）。
- **同族**：#1239 哨兵禁令、02 §字符串字节口径、#802（unicode 转义文案）。
- **立法缺口**：内嵌 NUL 的字符串长度语义（字节 3 / C 截断 1）001 未明文，须呈报裁决后
  双侧对齐（本件先修 v2「删除 NUL + 空串 0 哨兵」两条机制缺陷）。
