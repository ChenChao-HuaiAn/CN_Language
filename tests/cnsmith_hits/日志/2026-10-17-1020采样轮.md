### H1〔P1·双侧同病〕抽象方法不进虚表 → 抽象静态类型调用生成直调纯虚符号 LNK2019
- **现象**：`抽象 函数 f()` 声明 + 子类 `重写` + 通过抽象基类**引用或指针**调用
  → 宿主与 v2 **双侧**同点 LNK2019：`无法解析的外部符号 ?甲$f@@Y`（m01/m02/p04/a03 四探针）。
- **根因（宿主已锁）**：parser_oop.cpp `parseMethodModifiers` 对 `抽象` 只设 `isAbstract=true`，
  **未设 isVirtual**；class_resolver.cpp `assignVtable`（~840 行）过滤条件
  `if (!mi.isVirtual && !mi.isOverride) continue;` → 抽象方法**缺席虚表**；调用点遂按「非虚方法」
  生成对 `甲::f` 的直调符号，而纯虚无体无符号 → 链接失败。对照：`虚拟 函数` 显式修饰则一切正常
  （m03 宿主输出 3）。**旁证**：接口方法在 class_resolver.cpp:385 被强设 `isVirtual=true`（作者已
  意识到「无体=须虚」），唯类抽象声明遗漏同款映射。
- **v2 同病**：m01/m02 v2 同符号 LNK2019（v2 修饰位 8=256 抽象 vs 位6虚拟/位7重写——抽象位未映射
  虚语义·解析类.cn/分派链同构缺失）。修法=双侧同修（宿主 parser 或 class_resolver 单点；v2 修饰位映射）。
- **同族边界（实测矩阵·全阴性对照）**：
  - a01 抽象方法经**具体类直调** → 双侧绿（乙::f 有符号）→ 病限定「抽象静态类型的调用」
  - a02 抽象+并行虚方法 g 槽位 → 双侧绿（输出 20/20）→ 无槽位污染
  - a04 三级重写（甲抽象→乙重写3→丙重写5）经 乙* → 双侧绿（5/3 正确）→ **「槽位分裂静默错值」
    假说被实测否定**（阴性存照）
  - a03（862 形态）：非抽象重写 面积 通过 几何& 绿；抽象 周长 同 LNK → 病与「接口中间层」无关
- **立法对照**：§5.6「抽象成员=纯虚声明」——纯虚即虚；LNK2019 既非合法接受也非语义拒绝，
  属编译失败级缺陷（合法多态程序被拒）。

### H2〔P1·v2 独有·安全级〕v2 局部引用变量 + 成员访问全形态病（崩溃/空指针）
- **现象**（宿主全部正常·输出 3/7）：
  | 探针 | 形态 | v2 结果 |
  |---|---|---|
  | m03 | `甲& 参 = 对; 参.f()`（虚方法） | C0000005 访问违例崩 |
  | b02 | `参.x`（字段读） | C0000005 崩（RAX=7 当指针解引用） |
  | b03 | `参.x = 7`（字段写） | 运行时错误(错误码3) 空指针解引用 |
  | b05 | 重赋 `对` 后 `参.x`（别名语义） | C0000005 崩 |
  | b01 | `参.非虚方法()`（直调） | **绿** |
  | b04 | `函数 取(甲& 参)` 引用**形参** + 虚调 | **绿** |
- **根因指向（asm 对照实锤）**：v2 对局部引用变量的成员访问生成**双重解引用错位**：
  `mov rax,[rbp-56]`（引用槽）→ `mov rax,[rax]`（提前取 vtable）→ 存值槽 → 调用点
  `mov rcx,[该槽]; mov rax,[rcx]; call [rax]`（又按对象指针取 vtable）——同一值被两种语义消费。
  宿主基准（m03 asm）：`mov r13,[r12]; mov rcx,r13; mov rax,[rax]; mov rax,[rax+0]; call rax`
  单链正确。落点=v2「引用变量加载」与「成员/虚表派生（op=44）」与「调用点」三处的
  IR 降级语义不一致（引用形参路径正确→限定於**局部引用变量**）。
- **同族边界**：引用形参（b04）绿——波及面=局部 `类& 变量` 声明形态（含字段读写/虚调）。
- **安全级**：越权解引用（把字段值/空值当指针）——C0000005 与错误码3 都非「确定性安全失败」
  的合法终态（前者=脏崩溃）。

### H3〔P1·分叉〕v2 接口三查③「须用 虚拟 或 重写 修饰」检查恒 fail-open（三形态零拒绝）
- **现象**：宿主拒（「类 'X' 实现接口方法 'Y' 时须用 虚拟 或 重写 修饰」）；v2 放行。
  三形态全放行：n03（含构造+计数体）/n03b（无构造）/n03c（**E2E-712 同构仅去「重写」**）。
- **根因**：v2 语义分析尾.cn `方法定义层是虚修饰()` 遍历类节点成员匹配方法未命中时
  **落到末尾 `返回 真`（防御放行）**——注释自承「类节点未登记=防御放行」；实测该方法**从无命中**
  （三形态零拒绝；n02 签名不一致能拒=走的第三段「签名比对」，修饰段从未真正拦截）。
  即 413-b「宿主同款强制」在 v2 是**死路径/miss→静默放行**——648「miss 不可静默」又一实例。
- **修法指向**：定位匹配失效层（类节点 子起点/子终点 区间遍历 or `成员v.文本` 域）+
  fail-open 改 fail-closed（未命中=内部错误显形 per 648，或返回假由齐全性诊断接管）。
- **对照绿**：c01（实现方法写 `虚拟`）双侧绿——「虚拟 或 重写」两者皆可口径正确。

### H4〔P1·分叉·安全级〕v2 布局环检测显式豁免「数组字段」→ 值字段自含数组放行

  宿主布局环检测递归数组元素类型故双侧分叉。v2 放行后布局求解的错值危害面待量化

### H5〔P1·分叉〕命令行 `-D 中文宏名` 宿主不命中（argv GBK vs 源文件 UTF-8）
- **现象**：`-D 注入旗标` → 宿主输出「注入未命中」/ v2 输出「注入命中」；ASCII 宏名
  `-D TESTFLAG` 宿主正常命中。
- **根因（双侧证据链闭环）**：宿主 cn_main 窄 `main` → MSVC CRT 把宽命令行转 **ANSI（GBK）**；
  `options.macros`（std::string 集合）持 GBK 字节，与源码（UTF-8）中 `#如果定义 注入旗标` 的
  UTF-8 宏名比较恒不等 → 中文宏名永不命中。v2 `系统::参数`（system_api.cpp）走
  `GetCommandLineW + CommandLineToArgvW + WideCharToMultiByte(CP_UTF8)` → UTF-8 命中。
- **影响面**：仅「与源文本比较」的中文参数（-D 单点）；--output/货舱 路径走文件 API 不受影响
  （e01 特性旗标【货舱.toml 读取·UTF-8】双侧绿佐证）。E2E 24 注释自承「命令行宏注入由单元
  测试验证」——单测直接构造 options.macros 绕过 argv 编码，故该缺陷至今未被捕获。
- **修法**：宿主取参改宽字符 + UTF-8（对齐 v2 单点）。

## 方法论
- v2p CLI=位置参数 `v2p <源绝对路径> win-x64 [旗标...]`；ml64→link @rsp（`/ENTRY:WinMainCRTStartup`+
  v2p.obj 借链+/FORCE:MULTIPLE·v2asm.obj 在前）；运行时 objs 15 件（含 mem_pool）。
- 工作目录一律 ASCII（ml64/link 中文路径 GBK 误读 LNK1181）；探针源码目录中文无妨。
- 探针多文件（模块系统）：整目录拷贝·模块名=文件名·`导入 模块名::符号`。
- `-D 宏名` 是**两个参数**（编译选项.txt 须分两行）；中文宏名另见 H5。
- CN-Smith 随机轨道并发偶发假 build_err（>1 jobs 时 ml64 -1）——甄别法=单线程重跑。
- 判据复用 runner.py：正例=双侧编译运行+逐行输出一致；负例=双侧拒绝（含产物纪律）。
