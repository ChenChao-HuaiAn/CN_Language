## 工程纪律（第 586 轮：git quotepath 转义使中文路径写集被静默降级快速门禁——集成工具的门禁分类必须有反证自检；权重 9，2026-09-21）

**现象**：586-a 摘取 568 转批面（93 个 tests/e2e 通道文件·目录名全中文）走 integrate.py 集成，日志显示「快速门禁」后直接 push 成功（83de088a）——按 §8.2 写集触及 tests/ 应跑全量门禁。根因=git diff --name-only 默认 core.quotepath=true 对非 ASCII 路径输出带前导双引号的八进制转义形态，分类写集() 的 startswith("tests/") 对带引号路径恒假→**触及中文路径的写集全部被静默判为纯文档**。连带受害=冲突标记检查的 仓库根/文件 拼装（带引号路径 exists()=False→检查静默 skip）。本项目 tests/e2e 与 CN语言编译器v2 目录名以中文为主——**自设施启用以来所有中文路径写集的集成都被降级**（仅当写集恰好含 src/ 等 ASCII 路径文件时才侥幸触发全量）。

**Why**：①「写集分类」是集成的安全分级器，其输入（git 输出解析）无任何自检——git 的显示层配置（quotepath）漏进了机器判定层，显示形态与真实路径的偏差直接变成安全判定的偏差；②本项目工具链中文路径为主而分类判据用 ASCII 前缀——配置组合的暗雷；③83de088a 集成时「快速门禁（改动 93 个文件）」的日志本身就是异常信号（93 个 tests 文件不可能是快速门禁），但无人复核日志语义=缺少「分类结果×写集面」一致性抽查。

**How to apply**：①所有解析 git 输出做机器判定的脚本，git 调用一律显式 -c core.quotepath=false（或在解析端 strip 引号+转义还原）——显示配置不得影响判定逻辑；②集成/门禁工具的写集分类要有**反证自检**（用已知中文路径写集验证分类结果=须全量）；③看集成日志时对「门禁深度×写集构成」做一致性复核（tests 文件数>0 却只跑快速门禁=立即报警），该异常信号本案已出现但被忽略。

  - **根因**: ①**「一次性预扫 + 生成期基线」两种设计共存时预扫污染了基线依据**——预扫登记先于生成，使「基线 = 当时名单大小」的语义失效（基线机制的前提是「名单随生成进度增长」）；这类失效**静默**（编译通过、运行不崩、只是不释放）；②**RAII 出口覆盖面按路径枚举时漏了跳出路径**（宿主 72-a 补齐，v2 侧未同步——双侧同族缺口只修一侧是复发主因，lessons 第七十二轮预防⑥同族）；③**多路径共享槽不清零**——不截断名单意味着同一变量会被「跳出释放」与「函数级兜底」**两条路径**经过，若释放后不清零，第二次就是 double free（宿主 72-a 用「释放+清零」幂等模型已给出范式，v2 未同步）。
  - **解决**: ①**登记时机对齐宿主**——预扫职责收敛为「槽分配 + 入口零初始化 + 类型登记」，名单追加移至生成期（`生成变量声明` 字符串拥有化初始化后 / `生成容器局部` 非返回接收分支）+ 新增 `名单追加去重`（v2 局部槽=函数级映射，同名合槽须去重）；②**跳出 drop-on-jump**——`函数IR` 新增三枚循环体基线（`生成当` 进入体块前记录/退出后恢复，嵌套循环自然正确）+ 新增 `循环跳出析构`（按最近循环体基线释放，编译期名单**不截断**——同块内互斥路径（如「如果{中断}」与自然结束）各自仍须发射释放，截断会让另一路径无变量可释）；③**「释放+清零」幂等模型**——`函数IR.零寄存器`（预扫回填，函数入口常量 0 的寄存器号）+ 三处释放点（块出口析构容器/字符串段、结构体容器字段级联）释放后槽清零（容器字段须先另存字段地址寄存器再清零——加载会把值寄存器指向对象）；④`块出口析构` 新增 `截断` 参数（块出口=真/跳出=假，不截断模式遍历用下标递减防死循环）；⑤连带 v2 内置表补 `内存::活动分配数`（E2E 断言口径）。
  - **成效与防线**: 五形态（继续/中断/自然回边/如果体/容器跳出）20 万轮级残留 **199,999 → 0**（归零闭环，LD_PRELOAD 读 `__cn_alloc_live`）；v2p 编译 v2 树退出残留 2,755,596 → 2,757,891（同量级=编译器自身常驻结构）；**E2E 216_v2_块级作用域RAII内存回归**（七形态差值恒 0 + 内容校验，退出码 127）转正为门禁（宿主 213 的 v2 对应件，两侧防线自此对称）；悬垂风险扫描 = 0 命中（全树「块内声明→容器追加/静态存储/返回」零处，v2 树已按 A2 纪律迁移）。验证链：清场重建零警告 + 单测 1289/1289 + E2E **238 用例 233 过**（唯一败=194 既有待批）/4 跳 + 固定点 **266845**（新口径）逐字节一致 + 对拍 29/29。

## 工程纪律（第 296-a 轮：v2 节点池「子终点=建节点时 池.大小()=本节点自身索引」惯例——宿主端点直觉移植必错一档；权重 8，2026-09-17）

**事件**（296-a D35 波B：v2 错误传播 ? 全链实施）：宿主 `UnaryExpr(Propagate)` 是嵌套 AST（操作数=子节点指针），移植到 v2 平铺池模型时按「本节点居末位、操作数段=[子起点, 子终点-1)」直觉实现——结果语义检查把 `底层(v)?` 的操作数末节点定位到**实参 v**（推导出 整32）而非**调用节点**（结果$整32$整32），误报「操作数须为 结果/可选 类型」。真因=v2 建节点惯例：`池追加(池, 建节点(..., 整32(池.大小())))` 的 `池.大小()` 在追加**前**求值，故 节点_三元运算 等「区间尾节点」的 子终点=自身索引——操作数段=[子起点, 子终点)、末节点索引=子终点-1（三元消费方 生成三元运算 即按此约定取段）。

**教训一：移植宿主结构到 v2 平铺池，区间端点语义必须先对齐既有消费方（不只对齐宿主直觉）**——同一字段名（子终点）在两个代码库承载不同端点约定；判据=找一个既有同构节点（三元）读它的生产方（解析）与消费方（生成）各怎么用，禁止只看一处。

**教训二：后缀运算符在「平铺池+尾段判定」解析模型中的优先级须显式续接**——宿主错误传播 `?` 在 parsePostfix（后缀层，高于二元）消费，`x? + 1` 自然成立；v2 的 `?` 判定在二元链**之后**（尾段），错误传播建节点后若直接返回，`+ 1` 无人消费=「语句缺少分号」假象（60 用例行 30 实锤）。修法=建节点后**重复二元链判定**（左起点=起始·含传播节点），右结合三元递归同理保留。



## 306-a 事故轮（T21 首版主分发死循环 28.7GB OOM 连坐 ZCode——同一口径两处分叉=死循环签名；权重 9，2026-09-17）

- **教训② 收紧型改造必须带「拒绝路径消费性」验证**：任何「不再接受 X」的改造，X 落入的兜底路径必须验证**会消费输入**（ lexer 未知字符 default 分支 advance+诊断=安全；不消费=死循环）。验收探针：把被拒形态喂给编译器+内存上限（ulimit -v）+timeout，三个都过才算收紧完成（本次首版只验了「合法面通过」没验「拒绝面终止」——恰好漏掉致命半边）。
