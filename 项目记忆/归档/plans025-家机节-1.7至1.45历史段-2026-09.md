### 1.11 【701-a 在飞】002 收口续·v2 全局 128 位静态初始化发射修正（分支 `任务/家机-701-静态128发射`·基线 develop f5a4e233·wt701 独立树·2026-09-24）

**目标与验收判据**：根治 v2 侧 483_全局128静态初始化 双测失败（ml64 `error A2071: initializer magnitude too large for specified size`）——对齐宿主 467-a（T46）方案：128 位类型静态槽发射**双 quad**（低 64 位在前）。

**根因（699-a 定位·铁证）**：`代码生成.cn` `发射静态槽数据段`（约 1238~1277 行）分派=「`查结构体大小(类型) > 8` → 多槽 `dq 0,0,…`（忽略初值）；否则 → 单槽 `dq 初始值`」——128 位整数（16 字节）非结构体、`查结构体大小` 返回 ≤8 → 走单槽分支 → `dq 170141183460469231731687303715884105727` 超 64 位字面量容量 → ml64 A2071。**注：该缺口 467-a 当时已登记「v2 侧同面缺口（单 dq+槽 8 字节）」，本轮清偿**。

**初值文本形态（必须按此实现·699-a 源码实证）**：`程序.静态初始值们` 元素=**驻留文本 ID**；标量静态经 `IR/IR布局.cn:556 折叠常量值` 得 = 整数字面量**原文**（单节点=字面量文本；`节点_负号`+字面量= `驻留("-" + 文本)`）；容器静态恒 `驻留("0")`。即文本可能为 `42` / `-5` / `170141183460469231731687303715884105727` / `-170141183460469231731687303715884105728` / `0xDEADBEEFCAFEBABE` / `0`。

**实施方案（对齐宿主 `types::parseInt128InitText`·半字分解法）**：
1. **新增 CN 侧解析函数**（置于 `代码生成.cn` 静态段邻域或复用层）：`不安全 函数 解析128初值文本(字符串 文本, 布尔 有符号, 整64& 低出, 整64& 高出) -> 布尔`——①去首尾空白；②`"lo:hi"` 冒号十六进制两段形态（IR 常量约定·直接直读两段）；③符号 `+/-`（负数→two's complement 取反加一）；④进制前缀 `0x/0X/0b/0B/0o/0O`（默认 10）；⑤**逐位累加**：`(hi:lo) = (hi:lo)*base + d`，用 **u64 半字分解**（loLo/loHi/hiLo/hiHi × base + carry，各项 < 2^37 无溢出）——**不得依赖 CN 的 整128 运算**（避免与被修对象同源；宿主同款手工分解）。

3. **三后端同步**：`代码生成X64Linux.cn:1129`、`代码生成ARM64.cn:1066` 同面同改（ARM64 GAS 用 `.quad` 低, 高 两行）——**跨平台同族面一次改齐**（禁只改 win）。
4. **需注入面复核**：128 位标量若走 `静态需注入们` 路径（运行期构造写回）需确认与 .data 直存不冲突（`查结构体大小(类型) > 0 → 需注入` 对 128 位返回 0=直存 ✓ 实证待跑）。
