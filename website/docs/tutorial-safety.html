安全与并发

CN 的两条最高准绳：性能超过 C++ 编译器，安全接近 Rust——悬垂、越界、泄漏零容忍。 这一章讲它如何做到。

所有权与转移

字符串、容器、类对象这类「资源类型」有唯一的拥有者。 用内置函数 转移() 显式交接所有权（对标 C++ std::move）， 被转移的变量从此禁用——编译器替你盯着：

转移.cnCN

函数 主() -> 整32 {
    变量 v = 向量<整64>();
    变量 u = 转移(v);       // u 接管 v 的值
    // 打印行(v.大小());    // ✗ 编译错误：'v' 已转移，不能继续使用

    变量 w = 向量<整64>();
    w = u;                  // ✗ 纯赋值可以复活 v？不——这是 u 到 w 的拷贝
    返回 0;
}

两条贴心规则：

  • 赋值复活：转移后对源变量纯赋值（v = 表达式;） 视为重新初始化，之后可以继续用——不需要新的声明。
  • 最后使用消除（LUE）：如果拷贝之后源变量再也不用， 编译器自动把拷贝降级为转移（零拷贝）——多数时候你不需要手写 转移()。

lue.cnCN

函数 消费(字符串 s) -> 空类型 {
    打印行(s);
}

函数 主() -> 整32 {
    变量 名 = 字符串复制("甲");
    消费(名);        // 名 在此之后不再出现 → 编译器自动转移，零拷贝
    返回 0;
}

只读借用

常量 类型& 参数是只读借用（对标 Rust &T）： 函数体内不许改它，也不能把它再借给可变引用——借用互斥在编译期检查：

借用.cnCN

函数 求和(常量 向量<整64>& 数据) -> 整64 {
    整64 合 = 0;
    遍历 数据 中 每个 x { 合 = 合 + x; }
    返回 合;      // 数据只读：改动它 = 编译错误
}

不安全函数

底层指针操作（指针算术、裸下标写、联合体访问等）只允许出现在 不安全 函数 体内；安全代码里调用它是允许的——责任上移到标注处， 审计有明确的边界：

不安全.cnCN

不安全 函数 裸改(整64* p) -> 整64 {
    整64* q = p + 1;   // 指针算术：仅不安全函数内合法
    q[0] = 7;          // 指针下标写：同上
    返回 q[0];
}

同时，数组越界与空指针解引用在安全代码里默认有运行时检查 （-O2 亦生效），常量下标越界/除零则直接是编译期硬错误。

结果与可选：没有空指针异常的错误处理

可能失败的函数返回 结果<T, E>（成功=正常值，失败=错误码）， 可能缺席的值用 可选<T>。编译器强制你检查： 不检查就使用 = 编译错误（对标 Rust must_use）：

错误处理.cnCN

函数 除法(整32 a, 整32 b) -> 结果<整32, 整32> {
    如果 b == 0 {
        返回 错误(1);     // 错误码 1：除零
    }
    返回 正常(a / b);
}

函数 主() -> 整32 {
    结果<整32, 整32> 商 = 除法(10, 0);
    如果 商.正常 {
        打印行(商.值);
    } 否则 {
        打印行("除零错误: ", 商.错误);
    }
    返回 0;
}

后缀 ? 一键传播：正常取值继续，失败沿调用链上抛（Rust ? 同语义）：

传播.cnCN

函数 除法传播(整32 a, 整32 b) -> 结果<整32, 整32> {
    整32 结果值 = 除法(a, b)?;   // 失败则本函数立即返回该错误
    返回 正常(结果值);
}

线程与互斥锁

标准库 线程 模块提供 新线程(入口, 实参)。 进入新线程的值必须是「可搬运」的——编译器自动推导（对标 Rust Send）： 标量、字符串、函数指针恒可搬运；含裸指针字段的类型默认不可搬运， 跨线程传递 = 编译错误。数据竞争的温床在类型层面被拆除。

共享可变数据用 互斥锁<T>：锁与受护数据类型化绑定 （拿 A 锁护 B 数据的错误在类型检查下不可表达）：

互斥锁.cnCN

导入 线程::互斥锁;

函数 主() -> 整32 {
    互斥锁<整32> 计数 = 互斥锁(0);

    // 受护数据经 .值 字段访问，上锁/解锁 显式成对
    计数.上锁();
    计数.值 = 计数.值 + 1;
    计数.解锁();

    打印行(计数.值);   // 1
    返回 0;
}
诚实边界（当前实现状态） ①互斥锁第一版为显式 上锁()/解锁() 对，RAII 锁守卫随析构链成熟另立；②未上锁直接访问 .值 目前不拦（文档如实标注， 收紧为编译期拒绝已在计划内）；③Windows 后端的线程功能在推进中（Linux x64 为真 pthread 实现）。 语言仍在快速演进，以仓库最新公告为准。

安全哲学小结

原则含义
默认路径零规则正常写代码不需要标注或注解
显式 转移()想要性能时，显式交接所有权
危险面收口 不安全底层操作限定在显式标注的函数内
拷贝消除是编译器义务LUE 自动降级拷贝为转移，不牺牲表达力
