内存模型、指针与不安全域、手动内存、FFI、优化与调试——写给要压榨机器的开发者。

内存模型：三种生存期

CN 只有三种内存生存期，每种都有明确的所有者——理解了这张表，内存安全就不用背规则。

生存期谁分配/谁释放例子
栈（自动）编译器：进入作用域分配、退出释放（含类字段/容器元素级联）局部标量/结构体/类实例/容器
堆（拥有）拥有者变量：字符串/容器在声明处分配、作用域结束自动释放（RAII）字符串 变量、向量<T> 底层数组
堆（手动）你：分配 拿、释放 还——须在 不安全 域内分配(n) 返回的 空类型*

RAII 展示.cnCN

导入 容器::向量;

函数 主() -> 整32 {
    字符串 s = "堆上";            // 拥有型：分配落堆
    向量<字符串> 表 = 向量<字符串>();
    结果<空类型, 整32> 加 = 表.追加("元素一");
    加 = 表.追加("元素二");
    返回 0;                        // s、表、表内元素全部自动释放
}
泄漏统计随手可查内存::活动分配数() 返回当前未释放块数——程序收尾处断言它为 0，泄漏当场现形（见 内置函数·内存）。

安全区边界：不安全 域

CN 的安全默认不靠运行时罚站——危险操作（裸指针解引用/下标、手动分配释放、联合体字段访问）在编译期就要求位于 不安全 函数 内，把审计责任显式化。

边界外.cn（负例·编译拒绝）CN

函数 主() -> 整32 {
    整32 值 = 41;
    整32* p = &值;        // 取地址：安全（出参惯用法通道）
    打印(p[0]);           // ✗ 编译错误：[安全区边界] 指针下标读应在 不安全 函数 内
    返回 0;
}

正确形态.cnCN

不安全 函数 经指针改(整32* p, 整32 新值) -> 空类型 {
    p[0] = 新值;          // 下标写=解引用（p[0] 等价 *p，规避行首歧义）
}

函数 主() -> 整32 {
    整32 值 = 41;
    经指针改(&值, 42);
    打印(值);
    返回 0;
}

输出：42

  • 不安全 函数 整体放行危险面；不安全 块/表达式形态随语言演进以源码实测为准。
  • 标准库容器内部全是不安全域，但使用容器不需要不安全——危险面被库收口，这正是安全区的意义。
  • 不安全 是保留字（46 个保留字之一）。

手动内存：分配/释放/重新分配

逃生舱四件套对标 C（malloc/free/realloc/memcpy）；另有统计族（泄漏检测）与竞技场族（进程级一次性分配）。

动态数组.cnCN

不安全 函数 主() -> 整32 {   // 手动内存=不安全域
    整64* 表 = 分配(4 * 类型大小(整64));   // 4 个整64 槽
    循环 (整64 i = 0; i < 4; i++) { 表[i] = (i + 1) * 100; }
    空类型* 更大块 = 重新分配(表, 8 * 类型大小(整64));
    整64* 大表 = 更大块;                     // 旧值保留
    打印(大表[0], " ", 大表[3]);
    释放(大表);
    返回 0;
}
  • 企业级建议：动态容器直接用标准库 向量——扩容翻倍+RAII+元素析构全替你管好；手动内存留给 FFI 边界与极致优化点。
  • 重新分配 对 >2GiB 请求拒绝（stderr 诊断+返回 无）——垃圾尺寸静默失败会在解引用时崩，可观测拒绝前置。
  • 竞技场族（内存::竞技场分配）适合编译器式「长生命周期+一次分配」负载：只进不出，内存::竞技场重置 一次全清。

FFI：与 C 互操作

CN 与 C 的 ABI 天然互通：外部函数声明+--链接 库名；字符串边界遵守「借用/拥有」契约（字符* 借用视图 vs 字符串 拥有串）。

FFI.cn（C 运行时函数直调·三平台默认链接 libc/ucrt）CN

外部 函数 strlen(字符串 s) -> 整64

不安全 函数 主() -> 整32 {
    打印(strlen("中文"));     // 6（UTF-8 两汉字 3+3 字节）
    返回 0;
}

输出：6

  • 链接：cn build 程序.cn --链接 库名（可多次）；库搜索遵循平台惯例。
  • 字符串契约：字符*=借用（C 层持有的视图，不释放）；字符串=拥有（RAII）。借用转拥有用 字符串复制，反之直接传。
  • 整64 标量 FFI 形参的 arm64 传参 ABI 有在案限制（大值塌缩），跨平台 FFI 密集场景关注 仓库 021 总账 #110。

字符串与容器的性能面

拥有型字符串的每一次 + 都是分配+拷贝。高频拼接用字符串构建器（摊销 O(n)），高频读取用引用访问。

构建器.cnCN

函数 主() -> 整32 {
    整64 建 = 字符串构建器::新建();
    循环 (整32 i = 0; i < 1000; i++) {
        字符串构建器::追加(建, "行" + 整数转字符串(i) + "\n");
    }
    字符串 全文 = 字符串构建器::完成(建);
    打印(字符串长度(全文));
    返回 0;
}

引用读取避深拷.cnCN

导入 容器::向量;

函数 主() -> 整32 {
    向量<整64> 表 = 向量<整64>();
    循环 (整64 i = 0; i < 100; i++) { 结果<空类型, 整32> 加 = 表.追加(i); }
    整64 和 = 0;
    循环 (整64 i = 0; i < 100; i++) {
        和 = 和 + 表.元素(i);          // 副本读取（标量无拷贝负担）
    }
    表.元素引用(0) = 999;              // 引用写穿（不安全域·零拷贝）
    打印(和, " ", 表.元素(0));
    返回 0;
}

优化级别与调试

四级优化 -O0 ~ -O3；--debug 在汇编中嵌入源码位置注释；调试模式 编译期常量做发布/调试分支（死分支零开销消除）。

级别内容
-O0不做优化（默认）——编译最快，逐语句直译
-O1常量折叠+死代码消除+代数简化+复写传播
-O2增加 公共子表达式消除（CSE）+跨块死代码消除+寄存器分配启用
-O3增加 全局值传播

调试模式.cnCN

函数 主() -> 整32 {
    如果 (调试模式) {
        打印("[调试构建]");      // --发布 构建时整支直取消除
    }
    打印("核心逻辑");
    返回 0;
}
  • 调试模式 两个分支都做完整语义检查（区别于条件编译——不存在裁剪盲区）；未选中分支零运行时开销。
  • 调试实战：cn build 程序.cn --debug -O0 产出的汇编带源码行注记，配合 cn ir 程序.cn / cn ast 程序.cn 可逐层下探（详见 命令行参考）。

自举与双编译对照（项目故事）

CN 的终极目标是用 CN 编译器自己编译 CN 编译器。项目保持「宿主 C++ 实现」与「v2 CN 自举实现」两套功能完全一致的编译器，全部测试双跑对照（dual）——这也是文档示例可信的根基。

  • 自举固定点：v2 编译出的编译器再编译自己，产物逐字节一致（fix_p ≡ fix_s）——语言已完备到能承载自身工具链。
  • 双编译对照：每个用例同时跑宿主与 v2 两侧，任何行为分叉=缺陷（零分叉红线）。你看到的文档输出都经此流程。
  • 性能双目标：①编译速度对标 C++ 编译器；②内存安全对标 Rust（悬垂/越界/泄漏零容忍）——冲突时提交用户裁决。
